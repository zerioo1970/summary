# 账户文件迁移工具（ProfileCopy）

在 Windows 上新建账户后，把旧账户的桌面、文档、下载、图片等文件复制到新账户。
只复制**用户自己的数据**，不复制旧账户的设置（注册表 `NTUSER.DAT`、整个 `AppData`），避免把旧配置文件的问题（例如 ProfWiz 迁移后图标闪烁）一起带过去。

> ⚠️ 本程序在 Linux 上编译通过，**还没有在 Windows 上实际运行过**。正式使用前请先按下面的“测试步骤”在一台测试电脑上试一遍。

## 运行环境

| 项目 | 要求 |
|---|---|
| 系统 | Windows 10 / 11（自带 .NET Framework 4.8，不用另装） |
| 权限 | 管理员。双击时会弹出 UAC 窗口；新账户不是管理员时，输入一个管理员账户的密码即可 |
| 文件 | 只有一个 `发布/ProfileCopy.exe`（约 30 KB），复制到 U 盘或共享文件夹直接运行 |

## 使用步骤

1. **重启电脑**，保证旧账户已经完全注销。
2. 用**新账户**登录一次（第一次登录会生成 `C:\Users\新账户`），关闭 Chrome、Edge、Outlook、Word、便笺。
3. 双击 `ProfileCopy.exe`，在 UAC 窗口里点“是”或输入管理员密码。
4. **新账户**：程序会自动选中当前登录的账户，一般不用改。
5. **旧账户**：在下拉框里选。旧域的账户会显示为“未知账户（S-1-5-21-…）”，看后面的文件夹路径来认。
   列表里没有的，点“其他文件夹…”直接选 `C:\Users\旧账户` 文件夹。
6. 在列表里打钩选择要复制的项目。“大小”一列显示旧账户里这一项有多大，“没有”表示旧账户里不存在。
7. 选择同名文件的处理方式，点“开始复制”，确认后开始。
8. 完成后，新账户桌面上会有一个 `迁移日志_日期_时间.txt`，记录了每一项复制了哪些文件、有没有失败。

## 可以复制的项目

| 分组 | 项目 | 默认打钩 |
|---|---|---|
| 文件夹 | 桌面、文档、下载、图片、视频、音乐、收藏夹（IE） | ✅ |
| 文件夹 | 链接、联系人、保存的游戏、Outlook 签名 | |
| 单个文件 | Word 默认模板（Normal.dotm）、Chrome 书签、Edge 书签、便笺 | |

微信（`Documents\WeChat Files`）、QQ（`Documents\Tencent Files`）、Outlook 邮件存档（`Documents\Outlook Files\*.pst`）默认都在“文档”里，勾选“文档”就会一起复制。

## 复制规则

| 规则 | 说明 |
|---|---|
| 复制工具 | 调用 Windows 自带的 `robocopy`，失败重试 1 次 |
| 权限 | 不复制旧账户的文件权限，复制过去的文件自动使用新账户的权限 |
| 跳过的内容 | 链接文件夹（如“我的音乐”）、`desktop.ini`、`Thumbs.db`、Office 临时文件 `~$*` |
| 同名文件 · 跳过（默认） | 新账户里已有的文件一律不动，只复制新账户里没有的 |
| 同名文件 · 覆盖 | 旧账户里的文件较新时，替换新账户里的 |
| 单个文件 | 总是覆盖。覆盖前把新账户里原来的文件改名为 `文件名.bak-时间` 备份 |
| 停止 | 点“停止”会结束当前项目，后面的项目不再开始；已经复制的文件保留 |

## 不会迁移的内容（需要在新账户里重新设置）

- 浏览器保存的**密码**：按 Windows 账户加密，复制过去也打不开。请在旧账户里用浏览器的“导出密码”导出，或在新账户里登录浏览器账号同步。
- 网络驱动器、打印机、默认程序、输入法、壁纸、任务栏图标、各软件的登录状态。
- 个人证书（U 盾、数字证书）：先在旧账户里导出，再在新账户里导入。
- 如果旧账户的桌面、文档被重定向到 OneDrive 或服务器，`C:\Users\旧账户\Desktop` 里可能只有很少的文件，这时“大小”一列会很小，需要另外到重定向的位置去复制。

## 测试步骤（正式使用前做一遍）

在一台测试电脑上建两个本地账户 `test1`、`test2`，`test2` 设为管理员：

1. 用 `test1` 登录，在桌面、文档、下载里各放几个文件，其中至少一个中文文件名、一个子文件夹；在 Chrome 里加两个书签。注销。
2. 用 `test2` 登录，在桌面放一个和 `test1` 桌面上**同名但内容不同**的文件。
3. 运行 `ProfileCopy.exe`，确认：
   - 新账户自动选中 `test2`；旧账户下拉框里能看到 `test1`，“大小”一列有数字。
4. 勾选桌面、文档、下载、Chrome 书签，选“跳过”，开始复制。确认：
   - 所有文件都到了 `test2` 的对应文件夹，中文文件名正常；
   - 第 2 步那个同名文件**没有**被替换；
   - 打开 Chrome，能看到 `test1` 的书签；
   - 桌面上的迁移日志用记事本打开不乱码。
5. 再运行一次，选“覆盖”，确认第 2 步那个同名文件在 `test1` 的更新时才会被替换。
6. 用 `test1` 登录着（不注销），切换用户到 `test2` 运行程序，确认会提示“旧账户目前还登录着”。

测试中发现任何问题，把迁移日志的内容和界面截图发给 Kiro。

## 自己编译

源代码在 `src/ProfileCopy/`。在 VS 2026 里打开 `ProfileCopy.csproj` 生成即可；或在该目录执行：

```
dotnet build -c Release
```

生成的文件在 `bin/Release/net48/ProfileCopy.exe`（`ProfileCopy.exe.config` 和 `.pdb` 不需要复制）。

| 文件 | 内容 |
|---|---|
| `Program.cs` | 程序入口，检查管理员权限 |
| `MainForm.cs` | 窗口界面、计算大小、按顺序复制各项目 |
| `Profiles.cs` | 从注册表读出本机所有配置文件；取当前登录的账户 |
| `CopyItems.cs` | 可勾选项目的清单，想增减项目改这里 |
| `CopyRunner.cs` | 调用 robocopy、读取输出、翻译退出码 |
| `app.manifest` | 要求管理员权限、高分辨率屏幕支持 |
