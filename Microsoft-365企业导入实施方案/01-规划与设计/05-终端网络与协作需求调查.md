## 1.15 Office 版本、宏、插件和业务系统调查

Microsoft 365 Apps 与普通文档通常兼容，但企业真正的风险常来自 VBA 宏、COM 插件、旧格式文件和第三方系统集成。

### 1.15.1 电脑端调查字段

- 当前 Office 产品和版本。
- 32 位或 64 位。
- 安装语言。
- Windows 或 macOS 版本。
- Office 安装来源和激活方式。
- 是否使用 Outlook 本地 PST。
- 是否有 Access 数据库。
- 是否使用 Excel VBA、XLL、COM 或 VSTO 插件。
- 是否有 Word 模板、邮件合并或电子签章插件。
- 是否有财务、ERP、CRM、OA 调用 Office 的功能。
- 是否需要共享电脑激活、远程桌面或虚拟桌面。
- 是否存在旧版 Office 必须保留的原因。
- 当前版本是否仍受支持连接 Exchange Online、SharePoint Online 和 OneDrive。
- 客户端是否支持 TLS 1.2 和现代身份验证。

截至本篇复核日期，Office 2016 和 Office 2019 连接 Microsoft 365 服务已经不在支持范围内；Office LTSC 2021 的服务连接支持截止日期为 2026-10-13。旧版本有时仍能连接，不代表这种连接受微软支持或能够长期稳定工作。正式部署时应根据 [Office版本与Microsoft 365服务连接支持](https://learn.microsoft.com/en-us/microsoft-365-apps/end-of-support/microsoft-365-services-connectivity) 重新核对。

### 1.15.2 兼容性分级

| 等级 | 场景 | 处理原则 |
|---|---|---|
| 低风险 | 仅编辑普通 Word、Excel、PowerPoint 文件 | 标准试点验证 |
| 中风险 | 使用模板、PST、少量签章或浏览器插件 | 逐项测试并准备替代方案 |
| 高风险 | 关键财务宏、COM 插件、Access、业务系统自动化 | 未通过测试前不得批量替换旧版 Office |

### 1.15.3 测试不能只问“能不能打开”

必须验证：

- 宏是否能执行且结果正确。
- 插件能否加载、登录和升级。
- 文件能否保存回原位置。
- 打印、PDF、电子签章是否正常。
- Outlook 插件能否创建或处理邮件。
- 业务系统导出 Excel 的格式和公式是否正确。

> **高风险：** 不要在兼容性测试前批量卸载旧版 Office。先建立试点电脑和回退方式。

## 1.16 电脑、手机、网络、代理和防火墙调查

### 1.16.1 终端设备调查

| 项目 | 需要统计 |
|---|---|
| Windows 电脑 | 数量、版本、是否加域、是否公司所有 |
| Mac | 数量、版本、管理方式 |
| 手机和平板 | iOS/Android、公司设备或个人设备 |
| 共享电脑 | 前台、车间、会议室、远程桌面 |
| 会议室设备 | 摄像头、麦克风、Teams Rooms 等 |
| 打印机/扫描仪 | 是否通过 SMTP 发送扫描件 |
| 不受支持的旧设备 | 无法升级系统或 Office 的数量 |

### 1.16.2 网络调查

每个办公地点记录：

- 互联网出口带宽及实际高峰利用率。
- 上下行是否对称。
- 是否使用集中出口、代理或 VPN。
- 是否执行 HTTPS/SSL 解密检查。
- 防火墙是否按域名、IP 或端口放行。
- DNS 是否可以解析外部 Microsoft 365 地址。
- Wi-Fi 覆盖、频段和会议室质量。
- NAT 公网地址和端口资源。
- 用户到 Microsoft 365 的延迟、抖动和丢包。
- 是否允许 UDP 和 WebSocket。

微软建议在首次部署或迁移前估算并测试带宽；Teams 尤其需要检查互联网访问、Microsoft 365 端点和实时媒体质量。可参考 [Microsoft 365 网络规划](https://learn.microsoft.com/en-us/microsoft-365/enterprise/network-planning-and-performance?view=o365-worldwide) 和 [Teams 网络准备](https://learn.microsoft.com/en-us/microsoftteams/prepare-network)。

### 1.16.3 实际测试而不是只看合同带宽

至少选择：

- 总部有线网络一台电脑。
- 总部 Wi-Fi 一台电脑。
- 每个分支机构一台电脑。
- VPN 用户一台电脑。
- 远程办公用户一台电脑。

测试普通网页、Office 登录、Outlook、OneDrive 同步和 Teams 音视频。合同写着“千兆宽带”并不能证明代理、防火墙、Wi-Fi 和跨区域路由没有问题。

### 1.16.4 Teams 带宽估算提示

Teams 会根据网络状况调整媒体质量，单个视频终端和屏幕共享可能消耗明显带宽。项目应根据“每个地点的并发参会人数”，而不是总员工数，使用 Teams 管理中心的网络规划工具或官方最新带宽说明进行估算。

> **推荐：** 不要把实时 Teams 媒体流量无条件绕回总部或全部穿过容量不足的 VPN。是否采用本地互联网出口、分流和 QoS，应由网络管理员结合安全要求测试决定。

## 1.17 Teams 会议和外部协作需求调查

### 1.17.1 业务场景调查

询问业务部门实际需要，而不是只问“要不要 Teams”：

- 只参加会议，还是也要创建团队和频道。
- 是否需要一对一聊天和群聊。
- 是否需要会议录制、转录和字幕。
- 是否需要外部人员匿名参会。
- 是否需要与其他企业 Teams 用户聊天。
- 是否需要邀请客户或供应商进入团队。
- 是否需要外部人员共同编辑文件。
- 是否有大型会议、培训或网络研讨会。
- 是否需要电话系统、呼叫队列或会议室设备。
- 是否允许安装第三方 Teams 应用。
- 会议录制需要保存多久、由谁访问。

### 1.17.2 三个容易混淆的外部场景

| 场景 | 通俗理解 | 调查重点 |
|---|---|---|
| 外部访问 | 与另一家企业的 Teams 用户聊天 | 允许哪些域名、是否双向开放 |
| 来宾访问 | 外部人员进入本企业的团队和文件空间 | 权限、MFA、定期复核和退出机制 |
| 匿名会议 | 没有登录本企业账号的人参加会议 | 大厅、演示者、录制和会议信息保护 |

### 1.17.3 必须确定的治理问题

- 谁可以创建团队。
- 团队命名规则是什么。
- 每个团队至少有几名所有者。
- 项目结束后何时归档或删除。
- 外部来宾由谁批准。
- 来宾多久复核一次。
- 谁可以录制会议。
- 文件是否允许匿名链接。

> **推荐：** 默认每个正式团队至少设置两名内部所有者，避免唯一所有者离职后无人管理。

### 1.17.4 Teams 与其他 Microsoft 365 服务的依赖

Teams 不是完全独立的聊天工具。完整体验依赖 Microsoft Entra ID、Microsoft 365 组、Exchange、SharePoint 和 OneDrive 等服务：会议与日历会使用 Exchange；团队和频道文件存放在 SharePoint；聊天中分享的个人文件通常使用 OneDrive；团队成员关系与 Microsoft 365 组相关。因此，Teams 试点不能只验证“能聊天”，还要验证会议日历、文件上传与共享、搜索、权限和离职交接。

这不表示所有用户邮箱都必须先迁移到 Exchange Online 才能使用 Teams。微软支持用户邮箱位于 Exchange Online，也支持在满足版本、身份同步和 Exchange 混合配置要求时使用本地 Exchange 邮箱；但不同拓扑下的会议管理、日历和其他集成功能可能不同。项目应按实际邮件拓扑核对 [Exchange 与 Microsoft Teams 的交互要求](https://learn.microsoft.com/en-us/microsoftteams/exchange-teams-interact)，不能仅凭“已有本地邮箱”或“可以聊天”判断完整功能可用。

## 1.18 文件存储、共享、保留和备份需求调查

### 1.18.1 现有文件来源

- 员工电脑桌面和“文档”文件夹。
- 本地文件服务器和共享盘。
- NAS。
- 旧 SharePoint Server。
- 其他云盘。
- Teams 或 OneDrive 试用环境。
- 邮件附件和个人 PST。

### 1.18.2 分类原则

| 文件类型 | 推荐目标位置 | 原因 |
|---|---|---|
| 个人正在处理的工作文件 | OneDrive | 个人管理、同步和分享 |
| 部门或项目公共文件 | Teams/SharePoint | 不依赖某个员工账号 |
| 正式记录和长期档案 | 由合规要求决定的受控位置 | 需要保留、权限和审计 |
| 临时外部协作文件 | 受控 SharePoint/Teams 空间 | 可设置所有者和结束日期 |
| 应用数据库文件 | 不要默认放入同步盘 | 需确认应用是否支持 |

### 1.18.3 必须调查的治理需求

- 哪些文件属于敏感、机密或受监管数据。
- 哪些部门可以互相访问。
- 是否允许外部共享。
- 是否允许匿名链接。
- 外部链接最长有效期。
- 文件需要保留多久。
- 用户删除文件后需要恢复多久。
- 离职人员 OneDrive 由谁接收。
- 是否需要第三方备份。
- 备份需要覆盖 Exchange、Teams、SharePoint 和 OneDrive 中的哪些数据。
- 期望恢复到多近的时间点，以及多久必须恢复完成。

### 1.18.4 保留不等于备份

保留策略主要用于按照规则保存或删除内容；传统备份强调独立副本、恢复点和恢复流程。企业应根据误删除、恶意删除、勒索软件、长期归档、审计及恢复时间要求，决定 Microsoft 365 自带恢复能力是否足够。

> **高风险：** 不要把部门唯一一份公共资料放在某个员工的个人 OneDrive 中，也不要在没有清点文件所有权和权限的情况下直接整体迁移共享盘。

## 1.19 入职、转岗和离职流程调查

Microsoft 365 上线后，账号管理不是一次性工作。人员变动流程决定权限是否及时、数据是否交接以及许可证是否浪费。

### 1.19.1 入职流程需要确认

- 谁提交账号申请。
- 谁批准许可证和权限。
- 提前几天创建账号。
- 登录名和邮箱如何生成。
- 加入哪些部门组和 Teams。
- 如何注册 MFA。
- 谁发放电脑和手机。
- 谁进行安全培训。

### 1.19.2 转岗流程需要确认

- 旧部门权限何时取消。
- 新部门权限由谁批准。
- 邮件组、Teams 和文件权限如何调整。
- 原项目资料是否继续保留访问。
- 是否需要调整许可证。

### 1.19.3 离职流程需要确认

- 谁通知 IT，准确离职时间是什么。
- 何时禁止登录并撤销现有会话。
- 邮箱和 OneDrive 交给谁。
- 是否需要自动回复或邮件转发。
- 共享邮箱、团队和站点所有者如何交接。
- 公司设备如何回收或擦除。
- 许可证何时回收。
- 账号保留多久后删除。
- 审计或法务保留是否阻止删除。

> **必做：** 不能把“删除用户账号”当作离职流程的第一步。先停止访问、确认数据交接和保留要求，再按审批结果处理许可证和账号。
