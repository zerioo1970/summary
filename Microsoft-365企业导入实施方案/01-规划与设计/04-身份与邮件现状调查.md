## 1.12 现有账号和本地 Active Directory 调查

如果企业存在本地 Active Directory Domain Services（AD DS），必须先了解其健康状况，再决定是否同步到云端。

### 1.12.1 需要调查的内容

- AD 林和域名称。
- 域控制器数量、版本、位置和健康状态。
- 用户总数、启用用户数、停用用户数。
- 组织单位（OU）结构。
- 用户登录名后缀（UPN suffix）。
- 用户的 `mail`、`proxyAddresses` 等邮件属性。
- 重复 UPN、重复邮箱地址和无效字符。
- 服务账号、共享账号和管理员账号。
- 密码策略和账号锁定策略。
- 电脑加域情况。
- 依赖 AD 的文件服务器、打印、VPN 和业务应用。
- 是否已经安装 Entra Connect、Entra Cloud Sync 或其他同步工具。
- 是否使用 AD FS 或第三方身份提供商。

### 1.12.2 为什么要清理

身份同步会把选定对象复制到云端。现有 AD 中如果存在多年未用账号、重复邮箱地址或不规范属性，同步后问题会扩大到 Microsoft 365。

至少应分类：

| 账号类型 | 建议处理 |
|---|---|
| 正常在职用户 | 清理属性后纳入同步范围 |
| 已离职但未禁用 | 先按离职流程处理 |
| 测试账号 | 说明用途，默认不进入生产同步范围 |
| 服务账号 | 单独评估，不自动分配普通用户许可 |
| 共享登录账号 | 尽量改为个人账号加授权方式 |
| 管理员账号 | 与日常办公账号分离 |

> **验证点：** 本地 AD 用户数、计划同步用户数和计划购买许可证数可以不同，但差异必须有清晰说明。

## 1.13 现有邮箱系统和历史数据调查

邮件迁移的难度取决于源系统、数据类型、邮箱容量、网络速度和用户数量，不能只按“邮箱个数”估算。

### 1.13.1 邮件系统调查

- 源邮件系统名称和版本。
- 本地部署还是云服务。
- 是否支持 IMAP、EWS 或厂商迁移接口。
- 管理员能否批量导出邮件。
- 用户认证方式和 MFA 状态。
- 当前企业域名和 MX 指向。
- 邮件路由、网关、归档和防垃圾系统。
- 是否使用本地 Exchange 混合或联合身份。
- 是否有第三方归档、邮件审计或加密网关。
- 是否有 SMTP 中继设备和业务应用。

### 1.13.2 每个邮箱需要收集的数据

| 字段 | 用途 |
|---|---|
| 源邮箱地址 | 迁移来源 |
| 目标邮箱地址 | 迁移目标 |
| 邮箱类型 | 用户、共享、会议室、设备 |
| 邮件数据量 | 估算迁移时间和许可证 |
| 最大单封邮件 | 检查迁移限制 |
| 文件夹数量 | 发现异常结构 |
| 日历/联系人/任务 | 决定迁移工具 |
| 代理权限 | 迁移后重建 |
| 自动转发和规则 | 安全检查及重建 |
| 移动设备 | 切换后重新配置 |
| 重点用户 | 优先试迁移和现场支持 |

### 1.13.3 数据量估算

使用下面的简单方法：

```text
总迁移数据量 = 所有源邮箱实际已用容量之和
预估传输时间 = 总迁移数据量 ÷ 可用于迁移的实际吞吐量
```

实际时间还会受到源系统限流、Microsoft 365 服务限流、并发数、大量小邮件、失败重试和增量同步影响，因此公式只能用于初估，必须通过试迁移校准。

迁移调查还必须确认最终切换方式：何时停止在源系统产生新数据、何时修改 MX、最后一次增量同步如何执行、切换后误投到源系统的新邮件如何补迁，以及源系统保留多久。特别是 IMAP 迁移，迁移完成后新到源邮箱的邮件不会自动持续进入目标邮箱，不能把首次批量迁移当作完整切换。

除个人邮箱邮件外，还应盘点在线归档、公共文件夹、代理权限、Send As/代表发送、邮箱规则、保留或诉讼保留、邮件流规则、连接器和第三方邮件网关。

### 1.13.4 IMAP 迁移的关键限制

IMAP 迁移通常只处理邮件文件夹中的邮件，不会完整迁移联系人、日历和任务；目标邮箱还必须事先创建。微软的迁移概览对此有明确说明，可参考 [迁移多个邮箱到 Microsoft 365 的方式](https://learn.microsoft.com/en-us/exchange/mailbox-migration/mailbox-migration)。

> **高风险：** 如果用户依赖共享日历、联系人、任务、代表发送或复杂权限，仅凭“源系统支持 IMAP”就决定迁移方案，很可能造成数据和功能缺失。

## 1.14 共享邮箱、邮件组和会议室调查

用户邮箱只是邮件系统的一部分。很多迁移失败不是个人邮件丢失，而是公共地址和权限没有恢复。

### 1.14.1 资源分类

| 类型 | 示例（虚构） | 需要调查的重点 |
|---|---|---|
| 共享邮箱 | `sales@example.com` | 成员、完全访问、代表发送、发送方式 |
| 通讯组 | `all@example.com` | 成员、所有者、是否允许外部发信 |
| Microsoft 365 组 | 项目协作组 | 邮箱、Teams、SharePoint 的关联 |
| 会议室 | `room-a@example.com` | 容量、地点、审批、最长预订时间 |
| 设备邮箱 | `projector-1@example.com` | 可预订设备和审批规则 |
| 邮件联系人 | 外部合作人 | 是否仍有效、是否含敏感信息 |
| SMTP 地址 | 打印机、系统通知 | 发信方式、来源 IP、是否支持现代认证 |

### 1.14.2 权限必须单独导出

至少记录：

- 谁可以打开共享邮箱。
- 谁可以“代表发送”。
- 谁可以“发送方式”（Send As）。
- 谁是邮件组所有者。
- 谁可以向邮件组发信。
- 会议室是自动接受还是人工审批。
- 是否存在隐藏地址列表或嵌套组。

> **验证点：** 每个共享资源必须有业务负责人。无人确认用途的公共邮箱和邮件组不要直接迁移，应先进入待清理清单。
