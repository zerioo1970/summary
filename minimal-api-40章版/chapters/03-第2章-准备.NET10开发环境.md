# 第2章　准备.NET 10开发环境

本章的目标不是把软件都安装一遍，而是建立一个可以反复验证的开发环境：命令能执行、项目能创建、HTTPS证书可信、服务器能运行、浏览器能收到响应。

  --------------------------------------------------------------------------------------------------------
  **先把三个问题说清楚　**这是什么：开发环境由.NET 10 SDK、代码编辑器、HTTPS开发证书和API测试工具组成。\
  目的是什么：让后面的每一个示例都可以在同一套可靠环境中创建、编译、运行和排错。\
  最后得到什么：运行dotnet \--version看到10.x，创建空Web项目，浏览器访问实际端口得到Hello响应。
  --------------------------------------------------------------------------------------------------------

  --------------------------------------------------------------------------------------------------------

  -----------------------------------------------------------------------------------------------
  **本章操作路线　**安装SDK → 验证命令 → 信任HTTPS证书 → 创建项目 → 运行并访问 → 认识端口与工具

## 2.1 SDK、Runtime和Hosting Bundle应该装哪个

如果要在这台计算机上写代码和编译项目，安装.NET 10 SDK。SDK已经包含相应运行时，所以开发机通常不用再单独安装Runtime。只有服务器只负责运行现成程序时，才可能只安装Runtime；Windows服务器使用IIS托管时通常安装Hosting Bundle。

-   开发电脑：安装.NET 10 SDK。

-   只运行控制台程序的服务器：按应用需要安装.NET Runtime，或者使用自包含发布。

-   只运行ASP.NET Core网站的服务器：安装ASP.NET Core Runtime，或者使用自包含发布。

-   Windows IIS服务器：通常安装对应版本的Hosting Bundle，使IIS能够启动和转发到ASP.NET Core应用。

  ---------------------------------------------------------------------------------------------------------------------------------------------
  **版本判断　**dotnet \--version显示的是当前命令选中的SDK版本。只看到Runtime而没有10.x SDK时，dotnet new和dotnet build可能无法按本教程工作。

## 2.2 安装.NET 10 SDK并确认命令可用

在Windows上可以使用.NET官方下载的SDK安装程序，也可以在Visual Studio Installer中选择ASP.NET和Web开发工作负载。安装完成后关闭旧终端，再打开新的PowerShell或命令提示符，让PATH重新加载。

**示例2-1　验证SDK安装**

```bash
dotnet --version
dotnet --list-sdks
dotnet --info
```

-   dotnet \--version：应显示10开头的SDK版本，例如10.0.301。补丁号不同通常是正常的。

-   dotnet \--list-sdks：列出本机所有SDK及其安装位置。

-   dotnet \--info：同时显示操作系统、体系结构、SDK、Runtime和环境信息，排错时最有价值。

-   如果提示dotnet不是命令：先重开终端；仍失败则检查SDK是否安装成功以及PATH中是否包含dotnet目录。

## 2.3 信任本机HTTPS开发证书

开发证书的目的，是让本机https://localhost地址可以使用加密连接。它只用于开发，不是生产证书，也不会自动让公网域名获得HTTPS。

**示例2-2　检查和信任HTTPS开发证书**

```bash
dotnet dev-certs https --check --trust

# 如果证书状态混乱，可清理后重新信任
dotnet dev-certs https --clean
dotnet dev-certs https --trust
```

-   执行\--trust时操作系统可能弹出确认窗口，选择信任。

-   公司策略可能阻止自动信任；这时可以先使用终端显示的http地址学习，但不要把书中的https端口硬套进去。

-   浏览器仍提示证书错误时，先确认访问的是localhost，再重启浏览器和开发服务器。

## 2.4 从父目录创建第一个项目

命令必须从准备存放项目的父目录执行。-n负责创建项目名称和子目录，-f net10.0明确指定目标框架。创建后一定要cd进入项目目录，再运行后续命令。

**示例2-3　创建环境检查项目**

```bash
# 1. 进入准备保存练习项目的父目录
cd D:\dotnet-labs

# 2. 创建.NET 10空Web项目
dotnet new web -n EnvironmentCheck -f net10.0

# 3. 进入项目目录
cd EnvironmentCheck

# 4. 查看文件
dir
```

**示例2-4　创建成功后的主要目录**

```text
EnvironmentCheck/
├─ Properties/
│ └─ launchSettings.json
├─ appsettings.json
├─ appsettings.Development.json
├─ EnvironmentCheck.csproj
└─ Program.cs
```

  -----------------------------------------------------------------------------------------------------------------------------------------------
  **为什么先执行dir　**dotnet build、dotnet run和dotnet add package通常应该在包含csproj的目录执行。先确认目录，可以避免大量"找不到项目"的错误。

## 2.5 修改Program.cs并第一次运行

打开Program.cs，把内容改成下面代码。此时不加入数据库、Swagger或前端页面，只验证最基础的HTTP链路。

**示例2-5　环境检查API**

```csharp
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

app.MapGet("/", () => "Environment OK");

app.Run();
```

**示例2-6　编译并运行**

```bash
dotnet build
dotnet run
```

-   看到"生成成功"或0个错误，说明SDK和项目基本正确。

-   看到Now listening on: https://localhost:xxxx，说明Kestrel已经监听端口。

-   复制自己终端显示的完整地址到浏览器，不要照抄书中的端口。

-   页面显示Environment OK，说明浏览器、证书、端口、服务器和路由已经连通。

-   保持终端运行；按Ctrl+C才会停止服务器。

## 2.6 最常用的dotnet命令分别做什么

这些命令不是一组需要死记的缩写，而是项目生命周期中的不同动作。知道它们产生什么结果，比背命令更重要。

**示例2-7　入门阶段常用CLI**

```bash
dotnet new web -n Demo -f net10.0 # 按模板创建项目
dotnet restore # 下载并解析NuGet依赖
dotnet build # 编译并检查错误
dotnet run # 编译后启动项目
dotnet watch # 监听文件变化并热重载/重启
dotnet test # 运行测试项目
dotnet publish -c Release # 生成可部署文件
dotnet clean # 清理编译输出
```

  -------------------------------------------------------------------------------------------------------------------------------------------------
  **run与watch的区别　**dotnet run适合明确地启动一次；dotnet watch适合持续开发。代码变化后能否热更新取决于修改类型，不能热更新时watch会提示重启。

## 2.7 端口和launchSettings.json

URL由协议、主机、端口和路径组成。例如https://localhost:7123/api/hello中，https是协议，localhost是本机，7123是端口，/api/hello是路径。端口不是API代码的一部分。

Properties/launchSettings.json主要服务于本地开发启动配置。它可能设置applicationUrl和ASPNETCORE_ENVIRONMENT。正式发布后通常由服务器环境变量、命令行或托管平台决定监听地址。

**示例2-8　launchSettings.json核心结构示意**

```json
{
"profiles": {
"https": {
"commandName": "Project",
"launchBrowser": true,
"applicationUrl": "https://localhost:7123;http://localhost:5187",
"environmentVariables": {
"ASPNETCORE_ENVIRONMENT": "Development"
}
}
}
}
```

-   如果端口被占用，可修改本地启动配置或用\--urls临时指定。

-   不要把launchSettings.json中的Development理解为生产配置。

-   浏览器打不开时，优先复制终端实际输出，而不是猜测端口。

## 2.8 准备编辑器和测试工具

代码编辑器负责写代码和调试；API测试工具负责构造HTTP请求并查看状态码、请求头和响应体。浏览器地址栏只能方便地测试简单GET，不能代替所有接口测试。

-   VS Code：轻量，适合学习CLI和项目结构；安装C#开发扩展后可补全和调试。

-   Visual Studio：集成项目向导、调试器、NuGet、发布工具，Windows上使用方便。

-   Swagger UI：浏览器里的交互式API文档和人工测试页面，第6章详细讲解。

-   .http文件：把请求保存在项目中，适合重复执行和进入版本控制。

-   curl：跨平台命令行客户端，部署服务器排错时非常有用。

-   浏览器开发者工具：第8章用于观察前端发出的请求、响应和CORS问题。
