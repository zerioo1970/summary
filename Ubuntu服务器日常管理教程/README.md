# Ubuntu 服务器日常管理教程

> **版本基线**（2026-11）
>
> | 项 | 版本 |
> |---|---|
> | 服务器系统 | Ubuntu Server 26.04.1 LTS（只装命令行，不装桌面） |
> | 你的电脑 | Windows 10 / 11，命令在 **PowerShell** 里执行；使用 Windows 自带的 OpenSSH 客户端（`ssh`、`scp`、`ssh-keygen`） |
> | 用到的系统组件 | 26.04 默认的 `sudo-rs`（sudo）、`chrony`（时间同步）、`netplan`（网络配置）、`ufw`（防火墙）、`systemd`（服务、日志、定时器）；其他软件的具体版本在对应章节写作时核实 |

## 这本教程写给谁

- 你手上有（或马上要有）一台 Ubuntu 服务器，上面要跑网站，平时由你来管。
- 你会用 Windows Server，但没怎么用过 Linux 命令行。
- 你要的是日常要做的那些事**具体怎么操作**：装好后先配什么、加用户、装软件、管服务、看日志、磁盘满了怎么办、怎么备份、出了故障按什么顺序查。

每章的写法：

- 按"要办的一件事"组织，先用几句话说明为什么要做，然后是**编号的操作步骤**。
- 每一步写明在哪里执行：
  - `PS C:\Users\zhang>`：你自己的 Windows 电脑，PowerShell 窗口；
  - `ubuntu@web01:~$`：已经用 ssh 登录的服务器。
- 每条命令写清楚每个参数的作用，后面给出**实际运行的输出**，再告诉你看到什么算做对了。
- 文中服务器地址统一写成 `192.168.1.50`，用户名写成 `ubuntu`，主机名写成 `web01`，你的 Windows 用户名写成 `zhang`。照做时换成你自己的。

## 章节编号和文件组织

- 全书分 9 个部分，**每个部分的章单独编号**。章号写成"第 部分号-本部分内的章号 章"，例如第七部分的第 3 章是"第 7-3 章"，它的小节是 7-3.1、7-3.2……
- 在某个部分里增加章，不影响其他部分的编号；需要插在中间时用字母后缀（例如第 7-3A 章），本部分后面的章也不用顺延。
- 每个部分一个文件夹，这个部分的图片放在文件夹里的 `image/` 子文件夹；章里用到的脚本和配置文件放在 `code/部分号-章号/`：

```text
Ubuntu服务器日常管理教程/
├── README.md
├── docs/
│   ├── 01-安装和登录/
│   │   ├── 01-安装UbuntuServer.md
│   │   ├── 02-装好后先做的几件事.md
│   │   ├── 03-密钥登录.md
│   │   └── image/
│   ├── 02-Shell日常操作/
│   │   ├── 01-命令行基本功.md
│   │   └── image/
│   ├── ……（03 到 08 各部分同样的结构）
│   ├── 09-备份和故障处理/
│   └── 附录/

    ├── 02-07/          （第 2-7 章的脚本）
    └── 07-03/          （第 7-3 章的配置文件）
```

- 文件夹名和文件名里的部分号、章号都写两位数，保证按顺序排列；文件名里不放空格。

| 第 5-2 章 实时查看进程：top 和 htop | `top` 顶部五行（负载、任务数、CPU、内存、swap）怎么读；按 CPU、内存排序，只看某个用户；`htop` 的树形视图、搜索、筛选；进程状态 R、S、D、Z 的含义 |

| 第 5-4 章 前台、后台和断线不中断：nohup 和 tmux | `&` 放到后台、`jobs`、`fg`、`bg`、`Ctrl+Z`；ssh 断开后程序为什么会停；`nohup` 和输出文件；用 `tmux` 开会话、断开、重新连上，长时间的操作（大文件复制、系统升级）放在 tmux 里做 |

| 第 5-6 章 服务器变慢了：按顺序找出原因 | 排查顺序：`uptime` 看负载 → `top` 看 CPU → `free -h` 看内存和 swap → `vmstat 1` 看等待 → `iostat -x` 看磁盘 → 找出具体进程；每种情况的处理办法；用 `sar` 查看过去某个时间点的数据 |

### 第七部分 磁盘管理

| 章 | 一句话说明 |
|---|---|
| 第 7-1 章 认识磁盘：分区、文件系统和挂载点 | 磁盘、分区、文件系统、挂载点各是什么，和 Windows 的盘符有什么不同；`lsblk -f`、`blkid`、`df -hT`、`findmnt` 看懂当前服务器的磁盘布局；设备名 `sda`、`nvme0n1`、`vda` 的区别；为什么要用 UUID |
| 第 7-2 章 磁盘空间满了怎么办 | `df -h` 确认哪个分区满了；`du -sh *`、`du -xh --max-depth=1` 逐层找大目录；安装 `ncdu` 交互查看；清理日志（`journalctl --vacuum-size`）、apt 缓存、旧内核；文件删了空间没释放（`lsof +L1`）；空间还有但写不进文件（`df -i` 查 inode） |
| 第 7-3 章 加一块数据盘：分区、格式化、开机自动挂载 | `lsblk` 认出新盘；用 `parted` 建 GPT 分区；`mkfs.ext4` 格式化；`mount` 挂到 `/data`；按 UUID 写进 `/etc/fstab` 并加 `nofail`；用 `mount -a` 先检查再重启；把网站数据迁移到新盘 |
| 第 7-4 章 LVM：用上没分配的空间、加盘扩容 | 物理卷（PV）、卷组（VG）、逻辑卷（LV）三层的关系；`pvs`、`vgs`、`lvs` 查看；Ubuntu 安装时根分区默认只用了部分空间，用 `lvextend -r` 扩出来；加一块新盘并入卷组再扩容 |
| 第 7-5 章 虚拟机或云盘扩容后，让系统用上新空间 | 在虚拟化平台或云控制台把磁盘调大后，系统里看不到新空间的原因；`growpart` 扩分区 → `pvresize` → `lvextend` → `resize2fs` 扩文件系统；不用 LVM 时的做法；扩容前先做快照 |
| 第 7-6 章 交换空间 swap | swap 是什么、什么时候有用；`swapon --show`、`free -h` 查看；创建 swap 文件并写进 `fstab`；调整 `vm.swappiness`；swap 一直被大量使用说明什么 |
| 第 7-7 章 磁盘故障：只读、文件系统检查、硬盘健康 | 文件系统突然变成只读的原因和处理；`dmesg`、`journalctl -k` 里的 I/O 错误；`fsck` 只能在卸载后执行；`smartctl` 查看硬盘健康状态；硬盘快坏时先做什么 |
| 第 7-8 章 传文件、同步目录、打包压缩 | `scp` 和 `rsync` 在 Windows 与服务器、服务器与服务器之间传文件；`rsync` 只传变化的部分、`--delete` 的风险；`tar` 打包压缩和解压；`zip`、`unzip` |
