# LangChain 1.3 新手实用教程 · 目录（精简版）

> 版本基准：`langchain 1.3.x` + `langchain-core 1.5.x` + `langgraph 1.2.x`（实测组合：1.3.14 / 1.5.1 / 1.2.9）
> Python 3.10+（1.x 已不支持 3.9）
>
> **主线模型：DeepSeek**（`langchain-deepseek 1.1.0`，实测 `init_chat_model("deepseek:deepseek-chat")` 可用）
> 全书代码默认用 DeepSeek，国内直连、便宜、支持工具调用；其他厂商的替换写法见附录 B。
> 实测能力档案：`tool_calling: True`、`max_input_tokens: 1000000`、**`image_inputs: False`（不能直接喂图片）**、`reasoning_output: False`（要推理链用 `deepseek-reasoner`）。
> ⚠️ 因此"扫描件识别、发票拍照录入"这类需求需先 OCR 转文字，或该步骤换用支持视觉的模型——第 2 章会说明。
>
> **取舍原则**：只保留新手日常开发 90% 会碰到的内容。
> LangGraph 自定义图、多 Agent、Deep Agents、MCP、LCEL/Runnable、评估体系一律移出正文，只在附录 E 用两句话交代"什么时候你才需要它"。
>
> 每章固定四件套：**一张图 + 可直接跑的完整代码（含中文注释）+ 常见报错 + 一个小练习**

## 第一部分　上手（3 章，约 3 小时）

### 第 1 章　认识 LangChain，并跑出第一个程序
1. LangChain 是什么、不是什么（一页说完）
2. 装环境：Python 3.10+、`uv`、用 `.env` 存 API Key
3. 模型三选一：OpenAI ／ DeepSeek（国内，OpenAI 兼容协议）／ Ollama（完全离线）
4. 20 行代码：一个会查天气的 Agent
5. 把返回结果打印出来，逐项看懂
6. ⚠️ 新手四个必踩报错：模块找不到 / Key 没生效 / 模型名无效 / 代理超时

### 第 2 章　模型与消息
1. `init_chat_model()` 一句话换模型
2. 三个真正常用的参数：`temperature`、`max_tokens`、`timeout`
3. 四种消息：System / Human / AI / Tool
4. 取文字用 `.text`（⚠️ 1.x 起是属性，不要加括号）
5. 用 `usage_metadata` 看这次花了多少 token
6. 多轮对话：先手动传历史（第 8 章再自动化）

### 第 3 章　提示词怎么写
1. 系统提示的四段结构：角色、任务、约束、输出格式
2. 好提示 vs 坏提示的直接对比
3. 模板与变量替换（别用字符串拼接）
4. 给几个例子（Few-shot）
5. ⚠️ 三个最常犯的错误

## 第二部分　让 AI 会干活（4 章，约 5 小时 ← 全书重点）

### 第 4 章　工具：给 AI 装上手脚
1. `@tool` 装饰器
2. ⚠️ 函数名 + 类型标注 + docstring 就是给模型看的说明书
3. 🖼 图解：模型只是"申请"调用，真正执行的是你的代码
4. 工具里报错了怎么办
5. 让工具读到 `user_id`，但不让模型看见（`ToolRuntime` / 注入参数）
6. 实战：天气、汇率、查数据库（只读 + 参数化 + 行数上限三道保险）
7. ⚠️ 工具太多时模型会选错，怎么办

### 第 5 章　Agent：`create_agent`
1. 🖼 Agent 循环图：调模型 → 要不要用工具 → 执行工具 → 回到模型 → 没有工具调用就结束
2. 六个日常够用的参数：`model`、`tools`、`system_prompt`、`checkpointer`、`response_format`、`middleware`
3. 查看它中间调了哪些工具
4. 防止它自己转圈烧钱（`recursion_limit`）
5. ⚠️ 三个新手会撞的限制
   - 不能传已经绑定过工具的模型（pre-bound model）
   - `state_schema` 只支持 `TypedDict`
   - 工具错误处理归口到中间件（第 9 章）
6. 实战：旅行规划助手

### 第 6 章　结构化输出：拿到能直接入库的数据
1. 为什么"请只返回 JSON"不靠谱
2. 用 Pydantic 定义你要的形状
3. `response_format` 一行搞定
4. 三种策略一句话选型：`AutoStrategy`（不确定就用它）／`ProviderStrategy`（厂商原生）／`ToolStrategy`（通用兜底）
5. ⚠️ 提示式 JSON 输出（prompted output）在 1.x 已被移除，旧教程写法会失效
6. 校验失败怎么兜（`handle_errors`）
7. 实战：把一段投诉邮件变成工单记录

### 第 7 章　流式输出：别让用户看着空白屏幕
1. `stream()` 做打字机效果（最简写法）
2. 只要文字、不要一堆杂事件的写法
3. 工具调用过程也显示出来
4. 实战：FastAPI + SSE 推到网页（含约 30 行前端 JS）
5. ⚠️ 两个坑：只拿到最后一段；按节点名过滤失效（节点名已从 `agent` 改为 `model`）

## 第三部分　记得住、查得到（3 章，约 4 小时）

### 第 8 章　让 AI 记住对话
1. 🖼 短期记忆 vs 长期记忆
2. `checkpointer` + `thread_id`：三行代码实现多轮记忆
3. 存进 SQLite，重启不丢
4. 多用户会话隔离
5. 历史太长怎么办：交给摘要中间件自动处理
6. 跨会话记住用户偏好（`store` 最简用法）

### 第 9 章　中间件：只学这 6 个就够用
1. 🖼 一张图看清它挂在 Agent 的哪个位置
2. `SummarizationMiddleware` —— 对话太长自动摘要
3. `HumanInTheLoopMiddleware` —— 危险操作先人工确认
4. `PIIMiddleware` —— 手机号、身份证发出去之前脱敏
5. `ModelCallLimitMiddleware` + `ToolCallLimitMiddleware` —— 预算与死循环的保险丝
6. `ModelRetryMiddleware` —— 限流/超时自动重试
7. 自己写一个：给每次调用打日志（约 30 行）
8. 需要动态改系统提示时：`@dynamic_prompt`
9. 📌 顺带一提：还有 10 多个内置中间件，用到时查附录 A

### 第 10 章　RAG：让 AI 读你自己的资料
1. 🖼 原理图（用"开卷考试"理解）：切分 → 向量化 → 入库 → 检索 → 回答
2. 加载 PDF / Word / Markdown
3. 切分：`chunk_size` 和重叠怎么定，中文要注意什么
4. Embedding + Chroma 建库（完整脚本）
5. 两种用法
   - 固定流程：永远先检索再回答
   - **把检索做成一个工具**，让 Agent 自己决定查不查、查几次
6. 回答里带来源引用
7. ⚠️ "明明有资料却搜不到"排查五步
8. ⚠️ 高级检索器（MultiQuery / 上下文压缩 / ParentDocument）已移到 `langchain-classic`，直接 import 会报错
9. 实战：公司制度问答助手

## 第四部分　能交付出去（3 章，约 3 小时）

### 第 11 章　出问题了怎么查（按症状索引）
1. 工具始终不被调用
2. 工具被反复调用
3. Agent 不肯停下来
4. 结构化输出校验失败
5. 多轮对话串台
6. Token 超限 / 上下文溢出
7. 中文乱码
8. 流式输出不完整
9. `ImportError`（1.x 命名空间精简，东西搬到了 `langchain-classic`）
10. 旧教程代码整段跑不了
11. 太慢、太贵
12. LangSmith 5 分钟接上，看清每一步；不想用它时的结构化日志方案

### 第 12 章　省钱与提速
1. 算清一次请求花了多少钱
2. 提示缓存（Prompt Caching）—— 降本最大的一招
3. 精简工具描述能省多少（官方案例：单轮输入 token 降约 65%）
4. 便宜模型打头阵，失败再上贵的
5. 控制历史长度、加结果缓存

### 第 13 章　做成一个真正的服务
1. 推荐的项目目录结构
2. FastAPI 包一层：普通接口 + 流式接口 + 会话管理
3. 密钥与环境隔离
4. Docker 打包
5. ✅ 上线前 12 项检查清单
6. 安全三件事：提示注入、工具越权、日志脱敏

  - LangGraph 1.2 生产能力：节点超时、错误补偿、优雅停机、长会话检查点瘦身

  - LCEL / Runnable：流程完全固定、不需要模型做决策时
  - 评估体系：要把"感觉不错"变成可回归的指标时

## 附：18 个日常用得上的实战例子（贯穿全书当案例池）

**A 组·单次调用**（无工具、无记忆，10–30 行，学到第 6 章即可全部实现）
1. 邮件转工单：报修/投诉邮件 → 类别+紧急度+联系人+摘要，直接入库
2. 祖传 SQL 解读：300 行老存储过程 → 中文业务说明、涉及表、风险点
3. 口述需求转规范文档：一句话需求 → 字段清单、校验规则、验收标准
4. 脏数据批量归一：5000 条杂乱客户名/地址/规格 → 标准写法（`batch()` 批量）
5. 数据字典生成：表结构元数据 → 带中文含义与示例值的字典文档
6. 会议纪要整理：录音文字稿 → 纪要 + 待办（负责人、截止日）
7. 自由文本列拆字段："规格 20*30 蓝色 加厚" → 尺寸/颜色/工艺三列
8. 报表自动点评：月度数字表 → 一段中文经营点评

**B 组·带工具**（40–80 行，第 4、5、9 章）
9. 自然语言查数据库：问句 → 只读 SELECT → 执行 → 中文汇报（只读账号+参数化+行数上限三道保险）
10. 内部查询小助手：订单状态、库存、物流三个工具，模型自己选
11. 审批前置校验：读申请单 → 调规则接口 → 超额时停下等人工确认
12. 给老系统加自然语言入口："给张三加 3 天年假" → 调你已有的 API

**C 组·带记忆**（第 8 章）
13. 多轮追问的报表助手：能接住"那华东呢""再按月拆开"

**D 组·RAG**（60–100 行，第 10 章）
14. 公司制度问答：报销/请假/差旅 → 回答带条款出处，查不到就说没查到
15. 历史工单知识库：新故障进来先检索相似历史处理方案
16. 产品手册客服：几百页手册中定位答案并附页码

**E 组·开发者自用**（第 2、3、6 章）
17. 异常日志聚类：几千条报错 → 归类 + 可能原因 + 影响范围
18. 代码规范批检：按团队自有规范批量扫描挑问题
🎁 内联 SQL 批量转存储过程：按既定规则读页面文件 → 生成存储过程脚本 + 改写后的调用代码

**明确不适合它做的事**（避免走弯路）
- 精确计算（求和、对账、税额）：让它**生成 SQL 去算**可以，让它自己算不行
- 无人复核的财务/医疗决策：概率模型没有 100%
- 一个 `WHERE` 就能精确解决的查询：别为用 AI 而用 AI
- 强一致性事务判断：交给数据库约束
