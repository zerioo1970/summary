# 第 68 章：为什么写了类型声明，仍然需要检查接口数据？

前置：[第 67 章：如何让多个文件共用同一个数据类型？](第067章-如何让多个文件共用同一个数据类型.md)

## 一、本章要解决的问题

我们给文章写了类型，`npm.cmd run check` 也没有报错，看起来很安全。可是接口返回的数据是在页面运行时才拿到的，万一后端改了字段名，或者某个字段的值是错误的类型，会怎样？

本章先用练习服务故意返回格式错误的数据，看到页面整个变成空白；然后在保存数据之前检查它的格式，格式不对时显示“文章数据格式不正确，暂时无法显示。”，而不是让页面崩溃。

## 二、必要原理

### TypeScript 只检查你写的代码

TypeScript 在写代码和运行 `check` 时检查类型，它能确定的只有代码中写出来的东西。接口返回什么，要等页面运行、请求完成后才知道，这时 TypeScript 早已不参与了。

第 62 章写的 `(await response.json()) as Article[]` 是**类型断言**：你告诉 TypeScript“这是文章数组，相信我”，TypeScript 就照此检查后面的代码，但不会去核对数据本身。如果数据其实不是这个样子，错误会在后面使用数据时才爆发，而且往往离真正的原因很远。

练习服务的 `?mode=bad` 会返回 `[{ "id": "one", "title": 123 }]`：`id` 是字符串，`title` 是数字，没有摘要和日期。`ArticleList` 拿到 `undefined` 当作日期格式化时报错，整个页面变成空白。

### unknown：先承认“不知道是什么”

把 `response.json()` 的结果标成 `unknown`：

```tsx
const data: unknown = await response.json();
```

`unknown` 表示“不知道是什么类型”。TypeScript 不允许直接使用 `unknown` 的值，读取属性、传给组件都会报错，**必须先检查**，确认它是什么之后才能用。这正好逼着我们写检查代码。

### typeof 和 in：在运行时检查一个值

要检查数据，需要两个在页面运行时也能使用的工具。

**`typeof 值`** 得到一段文字，说明这个值是什么类型：

| 写法 | 结果 |
| --- | --- |
| `typeof 1` | `'number'` |
| `typeof '小林'` | `'string'` |
| `typeof true` | `'boolean'` |
| `typeof { id: 1 }` | `'object'` |
| `typeof [1, 2]` | `'object'`（数组也是对象） |
| `typeof null` | `'object'`（这是 JavaScript 的一个历史遗留问题） |
| `typeof undefined` | `'undefined'` |

所以 `typeof value.id === 'number'` 的意思是“`value.id` 是不是数字”。注意这里的 `typeof` 写在 `if` 或 `return` 的表达式中，是在**页面运行时**执行的；和类型声明中的 `: number` 不同，它真的会去看数据。

**`'属性名' in 对象`** 判断对象中有没有这个属性，有就是 `true`。例如 `'id' in { id: 1 }` 是 `true`，`'id' in { title: 'a' }` 是 `false`。

### 类型守卫：检查一篇文章的格式

把这些检查写进一个函数，放在 `src/types/article.ts` 中。下面先只检查 `id` 一个字段，看清写法，第三节第 2 步会把四个字段都写全：

```ts
export function isArticle(value: unknown): value is Article {
  return (
    typeof value === 'object' &&
    value !== null &&
    'id' in value &&
    typeof value.id === 'number'
  );
}
```

`&&` 表示“并且”：从左到右逐个检查，有一个不成立，整个结果就是 `false`，后面的也不再检查。

- `typeof value === 'object' && value !== null`：先确认它是一个对象。从上表可以看到 `typeof null` 也是 `'object'`，所以要单独排除 `null`。
- `'id' in value`：对象中有没有 `id` 这个属性。确认有了以后，才能读取 `value.id`。
- `typeof value.id === 'number'`：这个属性是不是数字。
- 返回类型 `value is Article` 叫**类型守卫**：函数返回 `true` 时，TypeScript 就把 `value` 当作 `Article`。

### 检查整个数组

```tsx
if (!Array.isArray(data) || !data.every(isArticle)) {
  // 格式不对
}
```

`Array.isArray(data)` 判断它是不是数组。数组的 `every` 对每一项调用检查函数，**全部**返回 `true` 时结果才是 `true`，有一项不符合就是 `false`。通过这个判断后，TypeScript 就知道 `data` 是 `Article[]`，可以直接交给 `setArticles`，不再需要 `as`。

## 三、动手实现

### 第 1 步：重现问题

把 `src/pages/ArticlePage.tsx` 中的请求地址临时改为 `'http://127.0.0.1:3001/api/articles?mode=bad'`，点击“加载文章”：页面变成空白，控制台中有 `Invalid time value`。Network（网络）的 Preview（预览）中可以看到返回的数据格式不对。保留 `?mode=bad`，继续下一步。

### 第 2 步：编写检查函数

在 `src/types/article.ts` 的末尾加入：

```ts
export function isArticle(value: unknown): value is Article {
  return (
    typeof value === 'object' &&
    value !== null &&
    'id' in value &&
    typeof value.id === 'number' &&
    'title' in value &&
    typeof value.title === 'string' &&
    'summary' in value &&
    typeof value.summary === 'string' &&
    'publishedAt' in value &&
    typeof value.publishedAt === 'string'
  );
}
```

### 第 3 步：保存前检查数据

在 `src/pages/ArticlePage.tsx` 中，在类型导入的上面加入：

```tsx
import { isArticle } from '../types/article';
```

把读取数据的两行：

```tsx
      const data = (await response.json()) as Article[];
      setArticles(data);
```

改为：

```tsx
      const data: unknown = await response.json();
      if (!Array.isArray(data) || !data.every(isArticle)) {
        setError('文章数据格式不正确，暂时无法显示。');
        return;
      }
      setArticles(data);
```

保存后点击“加载文章”，页面显示“文章数据格式不正确，暂时无法显示。”，不再变成空白。最后把地址中的 `?mode=bad` 删掉。

## 四、运行与检查

保持开发服务器和练习服务都在运行（准备篇二）。

1. 正常加载，4 篇文章显示正常。
2. 地址临时加上 `?mode=bad`，显示“文章数据格式不正确，暂时无法显示。”和“重试”按钮，页面没有变成空白。
3. 地址临时改为 `?mode=empty`，接口返回空数组，检查能通过（空数组的 `every` 结果是 `true`），列表为空。第 69 章会给这种情况加提示。
4. 去掉临时参数后，代码中不再有 `as Article[]`。

最后运行检查，应没有错误：

```powershell
npm.cmd run check
```

**小练习**：在 `isArticle` 中临时去掉对 `publishedAt` 的检查，用 `?mode=bad` 再试一次，看看页面会怎样。练习后恢复本章代码。

## 五、常见错误

| 现象 | 原因 | 怎么改 |
| --- | --- | --- |
| 编辑器提示类型 `object` 上不存在属性 `id` | 读取 `value.id` 之前没有先用 `'id' in value` 确认 | 每个字段先写 `in` 判断，再判断类型 |
| 编辑器提示 `value` 可能为 `null` | 漏了 `value !== null` | 在 `typeof value === 'object'` 后面加上 |
| 编辑器提示 `data` 的类型是 `unknown`，不能调用 `every` | 没有先用 `Array.isArray` 确认它是数组 | 写成 `!Array.isArray(data) \|\| !data.every(isArticle)` |
| 格式错误的数据仍然让页面空白 | 检查函数只检查了部分字段，组件用到的字段没有检查 | 组件用到的字段都要检查 |
| 正常的数据也被判为格式不对 | 检查函数中的字段名或类型写错，例如 `'publishAt'` | 对照 Network 中的真实数据核对 |
| 学完本章后，页面一直报错、一直显示空数据或加载很慢 | 步骤中临时加在请求地址上的 `?mode=`、`?fail=`、`?delay=`、`?cors=` 等参数忘了删 | 运行 `git diff` 查看本章改动，删掉地址中的临时参数 |

## 六、本章完整代码

### `src/types/article.ts`

```ts
export type Article = {
  id: number;
  title: string;
  summary: string;
  publishedAt: string;
};

export function isArticle(value: unknown): value is Article {
  return (
    typeof value === 'object' &&
    value !== null &&
    'id' in value &&
    typeof value.id === 'number' &&
    'title' in value &&
    typeof value.title === 'string' &&
    'summary' in value &&
    typeof value.summary === 'string' &&
    'publishedAt' in value &&
    typeof value.publishedAt === 'string'
  );
}
```

### `src/pages/ArticlePage.tsx`

```tsx
import { useState } from 'react';
import ArticleList from '../components/ArticleList';
import { isArticle } from '../types/article';
import type { Article } from '../types/article';

export default function ArticlePage() {
  const [articles, setArticles] = useState<Article[]>([]);
  const [error, setError] = useState('');
  const [isLoading, setIsLoading] = useState(false);

  async function handleLoad() {
    setError('');
    setIsLoading(true);
    try {
      const response = await fetch('http://127.0.0.1:3001/api/articles');
      if (!response.ok) {
        setError('文章读取失败：服务器返回了状态 ' + response.status + '。');
        return;
      }
      const data: unknown = await response.json();
      if (!Array.isArray(data) || !data.every(isArticle)) {
        setError('文章数据格式不正确，暂时无法显示。');
        return;
      }
      setArticles(data);
    } catch {
      setError('无法连接练习服务，请确认它已经启动。');
    } finally {
      setIsLoading(false);
    }
  }

  return (
    <main className="page">
      <h1>文章列表</h1>
      <button type="button" onClick={handleLoad} disabled={isLoading}>
        加载文章
      </button>
      {isLoading && <p role="status">正在加载文章……</p>}
      {error && (
        <div>
          <p role="alert">{error}</p>
          <button type="button" onClick={handleLoad}>
            重试
          </button>
        </div>
      )}
      <ArticleList articles={articles} />
    </main>
  );
}
```

## 七、本章改动小结

修改 `src/types/article.ts`：加入检查函数 `isArticle`；修改 `src/pages/ArticlePage.tsx`：读取的数据先检查格式，去掉类型断言。
