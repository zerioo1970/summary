# 第 80 章：为什么某些 Effect 会反复执行，甚至不断发送请求？

前置：[第 79 章：如何取消已经不再需要的请求？](第079章-如何取消已经不再需要的请求.md)

## 一、本章要解决的问题

依赖数组只有一行，却是 Effect 最容易出问题的地方：少写一个，Effect 读到旧的值，页面不更新；写得不对，Effect 每次渲染都执行，不停地发请求，练习服务的终端飞快地滚动。

本章不修改代码，用搜索页故意制造三种常见的依赖错误，观察现象，学会判断依赖数组该写什么，并了解代码检查怎样提前发现这类问题。

## 二、必要原理

### React 怎样判断依赖变了

每次渲染后，React 把依赖数组中的每一项和上一次渲染时的值逐个比较，比较方式和第 51 章（直接修改数组为什么页面有时不更新）说的一样：看是不是**同一个值**。字符串、数字只要内容相同就算相同；对象和数组则要求是同一个对象，内容相同的两个新对象也算“不同”。

只要有一项不同，Effect 就重新执行。

### 三种常见错误

| 写法 | 结果 |
| --- | --- |
| 不写依赖数组 | 每次渲染后都执行 |
| 依赖中有每次渲染都新建的对象或数组 | 每次渲染后都执行 |
| 漏写了 Effect 中用到的值 | 该执行时不执行，读到的是旧值 |

前两种如果遇上“Effect 中更新 state”，就会形成循环：Effect 执行时更新 state，state 变化引起渲染，渲染后 Effect 又执行，又更新 state……永不停止。搜索的 Effect 一开始就设置状态，每次执行还会发出一个请求，所以请求也一个接一个地发出去。

### 依赖数组该写什么

规则只有一条：**Effect 中用到的组件内的值，都要写进依赖数组**。组件内的值包括 state、props，以及在组件函数中由它们计算出来的变量和函数。组件外面定义的常量和函数（例如 `fetchSearchResults`）、set 函数不需要写。

依赖尽量是字符串、数字、布尔值这样的简单值。需要用到对象中的某个字段时，直接依赖这个字段，而不是整个对象。

### 让代码检查提前发现

项目在第 7 章加入的 oxlint 中启用了 `react/exhaustive-deps` 规则，它会检查 Effect 中用到的值是否都写进了依赖数组，并对每次渲染都会变化的依赖给出提示。运行 `npm.cmd run check` 时，这类问题会作为错误列出来，在页面出问题之前就能发现。遇到这条规则的提示，不要用注释把它关掉，而是按提示修改。

## 三、动手实现

保持开发服务器和练习服务都在运行（准备篇二），打开 Network（网络）面板。每个实验做完后，都把 `src/pages/SearchPage.tsx` 恢复为第 79 章的代码。

### 第 1 步：实验一，不写依赖数组

把搜索 Effect 末尾的 `}, [debouncedKeyword]);` 临时改为 `});`。

保存后，控制台立刻出现红色错误 `Maximum update depth exceeded`（超过了最大更新深度）。输入 `type`，页面一直显示“正在搜索……”，Network 中 `search` 请求密密麻麻地出现，大多数状态是 `(canceled)`，练习服务的终端也在飞快滚动。

原因：没有依赖数组的 Effect 在每次渲染后都执行。它一执行就调用 `setSearchState` 设置状态，状态变化引起渲染，渲染后 Effect 又执行……每次执行都发出一个请求，下一次执行前的清理又把它取消。React 发现组件在不停地更新，于是在控制台报错提醒。

这个实验会让浏览器很忙，看到现象后尽快恢复代码。

### 第 2 步：实验二，依赖一个每次新建的对象

在搜索的 `useEffect` 前面加入：

```tsx
  const options = { query: debouncedKeyword.trim() };
```

把 Effect 第一行改为 `const query = options.query;`，依赖数组改为 `[options]`。

现象和实验一相同：控制台报错，输入 `type` 后不停地发请求。`options` 的内容每次都一样，但每次渲染都是一个新对象，React 认为依赖变了。

运行 `npm.cmd run check`，oxlint 会对 `options` 这个依赖给出提示。

### 第 3 步：实验三，漏写依赖

把依赖数组临时改为 `[]`。

输入 `type`，页面一直显示提示文字“输入关键词，搜索文章标题。”，Network 中没有任何 `search` 请求。Effect 只在页面打开时执行了一次，那时关键词是空的，之后 `debouncedKeyword` 变化，它也不再执行。

运行 `npm.cmd run check`，oxlint 提示 Effect 缺少依赖 `debouncedKeyword`。

最后把代码恢复为第 79 章的样子。

## 四、运行与检查

1. 实验一和实验二：控制台出现 `Maximum update depth exceeded`，请求不停地出现，终端不停滚动。
2. 实验三：输入后一直显示提示文字，没有请求。
3. 实验二和实验三：`npm.cmd run check` 能发现问题。
4. 恢复代码后，输入 `type` 只发一个请求，`npm.cmd run check` 没有错误。

最后运行检查，应没有错误：

```powershell
npm.cmd run check
```

**小练习**：实验二中，如果非要用 `options` 对象，怎样修改依赖数组才不会反复执行？（提示：依赖对象中的字段 `options.query`，而不是整个对象。）练习后恢复本章代码。

## 五、常见错误

| 现象 | 原因 | 怎么改 |
| --- | --- | --- |
| 控制台报错 `Maximum update depth exceeded`，请求不停地出现 | 没写依赖数组，或依赖中有每次渲染都新建的对象、数组、函数 | 写上依赖数组，只依赖简单的值 |
| 值变了，Effect 却没有重新执行 | 漏写了这个依赖 | 按 `check` 的提示补上 |
| 为了让 `check` 不报错，把依赖数组整个删掉 | 删掉后 Effect 每次渲染都执行 | 写全依赖，而不是删掉数组 |
| 补上依赖后 Effect 执行得太频繁 | 依赖的是一个经常变化的值，例如未经防抖的 `keyword` | 改为依赖真正需要的值，例如 `debouncedKeyword` |
