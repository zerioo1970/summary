# 第 3 章：如何用一个带类型的对象保存一组资料？

前置：[第 2 章：如何把一个变量显示在网页中？](第002章-如何把一个变量显示在网页中.md)

## 一、本章要解决的问题

第 2 章把姓名放进了变量 `name`。一个人的资料不止姓名，还有身份和介绍。如果每一项都单独声明一个变量，变量会越来越多，也看不出它们属于同一个人。

本章把姓名、身份、介绍放进一个对象 `profile`，并用 TypeScript 写明这个对象应该有哪些字段。完成后，页面显示的内容和之前一样，但三项资料都来自同一个对象；写错字段名时，编辑器会立即标红提示。

## 二、必要原理

### 用对象把相关的数据放在一起

对象用花括号表示，里面是一组“属性名: 值”：

```ts
const profile = {
  name: '小林',
  role: '前端开发学习者',
};
```

读取属性用点号：`profile.name` 得到“小林”，`profile.role` 得到“前端开发学习者”。在 JSX 中同样放在花括号里：`<h2>{profile.name}</h2>`。

### 用 type 描述对象应有的样子

TypeScript 可以给数据规定一个“形状”，叫做**类型**。`type` 关键字定义一个类型并给它起名：

```ts
type Profile = {
  name: string;
  role: string;
  intro: string;
};
```

这表示：一个 `Profile` 必须有 `name`、`role`、`intro` 三个属性，值都是字符串（`string`）。类型名习惯用大写字母开头，和普通变量区分。

声明变量时，在变量名后面加冒号和类型名，表示这个变量必须符合该类型：

```ts
const profile: Profile = { …… };
```

之后如果少写了一个属性、属性名拼错，或者把数字写给了字符串属性，TypeScript 都会报错。

### 类型只在开发时起作用

类型是写给 TypeScript 检查用的。Vite 把代码交给浏览器之前，会把 `type` 定义和 `: Profile` 这样的标注全部去掉，浏览器运行的是普通 JavaScript。所以：

- 类型不会改变页面的显示效果。
- 类型错误不会阻止开发服务器显示页面。你需要看编辑器中的红色波浪线，或者运行 `npm.cmd run typecheck` 才能发现。

这也是文件扩展名是 `.tsx` 的原因：`ts` 表示 TypeScript，`x` 表示文件里可以写 JSX。

## 三、动手实现

### 第 1 步：定义 Profile 类型

打开 `src/App.tsx`，在文件最上方、`export default function App()` 之前加入：

```tsx
type Profile = {
  name: string;
  role: string;
  intro: string;
};
```

类型定义放在组件外面，文件中的其他代码都可以使用它。

### 第 2 步：用对象代替变量 name

把 `App` 函数中的 `const name = '小林';` 替换为：

```tsx
  const profile: Profile = {
    name: '小林',
    role: '前端开发学习者',
    intro: '正在用 React 制作自己的第一个页面。',
  };
```

每个属性后面的逗号用来分隔属性。最后一个属性后面也可以加逗号，这样以后添加新属性时不容易漏写。

### 第 3 步：在 JSX 中读取对象的属性

把 `<article>` 中的内容改为：

```tsx
      <article>
        <h2>{profile.name}</h2>
        <p>{profile.role}</p>
        <p>
          我是{profile.name}，{profile.intro}
        </p>
      </article>
```

身份和介绍原来是写死的文字，现在也都来自 `profile`。

### 第 4 步：故意写错，看看 TypeScript 的提示

把 `<h2>{profile.name}</h2>` 临时改成 `<h2>{profile.nmae}</h2>`。VS Code 会在 `nmae` 下面画红色波浪线。在终端运行：

```powershell
npm.cmd run typecheck
```

输出类似：

```text
src/App.tsx:18:22 - error TS2339: Property 'nmae' does not exist on type 'Profile'.
```

这句话的意思是：“`Profile` 类型上没有 `nmae` 这个属性。”开头的 `src/App.tsx:18:22` 表示问题出在这个文件的第 18 行第 22 列，`TS2339` 是这类错误的编号，搜索资料时可以用到。

此时看看浏览器：页面没有报错，但姓名的位置变成了空白。因为浏览器只运行 JavaScript，`profile.nmae` 的结果是“没有值”，React 什么都不显示。这正是需要类型检查的原因：有些错误页面不会主动告诉你。

确认后改回 `profile.name`。

## 四、运行与检查

保持开发服务器运行（`npm.cmd run dev`），保存文件后在浏览器中查看。

1. 页面显示的内容和第 2 章相同：姓名“小林”、身份“前端开发学习者”、介绍“我是小林，正在用 React 制作自己的第一个页面。”。
2. 把 `profile` 中的 `role` 改成“React 初学者”，保存，页面上的身份跟着变化。检查后改回原文。
3. 删掉 `profile` 中的 `intro` 那一行，`profile` 下方出现红色波浪线。把鼠标移到上面，提示中有 `Property 'intro' is missing`，意思是缺少 `intro` 属性。检查后恢复这一行。

最后运行类型检查，应没有错误输出：

```powershell
npm.cmd run typecheck
```

**小练习**：给 `Profile` 类型和 `profile` 对象都加上 `city` 属性（例如“杭州”），并在介绍文字后面显示“来自杭州”。再试试只在类型中加 `city`、不在对象中加，看看 TypeScript 怎样提示。练习后恢复本章代码（先存档再练习，练习后用 `git restore .` 恢复，见[准备篇三](准备篇三-怎样用Git保存每一章的进度.md)最后的“做小练习和实验的顺序”）。

## 五、常见错误

| 现象 | 原因 | 怎么改 |
| --- | --- | --- |
| 编辑器提示 `Cannot find name 'name'` | 删除了变量 `name`，JSX 中还有地方写着 `{name}` | 改成 `{profile.name}` |
| 编辑器提示缺少某个属性 | 对象中少写了类型要求的属性 | 补上属性，或检查属性名拼写 |
| 编辑器提示 `Type 'number' is not assignable to type 'string'` | 给字符串属性写了数字，例如 `role: 1` | 字符串要放在引号里 |
| 对象中属性之间报语法错误 | 属性之间漏了逗号，或把冒号写成了等号 | 写成 `name: '小林',` 的形式 |
| 页面正常，但 typecheck 报错 | 类型错误不会阻止页面显示 | 以 typecheck 的结果为准，修好再继续 |

## 六、本章完整代码

### `src/App.tsx`

```tsx
type Profile = {
  name: string;
  role: string;
  intro: string;
};

export default function App() {
  const profile: Profile = {
    name: '小林',
    role: '前端开发学习者',
    intro: '正在用 React 制作自己的第一个页面。',
  };

  return (
    <main>
      <h1>个人介绍</h1>
      <article>
        <h2>{profile.name}</h2>
        <p>{profile.role}</p>
        <p>
          我是{profile.name}，{profile.intro}
        </p>
      </article>
    </main>
  );
}
```

## 七、本章改动小结

修改 `src/App.tsx`：新增 `Profile` 类型，用对象 `profile` 代替变量 `name`，身份和介绍也改为读取对象属性。
