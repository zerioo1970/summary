# 第 6 章：页面一片空白时，如何找到第一条有用的错误信息？

前置：[第 5 章：如何在页面上显示一张本地图片？](第005章-如何在页面上显示一张本地图片.md)

## 一、本章要解决的问题

改了几行代码，保存后页面突然变成一片空白，什么提示都没有。新手遇到这种情况，常常只能把刚才的修改一行行撤回去试。

本章故意制造两种常见错误，学会到哪里找错误信息、怎样读懂第一条有用的信息，再根据它定位到出错的那一行。本章结束后，代码恢复为第 5 章的样子。

## 二、必要原理

### 错误信息出现在三个地方

| 位置 | 什么错误会出现在这里 | 怎么打开 |
| --- | --- | --- |
| 浏览器页面上的错误层 | 代码写法错误，Vite 无法转换代码，例如漏写结束标签 | 自动出现在页面上 |
| 浏览器控制台 | 代码能转换，但运行时出错，例如读取了不存在的数据 | 按 F12，切换到 Console（控制台）面板 |
| 运行 `dev` 的终端 | 与页面上的错误层内容相同 | 切换到对应的终端窗口 |

页面空白而且页面上没有错误层时，几乎总是第二种情况：代码运行时出错，React 无法生成页面。这时第一件事就是打开控制台。

### 为什么一个错误会让整页空白

React 在显示组件时如果遇到错误，无法确定这个组件应该显示什么。为了避免显示一半错误的内容，它会移除整个页面。所以哪怕只有一行出错，看到的也是一片空白。第 135 章会讲怎样只让出错的区域显示提示，其他部分正常显示。

### 怎样读错误信息

控制台可能一下子出现好几条红色信息，不需要全部读懂。按这个顺序看：

1. **找第一条红色错误。** 后面的信息常常是第一条错误引起的连锁反应。
2. **读错误类型和说明。** 例如 `TypeError: Cannot read properties of undefined`，说明“想从一个不存在的值上读取属性”。
3. **找文件名和行号。** 错误信息中类似 `App.tsx:21` 的部分是可以点击的链接，点开会直接跳到出错的那一行。
4. **回到编辑器看这一行。** 结合错误说明，看这一行用到的哪个值不对。

## 三、动手实现

### 第 1 步：制造一个运行时错误

打开 `src/App.tsx`，把显示姓名的这一行：

```tsx
        <h2>{profile.name}</h2>
```

临时改成：

```tsx
        <h2>{profile.nmae.length}</h2>
```

这一行想显示“姓名的字数”，但把 `name` 拼成了 `nmae`。保存后，浏览器页面变成一片空白。

### 第 2 步：在控制台中读第一条错误

按 F12，切换到 Console 面板。第一条红色信息类似：

```text
Uncaught TypeError: Cannot read properties of undefined (reading 'length')
    at App (App.tsx:28:27)
```

逐段理解：

- `TypeError`：值的类型不对，这里是对“没有值”的东西做了操作。
- `Cannot read properties of undefined (reading 'length')`：想从 `undefined`（没有值）上读取 `length` 属性。
- `at App (App.tsx:28:27)`：错误发生在 `App` 组件中，`App.tsx` 第 28 行第 27 列。点击这个链接，开发者工具会打开源代码并定位到这一行。

结合起来就能推断：`length` 前面的 `profile.nmae` 是 `undefined`，也就是 `profile` 中没有 `nmae` 这个属性。检查拼写，问题找到了。

下面可能还有一条以 `An error occurred in the <App> component` 开头的信息，这是 React 补充说明“错误发生在哪个组件中”，与第一条指向同一个问题。

另外，第 3 章学过的类型检查也能提前发现这个错误：编辑器中 `nmae` 下面有红色波浪线。养成习惯：保存后如果编辑器中有红线，先处理红线。

把这一行改回 `<h2>{profile.name}</h2>`，页面恢复正常。

### 第 3 步：制造一个写法错误

把 `</article>` 这一行删掉，保存。

这次页面上会出现一个深色的错误层，标题中有出错的文件路径 `src/App.tsx` 和行号，下面显示出错位置附近的代码，并用标记指出问题所在。错误说明的大意是：某个标签缺少对应的结束标签。运行 `dev` 的终端中也会出现同样的信息。

这类错误发生在 Vite 转换代码的阶段，代码还没有开始运行，所以控制台中不一定有错误，要看页面上的错误层或终端。

把 `</article>` 加回原来的位置，保存。错误层自动消失，页面恢复正常。

## 四、运行与检查

保持开发服务器运行（`npm.cmd run dev`），按第三节的步骤操作。

1. 第 1 步保存后页面空白；在控制台中能找到 `TypeError` 和 `App.tsx` 的行号，点击链接能跳到 `profile.nmae.length` 那一行。
2. 改回后页面恢复，控制台中不再出现新的红色错误。可以点击控制台左上方的清除按钮（带斜线的圆形图标），清掉旧的信息再观察。
3. 第 3 步保存后页面上出现错误层，并能从中读出文件名和行号；加回结束标签后错误层消失。
4. 全部恢复后，页面与第 5 章完全相同。

最后运行类型检查，应没有错误输出：

```powershell
npm.cmd run typecheck
```

**小练习**：把 `import avatarLin from './assets/avatar-lin.svg';` 中的文件名临时改成 `avatar.svg`，保存，看看错误出现在哪里，并从错误信息中找出“找不到哪个文件”。练习后改回。

## 五、常见错误

| 现象 | 原因 | 怎么改 |
| --- | --- | --- |
| 控制台中信息太多，找不到重点 | 旧的信息和新的混在一起 | 先清除控制台，再刷新页面，看第一条红色错误 |
| 控制台中没有红色错误，页面却是空白 | 错误可能被筛选隐藏了 | 确认控制台上方的筛选下拉框中勾选了“错误”（Errors） |
| 改好代码后页面仍然空白 | 还有别的错误，或者文件没有保存 | 保存后清除控制台，看是否有新的第一条错误 |
| 错误层消失后页面仍显示旧内容 | 浏览器还停留在出错时的状态 | 手动刷新一次页面 |
| 点击行号后看到的代码和自己写的不太一样 | 开发者工具显示的是 Vite 转换前后的对应位置，个别情况下列号会有偏差 | 以行号为准，回到编辑器中查看这一行 |
