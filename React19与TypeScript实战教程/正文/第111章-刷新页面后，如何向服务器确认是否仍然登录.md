# 第 111 章：刷新页面后，如何向服务器确认是否仍然登录？

前置：[第 110 章：如何让所有页面都能读取当前登录用户？](第110章-如何让所有页面都能读取当前登录用户.md)

## 一、本章要解决的问题

登录以后按 F5 刷新，导航栏又显示“登录”。用户明明没有退出，却要重新登录一次，关掉标签页再打开也一样。上一章已经看到，浏览器中的登录 Cookie 其实还在，服务器也还记得这个用户，只是页面在刷新后忘了。

本章让应用在打开时先问一次服务器“我现在登录了吗”。完成后：登录以后刷新页面，导航栏片刻之后显示“管理员小林”，不需要重新登录；没有登录时刷新，显示“登录”；确认的这一小段时间里，导航栏右侧什么也不显示，不会先闪一下“登录”。

## 二、必要原理

### 问服务器“我是谁”

练习服务提供了一个接口，专门回答“当前是谁登录”：

| 请求 | 已经登录 | 没有登录或登录已失效 |
| --- | --- | --- |
| `GET /api/auth/me` | 状态 200，返回用户信息，格式和登录接口相同 | 状态 401 |

浏览器会自动带上登录 Cookie（第 109 章），服务器据此判断。前端什么都不用传，只需要发出请求。

401 在这里同样不是“出错”，而是“没有登录”这个正常的答案，所以 `fetchCurrentUser` 遇到 401 返回 `null`，和第 101 章的 404 一样处理。

### 应用一打开就确认

确认登录状态是整个应用的事，不属于某一个页面，所以写在 `AuthProvider` 中：它在最外层，应用打开时它第一个显示，之后一直都在。

写法是第 74 章“打开页面时自动读取”：Effect 的依赖数组是 `[]`，只在打开时执行一次；用 `ignore` 防止开发环境中执行两次时出错（第 75 章）。读到用户就保存，读到 `null` 或请求失败都按“没有登录”处理。请求失败时不显示错误：用户仍然可以去登录页重新登录。

### 确认的结果晚到时，不要覆盖刚登录的用户

如果用户直接打开登录页，确认请求和登录请求几乎同时发出。登录先完成时，`user` 已经是刚登录的用户；随后确认的结果才回来，它是在登录之前发出的，答案是“没有登录”。如果这时直接 `setUser(null)`，刚登录的用户就被清掉了，这和第 78 章“先发出的请求覆盖后面的结果”是同一类问题。

所以确认的结果用第 28 章的更新函数写入，以当前的值为准：

```tsx
setUser((current) => current ?? currentUser);
```

当前已经有用户（刚登录），就保留它；当前没有用户，才用确认得到的结果。请求失败时什么也不改，保持“没有登录”。

### 第三种状态：还不知道

请求发出去到收到回答，大约要半秒。这段时间里 `user` 是 `null`，如果导航栏照常显示，会先显示“登录”，半秒后又变成“管理员小林”，看起来像出了问题。第 112 章还要根据登录状态决定能不能进入某个页面，这时把“还不知道”当成“没有登录”，就会误把已登录的用户赶去登录页。

所以要多记一件事：是否还在确认中。

```tsx
const [checking, setChecking] = useState(true);
```

初始值是 `true`，确认完（不论结果如何）在 `finally` 中改为 `false`。Context 中同时提供 `checking`，导航栏在确认期间不显示用户区域。

这样，登录状态实际上有三种：

| `checking` | `user` | 含义 |
| --- | --- | --- |
| `true` | `null` | 还在问服务器，不知道 |
| `false` | `null` | 确认过了，没有登录 |
| `false` | 用户对象 | 确认过了，已经登录 |

### 控制台中的 401

没有登录时，浏览器的控制台中会出现一行红色的 `GET http://127.0.0.1:5173/api/auth/me 401 (Unauthorized)`。这是浏览器自动记录的“请求返回了错误状态”，不是代码出错，没有登录时它就是正常的回答。

## 三、动手实现

### 第 1 步：读取当前用户的请求

打开 `src/lib/authApi.ts`，在文件最后加入：

```ts

// 返回 null 表示没有登录：浏览器没有 Cookie，或者服务器上的登录已经失效
export async function fetchCurrentUser(): Promise<User | null> {
  let response: Response;
  try {
    response = await fetch(apiUrl('/auth/me'));
  } catch {
    throw new Error('无法连接练习服务，请确认它已经启动。');
  }
  if (response.status === 401) {
    return null;
  }
  if (!response.ok) {
    throw new Error('读取登录状态失败：服务器返回了状态 ' + response.status + '。');
  }
  const data: unknown = await response.json();
  if (!isUser(data)) {
    throw new Error('用户信息格式不正确。');
  }
  return data;
}
```

### 第 2 步：Context 中加入 checking

打开 `src/lib/authContext.ts`，在 `AuthContextValue` 中 `user` 的下面加入：

```ts
  // 打开页面后先向服务器确认登录状态，确认完之前为 true
  checking: boolean;
```

### 第 3 步：AuthProvider 在打开时确认

把 `src/components/AuthProvider.tsx` 改为：

```tsx
import { useEffect, useState } from 'react';
import type { ReactNode } from 'react';
import { fetchCurrentUser } from '../lib/authApi';
import { AuthContext } from '../lib/authContext';
import type { User } from '../types/user';

type AuthProviderProps = {
  children: ReactNode;
};

export default function AuthProvider({ children }: AuthProviderProps) {
  // null 表示没有登录
  const [user, setUser] = useState<User | null>(null);
  const [checking, setChecking] = useState(true);

  useEffect(() => {
    let ignore = false;

    async function checkOnOpen() {
      try {
        const currentUser = await fetchCurrentUser();
        if (!ignore) {
          // 确认期间用户可能已经在登录页登录了，这时以登录得到的用户为准
          setUser((current) => current ?? currentUser);
        }
      } catch {
        // 确认失败时保持“没有登录”，用户仍然可以去登录页重新登录
      } finally {
        if (!ignore) {
          setChecking(false);
        }
      }
    }

    checkOnOpen();
    return () => {
      ignore = true;
    };
  }, []);

  return <AuthContext value={{ user, checking, setUser }}>{children}</AuthContext>;
}
```

### 第 4 步：确认期间导航栏不显示用户区域

打开 `src/components/AppLayout.tsx`，把读取当前用户的一行改为：

```tsx
  const { user, checking } = useAuth();
```

把显示用户名和“登录”的那一段改为：

```tsx
        {/* 确认登录状态期间什么也不显示，避免先闪一下“登录”再变成用户名 */}
        {!checking && user && <span className="nav-user">{user.displayName}</span>}
        {!checking && !user && (
          <NavLink to="/login" className="nav-user">
            登录
          </NavLink>
        )}
```

三种状态各对应一种显示：确认中两个条件都不成立，什么也不显示。

## 四、运行与检查

保持开发服务器和练习服务都在运行（准备篇二）。

1. 没有登录时打开首页。导航栏右侧先是空的，半秒后出现“登录”。Network（网络）中有 `/api/auth/me` 的请求，状态 401；控制台中有一行红色的 401 记录，这是正常的。
2. 用 `admin` 登录，然后在地址栏打开 `http://127.0.0.1:5173/news`。页面重新加载，导航栏右侧先是空的，半秒后显示“管理员小林”，不需要重新登录。这次 `/api/auth/me` 的状态是 200。
3. 关掉这个标签页，重新打开 `http://127.0.0.1:5173/`，仍然是登录状态。
4. 在练习服务的终端按 Ctrl+C，再运行 `npm.cmd run api` 重启它，然后刷新页面。导航栏显示“登录”：练习服务把登录记录保存在内存中，重启后就忘了（准备篇二），浏览器中的 Cookie 也就不再有效。
5. 在 React 开发者工具中选中 `AuthProvider`，刷新页面时可以看到第二个 State 从 `true` 变为 `false`。

最后运行检查，应没有错误：

```powershell
npm.cmd run check
```

**小练习**：把练习服务的等待时间临时加长，观察确认期间的样子：在 `fetchCurrentUser` 中把地址改成 `apiUrl('/auth/me?delay=3000')`，刷新页面，导航栏右侧空三秒后才显示。再试着在确认期间显示“正在确认……”几个字。练习后恢复本章代码。

## 五、常见错误

| 现象 | 原因 | 怎么改 |
| --- | --- | --- |
| 已经登录，刷新时导航栏先闪一下“登录”，再变成用户名 | 没有区分“还在确认”和“没有登录”，确认期间 `user` 为 `null` 就显示了“登录” | 增加 `checking`，确认完之前不显示用户区域 |
| 导航栏右侧一直是空的 | `setChecking(false)` 写在了 `try` 中，请求失败时没有执行 | 写在 `finally` 中，不论成功失败都要结束确认 |
| 没有登录时，页面上显示“读取登录状态失败：服务器返回了状态 401。” | 把 401 当成错误抛出了 | 401 返回 `null`，表示没有登录 |
| Network 中 `/api/auth/me` 一直在重复发送 | Effect 的依赖数组中写了 `user`，每次 `setUser` 都让 Effect 重新执行（第 80 章） | 依赖数组写 `[]`，只在打开时确认一次 |
| 在登录页很快登录成功后，导航栏却又显示“登录” | 确认请求的结果晚于登录才回来，`setUser(currentUser)` 把刚登录的用户换成了 `null` | 用更新函数：`setUser((current) => current ?? currentUser)` |

## 六、本章完整代码

### `src/lib/authApi.ts`

```ts
import { apiUrl } from './api';
import { isUser } from '../types/user';
import type { User } from '../types/user';

export type LoginResult = { status: 'success'; user: User } | { status: 'failed'; message: string };

async function readMessage(response: Response, fallback: string): Promise<string> {
  try {
    const data: unknown = await response.json();
    if (typeof data === 'object' && data !== null && 'message' in data) {
      if (typeof data.message === 'string') {
        return data.message + '。';
      }
    }
  } catch {
    // 返回的不是 JSON 时，使用默认的提示
  }
  return fallback;
}

export async function login(username: string, password: string): Promise<LoginResult> {
  let response: Response;
  try {
    response = await fetch(apiUrl('/auth/login'), {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ username, password }),
    });
  } catch {
    throw new Error('无法连接练习服务，请确认它已经启动。');
  }
  // 401 表示用户名或密码不对，这是用户可以改正的情况，不当作程序出错
  if (response.status === 401) {
    return { status: 'failed', message: await readMessage(response, '用户名或密码不正确。') };
  }
  if (!response.ok) {
    throw new Error('登录失败：服务器返回了状态 ' + response.status + '。');
  }
  const data: unknown = await response.json();
  if (!isUser(data)) {
    throw new Error('登录成功，但返回的用户信息格式不正确。');
  }
  return { status: 'success', user: data };
}

// 返回 null 表示没有登录：浏览器没有 Cookie，或者服务器上的登录已经失效
export async function fetchCurrentUser(): Promise<User | null> {
  let response: Response;
  try {
    response = await fetch(apiUrl('/auth/me'));
  } catch {
    throw new Error('无法连接练习服务，请确认它已经启动。');
  }
  if (response.status === 401) {
    return null;
  }
  if (!response.ok) {
    throw new Error('读取登录状态失败：服务器返回了状态 ' + response.status + '。');
  }
  const data: unknown = await response.json();
  if (!isUser(data)) {
    throw new Error('用户信息格式不正确。');
  }
  return data;
}
```
