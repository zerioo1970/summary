# 准备篇三：怎样用 Git 保存每一章的进度？

前置：[准备篇二：怎样启动教程配套的练习服务？](准备篇二-怎样启动教程配套的练习服务.md)

## 一、本章要解决的问题

本教程从头到尾在同一个项目中修改代码，一共一百多章。难免会遇到这种情况：改着改着页面坏了，想回到上一章结束时能正常运行的样子，却记不清改过哪些地方。

本章用 Git 给项目“存档”。每学完一章存一次，改坏时可以查看改了什么，也能撤销还没存档的修改。完成后，项目中有第一个存档，你会用命令查看存档记录。

## 二、必要原理

### Git 是什么

Git 是一个记录文件变化的工具。你告诉它“现在的状态存一份”，它就把项目中所有文件当时的内容记录下来，这一份记录叫一次**提交**（commit）。之后可以随时查看两次提交之间改了什么，或者把文件恢复成某次提交时的样子。

实际工作中，几乎所有团队都用 Git 管理代码。本教程只用到其中最基本的几个命令。

### 存档分两步：add 和 commit

1. `git add`：选择要存档的文件。`git add -A` 表示选择所有有变化的文件。
2. `git commit`：把选好的文件存成一次提交，并写一句说明，例如“完成第 5 章”。

### 哪些文件不存档

准备篇一建立、准备篇二补充的 `.gitignore` 列出了不需要存档的文件夹：`node_modules` 可以随时用 `npm.cmd install` 重新下载，`dist` 是构建时自动生成的，`server/data` 是练习服务的运行数据。Git 会自动跳过这些文件夹。

## 三、动手实现

### 第 1 步：安装 Git

从 [Git 官网](https://git-scm.com/downloads/win) 下载 Git for Windows，安装时全部使用默认选项。安装完成后，关闭并重新打开 PowerShell，检查版本：

```powershell
git --version
```

显示类似 `git version 2.xx.x.windows.1` 即可。

### 第 2 步：设置你的名字和邮箱

每次提交都会记录是谁做的。第一次使用 Git 时设置一次即可，以后不用再设：

```powershell
git config --global user.name "你的名字"
git config --global user.email "you@example.com"
```

名字和邮箱只记录在提交信息里，不会发送到任何地方。

### 第 3 步：把项目交给 Git 管理

在项目文件夹 `react-daily-practice` 中运行：

```powershell
git init
```

这会在项目中建立一个隐藏的 `.git` 文件夹，以后的提交都保存在里面。这个命令每个项目只需要运行一次。

### 第 4 步：完成第一次提交

先看看当前有哪些文件会被存档：

```powershell
git status
```

列出的文件中应该有 `package.json`、`src/` 等，但没有 `node_modules/` 和 `server/data/`，因为它们已经写在 `.gitignore` 中。确认后存档：

```powershell
git add -A
git commit -m "完成准备篇"
```

`-m` 后面引号中的文字就是这次提交的说明。

## 四、运行与检查

1. 运行 `git log --oneline`，可以看到一行记录，最后面是“完成准备篇”。前面的一串字母数字是这次提交的编号。
2. 把 `src/App.tsx` 中的“项目已启动”改成“测试修改”，保存。
3. 运行 `git status`，`src/App.tsx` 显示为已修改（modified）。
4. 运行 `git diff`，可以看到改动：前面带 `-` 的是原来的内容，带 `+` 的是新内容。内容较多时按空格键翻页，按 Q 键退出。
5. 运行下面的命令撤销这次修改：

   ```powershell
   git restore src/App.tsx
   ```

   回到 VS Code，文件恢复成“项目已启动”。再运行 `git status`，显示没有需要提交的修改。

**以后每章的习惯**：学完一章、确认页面正常并且检查命令通过后，存档一次：

```powershell
git add -A
git commit -m "完成第 1 章"
```

页面改坏又找不到原因时，先用 `git diff` 看看自上次存档后改了哪些地方。确定要放弃这些修改时，用 `git restore 文件路径` 恢复单个文件，或用 `git restore .` 恢复所有文件。注意：`git restore` 会直接丢掉还没提交的修改，无法撤回，运行前先确认。

**做小练习和实验的顺序**：很多章末尾有小练习，最后写着“练习后恢复本章代码”；有些章的步骤中也会让你临时改一处代码，观察完再改回。按下面的顺序做，恢复时就不会出错：

1. 先完成本章的全部步骤，运行 `npm.cmd run check` 通过后，**先存档**（`git add -A` 和 `git commit`）。
2. 再做小练习，随便怎么改都可以。
3. 做完后运行 `git restore .`，所有文件回到刚才存档时的样子，也就是本章完成时的代码。练习中新建的文件不会被 `git restore` 删除，`git status` 会把它们列为 untracked（未跟踪），手动删掉即可。

如果顺序反了，先做练习、还没存档就运行 `git restore .`，本章刚写的代码会和练习的修改一起被撤销。

章节步骤中途的临时修改（例如“把地址临时改为……，观察后改回”），还没到存档的时候，用编辑器的撤销（Ctrl+Z）或照原样改回即可。改完后可以运行 `git diff`，确认只剩本章应有的修改，没有忘记改回的地方。

## 五、常见错误

| 现象 | 原因 | 怎么改 |
| --- | --- | --- |
| 提示 `git` 不是可识别的命令 | 安装后没有重新打开终端 | 关闭所有终端后重新打开 |
| 提交时提示 `Please tell me who you are` | 没有完成第 2 步的名字和邮箱设置 | 运行第 2 步的两条命令后重新提交 |
| `git status` 列出了 `node_modules` 中的大量文件 | `.gitignore` 不在项目根目录，或文件名写错了 | 确认文件名是 `.gitignore`，与 `package.json` 在同一个文件夹 |
| 提示 `not a git repository` | 当前位置不是项目文件夹，或还没有运行 `git init` | 先 `cd` 到项目文件夹，再运行命令 |
| 提交时出现 `LF will be replaced by CRLF` 之类的提示 | Windows 和其他系统的换行符不同，Git 在自动转换 | 这是提示不是错误，不影响使用 |

## 六、本章完整代码

本章没有新增或修改项目文件。运行 `git init` 后，项目中多了一个由 Git 管理的隐藏文件夹 `.git`，不需要手动修改它。

## 七、本章改动小结

项目文件没有变化；项目开始由 Git 管理，并有了第一次提交“完成准备篇”。
