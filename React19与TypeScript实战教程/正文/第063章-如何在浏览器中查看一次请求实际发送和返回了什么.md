# 第 63 章：如何在浏览器中查看一次请求实际发送和返回了什么？

前置：[第 62A 章：请求失败时，如何在页面上显示错误提示？](第062A章-请求失败时，如何在页面上显示错误提示.md)

## 一、本章要解决的问题

上一章点击“加载文章”后，要么出现文章，要么出现“文章读取失败”。一旦失败，页面只给出一句笼统的提示：请求到底有没有发出去？发到了哪个地址？服务器回了什么？光看页面是不知道的。

浏览器开发者工具中的 Network（网络）面板会记录页面发出的每一个请求。本章不修改代码，而是学会在 Network 面板中看清一次请求的地址、状态码、返回内容和耗时，并用它找出上一章错误提示中的一个问题。

## 二、必要原理

### 一次请求包含什么

每次 `fetch`，浏览器都会发出一个**请求**，服务器回一个**响应**。排查问题时最常看的是这几项：

| 项目 | 在哪里看 | 说明 |
| --- | --- | --- |
| 请求地址 | Headers（标头）中的 Request URL | 实际请求的完整网址，地址写错一眼就能看出来 |
| 请求方式 | Headers 中的 Request Method | 读取数据是 `GET`，第 10 部分保存数据时会用到 `POST` 等 |
| 状态码 | Status 列，或 Headers 中的 Status Code | 服务器处理的结果 |
| 返回内容 | Preview（预览）和 Response（响应） | 服务器实际返回的数据 |
| 耗时 | Time 列，或 Timing | 从发出到收完响应用了多久 |

### 常见的状态码

状态码是一个三位数，第一位数字表示大类：

- **2 开头**表示成功，最常见的是 `200`。
- **4 开头**表示请求有问题，例如 `404` 找不到、`401` 没有登录、`422` 提交的数据不符合要求。
- **5 开头**表示服务器出了问题，例如 `500` 服务器内部错误。

Network 面板会把 4 开头和 5 开头的请求标成红色。如果请求根本没有到达服务器，例如服务器没有启动，状态一栏显示 `(failed)`，并没有状态码。

### 只看接口请求

页面加载时还会请求脚本、样式、图片等文件，列表会很长。面板顶部的筛选按钮中选择 **Fetch/XHR**，就只显示 `fetch` 发出的请求。

### 练习服务的两个练习参数

练习服务的所有接口都支持两个参数，加在地址末尾：

- `?delay=3000`：等 3000 毫秒（3 秒）再响应，用来观察“请求进行中”。
- `?fail=500`：直接返回指定的错误状态码，用来练习失败处理。

## 三、动手实现

保持开发服务器和练习服务都在运行（准备篇二）。本章对代码的修改都是临时的，做完后恢复为第 62 章的代码。

### 第 1 步：找到文章请求

在文章页按 F12 打开开发者工具，切换到 **Network** 面板，在筛选按钮中选择 **Fetch/XHR**。点击页面上的“加载文章”，列表中出现一行 `articles`，Status 是 `200`。

### 第 2 步：查看请求的详细信息

点击 `articles` 这一行，右侧出现详细信息：

- **Headers**：Request URL 是 `http://127.0.0.1:3001/api/articles`，Request Method 是 `GET`，Status Code 是 `200 OK`。
- **Preview**：以可以展开的树形显示返回的数组，能看到 4 篇文章，每篇有 `id`、`title`、`summary`、`publishedAt`。
- **Response**：返回的原始文字。

Time 列显示大约 500 毫秒，这是练习服务故意等待的时间。

### 第 3 步：观察进行中的请求

把 `src/pages/ArticlePage.tsx` 中的请求地址临时改为：

```tsx
      const response = await fetch('http://127.0.0.1:3001/api/articles?delay=3000');
```

保存后点击“加载文章”。在 3 秒内，Network 中这一行的 Status 显示 `(pending)`，表示还在等待响应。

### 第 4 步：观察服务器返回错误

把地址中的 `?delay=3000` 改为 `?fail=500`，保存后点击“加载文章”。

Network 中这一行变成红色，Status 是 `500`。Preview 中能看到练习服务返回的 `message`。再看页面：显示的是“文章读取失败，请确认练习服务已经启动。”——可练习服务明明在运行。上一章把所有失败都归为“服务没有启动”，提示和真实原因不符。第 65 章会把这两种失败分开。

### 第 5 步：观察连接失败

把地址恢复为 `'http://127.0.0.1:3001/api/articles'`。在运行练习服务的终端按 Ctrl+C 停止它，再点击“加载文章”。Network 中的 Status 显示 `(failed)`，点开后看不到任何响应内容，因为请求根本没有到达服务器。

最后重新运行 `npm.cmd run api`。

## 四、运行与检查

保持开发服务器和练习服务都在运行，按第三节的步骤操作。

1. 正常请求：Status 是 `200`，Preview 中有 4 篇文章，Time 约 500 毫秒。
2. 加上 `?delay=3000`：3 秒内 Status 是 `(pending)`。
3. 加上 `?fail=500`：这一行变红，Status 是 `500`，页面却提示“请确认练习服务已经启动”。
4. 停止练习服务：Status 是 `(failed)`。
5. 恢复代码并重新启动练习服务后，加载正常，页面与第 62A 章相同。

最后运行检查，应没有错误：

```powershell
npm.cmd run check
```

**小练习**：把地址临时改成 `http://127.0.0.1:3001/api/article`（少一个 `s`），点击加载，在 Network 中看 Status 和 Preview 中的 `message`，说出问题出在哪里。练习后恢复本章代码。

## 五、常见错误

| 现象 | 原因 | 怎么改 |
| --- | --- | --- |
| Network 面板是空的 | 打开面板之前请求已经发完了；面板只记录打开以后发出的请求 | 先打开 Network，再点击“加载文章” |
| 列表中有很多 `.tsx`、`.css` 文件，找不到 `articles` | 没有筛选请求类型 | 选择 Fetch/XHR，或在过滤框中输入 `articles` |
| 刷新页面后，之前的请求记录不见了 | Network 默认在刷新时清空记录 | 勾选面板上方的 Preserve log（保留日志）可以保留记录 |
| Preview 中显示的是网页而不是数据 | 请求地址写错，请求到了开发服务器的页面，而不是练习服务 | 对照 Headers 中的 Request URL 检查地址 |
| 学完本章后，页面一直报错、一直显示空数据或加载很慢 | 步骤中临时加在请求地址上的 `?mode=`、`?fail=`、`?delay=`、`?cors=` 等参数忘了删 | 运行 `git diff` 查看本章改动，删掉地址中的临时参数 |
