# 第 18 章：为什么列表中的每一项需要一个稳定的 key？

前置：[第 17 章：如何把一个数组显示成列表？](第017章-如何把一个数组显示成列表.md)

## 一、本章要解决的问题

第 17 章用 `map` 生成列表时，给每个 `<li>` 写了 `key={item.id}`。很多人第一次遇到这个要求时会想：既然只是为了消除警告，用数组下标 `index` 当 key 不是更省事吗？

本章用一个实验说明：key 决定了 React 把每一项“认成”哪一条数据。key 用错了，列表顺序变化时，页面上的内容会对错位置。完成后，你能说清楚为什么要用数据自己的 `id` 作为 key，以及什么时候不能用下标。本章结束后，代码与第 17 章相同。

## 二、必要原理

### React 怎样更新列表

数据变化后，React 会重新运行组件，得到一份新的列表描述，再和页面上现有的列表对比，只修改不同的地方，而不是把整个列表删掉重建。

对比时，React 需要知道新列表中的每一项对应旧列表中的哪一项。它靠的就是 `key`：**key 相同，React 就认为是同一项**，会保留这一项在页面上已有的元素和状态，只更新变化的文字。

### 为什么用下标会出错

假设原来的列表是 A、B、C，用下标当 key，就是 0、1、2。现在有一条新闻 C 被置顶，列表变成 C、A、B，下标仍是 0、1、2。

React 看到 key 为 0 的项还在，就认为它还是原来那一项，只是文字从 A 变成了 C。于是第一行的元素被保留下来、只换了文字。如果这一行上还带着别的东西（例如用户勾选的复选框、输入了一半的文字、展开的状态），它们会留在第一行，和新的文字 C 配在一起，而不是跟着 A 移到第二行。

用 `id` 作为 key 时，A 的 key 一直是 A 的 id。React 知道 A 只是换了位置，会把 A 的整个元素连同它的状态一起移动。

### 什么样的 key 是好的

- **稳定**：同一条数据，每次显示时 key 都相同。
- **唯一**：同一个列表中没有两项的 key 相同。
- **来自数据本身**：通常用数据的 `id`。

下标只有在列表永远不会排序、插入、删除时才安全，但实际开发中很难保证这一点。也不要用随机数当 key，例如 `Math.random()`，它每次显示都不一样，React 会认为每一项都是新的，全部重建。

## 三、动手实现

本节的修改都是临时的，用来观察现象，最后全部恢复。

### 第 1 步：给每条新闻加一个复选框

打开 `src/pages/NewsPage.tsx`，在 `<h2>` 前面临时加一个复选框：

```tsx
          <li key={item.id} className={styles.item}>
            <input type="checkbox" aria-label="标记已读" />
            <h2>{item.title}</h2>
```

`aria-label` 给复选框起一个名字，读屏软件会读出“标记已读”。复选框是否勾选，由浏览器自己记在这个元素上，React 没有保存它。只要元素被保留，勾选状态就会保留。

### 第 2 步：先用下标作为 key

把 `map` 改为接收第二个参数 `index`（当前元素的下标，从 0 开始），并用它作为 key：

```tsx
        {newsItems.map((item, index) => (
          <li key={index} className={styles.item}>
```

保存后，勾选第一条“学习小组本周开始新的练习”前面的复选框。

### 第 3 步：调整数据顺序

打开 `src/data/news.ts`，把第三条（`id: 3`，代码分享会）剪切，粘贴到数组的最前面，保存。

观察页面：代码分享会移到了第一行，但**勾选标记仍然在第一行**，现在勾选的是代码分享会，而你刚才勾选的是“学习小组本周开始新的练习”。

### 第 4 步：换回 id 作为 key，再做一次

把 key 改回 `key={item.id}`（`index` 参数可以一起删掉），保存。刷新页面，让勾选状态清零。

勾选“学习小组本周开始新的练习”，再到 `news.ts` 中把第一条（代码分享会）移回数组末尾，保存。这次勾选标记跟着“学习小组本周开始新的练习”一起移动了。

### 第 5 步：恢复代码

删除临时加的复选框，确认 `news.ts` 中三条新闻的顺序是 id 1、2、3，`NewsPage.tsx` 与第 17 章相同。

## 四、运行与检查

保持开发服务器运行（`npm.cmd run dev`），按第三节的步骤操作。

1. 用下标作为 key 时，调整顺序后勾选标记停留在原来的位置，和错误的新闻配在一起。
2. 用 `id` 作为 key 时，勾选标记跟着原来那条新闻移动。
3. 恢复后，页面与第 17 章相同。

如果保存 `news.ts` 后整个页面刷新了，勾选全部消失，说明这次修改让开发服务器重新加载了整页，看不到效果。重新勾选后，再调整一次顺序即可。

最后运行检查，应没有错误：

```powershell

```

## 五、常见错误

| 现象 | 原因 | 怎么改 |
| --- | --- | --- |
| 控制台警告 `Encountered two children with the same key` | 两项的 key 相同，例如数据中有两个相同的 `id` | 检查数据，确保 `id` 唯一 |
| 排序或删除后，输入框、勾选状态和内容对不上 | 用下标作为 key | 改用数据的 `id` |
| 每次页面更新，列表中所有输入框都被清空 | 用随机数作为 key，每次都被当成新元素 | 用稳定的 `id` |
| 把 key 写在了 `li` 里面的 `h2` 上，仍然有警告 | key 要写在 `map` 直接返回的最外层元素上 | 写在 `li` 上 |
| 在组件内部读取 `props.key` 得到 `undefined` | key 是给 React 用的，不会作为普通 prop 传给组件 | 组件需要 id 时，另外传一个 prop，例如 `id={item.id}` |
