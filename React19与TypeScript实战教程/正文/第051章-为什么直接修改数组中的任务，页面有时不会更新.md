# 第 51 章：为什么直接修改数组中的任务，页面有时不会更新？

前置：[第 50 章：如何根据现有任务计算未完成数量？](第050章-如何根据现有任务计算未完成数量.md)

## 一、本章要解决的问题

前几章反复强调：不能用 `push`，不能直接改任务对象，要用展开语法、`filter`、`map` 创建新数组和新对象。可是直接修改的代码更短，而且有时候看起来也能用，为什么非要这么麻烦？

本章不加新功能，而是故意写三种错误的更新方式，亲眼看看它们会出什么问题。看过这些现象，以后遇到“数据明明改了，页面却没变”或“改了一个地方，别的地方莫名其妙也变了”，就知道该往哪里找原因。

## 二、必要原理

### React 怎样判断 state 变了

调用 `setTasks(新值)` 时，React 先比较新值和旧值**是不是同一个东西**（用 `Object.is` 比较）。对数组和对象来说，比较的不是内容，而是“是不是同一个数组、同一个对象”。

- `setTasks([...tasks, newTask])`：方括号创建了一个新数组，和旧的不是同一个，React 重新渲染。
- `tasks.push(newTask); setTasks(tasks)`：数组内容变了，但还是原来那个数组，React 认为没有变化，可以跳过这次更新。

修改数组中的某个对象也一样：`task.completed = true` 改的是原来的对象，`tasks` 还是原来的数组。

### 为什么“有时”能更新

直接修改的数据并没有消失，它就留在 `tasks` 中。只要**别的原因**让组件重新渲染了，渲染时读到的就是改过的数据，页面就“突然”更新了。所以直接修改带来的问题很难排查：有时完全没反应，有时在另一个操作之后才显示，有时碰巧和别的 state 一起更新，看起来一切正常。

### 本章会用到的 find

实验一要找到某一条任务。数组的 `find` 方法和 `filter` 类似，也接收一个判断函数，但它返回**第一个**符合条件的元素本身，而不是新数组；找不到时返回 `undefined`：

```tsx
const task = tasks.find((item) => item.id === id);
```

## 三、动手实现

本章的修改都在 `src/pages/TaskPage.tsx` 中，每个实验做完都要恢复成第 50 章的代码。开始前确认“只看未完成”没有勾选。

### 第 1 步：实验一，直接修改对象后交回原数组

把 `handleToggle` 临时改为：

```tsx
  function handleToggle(id: string) {
    const task = tasks.find((item) => item.id === id);
    if (task) {
      task.completed = !task.completed;
    }
    setTasks(tasks);
  }
```

点击“完成注册表单练习”的复选框：勾选没有出现，数量仍是“还有 2 项未完成”，看起来什么都没发生。

接着勾选“只看未完成”：列表中只剩“预习数组的 map 和 filter”，数量突然变成“还有 1 项未完成”。刚才那次点击其实已经改了数据，只是直到这一次重新渲染才显示出来。

做完后把 `handleToggle` 恢复为第 50 章的写法，并取消勾选“只看未完成”。

### 第 2 步：实验二，用 push 添加

把 `handleAdd` 中的 `setTasks([...tasks, newTask]);` 临时改为：

```tsx
    tasks.push(newTask);
    setTasks(tasks);
```

添加一条任务，它能正常显示，看起来没有问题。这是因为下一行的 `setNewTitle('')` 改变了另一个 state，组件重新渲染时读到了被 `push` 过的数组。

再把下一行 `setNewTitle('');` 也临时删掉，输入“测试”后点击“添加”：列表没有变化。在输入框中再输入一个字，“测试”这条任务才出现在列表中。

做完后恢复这两行。

### 第 3 步：实验三，在 map 中直接修改对象

有人知道要创建新数组，于是写成：

```tsx
  function handleToggle(id: string) {
    setTasks((current) =>
      current.map((task) => {
        if (task.id === id) {
          task.completed = !task.completed;
        }
        return task;
      }),
    );
  }
```

`map` 确实返回了新数组，但里面还是原来的对象，`task.completed = ...` 修改了它们。这里还用了第 28 章的更新函数写法。

点击“完成注册表单练习”的复选框：勾选仍然没有出现。开发时 `main.tsx` 中的 `<StrictMode>` 会故意把更新函数执行两次，用来暴露这类问题：第一次把 `completed` 改成 `true`，第二次在同一个对象上又改回 `false`，结果等于没改。上线后的版本只执行一次，这段代码会“正常”工作，问题就被藏起来了。

做完后恢复 `handleToggle`。

## 四、运行与检查

保持开发服务器运行（`npm.cmd run dev`），按第三节的步骤操作。

2. 实验二：保留 `setNewTitle('')` 时添加正常；删掉它后，点击“添加”没有反应，再输入一个字才显示。
3. 实验三：点击复选框，勾选状态不变。
4. 全部恢复后，三个操作都和第 50 章一样正常。

如果保存文件后页面整体刷新、数据回到初始状态，重新操作一次即可。

最后运行检查，应没有错误：

```powershell
npm.cmd run check
```

**小练习**：把实验三中的 `task.completed = !task.completed; return task;` 改为 `return { ...task, completed: !task.completed };`（不符合条件的仍返回 `task`），看看问题是否消失，想一想为什么。练习后恢复本章代码。

## 五、常见错误

| 现象 | 原因 | 怎么改 |
| --- | --- | --- |
| 点击后页面没变化，做别的操作后才更新 | 修改了原数组或原对象，再把同一个数组交给 set 函数 | 用展开语法、`filter`、`map` 创建新数组，修改的那一项创建新对象 |
| 添加看起来正常，删掉一行无关代码后就不更新了 | 用了 `push`，之前是别的 state 碰巧带动了重新渲染 | 改为 `setTasks([...tasks, newTask])` |
| 开发时勾选无效，上线后却正常 | 更新函数中修改了原对象，StrictMode 执行两次后效果抵消 | 更新函数中只返回新对象，不修改参数 |
| 改了一个变量，另一个地方的数据也跟着变 | 两个变量指向同一个对象，修改的是同一份数据 | 需要不同的数据时，用展开语法复制出新对象 |
