# 第 137 章：为什么开发时能显示页面，正式构建却会失败？

前置：[第 136 章：按钮操作中的异步错误，如何展示给用户？](第136章-按钮操作中的异步错误，如何展示给用户.md)

## 一、本章要解决的问题

到现在为止，我们一直用开发服务器看页面。网站要给别人用，需要先**构建**（build）出正式版本：把所有代码整理成浏览器直接能用的几个文件，再把这些文件放到服务器上。

常见的情况是：开发服务器中页面一切正常，一运行构建命令就失败了，终端中只有一行看不太懂的错误。本章第一次运行正式构建，看懂它输出了什么；再故意制造一次“开发时正常、构建失败”，学会从错误中找到出错的文件和行号。

本章不修改项目代码。完成后：你知道 `npm.cmd run build` 做了哪两件事、构建结果在哪里；构建失败时，能找到出错的位置并改正。

## 二、必要原理

### 开发服务器和正式构建的区别

| | 开发服务器 `npm.cmd run dev` | 正式构建 `npm.cmd run build` |
| --- | --- | --- |
| 用途 | 写代码时随时查看 | 生成要上线的文件 |
| 类型检查 | 不做，只把代码转换成浏览器能运行的形式 | 先做，有错误就停止 |
| 结果放在哪里 | 不生成文件，改了代码页面马上更新 | 写入项目中的 `dist` 文件夹 |
| 接口地址 | 读取 `.env.development` | 读取 `.env.production`（第 73 章，开发环境和正式环境使用不同的接口地址） |

第 7 章（写错代码时，如何让检查命令提前发现问题）说过：开发服务器为了快，不做类型检查，页面能显示不代表代码没有问题。构建时不能这样，类型有错误的代码不应该上线。

### 构建命令做了两件事

打开 `package.json`，`build` 这一行是：

```json
"build": "npm run typecheck && vite build",
```

`&&` 的意思是：前一个命令成功了，才运行后一个命令。所以构建分两步：

1. `npm run typecheck`：运行 `tsc --noEmit`，检查整个项目的类型，和 `npm.cmd run check` 中的类型检查相同。
2. `vite build`：类型检查通过以后，才把代码打包写入 `dist`。

类型检查只要有一个错误，第二步就不会运行，`dist` 中的文件不会更新。

### 构建出来的文件

构建成功后，`dist` 文件夹中是这样几个文件：

| 文件 | 内容 |
| --- | --- |
| `index.html` | 网站唯一的页面，和项目根目录的 `index.html` 相似，只是引用的是下面两个文件 |
| `assets/index-一串字符.js` | 所有组件和用到的库合并成的一个 JavaScript 文件 |
| `assets/index-一串字符.css` | 所有样式合并成的一个 CSS 文件 |

文件名中的“一串字符”由文件内容算出来，内容变了，这串字符也会变。第 5 章（在页面上显示一张本地图片）提到过它的作用：避免浏览器继续使用缓存中的旧文件。

`dist` 中的文件就是要放到服务器上的全部内容。上线时不需要 `src`、`node_modules`，只需要 `dist`。

### 常见的“开发时正常”

调试时，经常临时注释掉一段代码。例如把 `AppLayout` 中的断网提示注释掉，页面照常显示；可是这段代码中用到的变量 `online` 就没有地方用了。我们的 `tsconfig.json` 中开启了 `noUnusedLocals`，声明了却没有使用的变量算作错误。开发服务器不管它，构建却会因此失败。

## 三、动手实现

### 第 1 步：运行一次正式构建

在项目根目录打开一个新的终端（开发服务器不用停止），运行：

```powershell
npm.cmd run build
```

终端中先显示类型检查的命令，接着是 Vite 打包的过程，最后几行类似下面这样：

```text
✓ 185 modules transformed.
rendering chunks...
computing gzip size...
dist/index.html                   0.45 kB │ gzip:   0.31 kB
dist/assets/index-DNCm1zZw.css   12.02 kB │ gzip:   2.90 kB
dist/assets/index-BZRdFXJ0.js   326.58 kB │ gzip: 100.60 kB

✓ built in 214ms
```

文件名中的字符、文件大小和用时可能与你的不同。每一行是一个生成的文件和它的大小；`gzip` 后面是压缩后的大小，服务器一般会压缩后再发送，用户实际下载的接近这个数字。

### 第 2 步：看看构建结果

打开项目中的 `dist` 文件夹，里面有 `index.html` 和 `assets` 文件夹，`assets` 中是一个 `.js` 文件和一个 `.css` 文件，和第 1 步输出的文件名相同。

用记事本打开 `dist/index.html`，可以看到它引用的就是这两个文件：

```html
    <script type="module" crossorigin src="/assets/index-BZRdFXJ0.js"></script>
    <link rel="stylesheet" crossorigin href="/assets/index-DNCm1zZw.css">
```

### 第 3 步：制造一次构建失败

打开 `src/components/AppLayout.tsx`，把断网提示的这一段临时注释掉：

```tsx
      {/* {!online && (
        <p role="status" className="offline-banner">
          网络已断开，需要连接服务器的功能暂时无法使用。
        </p>
      )} */}
```

保存后看浏览器，各个页面都能正常显示，开发服务器没有任何提示。再运行一次：

```powershell
npm.cmd run build
```

这次类型检查之后，出现了一行错误，后面没有 Vite 打包的内容：

```text
src/components/AppLayout.tsx(15,9): error TS6133: 'online' is declared but its value is never read.
```

这一行从左到右是：出错的文件、括号中的“第 15 行第 9 个字符”、错误编号 `TS6133`、错误说明“`online` 声明了，但它的值从来没有被读取”。打开这个文件的第 15 行，正是 `const online = useOnlineStatus();`。

再打开 `dist/assets`，文件名还是第 1 步的那两个：打包没有运行，`dist` 中仍是上一次成功构建的结果。

### 第 4 步：改正后重新构建

去掉第 3 步加的注释符号，恢复断网提示，保存。再运行一次 `npm.cmd run build`，又能看到 `✓ built in` 一行，构建成功。

## 四、运行与检查

1. 第 1 步的构建成功，最后一行是 `✓ built in`，项目中出现了 `dist` 文件夹。
2. 第 3 步注释掉断网提示后，页面照常显示；构建失败，错误中有文件名 `src/components/AppLayout.tsx`、行号和 `TS6133`，`dist` 中的文件没有变化。
3. 第 4 步恢复后，构建再次成功。

最后运行检查，应没有错误：

```powershell
npm.cmd run check
```

**小练习**：把 `src/pages/GroupPage.tsx` 中“我们每周一起完成一个 React 小练习。”的句号改成感叹号，运行 `npm.cmd run build`，对比构建前后 `.js` 文件名中的字符是否变化，`.css` 文件名是否变化，说说为什么。练习后恢复本章代码，并重新构建一次。

## 五、常见错误

| 现象 | 原因 | 怎么改 |
| --- | --- | --- |
| 开发服务器中一切正常，`npm.cmd run build` 却失败了 | 开发服务器不做类型检查，构建会先做 | 看以 `error TS` 开头的那一行，按其中的文件名和行号改正；平时每章运行 `npm.cmd run check`，能更早发现 |
| 构建失败了，却把 `dist` 中的文件当成新版本拿去上线 | 类型检查失败时打包不会运行，`dist` 中还是上一次成功构建的旧文件 | 只有最后看到 `✓ built in` 时，`dist` 才是新的结果 |
| 双击 `dist/index.html`，浏览器中一片空白，控制台提示 `Access to script at 'file:///assets/…' … has been blocked by CORS policy` | 直接打开文件时，地址以 `file:///` 开头，浏览器不允许这样加载模块脚本 | 构建结果要通过服务器打开，见下一章 |
