# 第 71 章：如何排查页面访问接口时的跨域错误？

前置：[第 70 章：【组合】如何在重新加载时保留原有内容？](第070章-如何在重新加载时保留原有内容.md)

## 一、本章要解决的问题

前端开发中最常见、也最让新手困惑的一种错误：练习服务明明在运行，在浏览器地址栏中直接打开接口地址也能看到数据，页面上却显示“无法连接练习服务”，控制台中有一条带 `CORS` 字样的红色错误。

本章用练习服务的 `?cors=off` 参数重现这个错误，弄清浏览器为什么拦下它，以及应该在哪里解决。本章不修改代码。

## 二、必要原理

### 什么是“源”

浏览器把“协议 + 主机名 + 端口”三部分合起来叫作一个**源**（origin）。三部分完全相同才是同一个源：

| 地址 | 源 |
| --- | --- |
| `http://127.0.0.1:5173/` | 开发服务器，`http` + `127.0.0.1` + `5173` |
| `http://127.0.0.1:3001/api/articles` | 练习服务，`http` + `127.0.0.1` + `3001` |
| `http://localhost:5173/` | 和第一行**不是**同一个源，主机名不同 |

文章页在 5173 端口，接口在 3001 端口，端口不同，所以页面请求接口属于**跨源**请求，通常叫“跨域”。

### 浏览器的同源策略

为了安全，浏览器默认不允许一个网页读取另一个源返回的数据。否则你打开的任何网站，都可以悄悄读取你已登录的其他网站上的数据。

但跨源请求在实际开发中很常见，所以有一套许可机制，叫 CORS（跨源资源共享）：**服务器**在响应中加上 `Access-Control-Allow-Origin` 这个响应头，写明允许哪个源读取。浏览器收到响应后检查它：

- 响应头中允许了页面所在的源：把数据交给页面。
- 没有这个响应头，或者允许的不是这个源：拦下响应，`fetch` 失败，控制台出现 CORS 错误。

练习服务的响应中写了允许 `http://127.0.0.1:5173` 和 `http://localhost:5173`，所以前几章一直能正常读取。

### 请求其实已经到达了服务器

CORS 错误最容易误会的地方是：请求**已经发出、服务器也已经正常处理并返回了 200**，只是浏览器检查许可后，不把结果交给页面。所以：

- 练习服务的终端中能看到这次请求，状态是 200。
- 页面上的 `fetch` 失败，进入 `catch`，看起来和“连不上服务器”一样。JavaScript 拿不到任何区分两者的信息，原因只能在控制台中看。

### 在哪里解决

CORS 许可只能由**服务器**给出，前端代码无法绕过。修改 `fetch` 的写法不能解决问题。实际开发中有两种做法：请后端在响应中加上许可；或者让页面和接口变成同一个源，下一章就用开发服务器的代理做到这一点。

## 三、动手实现

保持开发服务器和练习服务都在运行（准备篇二）。本章对代码的修改都是临时的，做完后恢复为第 70 章的代码。

### 第 1 步：重现跨域错误

把 `src/pages/ArticlePage.tsx` 中的请求地址临时改为：

```tsx
      const response = await fetch('http://127.0.0.1:3001/api/articles?cors=off');
```

`?cors=off` 让练习服务这一次不在响应中加许可。保存后点击“加载文章”，页面显示“无法连接练习服务，请确认它已经启动。”

### 第 2 步：在三个地方找线索

- **控制台**：有一条红色错误，大意是来自 `http://127.0.0.1:5173` 的请求被 CORS 策略拦截，因为响应中没有 `Access-Control-Allow-Origin` 头。
- **Network（网络）面板**：这次请求的 Status 显示 `CORS error`（不同版本的浏览器写法略有不同）。
- **练习服务的终端**：最后一行是 `GET /api/articles?cors=off → 200`。服务器确实收到并正常返回了。

三处线索合起来就能确定：不是服务没启动，也不是地址错了，而是缺少跨域许可。

### 第 3 步：对比直接打开接口

在浏览器新标签页的地址栏中直接打开 `http://127.0.0.1:3001/api/articles?cors=off`，能看到文章数据。直接打开不是“一个网页读取另一个源”，所以不受同源策略限制。这就是“地址栏能打开，页面却读不到”的原因。

最后把请求地址恢复为 `'http://127.0.0.1:3001/api/articles'`。

## 四、运行与检查

1. 加上 `?cors=off` 后，页面提示无法连接，控制台有 CORS 错误，练习服务终端显示 200。
2. 直接在地址栏打开同一个接口地址，可以看到数据。
3. 用 `http://localhost:5173/` 打开文章页（不加 `?cors=off`），文章能正常加载，因为练习服务也允许了这个源。
4. 恢复代码后，用 `http://127.0.0.1:5173/` 打开页面，加载正常。

最后运行检查，应没有错误：

```powershell
npm.cmd run check
```

**小练习**：在第 1 步的状态下，把 `catch` 中的提示临时改成“请求失败，请查看控制台中的错误信息。”，想一想为什么前端无法给出比这更准确的提示。练习后恢复本章代码。

## 五、常见错误

| 现象 | 原因 | 怎么改 |
| --- | --- | --- |
| 控制台出现 CORS 错误，就去修改 `fetch` 的写法 | 误以为是前端代码的问题 | 许可只能由服务器给出；开发时用下一章的代理 |
| 看到“无法连接”，就一直检查练习服务有没有启动 | CORS 错误在 JavaScript 中和连接失败看起来一样 | 先看控制台和练习服务终端：终端显示 200 就是跨域问题 |
| 用 `127.0.0.1` 能读取，换成别的地址打开页面就报 CORS 错误 | 服务器只允许了特定的源，新地址的端口或主机名不在其中 | 用开发服务器打印的地址打开页面，或者请后端加上这个源 |
| 网上查到要装浏览器插件或关闭浏览器安全设置 | 这样只在自己的电脑上“好了”，用户那里仍然会出错 | 不要这样做，在服务器或代理上解决 |
| 学完本章后，页面一直报错、一直显示空数据或加载很慢 | 步骤中临时加在请求地址上的 `?mode=`、`?fail=`、`?delay=`、`?cors=` 等参数忘了删 | 运行 `git diff` 查看本章改动，删掉地址中的临时参数 |
