# 附录 D：浏览器开发者工具使用说明

本教程的“运行与检查”经常要用到浏览器的开发者工具。本附录集中说明它的打开方式、各面板的用途和常用操作，并给出中英文界面的名称对照。各节注明了正文中第一次用到它的章节，读到那一章时可以回来查阅。

本附录以 Chrome 为例，Windows 自带的 Edge 用的是同样的内核，界面和操作基本相同。

## 一、开发者工具是什么

开发者工具是浏览器自带的一组检查工具，用来查看“浏览器实际拿到了什么、做了什么”：

- 页面上实际有哪些标签、每个标签用了哪些样式；
- 代码运行时出了什么错；
- 页面向服务器发了哪些请求，服务器返回了什么。

编辑器中看到的是你写的代码，开发者工具中看到的是代码运行后的结果。两者对照，才能找到问题出在哪里。在开发者工具中做的任何修改都是临时的，刷新页面就恢复，不会改动你的项目文件。

## 二、打开、关闭和调整位置

| 操作 | 方法 |
| --- | --- |
| 打开或关闭 | 按 F12；或按 Ctrl+Shift+I |
| 打开并直接选中某个元素 | 在页面上右键单击这个元素，选择“检查” |
| 调整位置 | 点击开发者工具右上角的 ⋮（Edge 中是 …），在“停靠侧”中选择停靠在右侧、底部，或单独成为一个窗口 |
| 调整大小 | 拖动开发者工具与页面之间的分隔线 |

本教程的检查步骤一般建议停靠在**底部**或**右侧**，一边看页面一边看面板。

开发者工具的界面语言跟随浏览器的语言，也可以单独设置：点击右上角的齿轮图标（设置），在“偏好设置”的“外观”中找到“语言”，选择后按提示重新加载开发者工具。

## 三、中英文名称对照

本教程写作“英文名（中文名）”，例如“Network（网络）”。下表是常用名称的对照。Edge 中个别名称的译法略有不同，可以按位置和图标对照。

| 英文界面 | 中文界面 | 位置和用途 |
| --- | --- | --- |
| Elements | 元素 | 面板：页面上实际的标签结构 |
| Styles | 样式 | 元素面板右侧：选中元素用到的 CSS |
| Computed | 计算样式 | 元素面板右侧：选中元素最终生效的样式值 |
| Console | 控制台 | 面板：错误、警告和 `console.log` 输出 |
| Sources | 来源 | 面板：查看源代码、设置断点 |
| Network | 网络 | 面板：页面发出的所有请求 |
| Application | 应用 | 面板：浏览器为网站保存的数据 |
| Headers | 标头 | 网络面板中点开请求后的标签：请求地址、方法、状态码 |
| Payload | 载荷 | 同上：请求发送的内容 |
| Preview | 预览 | 同上：整理过格式的返回内容 |
| Response | 响应 | 同上：返回内容的原始文字 |
| Preserve log | 保留日志 | 网络面板上方的复选框：刷新页面时不清空记录 |
| Disable cache | 停用缓存 | 网络面板上方的复选框：不使用浏览器缓存 |
| No throttling | 已停用节流模式 | 网络面板上方的下拉框：模拟慢速网络 |
| Fetch/XHR | Fetch/XHR | 网络面板的筛选按钮：只显示代码发出的请求 |
| Toggle device toolbar | 切换设备工具栏 | 左上角的手机图标：手机模式 |
| Components | Components | React 开发者工具扩展添加的面板（只有英文） |

## 四、元素（Elements）面板

**正文第一次用到**：第 1 章；查看样式从第 4 章开始。

元素面板显示的是页面**此刻**真实的标签结构。React 生成的内容都在 `<div id="root">` 里面，展开它就能看到组件最终变成了哪些标签。

常用操作：

- **选中页面上的元素**：点击面板左上角的箭头图标（或按 Ctrl+Shift+C），再到页面上点击某个元素，面板中会自动定位到对应的标签。
- **查看样式**：选中一个标签后，右侧的“样式”中列出它用到的所有 CSS 规则。被划掉的规则表示被别的规则覆盖了，没有生效。第 15 章用它查看 CSS Modules 生成的类名。
- **查看属性**：标签上的 `class`、`aria-invalid`、`inputmode` 等属性直接显示在标签中。第 43、44 章用它确认属性是否加上了。
- **临时修改**：双击标签中的文字或属性值可以临时修改，用来试验效果。刷新页面后恢复。

## 五、控制台（Console）面板

**正文第一次用到**：第 6 章。

控制台显示代码运行时的信息：

- **红色**：错误。页面空白时，第一件事就是看这里有没有红色错误（第 6 章）。
- **黄色**：警告。不一定影响运行，但通常提示了写法上的问题，例如列表缺少 `key`（第 17 章）。
- **普通文字**：代码中 `console.log(...)` 输出的内容。正文中多次临时加入 `console.log` 来观察代码的执行顺序，例如第 25、75 章。

常用操作：

- 错误信息末尾的 `App.tsx:28` 这样的链接可以点击，开发者工具会打开对应的源代码并定位到这一行。
- 左上角的 🚫 图标（清除控制台）可以清空已有的输出，方便只看接下来的新信息。
- 输出太多时，可以用上方的级别下拉框只看错误，或在筛选框中输入文字只看包含这段文字的信息。

## 六、网络（Network）面板

**正文第一次用到**：第 63 章。

网络面板记录页面发出的每一个请求。**要先打开网络面板，再操作页面**，打开之前发出的请求不会被记录；看不到请求时，刷新页面即可。

请求列表中常看的几列：

| 列 | 含义 |
| --- | --- |
| 名称（Name） | 请求地址的最后一段，例如 `articles`、`search?q=type` |
| 状态（Status） | 状态码：200、201、204 表示成功；404、422、500 表示失败；`(canceled)` 表示请求被取消（第 79 章） |
| 类型（Type） | 代码发出的请求显示为 `fetch` |
| 时间（Time） | 从发出到收到结果用了多久 |

常用操作：

- **只看接口请求**：点击上方的“Fetch/XHR”筛选按钮，页面加载的脚本、样式、图片等请求就不显示了。
- **查看一次请求的详情**：点击请求名称，右侧出现几个标签：“标头”中有完整地址、请求方式（GET、POST 等）和状态码；“载荷”中是发送的内容（第 86 章）；“预览”和“响应”中是服务器返回的内容。
- **保留日志**：勾选后，刷新页面时不会清空之前的记录，方便对比刷新前后的请求。
- **清空记录**：点击 🚫 图标，只看接下来的新请求。
- **模拟慢速网络**：在“已停用节流模式”下拉框中选择“低速 4G”或“3G”。本教程一般用练习服务的 `?delay=` 参数制造延迟（准备篇二），效果更稳定。

## 七、来源（Sources）面板

**正文中的用法**：第 7 章的 `debugger;`；断点调试的完整步骤见附录 E。

来源面板可以查看浏览器加载的源代码，并在某一行设置**断点**：代码运行到这一行时暂停，可以逐行执行，查看每个变量此刻的值。

- 按 Ctrl+P，输入文件名（例如 `App.tsx`），可以打开对应的文件。
- 点击行号设置断点，再次点击取消。
- 代码中写了 `debugger;` 时，只要开发者工具开着，运行到这一行也会暂停。页面变成灰色，顶部显示“已在调试程序中暂停”。按 F8 或点击 ▶ 继续运行。

## 八、应用（Application）面板

应用面板显示浏览器为当前网站保存的数据，例如本地存储（Local Storage）和 Cookie。第 123 章把设置保存到本地存储时，可以在这里查看和删除保存的内容。

## 九、手机模式（切换设备工具栏）

**正文第一次用到**：第 13 章。

点击开发者工具左上角的手机图标（切换设备工具栏），页面会按手机的屏幕宽度显示，用来检查窄屏下的布局。在开发者工具中按 Ctrl+Shift+M 也能切换（注意要先点一下开发者工具，让它处于选中状态；否则这个快捷键会被别的程序使用，例如在 VS Code 中它是打开“问题”面板）。

- 上方可以选择设备型号，或直接输入宽度，例如 375。
- 手机模式只模拟屏幕尺寸和触摸，**不会弹出手机的虚拟键盘**。`inputMode` 的效果要在真正的手机上才能看到。
- 检查完后再点一次手机图标，回到普通模式。

## 十、React 开发者工具

**正文第一次用到**：第 33 章，安装步骤也在那一章。

React 开发者工具是浏览器扩展，安装后开发者工具中会多出两个面板：

- **Components**：按组件的层级显示页面，选中一个组件，右侧显示它当前的 props 和 state，还可以临时修改它们，观察页面的变化。
- **Profiler**：记录每次渲染花了多少时间，用来分析页面为什么变慢。

这两个面板只有英文名称。商店无法访问时，可以先跳过第 33 章，后续章节不依赖这个扩展：需要观察 state 变化的地方，都可以用页面上的显示或临时加入的 `console.log` 代替。
