# 第 73 章：如何让开发环境和正式环境使用不同的接口地址？

前置：[第 72 章：如何通过开发服务器代理连接接口？](第072章-如何通过开发服务器代理连接接口.md)

## 一、本章要解决的问题

上一章的代理只在开发服务器中存在。以后网站上线时（第 137 章），要先把代码打包成普通的网页文件，交给别的服务器托管，那里没有这个代理，请求 `/api/articles` 会落空。正式环境中，页面要直接请求接口服务器的完整地址。

同一份代码，开发时要用 `/api`，上线后要用接口服务器的完整地址（本教程的练习环境中是 `http://127.0.0.1:3001/api`）。如果每次上线前手动改代码，迟早会忘。

本章把接口地址的开头写进两个**环境变量文件**，开发时和打包时 Vite 会自动选用对应的那一个；再写一个 `apiUrl` 函数，页面中只写接口的路径部分。以后所有请求都通过它生成地址。打包上线留到第 137 章，本章在开发服务器中确认这套配置能正确切换。

## 二、必要原理

### 什么是环境变量

**环境**指代码运行的场合：在你的电脑上开发时，是“开发环境”；打包上线、给用户使用时，是“正式环境”（也叫生产环境，英文 production）。

**环境变量**是“随环境不同而取不同值”的设置。代码中只写变量名，具体的值由当前环境决定。接口地址正是这样的设置：代码中写同一个名字，开发时取 `/api`，正式环境取完整地址。

### Vite 的环境变量文件

在项目根目录（和 `package.json` 同一层）可以放这样的文件：

| 文件 | 什么时候使用 |
| --- | --- |
| `.env.development` | 运行 `npm.cmd run dev` 启动开发服务器时 |
| `.env.production` | 打包上线时（第 137 章） |

文件中每行写一个变量，`名称=值`，值不加引号：

```text
VITE_API_BASE_URL=/api
```

文件名以点开头，没有 `.txt` 这样的扩展名。在 VS Code 中新建文件并直接输入完整的文件名即可。不要用 Windows 的记事本另存，它可能悄悄在后面加上 `.txt`。

### 在代码中读取：import.meta.env

在代码中写 `import.meta.env.VITE_API_BASE_URL` 读取这个值。`import.meta` 是当前文件的一些附加信息，Vite 把环境变量放在它的 `env` 属性中。它不需要导入，直接写就可以。

只有名称以 `VITE_` 开头的变量会被放进页面代码，这是为了防止把电脑上其他的环境变量误放进网页。

Vite 在启动开发服务器（或打包）时，把代码中的 `import.meta.env.VITE_API_BASE_URL` 直接替换成文件中的值。所以：

- 修改 `.env` 文件后，要**重启开发服务器**，新值才会生效。
- 这些值最终会出现在用户浏览器下载的代码中，任何人都能看到。**不要把密码、密钥写进这里。**

### 用一个函数集中生成接口地址

新建 `src/lib/api.ts`：

```ts
const baseUrl = import.meta.env.VITE_API_BASE_URL;

export function apiUrl(path: string) {
  return baseUrl + path;
}
```

页面中写 `apiUrl('/articles')`：开发时得到 `/api/articles`，经过代理转发；上线后得到 `http://127.0.0.1:3001/api/articles`，直接请求接口服务器。

以后所有请求都写成 `fetch(apiUrl('/路径'))`。接口地址的规则只写在这一个文件中，需要调整时只改一处。`src/lib` 文件夹用来放这类不属于任何页面的工具函数。

### 正式环境中仍然需要跨域许可

上线后页面直接请求接口服务器，又变成了跨域请求，需要接口服务器允许正式网站的地址（第 71 章）。练习服务已经提前允许了第 137 章将要使用的预览地址，到时候可以直接验证。

## 三、动手实现

### 第 1 步：新建两个环境变量文件

在项目根目录新建 `.env.development`：

```text
VITE_API_BASE_URL=/api
```

再新建 `.env.production`：

```text
VITE_API_BASE_URL=http://127.0.0.1:3001/api
```

### 第 2 步：新建生成地址的函数

新建文件夹 `src/lib`，在其中新建 `api.ts`：

```ts
const baseUrl = import.meta.env.VITE_API_BASE_URL;

export function apiUrl(path: string) {
  return baseUrl + path;
}
```

### 第 3 步：文章页改用 apiUrl

在 `src/pages/ArticlePage.tsx` 中，在 `ArticleList` 的导入下面加入：

```tsx
import { apiUrl } from '../lib/api';
```

把请求的一行改为：

```tsx
      const response = await fetch(apiUrl('/articles'));
```

保存后，在运行开发服务器的终端按 Ctrl+C，再运行 `npm.cmd run dev`，让新的环境变量生效。

### 第 4 步：确认地址确实来自环境变量（临时）

`.env.production` 要到第 137 章打包时才会用到。现在可以临时修改开发环境的文件，确认“改文件就能切换地址”这件事确实成立。

1. 把 `.env.development` 中的值临时改为正式环境的地址：

   ```text
   VITE_API_BASE_URL=http://127.0.0.1:3001/api
   ```

2. 重启开发服务器，点击“加载文章”，文章正常显示。打开 Network（网络）面板，点开 `articles` 请求，“标头”中的请求网址变成了 `http://127.0.0.1:3001/api/articles`：页面绕过代理，直接请求了练习服务。练习服务允许来自 5173 端口的跨域请求，所以能正常读取。
3. 把 `.env.development` 改回 `VITE_API_BASE_URL=/api`，再重启一次开发服务器。

整个过程中，`ArticlePage.tsx` 一行都没有改，地址完全由环境变量文件决定。上线时，Vite 读取的是 `.env.production`，道理相同。

## 四、运行与检查

保持开发服务器和练习服务都在运行（准备篇二）。

1. 点击“加载文章”，文章正常显示。Network 中 `articles` 请求的网址是 `http://127.0.0.1:5173/api/articles`，仍然经过代理。
2. 第三节第 4 步中，临时修改 `.env.development` 并重启后，请求网址变成了 `http://127.0.0.1:3001/api/articles`；改回并重启后，又变回 5173。
3. 项目根目录中有 `.env.development` 和 `.env.production` 两个文件，文件名后面没有 `.txt`。在 VS Code 左侧的文件列表中看到的名字，应该和第三节第 1 步完全一致。
4. `ArticlePage.tsx` 中不再出现 `http://127.0.0.1:3001`，接口地址只写在两个环境变量文件中。

最后运行检查，应没有错误：

```powershell
npm.cmd run check
```

**小练习**：在 `src/lib/api.ts` 中临时加一行 `console.log('接口地址开头：', baseUrl);`，刷新页面，在控制台中看看打印出的值。再把 `.env.development` 中的变量名临时改成 `API_BASE_URL`（去掉 `VITE_`），重启开发服务器，看看打印出什么、文章还能不能加载。练习后恢复本章代码，并重启开发服务器。

## 五、常见错误

| 现象 | 原因 | 怎么改 |
| --- | --- | --- |
| Network 中的地址变成了 `/undefined/articles` 一类 | 变量名没有以 `VITE_` 开头，或代码中的名称和文件中的不一致，读到的是 `undefined` | 名称以 `VITE_` 开头，两处完全一致 |
| 修改了 `.env` 文件，页面中的地址没有变 | 环境变量在启动开发服务器时就已经替换进代码了 | 重启开发服务器 |
| `.env.development` 没有生效 | 文件放进了 `src` 文件夹，或文件名写成了 `env.development`（少了开头的点） | 放在项目根目录，文件名以点开头 |
| `.env.development` 没有生效，文件看起来也没问题 | 文件实际叫 `.env.development.txt`。用记事本保存时自动加上了扩展名，而 Windows 默认隐藏扩展名 | 在 VS Code 的文件列表中查看完整文件名，重命名为 `.env.development` |
| 地址中出现两个斜线或少了斜线，例如 `/apiarticles` | 调用时路径没有以 `/` 开头，或环境变量末尾多写了 `/` | 环境变量末尾不加 `/`，路径以 `/` 开头 |

## 六、本章完整代码

### `.env.development`

```text
VITE_API_BASE_URL=/api
```

### `.env.production`

```text
VITE_API_BASE_URL=http://127.0.0.1:3001/api
```

### `src/lib/api.ts`

内容同第三节第 2 步。

### `src/pages/ArticlePage.tsx`

```tsx
import { useState } from 'react';
import ArticleList from '../components/ArticleList';
import { apiUrl } from '../lib/api';
import { isArticle } from '../types/article';
import type { Article } from '../types/article';

type LoadState =
  | { status: 'idle' }
  | { status: 'loading'; articles: Article[] }
  | { status: 'success'; articles: Article[] }
  | { status: 'error'; message: string; articles: Article[] };

export default function ArticlePage() {
  const [loadState, setLoadState] = useState<LoadState>({ status: 'idle' });
  const articles = loadState.status === 'idle' ? [] : loadState.articles;
  const hasLoaded = loadState.status === 'success' || articles.length > 0;

  async function handleLoad() {
    setLoadState({ status: 'loading', articles });
    try {
      const response = await fetch(apiUrl('/articles'));
      if (!response.ok) {
        setLoadState({
          status: 'error',
          message: '文章读取失败：服务器返回了状态 ' + response.status + '。',
          articles,
        });
        return;
      }
      const data: unknown = await response.json();
      if (!Array.isArray(data) || !data.every(isArticle)) {
        setLoadState({ status: 'error', message: '文章数据格式不正确，暂时无法显示。', articles });
        return;
      }
      setLoadState({ status: 'success', articles: data });
    } catch {
      setLoadState({ status: 'error', message: '无法连接练习服务，请确认它已经启动。', articles });
    }
  }

  return (
    <main className="page">
      <h1>文章列表</h1>
      <button type="button" onClick={handleLoad} disabled={loadState.status === 'loading'}>
        {hasLoaded ? '重新加载' : '加载文章'}
      </button>
      {loadState.status === 'loading' && (
        <p role="status">{articles.length === 0 ? '正在加载文章……' : '正在更新……'}</p>
      )}
      {loadState.status === 'error' && (
        <div>
          <p role="alert">{loadState.message}</p>
          <button type="button" onClick={handleLoad}>
            重试
          </button>
        </div>
      )}
      {loadState.status === 'success' && articles.length === 0 && <p>暂时还没有文章。</p>}
      {articles.length > 0 && <ArticleList articles={articles} />}
    </main>
  );
}
```

## 七、本章改动小结

新增 `.env.development`、`.env.production`、`src/lib/api.ts`；修改 `src/pages/ArticlePage.tsx`：请求地址改由 `apiUrl` 生成。
