# 第 73A 章：如何把读取文章的代码提取成组件外面的函数？

前置：[第 73 章：如何让开发环境和正式环境使用不同的接口地址？](第073章-如何让开发环境和正式环境使用不同的接口地址.md)

## 一、本章要解决的问题

文章页的 `handleLoad` 现在有二十多行：设置加载状态、发送请求、检查状态码、检查数据格式、处理连接失败，每一种失败都要写一遍 `setLoadState`。请求的细节和页面的状态混在一起，读起来很费劲。

下一部分还要让文章页“一打开就自动读取”，到时候又要用到同样的请求代码。如果再复制一份，以后改一处就得记得改两处。

本章把“请求文章并检查结果”这部分提取成组件外面的一个函数 `fetchArticles`，`handleLoad` 只负责更新页面状态。完成后，页面的外观和所有操作都与第 73 章相同。

## 二、必要原理

### 两件事分开：拿数据，和更新页面

`handleLoad` 其实在做两件事：

1. **拿数据**：发请求、检查状态码、检查格式，最后得到文章数组，或者知道失败的原因。这件事和 React 无关，不需要任何 state。
2. **更新页面**：开始时设为加载中，成功时显示文章，失败时显示原因。这件事只能在组件里做。

第一件事提取成组件外面的函数 `fetchArticles`。它不使用 state 和 props，可以写在组件外面，任何地方都能调用。

### 用 throw 把失败的原因交给调用者

`fetchArticles` 不能自己调用 `setLoadState`，因为它在组件外面。失败时，它用第 62A 章学过的 `throw` 抛出一个错误，把提示文字放在错误中：

```ts
throw new Error('文章读取失败：服务器返回了状态 ' + response.status + '。');
```

调用它的 `handleLoad` 用 `try...catch` 接住，再把提示文字显示到页面上。成功时，`fetchArticles` 用 `return data` 把文章数组交出去。

### async 函数的返回类型：Promise<Article[]>

`async` 函数不会立刻得到结果，调用它得到的是一个 Promise（第 62 章），`await` 之后才是真正的结果。所以返回类型写成 `Promise<Article[]>`，意思是“将来会得到一个文章数组”。调用时写 `const data = await fetchArticles();`，`data` 就是 `Article[]`。

### let response 写在 try 的外面

```ts
let response: Response;
try {
  response = await fetch(apiUrl('/articles'));
} catch {
  throw new Error('无法连接练习服务，请确认它已经启动。');
}
```

连不上服务器时，`fetch` 抛出的错误只有一句英文，所以单独用一个 `try` 包住 `fetch`，在 `catch` 中换成中文提示再抛出。

`response` 要在 `try` 后面继续使用，所以先在外面用 `let` 声明，只写类型、不给值；在 `try` 中再赋值。如果写成 `try { const response = … }`，`response` 只在这对花括号里有效，后面就用不到了。`Response` 是浏览器提供的类型，表示一次请求的响应，不需要导入。

### 从错误对象中取出提示文字

`catch (error)` 括号中的 `error` 就是被抛出的东西。JavaScript 允许 `throw` 任何值，所以它的类型是 `unknown`，不能直接读取 `error.message`。

`error instanceof Error` 判断它是不是用 `new Error(…)` 创建的错误对象。是，就可以读取 `error.message`，也就是创建时写的那段文字。把这个判断写成一个小函数 `getErrorMessage`：

```ts
function getErrorMessage(error: unknown) {
  return error instanceof Error ? error.message : '文章读取失败。';
}
```

`条件 ? 值1 : 值2` 在第 19 章用过：条件成立时得到值 1，否则得到值 2。

## 三、动手实现

本章只修改 `src/pages/ArticlePage.tsx`。

### 第 1 步：在组件外面加入两个函数

在 `LoadState` 类型的后面、`export default function ArticlePage()` 的前面加入：

```tsx
async function fetchArticles(): Promise<Article[]> {
  let response: Response;
  try {
    response = await fetch(apiUrl('/articles'));
  } catch {
    throw new Error('无法连接练习服务，请确认它已经启动。');
  }
  if (!response.ok) {
    throw new Error('文章读取失败：服务器返回了状态 ' + response.status + '。');
  }
  const data: unknown = await response.json();
  if (!Array.isArray(data) || !data.every(isArticle)) {
    throw new Error('文章数据格式不正确，暂时无法显示。');
  }
  return data;
}

function getErrorMessage(error: unknown) {
  return error instanceof Error ? error.message : '文章读取失败。';
}
```

把它和原来的 `handleLoad` 对照：三种失败的提示文字和原来完全一样，只是从 `setLoadState({ … message: … })` 变成了 `throw new Error(…)`。

### 第 2 步：让 handleLoad 调用 fetchArticles

把整个 `handleLoad` 函数替换为：

```tsx
  async function handleLoad() {
    setLoadState({ status: 'loading', articles });
    try {
      const data = await fetchArticles();
      setLoadState({ status: 'success', articles: data });
    } catch (error) {
      setLoadState({ status: 'error', message: getErrorMessage(error), articles });
    }
  }

```

`handleLoad` 从二十多行变成了 8 行：开始时设为加载中，`try` 中等待 `fetchArticles` 的结果，成功就显示文章，失败就显示错误中的提示文字。

## 四、运行与检查

保持开发服务器和练习服务都在运行（准备篇二）。本章只是整理代码，下面每一项都应该和第 73 章完全相同。

1. 点击“加载文章”，显示 4 篇文章，按钮变为“重新加载”。
2. 把 `fetchArticles` 中的地址临时改为 `apiUrl('/articles?fail=500')`，点击按钮，显示“文章读取失败：服务器返回了状态 500。”和“重试”。
3. 地址临时改为 `apiUrl('/articles?mode=bad')`，显示“文章数据格式不正确，暂时无法显示。”。检查后删掉临时参数。
4. 停止练习服务，点击按钮，显示“文章读取失败：服务器返回了状态 500。”（请求经过开发服务器的代理，第 72 章）。重新启动练习服务后，点击“重试”，文章出现。

最后运行检查，应没有错误：

```powershell
npm.cmd run check
```

**小练习**：把 `getErrorMessage` 改成直接返回 `error.message`（去掉 `instanceof` 的判断），运行 `npm.cmd run check`，读一读提示，再想想为什么需要先判断。练习后恢复本章代码。

## 五、常见错误

| 现象 | 原因 | 怎么改 |
| --- | --- | --- |
| 编辑器提示在 `fetchArticles` 中找不到 `setLoadState` | 还保留着原来的 `setLoadState` 写法，组件外面用不到组件里的 state | 失败时改为 `throw new Error(…)`，成功时 `return data` |
| 编辑器提示 `response` 在赋值前被使用 | 写成了 `const response` 并放在 `try` 里面，或者 `catch` 中没有 `throw`，`response` 可能没有值 | 按第 1 步，`let response` 写在外面，`catch` 中一定要 `throw` |
| 编辑器提示 `error.message` 不存在 | `error` 是 `unknown`，没有先确认它是错误对象 | 用 `getErrorMessage(error)` 取出提示文字 |
| 失败时页面一直显示“正在加载文章……” | `handleLoad` 中漏写了 `catch`，或调用时漏写了 `await` | 写成 `const data = await fetchArticles();`，并保留 `catch` |
| 学完本章后，页面一直报错或显示格式不正确 | 第四节临时加的 `?fail=` 或 `?mode=` 忘了删 | 运行 `git diff` 查看，删掉地址中的临时参数 |

## 六、本章完整代码

### `src/pages/ArticlePage.tsx`

```tsx
import { useState } from 'react';
import ArticleList from '../components/ArticleList';
import { apiUrl } from '../lib/api';
import { isArticle } from '../types/article';
import type { Article } from '../types/article';

type LoadState =
  | { status: 'idle' }
  | { status: 'loading'; articles: Article[] }
  | { status: 'success'; articles: Article[] }
  | { status: 'error'; message: string; articles: Article[] };

async function fetchArticles(): Promise<Article[]> {
  let response: Response;
  try {
    response = await fetch(apiUrl('/articles'));
  } catch {
    throw new Error('无法连接练习服务，请确认它已经启动。');
  }
  if (!response.ok) {
    throw new Error('文章读取失败：服务器返回了状态 ' + response.status + '。');
  }
  const data: unknown = await response.json();
  if (!Array.isArray(data) || !data.every(isArticle)) {
    throw new Error('文章数据格式不正确，暂时无法显示。');
  }
  return data;
}

function getErrorMessage(error: unknown) {
  return error instanceof Error ? error.message : '文章读取失败。';
}

export default function ArticlePage() {
  const [loadState, setLoadState] = useState<LoadState>({ status: 'idle' });
  const articles = loadState.status === 'idle' ? [] : loadState.articles;
  const hasLoaded = loadState.status === 'success' || articles.length > 0;

  async function handleLoad() {
    setLoadState({ status: 'loading', articles });
    try {
      const data = await fetchArticles();
      setLoadState({ status: 'success', articles: data });
    } catch (error) {
      setLoadState({ status: 'error', message: getErrorMessage(error), articles });
    }
  }

  return (
    <main className="page">
      <h1>文章列表</h1>
      <button type="button" onClick={handleLoad} disabled={loadState.status === 'loading'}>
        {hasLoaded ? '重新加载' : '加载文章'}
      </button>
      {loadState.status === 'loading' && (
        <p role="status">{articles.length === 0 ? '正在加载文章……' : '正在更新……'}</p>
      )}
      {loadState.status === 'error' && (
        <div>
          <p role="alert">{loadState.message}</p>
          <button type="button" onClick={handleLoad}>
            重试
          </button>
        </div>
      )}
      {loadState.status === 'success' && articles.length === 0 && <p>暂时还没有文章。</p>}
      {articles.length > 0 && <ArticleList articles={articles} />}
    </main>
  );
}
```

## 七、本章改动小结

修改 `src/pages/ArticlePage.tsx`：新增组件外面的 `fetchArticles` 和 `getErrorMessage`，`handleLoad` 改为调用 `fetchArticles`。页面外观和操作不变。
