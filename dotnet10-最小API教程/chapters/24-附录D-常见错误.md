# 附录 D　常见错误与排查

新手最容易踩的坑集中在这里，遇到问题先来这里对照。

## D.1 启动与配置类

**问题：在 `builder.Build()` 之后调用 `builder.Services.Add...`，报错。**
服务注册必须在 `Build()` **之前**。中间件与端点（`Use/Map`）必须在 `Build()` **之后**（第 2 章）。

**问题：`app.Run()` 后面的代码不执行。**
`app.Run()` 会阻塞直到程序关闭，它之后的语句在服务器运行期间不会执行。把逻辑放到它之前。

**问题：改了配置不生效。**
注意配置优先级——环境变量/命令行会**覆盖** appsettings.json（第 14 章）。检查是否被更高优先级来源覆盖。

## D.2 路由与绑定类

**问题：访问接口返回 404。**
- 方法或路径不匹配（GET 写成了 POST？路径拼错？）。
- 路由约束不满足，如 `{id:int}` 传了非数字。
- 分组前缀 + 子路径拼接后与你想的不一致。

**问题：`InvalidOperationException`——无法从请求体绑定 / 请求体读取多次。**
一个端点**只能有一个**请求体参数（复杂对象）。多个复杂参数会冲突，用 `[FromQuery]`/`[FromHeader]` 明确来源，或合并成一个对象。

**问题：GET 请求带了复杂对象参数却拿不到值。**
GET 通常没有请求体。复杂数据要么改用 POST，要么用 `[AsParameters]` 从查询串聚合。

**问题：参数总是 null / 默认值。**
名字对不上（路由参数名与函数参数名要一致），或该来源里根本没传值。加 `?` 设为可选并处理 null。

## D.3 依赖注入类

**问题：`Unable to resolve service for type 'X'`。**
忘了注册。补上 `builder.Services.AddScoped<X>()`（或对应生命周期）。

**问题：`Cannot consume scoped service from singleton`。**
在 Singleton 里注入了 Scoped 服务（第 7 章误区）。把消费方改成 Scoped，或改依赖设计。

**问题：`DbContext` 相关的并发/释放异常。**
`DbContext` 要注册为 **Scoped**，不要在单例里长期持有，也不要在多个线程间共享同一个实例。

## D.4 校验与返回类

**问题：`[Required]` 等特性不起作用。**
.NET 10 需要先 `builder.Services.AddValidation()` 开启内置校验（第 8 章）。

**问题：返回的 JSON 字段名大小写和预期不同。**
默认采用 camelCase（`myField`）。如需自定义，配置 `JsonOptions` 的命名策略。

**问题：想返回 404 却返回了 200 + null。**
直接返回可能为 null 的对象会被序列化成 `null`（200）。应显式 `return TypedResults.NotFound()`（第 6 章）。

## D.5 跨域（CORS）类

**问题：前端报 CORS 错误，请求被浏览器拦截。**
后端要 `AddCors` + `UseCors`（第 15 章）。检查 `WithOrigins` 是否包含前端的**确切**地址（协议+域名+端口都要一致）。

**问题：加了 `AllowCredentials()` 后 CORS 反而失败。**
`AllowCredentials()` 不能与 `AllowAnyOrigin()` 共用，必须用 `WithOrigins` 明确列出来源。

**问题：`UseCors` 位置不对导致不生效。**
`UseCors` 要在**认证/授权之前**、且在会用到它的端点之前调用。

## D.6 EF Core 类

**问题：`no such table` / 表不存在。**
没执行迁移。运行 `dotnet ef migrations add Init` 和 `dotnet ef database update`（第 9 章）。

**问题：查询很慢 / 数据量大时内存飙升。**
可能先 `ToList()` 再在内存里过滤，或存在 N+1 查询。把过滤/排序/分页放在 `IQueryable` 上，关联数据用 `Include` 或投影一次取够（第 9/19 章）。

**问题：改了对象但数据库没变。**
忘了 `await db.SaveChangesAsync()`。

## D.7 排查通用建议

1. **先看日志和异常消息**：.NET 的异常信息通常很直白，往往直接点明原因。
2. **开发环境看详细错误页**：不要在开发环境启用 `UseExceptionHandler` 隐藏细节。
3. **用 Swagger UI / Scalar / `.http` 隔离前后端**：先确认后端接口本身正确，再排查前端。
4. **最小复现**：把问题缩小到最少代码，往往一下就看清了。
5. **查官方文档**：最小 API 每个版本都在变，认准 .NET 10 对应的文档。

> **【结语】** 报错不可怕，它是最好的老师。养成"读错误消息 → 定位到章节 → 对照修正"的习惯，你会越来越快。祝你排错顺利、编码愉快！
