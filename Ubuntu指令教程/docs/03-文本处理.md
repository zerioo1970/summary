## 014 ★★★&nbsp;&nbsp;echo：输出一行文本

> 级别：★★★ 初级 · 来源：bash 内建命令

### 1. 作用

`echo` 把后面的文字原样输出到屏幕。它最常见的三种用途：

- 查看变量的值，比如 `echo $PATH`；
- 在脚本里打印提示信息；
- 配合 `>`、`>>` 把一行内容写进文件。

### 2. 基本格式

```bash
echo [参数] [文本...]
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-n` | 输出后不换行 |
| `-e` | 解释转义字符：`\n` 换行，`\t` 制表符 |
| `-E` | 不解释转义字符（默认行为） |

### 4. 常用示例

#### 4.1 输出文本和变量

```
$ echo hello
hello

$ echo $SHELL $USER
/bin/bash tom
```

#### 4.2 双引号和单引号的区别

```
$ echo "价格：$HOME"
价格：/home/tom

$ echo '价格：$HOME'
价格：$HOME
```

双引号里的 `$变量` 会被替换成值；单引号里的内容完全原样输出。要输出 `$` 本身，用单引号。

#### 4.3 `-e`：换行和制表符

```
$ echo -e "第一行\n第二行\t制表"
第一行
第二行	制表

$ echo "第一行\n第二行"
第一行\n第二行
```

不加 `-e`，`\n` 会原样输出。

#### 4.4 `-n`：不换行

```
$ echo -n "no newline"; echo "|"
no newline|
```

#### 4.5 写入文件

```
$ echo "log line" > out.txt; cat out.txt
log line

$ echo "line2" >> out.txt; cat out.txt
log line
line2
```

`>` 覆盖，`>>` 追加。往配置文件末尾加一行时，一定要用 `>>`。

#### 4.6 `echo $?`：看上一条命令是否成功

```
$ ls nothere; echo $?
ls: cannot access 'nothere': No such file or directory
2
```

`$?` 是上一条命令的退出码：0 表示成功，非 0 表示失败。写脚本判断某一步是否成功，就靠它。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 想往配置文件追加一行，结果整个文件只剩这一行 | 把 `>>` 写成了 `>` | 追加用 `>>`；改重要文件前先备份 |
| `echo *.txt` 输出的是一串文件名，不是 `*.txt` | `*` 被 Shell 展开成匹配的文件名 | 要原样输出就加引号：`echo "*.txt"` |
| `echo "x" >> /etc/hosts` 加了 sudo 还是 `Permission denied` | 重定向是当前 Shell 做的，不受 sudo 影响 | 用 `echo "x" \| sudo tee -a /etc/hosts`，见 [sudo](05-用户和权限.md#cmd-sudo) |
| 需要精确控制格式（补零、对齐小数） | echo 不支持格式化 | 改用 `printf`，如 `printf "%05d\n" 42` |

第二条的实测：

```
$ echo *.txt
link.txt out.txt readme.txt

$ echo "*.txt"
*.txt
```

### 6. 一句话总结

看变量用 `echo $变量`，写文件分清 `>` 和 `>>`，`$?` 查上一步成没成功。

## 021 ★★★&nbsp;&nbsp;grep：按关键词搜索文本

> 级别：★★★ 初级 · 软件包：`grep`（GNU 版）

### 1. 作用

`grep` 在文件里逐行查找包含某个关键词的行，把匹配的行打印出来。查日志里的报错、在一堆配置文件里找某个参数、从命令输出里过滤出想看的那几行，都用 grep。

关键词可以是普通文字，也可以是正则表达式（regular expression，用特殊符号描述“一类文字”的写法，比如 `[0-9]+` 表示一串数字）。

### 2. 基本格式

```bash
grep [参数] 关键词 [文件...]
命令 | grep [参数] 关键词
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-i` | `--ignore-case` | 忽略大小写 |
| `-n` | `--line-number` | 显示行号 |
| `-v` | `--invert-match` | 反向：显示**不**包含关键词的行 |
| `-c` | `--count` | 只显示匹配的行数 |
| `-r` | `--recursive` | 递归搜索目录下的所有文件 |
| `-l` | `--files-with-matches` | 只列出包含关键词的文件名 |
| `-w` | `--word-regexp` | 整词匹配 |
| `-E` | `--extended-regexp` | 使用扩展正则，可以写 `A\|B` 这种“或” |
| `-o` | `--only-matching` | 只输出匹配到的部分，不输出整行 |
| `-A 数字` | `--after-context` | 同时显示匹配行之后的 N 行 |
| `-B 数字` | `--before-context` | 同时显示匹配行之前的 N 行 |
| `-C 数字` | `--context` | 同时显示前后各 N 行 |

### 4. 常用示例

演示用的日志 `logs/app.log` 共 8 行，见 [目录页](../README.md#演示环境)。

#### 4.1 找出所有错误

```
$ grep ERROR logs/app.log
2026-10-28 10:02:13 ERROR 订单 A1002 保存失败：超时
2026-10-28 11:30:40 ERROR 连接数据库失败
```

#### 4.2 `-i`：忽略大小写

```
$ grep -i error logs/app.log
2026-10-28 10:02:13 ERROR 订单 A1002 保存失败：超时
2026-10-28 11:30:40 ERROR 连接数据库失败
```

不加 `-i` 时，`grep error` 找不到任何行，因为日志里写的是大写的 ERROR。

#### 4.3 `-n` 和 `-c`：行号和数量

```
$ grep -n ERROR logs/app.log
4:2026-10-28 10:02:13 ERROR 订单 A1002 保存失败：超时
7:2026-10-28 11:30:40 ERROR 连接数据库失败

$ grep -c ERROR logs/app.log
2
```

#### 4.4 `-v`：排除干扰

```
$ grep -v INFO logs/app.log
2026-10-28 09:15:22 WARN  价格表缓存过期，重新加载
2026-10-28 10:02:13 ERROR 订单 A1002 保存失败：超时
2026-10-28 11:30:40 ERROR 连接数据库失败
```

去掉所有 INFO，剩下的就是需要关注的。查看配置文件时，`grep -v "^#" 文件` 可以去掉注释行。

#### 4.5 `-E`：同时找多个关键词

```
$ grep -E "WARN|ERROR" logs/app.log
2026-10-28 09:15:22 WARN  价格表缓存过期，重新加载
2026-10-28 10:02:13 ERROR 订单 A1002 保存失败：超时
2026-10-28 11:30:40 ERROR 连接数据库失败
```

#### 4.6 `-A`、`-B`、`-C`：看出错前后发生了什么

```
$ grep -A 1 "保存失败" logs/app.log
2026-10-28 10:02:13 ERROR 订单 A1002 保存失败：超时
2026-10-28 10:02:14 INFO  重试订单 A1002

$ grep -B 1 -n "连接数据库失败" logs/app.log
6-2026-10-28 10:02:15 INFO  订单 A1002 保存成功
7:2026-10-28 11:30:40 ERROR 连接数据库失败
```

带 `-n` 时，匹配行的行号后面是冒号 `:`，上下文行后面是减号 `-`。

#### 4.7 `-r` 和 `-l`：在整个目录里找

```
$ grep -r "A1002" .
./logs/app.log:2026-10-28 10:02:13 ERROR 订单 A1002 保存失败：超时
./logs/app.log:2026-10-28 10:02:14 INFO  重试订单 A1002
./logs/app.log:2026-10-28 10:02:15 INFO  订单 A1002 保存成功

$ grep -rl ERROR .
./logs/app.log
```

想知道“哪个配置文件里设置了端口 8080”，用 `grep -rn 8080 /etc/nginx/`。

#### 4.8 `-w`：整词匹配

```
$ grep -w 探头A src/products.csv
U001,探头A,探头,12000
U005,探头A,探头,12000
```

不加 `-w` 时，搜 `探头` 还会匹配到“探头B”。

#### 4.9 `-o`：只取出匹配的内容

```
$ grep -o "A[0-9]\+" logs/app.log
A1002
A1002
A1002
```

`A[0-9]\+` 表示“A 后面跟一个或多个数字”。从日志里提取订单号、IP 地址时常用。

#### 4.10 过滤其他命令的输出

```bash
ps aux | grep nginx
history | grep ssh
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `grep error` 什么都没找到 | grep 默认区分大小写 | 加 `-i` |
| `grep: logs: Is a directory` | 对目录搜索要加 `-r` | `grep -r ERROR logs` |
| 关键词里有空格，报 `No such file or directory` | 空格后面的部分被当成了文件名 | 关键词加引号：`grep "订单 A1002" 文件` |
| 搜 `1.5` 却匹配到了 `125` | `.` 在正则里表示“任意一个字符” | 按普通文字搜索用 `-F`：`grep -F "1.5" 文件` |
| `ps aux \| grep nginx` 结果里总有一行 `grep nginx` 自己 | grep 进程本身也在 ps 列表里 | 写成 `grep "[n]ginx"`，或改用 `pgrep -a nginx` |
| 脚本里判断“没找到”时出错退出 | 没有匹配时 grep 的退出码是 1，`set -e` 的脚本会因此中止 | 写成 `grep xxx 文件 \|\| true` |

没有匹配时的退出码：

```
$ grep error logs/app.log; echo "退出码=$?"
退出码=1
```

### 6. 一句话总结

`grep -rni 关键词 目录` 能解决大部分查找；看上下文加 `-C`，排除用 `-v`。

## 047 ★★★&nbsp;&nbsp;wc：统计行数、字数、字节数

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`wc`（word count）统计文件有多少行、多少个单词、多少字节。最常用的是 `wc -l` 数行数：日志里今天有多少条错误、CSV 有多少条记录、目录里有多少个文件。

### 2. 基本格式

```bash
wc [参数] [文件...]
命令 | wc [参数]
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-l` | `--lines` | 行数 |
| `-w` | `--words` | 单词数（以空格分隔） |
| `-c` | `--bytes` | 字节数 |
| `-m` | `--chars` | 字符数（一个中文算 1 个字符） |

不加参数时，依次输出行数、单词数、字节数。

### 4. 常用示例

#### 4.1 不加参数

```
$ wc logs/app.log
  8  37 404 logs/app.log
```

8 行，37 个单词，404 字节。

#### 4.2 `-l`：数行数

```
$ wc -l logs/app.log src/products.csv
  8 logs/app.log
  6 src/products.csv
 14 total
```

products.csv 有 6 行，去掉表头就是 5 条数据。

#### 4.3 配合管道计数

```
$ grep ERROR logs/app.log | wc -l
2

$ ls | wc -l
6
```

“统计某个接口今天被调用了多少次”：`grep "/api/order" access.log | wc -l`。

#### 4.4 只要数字，不要文件名

```
$ wc -l < logs/app.log
8
```

用 `<` 把文件内容送给 wc，输出里就没有文件名，脚本里赋值给变量更方便：`n=$(wc -l < app.log)`。

#### 4.5 字节数和字符数

```
$ wc -m src/products.csv; wc -c src/products.csv
112 src/products.csv
152 src/products.csv
```

文件里有中文，UTF-8 下一个中文占 3 个字节，所以字节数（152）比字符数（112）多。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 文件明明有 10 行，`wc -l` 显示 9 | wc 数的是换行符个数，最后一行末尾没有换行符就不算 | 这是正常行为；生成文件时让最后一行也以换行结尾 |
| `ls \| wc -l` 和实际文件数对不上 | 不含隐藏文件 | 用 `ls -A \| wc -l` |

### 6. 一句话总结

数行数用 `wc -l`，常接在 grep 后面计数，只要数字用 `wc -l < 文件`。

## 048 ★★★&nbsp;&nbsp;sort：排序

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`sort` 把文本按行排序后输出，可以按数字、按指定列、正序或倒序。它不修改原文件。和 [uniq](#cmd-uniq)、[cut](#cmd-cut)、[head](02-文件查看和编辑.md#cmd-head) 组合起来，在命令行里就能做简单的统计报表。

### 2. 基本格式

```bash
sort [参数] [文件...]
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-n` | `--numeric-sort` | 按数值大小排序 |
| `-r` | `--reverse` | 倒序 |
| `-h` | `--human-numeric-sort` | 按带单位的大小排序（2K、1M、3G） |
| `-u` | `--unique` | 去掉重复行 |
| `-t 字符` | `--field-separator` | 指定列分隔符，如 `-t,` |
| `-k 列` | `--key` | 按第几列排序，如 `-k4`；`-k4,4` 表示只用第 4 列 |
| `-o 文件` | `--output` | 结果写入文件，可以写回原文件 |

### 4. 常用示例

演示文件 n.txt 有 4 行：300、25、1000、25。

#### 4.1 默认排序和 `-n`

```
$ sort n.txt
1000
25
25
300

$ sort -n n.txt
25
25
300
1000
```

不加 `-n`，sort 按字符逐个比较，`"1000"` 的第一个字符 `1` 比 `"25"` 的 `2` 小，所以排在前面。数字一定要加 `-n`。

#### 4.2 `-nr`：从大到小

```
$ sort -nr n.txt
1000
300
25
25
```

#### 4.3 `-u`：排序并去重

```
$ sort -u n.txt
1000
25
300
```

#### 4.4 `-t -k`：按 CSV 的某一列排序

按第 4 列（价格）从高到低，`tail -n +2` 先去掉表头：

```
$ tail -n +2 src/products.csv | sort -t, -k4 -nr
U003,主机X,主机,280000
U002,探头B,探头,15000
U005,探头A,探头,12000
U001,探头A,探头,12000
U004,凝胶,耗材,35
```

先按第 3 列（分类）排，同一分类里再按价格倒序：

```
$ tail -n +2 src/products.csv | sort -t, -k3,3 -k4,4nr
U003,主机X,主机,280000
U002,探头B,探头,15000
U001,探头A,探头,12000
U005,探头A,探头,12000
U004,凝胶,耗材,35
```

相当于 SQL 的 `ORDER BY category, price DESC`。

#### 4.5 `-h`：按文件大小排序

```
$ du -sh * | sort -h
0       link.txt
4.0K    logs
4.0K    n.txt
4.0K    readme.txt
4.0K    run.sh
4.0K    src
2.4M    big.iso
```

#### 4.6 `-o`：写回原文件

```
$ sort n.txt -o n.txt
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 1000 排在了 25 前面 | 没加 `-n`，按字符排序 | 加 `-n` |
| `sort n.txt > n.txt` 之后文件变空了 | Shell 先清空 n.txt，sort 读到的是空文件 | 用 `sort n.txt -o n.txt` |
| `-k4` 排序结果和预期不一致 | `-k4` 表示“从第 4 列一直到行尾”作为排序依据 | 只按某一列排写成 `-k4,4` |
| 表头也被排进了数据中间 | sort 不知道哪行是表头 | 先 `tail -n +2` 去掉表头 |
| 中文排序不是按拼音 | sort 按字符编码排序 | 命令行里无法按拼音排，需要在程序或数据库里处理 |

### 6. 一句话总结

数字排序加 `-n`，倒序加 `-r`，CSV 用 `-t, -kN,N`，写回原文件用 `-o`。

## 049 ★★★&nbsp;&nbsp;uniq：去重和计数

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`uniq` 去掉**相邻的**重复行，加 `-c` 可以统计每一行出现了几次。它几乎总是和 `sort` 一起用：先排序让相同的行挨在一起，再交给 uniq。`sort | uniq -c` 相当于 SQL 的 `GROUP BY ... COUNT(*)`。

### 2. 基本格式

```bash
sort 文件 | uniq [参数]
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-c` | `--count` | 每行前面加上出现次数 |
| `-d` | `--repeated` | 只显示有重复的行 |
| `-u` | `--unique` | 只显示没有重复的行 |
| `-i` | `--ignore-case` | 比较时忽略大小写 |

### 4. 常用示例

#### 4.1 为什么要先 sort

```
$ printf "b\na\nb\n" | uniq
b
a
b

$ printf "b\na\nb\n" | sort | uniq
a
b
```

两个 b 不相邻，uniq 不会去重。

#### 4.2 `-c`：统计每种日志级别各有多少条

```
$ awk '{print $3}' logs/app.log | sort | uniq -c
      2 ERROR
      5 INFO
      1 WARN
```

`awk '{print $3}'` 取出每行的第 3 列（日志级别），见中级篇 awk。

#### 4.3 统计并按次数排序

```
$ cut -d, -f2 src/products.csv | tail -n +2 | sort | uniq -c | sort -nr
      2 探头A
      1 探头B
      1 凝胶
      1 主机X
```

这一串命令是：取第 2 列（品名）→ 去掉表头 → 排序 → 计数 → 按次数从高到低排。分析访问日志里“哪个 IP 访问最多”，用的也是这个套路：

```bash
awk '{print $1}' access.log | sort | uniq -c | sort -nr | head
```

#### 4.4 `-d` 和 `-u`：找重复、找唯一

```
$ cut -d, -f2 src/products.csv | tail -n +2 | sort | uniq -d
探头A

$ cut -d, -f2 src/products.csv | tail -n +2 | sort | uniq -u
主机X
凝胶
探头B
```

导入数据前用 `uniq -d` 查一下编码列有没有重复。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| uniq 之后还有重复行 | 重复的行不相邻 | 先 `sort` 再 `uniq` |
| 看起来一样的两行没被合并 | 其中一行末尾多了空格，或者有 Windows 换行符 `\r` | 用 `cat -A` 检查不可见字符 |

### 6. 一句话总结

`sort | uniq -c | sort -nr` 是命令行里的“分组计数并排序”。

## 078 ★★★&nbsp;&nbsp;diff：比较两个文件的差异

> 级别：★★★ 初级 · 软件包：`diffutils`

### 1. 作用

`diff` 逐行比较两个文件，列出哪些行不同。改配置之前备份了一份，改完后用 diff 和备份对比，就能确认到底改了什么；两台服务器的配置不一致，也用它找差别。

### 2. 基本格式

```bash
diff [参数] 文件1 文件2
diff -r [参数] 目录1 目录2
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-u` | `--unified` | 统一格式，前面带 `-`/`+`，最易读，git 也用这种格式 |
| `-y` | `--side-by-side` | 左右并排显示 |
| `-W 宽度` | `--width` | 并排显示时的总宽度 |
| `-q` | `--brief` | 只说是否不同，不列出细节 |
| `-r` | `--recursive` | 比较两个目录 |
| `-i` | `--ignore-case` | 忽略大小写 |
| `-w` | `--ignore-all-space` | 忽略所有空白的差异 |
| `-B` | `--ignore-blank-lines` | 忽略空行 |

### 4. 常用示例

演示用的两个配置文件：

| a.conf | b.conf |
|---|---|
| `host=db01` | `host=db02` |
| `port=1433` | `port=1433` |
| `user=sa` | `user=app` |
| | `timeout=30` |

#### 4.1 `-u`：推荐的格式

```
$ diff -u a.conf b.conf
--- a.conf      2026-10-29 07:03:59.000975292 +0000
+++ b.conf      2026-10-29 07:03:59.000975292 +0000
@@ -1,3 +1,4 @@
-host=db01
+host=db02
 port=1433
-user=sa
+user=app
+timeout=30
```

`-` 开头的行只在 a.conf 里，`+` 开头的只在 b.conf 里，空格开头的两边一样。`@@ -1,3 +1,4 @@` 表示这一段对应 a.conf 的第 1 行起共 3 行、b.conf 的第 1 行起共 4 行。

#### 4.2 默认格式

```
$ diff a.conf b.conf
1c1
< host=db01
---
> host=db02
3c3,4
< user=sa
---
> user=app
> timeout=30
```

`1c1` 表示第 1 行被修改（c = change），`a` 是新增（add），`d` 是删除（delete）。`<` 是第一个文件的内容，`>` 是第二个文件的。

#### 4.3 `-y`：并排对比

```
$ diff -y -W 40 a.conf b.conf
host=db01          |    host=db02
port=1433               port=1433
user=sa            |    user=app
                   >    timeout=30
```

`|` 表示这一行两边不同，`>` 表示只有右边有。

#### 4.4 `-q`：只问是否相同

```
$ diff -q a.conf b.conf
Files a.conf and b.conf differ

$ diff a.conf a.conf; echo "退出码=$?"
退出码=0
```

完全相同时没有任何输出，退出码为 0；有差异时退出码为 1。脚本里可以据此判断配置有没有被改过。

#### 4.5 `-r`：比较两个目录

```
$ diff -q -r d1 d2
Files d1/a.conf and d2/a.conf differ
Only in d2: new.txt
```

升级程序前后，对比两个版本的配置目录，很快就能看出新增了哪些文件、哪些文件有改动。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 两个文件看起来一模一样，diff 却说每一行都不同 | 一个是 Windows 换行（`\r\n`），一个是 Linux 换行 | 用 `cat -A` 确认；`diff --strip-trailing-cr` 可以忽略这个差异 |
| 只是缩进从 Tab 改成了空格，diff 报了一大片 | 空白字符也算差异 | 加 `-w` 忽略空白 |

### 6. 一句话总结

对比配置用 `diff -u 旧 新`，`-` 是删掉的，`+` 是新加的；比目录加 `-r`。

## 079 ★★★&nbsp;&nbsp;cut：按列截取文本

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`cut` 从每一行里截取出指定的列（字段）或指定位置的字符。CSV 文件、`/etc/passwd`、日志这类“每行格式固定”的文本，用 cut 取出其中一两列，再交给 sort、uniq 做统计。

### 2. 基本格式

```bash
cut -d 分隔符 -f 列号 [文件...]
cut -c 字符位置 [文件...]
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-d 字符` | `--delimiter` | 指定分隔符，默认是 Tab |
| `-f 列号` | `--fields` | 取第几列：`-f2` 一列，`-f1,4` 多列，`-f2-` 第 2 列到最后 |
| `-c 位置` | `--characters` | 按字符位置截取，如 `-c1-10` |
| | `--complement` | 反选：取除了指定列以外的所有列 |

### 4. 常用示例

#### 4.1 取 CSV 的某一列

```
$ cut -d, -f2 src/products.csv
name
探头A
探头B
主机X
凝胶
探头A
```

#### 4.2 取多列

```
$ cut -d, -f1,4 src/products.csv
code,price
U001,12000
U002,15000
U003,280000
U004,35
U005,12000
```

输出的列之间仍然用原来的分隔符（逗号）连接。相当于 SQL 的 `SELECT code, price`。

#### 4.3 取从某列开始到最后

```
$ cut -d, -f2- src/products.csv | head -2
name,category,price
探头A,探头,12000
```

#### 4.4 `/etc/passwd`：列出用户和他们的 Shell

```
$ cut -d: -f1,7 /etc/passwd | head -3
root:/bin/bash
daemon:/usr/sbin/nologin
bin:/usr/sbin/nologin
```

/etc/passwd 每行 7 列，用冒号分隔，第 1 列是用户名，第 7 列是登录 Shell。

#### 4.5 `-c`：按字符位置截取

```
$ cut -c1-10 logs/app.log | head -2
2026-10-28
2026-10-28
```

日志行开头的 10 个字符正好是日期。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 用空格做分隔符，取出来的列错位 | 两列之间有多个连续空格时，cut 把每个空格都当一个分隔符 | 改用 `awk '{print $3}'`，awk 会把连续空格当成一个 |
| CSV 里某个字段本身带逗号（如 `"探头,高频"`），列全乱了 | cut 不识别引号 | 简单场景改用 awk；复杂 CSV 用 Python 的 csv 模块处理 |
| 不加 `-d` 时，`cut -f2` 原样输出了整行 | 默认分隔符是 Tab，文件里没有 Tab | 指定 `-d` |

### 6. 一句话总结

`cut -d, -f列号` 取 CSV 的列，`-c` 按位置截取；空格分隔的文本改用 awk。

## 080 ★★★&nbsp;&nbsp;tee：同时输出到屏幕和文件

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`tee` 从管道读入内容，一份照常输出到屏幕（或者传给下一个命令），一份写进文件。名字来自水管的 T 形三通接头。

两个典型用途：

- 一边看命令的输出，一边把它存成日志；
- 配合 sudo 写入普通用户没有权限的文件（`echo ... | sudo tee 文件`）。

### 2. 基本格式

```bash
命令 | tee [参数] 文件...
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-a` | `--append` | 追加到文件末尾，不覆盖 |

### 4. 常用示例

#### 4.1 屏幕上看，同时存文件

```
$ grep ERROR logs/app.log | tee errors.txt
2026-10-28 10:02:13 ERROR 订单 A1002 保存失败：超时
2026-10-28 11:30:40 ERROR 连接数据库失败

$ cat errors.txt
2026-10-28 10:02:13 ERROR 订单 A1002 保存失败：超时
2026-10-28 11:30:40 ERROR 连接数据库失败
```

#### 4.2 `-a`：追加

```
$ grep WARN logs/app.log | tee -a errors.txt; wc -l errors.txt
2026-10-28 09:15:22 WARN  价格表缓存过期，重新加载
3 errors.txt
```

#### 4.3 中间存一份，继续往下传

```
$ ls | tee list.txt | wc -l
15
```

文件列表存进了 list.txt，同时交给 wc 统计数量。

#### 4.4 配合 sudo 写系统文件

```bash
echo "192.168.1.10 db01" | sudo tee -a /etc/hosts > /dev/null
```

`> /dev/null` 把 tee 输出到屏幕的那一份丢掉，只写文件。为什么不能写成 `sudo echo ... >> /etc/hosts`，见 [sudo](05-用户和权限.md#cmd-sudo) 的踩坑表。

#### 4.5 记录升级过程

```bash
sudo apt upgrade 2>&1 | tee upgrade-$(date +%F).log
```

`2>&1` 把错误输出也并进来，一起写进日志文件。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 用 tee 往 /etc/hosts 追加一行，结果整个文件只剩这一行 | 少了 `-a`，tee 默认覆盖 | 追加一定加 `-a`；改系统文件前先备份 |
| 报错信息没有写进 tee 的文件 | 管道只传递标准输出，错误输出（stderr）不经过管道 | 在管道前加 `2>&1` |

### 6. 一句话总结

`命令 | tee 文件` 边看边存，追加加 `-a`，写系统文件用 `| sudo tee -a`。

## 102 ★★&nbsp;&nbsp;sed：流式文本替换

> 级别：★★ 中级 · 软件包：`sed`（GNU sed 4.9）

### 1. 作用

`sed`（stream editor）逐行读入文本，按你给的规则修改后输出。最常用的是**查找替换**，其次是删除某些行、只打印某几行、在指定位置插入一行。加 `-i` 可以直接修改文件，所以它是脚本里批量改配置文件的主力工具。

和 nano、vim 的区别：编辑器要人打开文件手动改；sed 用一条命令完成修改，可以写进部署脚本，在 100 台服务器上执行结果都一样。

### 2. 基本格式

```bash
sed [参数] '命令' 文件...
命令 | sed '命令'
```

| 常用命令 | 含义 |
|---|---|
| `s/旧/新/` | 替换每行第一次出现的“旧” |
| `s/旧/新/g` | 替换每行所有的“旧”（g = global） |
| `/模式/d` | 删除匹配的行 |
| `3,5p` | 打印第 3 到第 5 行（配合 `-n`） |
| `2i 文本` | 在第 2 行前插入一行 |
| `$a 文本` | 在最后一行后追加一行 |

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-i` | 直接修改文件（不输出到屏幕） |
| `-i.bak` | 修改文件前先备份成 `文件.bak` |
| `-n` | 不自动输出每一行，只输出 `p` 命令指定的行 |
| `-E` | 使用扩展正则（括号分组、`+`、`?`、`{n}` 不用加反斜杠） |
| `-e 命令` | 一次执行多条命令 |

### 4. 常用示例

#### 4.1 替换

```
$ sed 's/INFO/信息/' logs/app.log | head -3
2026-10-28 09:00:01 信息  服务启动
2026-10-28 09:00:05 信息  连接数据库成功
2026-10-28 09:15:22 WARN  价格表缓存过期，重新加载

$ sed 's/A1002/A2002/g' logs/app.log | grep A2002
2026-10-28 10:02:13 ERROR 订单 A2002 保存失败：超时
2026-10-28 10:02:14 INFO  重试订单 A2002
2026-10-28 10:02:15 INFO  订单 A2002 保存成功
```

不加 `-i` 时，sed 只把结果输出到屏幕，原文件不变。先这样预览，确认无误再加 `-i`。

#### 4.2 `-i`：直接修改配置文件

```
$ printf 'port=8080\nhost=db01\n' > app.conf

$ sed -i 's/^port=.*/port=9090/' app.conf; cat app.conf
port=9090
host=db01
```

`^port=.*` 表示“以 port= 开头的整行”，不管原来的端口是多少，都改成 9090。部署脚本里改配置项最常用这种写法。

#### 4.3 `-i.bak`：改之前自动备份

```
$ sed -i.bak 's/,35$/,38/' p.csv; ls p.csv*
p.csv
p.csv.bak
```

`,35$` 里的 `$` 表示行尾，只替换行尾的“,35”，不会误改别处的 35。

#### 4.4 只打印某些行

```
$ sed -n '3,5p' logs/app.log
2026-10-28 09:15:22 WARN  价格表缓存过期，重新加载
2026-10-28 10:02:13 ERROR 订单 A1002 保存失败：超时
2026-10-28 10:02:14 INFO  重试订单 A1002

$ sed -n '$=' logs/app.log
8
```

`$=` 打印最后一行的行号，也就是总行数。从几 GB 的日志里截取第 100000 到 100100 行，`sed -n '100000,100100p'` 比用编辑器打开快得多。

#### 4.5 删除行

```
$ sed '/INFO/d' logs/app.log
2026-10-28 09:15:22 WARN  价格表缓存过期，重新加载
2026-10-28 10:02:13 ERROR 订单 A1002 保存失败：超时
2026-10-28 11:30:40 ERROR 连接数据库失败

$ sed '1d' src/products.csv
U001,探头A,探头,12000
U002,探头B,探头,15000
U003,主机X,主机,280000
U004,凝胶,耗材,35
U005,探头A,探头,12000
```

`1d` 删除第 1 行，常用来去掉 CSV 的表头。

#### 4.6 插入和追加

```
$ sed '2i # 插入的一行' src/products.csv | head -4
code,name,category,price
# 插入的一行
U001,探头A,探头,12000
U002,探头B,探头,15000

$ sed '$a U006,新品,耗材,99' src/products.csv | tail -2
U005,探头A,探头,12000
U006,新品,耗材,99
```

#### 4.7 路径里有斜杠：换个分隔符

```
$ sed 's#/var/log#/data/log#' <<< "path=/var/log/app"
path=/data/log/app
```

`s` 后面的第一个字符就是分隔符，可以用 `#`、`|`，免得把路径里的每个 `/` 都写成 `\/`。

#### 4.8 `-E`：分组引用

```
$ sed -E 's/([0-9]{2}):([0-9]{2}):([0-9]{2})/\1时\2分/' logs/app.log | head -2
2026-10-28 09时00分 INFO  服务启动
2026-10-28 09时00分 INFO  连接数据库成功
```

括号里匹配到的内容，在替换部分用 `\1`、`\2` 引用。

#### 4.9 去掉 Windows 换行符

```
$ printf 'a\r\nb\r\n' > win.txt; sed -i 's/\r$//' win.txt; cat -A win.txt
a$
b$
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `sed -i` 改错了，原文件已经覆盖 | `-i` 不留备份 | 重要文件用 `-i.bak`；或先不加 `-i` 预览 |
| 替换内容里有 `/`，报 `unknown option to 's'` | `/` 被当成了分隔符 | 换分隔符：`s#旧#新#` |
| `s/1.5/2.0/` 把 `125` 也改了 | `.` 在正则里是“任意字符” | 写成 `s/1\.5/2.0/` |
| 用了 `+`、`{2}`、`()` 没有效果 | 默认是基础正则，这些符号要加反斜杠 | 加 `-E` |
| 在 macOS 上写的 `sed -i '' 's/a/b/' 文件` 到 Ubuntu 上报错 | macOS 的 sed 和 GNU sed 的 `-i` 写法不同 | Ubuntu 上直接写 `sed -i 's/a/b/' 文件` |
| `sed: can't read nothere: No such file or directory` | 文件名写错 | 检查路径 |

### 6. 一句话总结

`sed 's/旧/新/g'` 先预览，确认后加 `-i.bak` 改文件；`-n '起,止p'` 截取行。

<a id="cmd-awk"></a>

## 103 ★★&nbsp;&nbsp;awk：按列处理文本

> 级别：★★ 中级 · 软件包：`mawk`（Ubuntu 默认的 awk 是 mawk 1.3.4）

### 1. 作用

`awk` 把每一行按分隔符（默认是空格和 Tab）拆成若干列，用 `$1`、`$2`…… 引用，然后按条件筛选、计算、格式化输出。它本身是一门小型编程语言，日常最常用的是三件事：**取某几列**、**按条件过滤行**、**分组求和计数**。

如果说 [cut](#cmd-cut) 只能截取列，awk 就是能写 WHERE 条件、能做 SUM 和 GROUP BY 的 cut。

### 2. 基本格式

```bash
awk [参数] '条件 {动作}' 文件...
```

| 写法 | 含义 |
|---|---|
| `'{print $1}'` | 对每一行执行：打印第 1 列 |
| `'$3=="ERROR"'` | 只写条件不写动作：打印满足条件的整行 |
| `'NR>1 {...}'` | 从第 2 行开始执行（跳过表头） |
| `'BEGIN {...}'` / `'END {...}'` | 处理第一行之前 / 最后一行之后执行一次 |

| 内置变量 | 含义 |
|---|---|
| `$0` | 整行 |
| `$1` … `$n` | 第 1 … n 列 |
| `NF` | 这一行有几列，`$NF` 是最后一列 |
| `NR` | 当前是第几行 |

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-F 分隔符` | 指定列分隔符，如 `-F,`、`-F:` |
| `-v 变量=值` | 传入变量；`-v OFS='\t'` 设置输出的列分隔符 |

### 4. 常用示例

#### 4.1 取列

```
$ awk '{print $1, $3}' logs/app.log | head -2
2026-10-28 INFO
2026-10-28 INFO

$ awk -F, '{print $2, $4}' src/products.csv
name price
探头A 12000
探头B 15000
主机X 280000
凝胶 35
探头A 12000
```

和 cut 不同，awk 把连续的多个空格当成一个分隔符，所以日志里 `INFO` 后面的两个空格不会造成错位。

#### 4.2 按条件过滤

```
$ awk '$3=="ERROR"' logs/app.log
2026-10-28 10:02:13 ERROR 订单 A1002 保存失败：超时
2026-10-28 11:30:40 ERROR 连接数据库失败

$ awk -F, 'NR>1 && $4>10000 {print $1, $4}' src/products.csv
U001 12000
U002 15000
U003 280000
U005 12000
```

相当于 SQL 的 `SELECT code, price FROM products WHERE price > 10000`。

#### 4.3 求和

```
$ awk -F, 'NR>1 {sum+=$4} END {print "合计:", sum}' src/products.csv
合计: 319035
```

#### 4.4 分组汇总

```
$ awk -F, 'NR>1 {s[$3]+=$4; n[$3]++} END {for (k in s) print k, n[k], s[k]}' src/products.csv
主机 1 280000
探头 3 39000
耗材 1 35
```

`s[$3]` 是以分类为键的数组。这条命令相当于 `SELECT category, COUNT(*), SUM(price) ... GROUP BY category`。输出顺序不固定，需要排序就接 `| sort`。

#### 4.5 格式化输出

```
$ awk -F, 'NR>1 {printf "%-6s %10.2f\n", $1, $4}' src/products.csv
U001     12000.00
U002     15000.00
U003    280000.00
U004        35.00
U005     12000.00
```

#### 4.6 计算后输出 Tab 分隔

```
$ awk -F, -v OFS='\t' 'NR>1 {print $1, $4*1.13}' src/products.csv
U001    13560
U002    16950
U003    316400
U004    39.55
U005    13560
```

#### 4.7 处理其他命令的输出

```
$ awk -F: '$3>=1000 {print $1}' /etc/passwd
nobody
tom

$ df -h | awk 'NR>1 && $5+0 > 0 {print $6, $5}'
/ 3%
/home 1%
```

第一条列出 UID ≥ 1000 的账号（普通用户）。第二条 `$5+0` 把 `3%` 转成数字 3，用来找使用率超过某个值的分区。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `awk "{print $1}"` 输出的是整行 | 双引号里的 `$1` 先被 Shell 展开成了空值 | awk 程序一律用单引号 |
| 取第 5 列，输出全是空行 | 这一行没有第 5 列（CSV 只有 4 列） | 先 `awk -F, '{print NF}'` 看有几列 |
| `awk: line 2: missing } near end of file` | 花括号没有配对 | 检查 `{` `}` 是否成对 |
| 网上的 awk 脚本用了 `strftime()`、`gensub()`，在 Ubuntu 上报错 | 这些是 gawk 的扩展，Ubuntu 默认的 mawk 不支持 | `sudo apt install gawk`，然后用 `gawk` 执行 |
| CSV 字段里带逗号（`"探头,高频"`），列全乱了 | awk 不识别引号 | 复杂 CSV 用 Python 的 csv 模块 |

### 6. 一句话总结

`awk -F分隔符 '条件 {print $列}'`；求和分组用数组加 `END`；程序永远用单引号。

<a id="cmd-xargs"></a>

## 104 ★★&nbsp;&nbsp;xargs：把输入转成命令参数

> 级别：★★ 中级 · 软件包：`findutils`

### 1. 作用

很多命令（rm、cp、curl）只从参数读取文件名，不从管道读取。`xargs` 从标准输入读入一串内容，把它们拼成参数，交给后面的命令执行。典型用法是 `find ... | xargs 命令`：先找出一批文件，再一次性处理。

### 2. 基本格式

```bash
命令1 | xargs [参数] 命令2 [命令2的固定参数]
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-0` | 输入以空字符分隔（配合 `find -print0`，能正确处理带空格的文件名） |
| `-n 数量` | 每次最多传几个参数 |
| `-I{}` | 把每一项代入命令中 `{}` 的位置，每项执行一次 |
| `-P 数量` | 同时并行运行几个进程 |
| `-t` | 执行前先打印要执行的命令 |
| `-r` | 输入为空时不执行命令 |

### 4. 常用示例

#### 4.1 默认：拼成一条命令

```
$ printf 'U001\nU002\nU003\n' | xargs echo 处理
处理 U001 U002 U003
```

#### 4.2 `-n 1`：每项执行一次

```
$ printf 'U001\nU002\nU003\n' | xargs -n 1 echo 处理
处理 U001
处理 U002
处理 U003
```

#### 4.3 `-I{}`：把每项放到指定位置

```
$ printf 'U001\nU002\n' | xargs -I{} echo "curl https://api.example.com/item/{}"
curl https://api.example.com/item/U001
curl https://api.example.com/item/U002
```

把 echo 去掉，就会对每个编码真正调用一次接口。

#### 4.4 `-t`：先看看会执行什么

```
$ printf 'logs\nsrc\n' | xargs -t du -sh
du -sh logs src
4.0K    logs
4.0K    src
```

#### 4.5 `-P`：并行执行

```bash
find /data/logs -name "*.log" -mtime +1 | xargs -P 4 -n 1 gzip
```

同时开 4 个 gzip 进程压缩旧日志，多核机器上比一个一个压快得多。

#### 4.6 正确处理带空格的文件名

```
$ touch a.tmp b.tmp "c d.tmp"

$ find . -name "*.tmp" | xargs rm
rm: cannot remove './c': No such file or directory
rm: cannot remove 'd.tmp': No such file or directory

$ find . -name "*.tmp" -print0 | xargs -0 rm -v
removed './c d.tmp'
```

不加 `-0` 时，xargs 按空格切分，`c d.tmp` 被拆成了两个名字。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 文件名带空格，xargs 处理出错 | 默认按空白切分 | `find -print0 \| xargs -0` |
| 输入为空时，`xargs rm` 报 `missing operand` | 没有输入时 GNU xargs 默认仍执行一次命令 | 加 `-r` |
| 批量删除前没检查，删多了 | xargs 不会询问 | 先用 `xargs -t echo rm` 预览 |

### 6. 一句话总结

`find ... -print0 | xargs -0 命令` 批量处理；每项一次用 `-I{}`，并行用 `-P`。

## 105 ★★&nbsp;&nbsp;tr：替换或删除字符

> 级别：★★ 中级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`tr`（translate）逐个字符地替换、删除或压缩重复字符。它只处理单个字符，不处理字符串（替换字符串用 [sed](#cmd-sed)）。常用来转换大小写、把逗号换成换行、去掉 Windows 换行符、只保留数字。

tr 只从标准输入读取，不接受文件名参数。

### 2. 基本格式

```bash
命令 | tr [参数] 字符集1 [字符集2]
tr [参数] 字符集1 [字符集2] < 文件
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| （不加） | 把字符集 1 中的字符逐个换成字符集 2 中对应的字符 |
| `-d` | 删除字符集 1 中的字符 |
| `-s` | 连续重复的字符压缩成一个 |
| `-c` | 取反：对“不在字符集 1 中”的字符操作 |

| 字符集写法 | 含义 |
|---|---|
| `a-z` | 小写字母 |
| `[:upper:]` / `[:lower:]` | 大写 / 小写字母 |
| `[:digit:]` 或 `0-9` | 数字 |
| `'\n'` `'\r'` `'\t'` | 换行、回车、制表符 |

### 4. 常用示例

```
$ echo "hello world" | tr a-z A-Z
HELLO WORLD

$ echo "a,b,c" | tr ',' '\n'
a
b
c

$ echo "a   b    c" | tr -s ' '
a b c

$ echo "tel: 138-0013-8000" | tr -d '-'
tel: 13800138000

$ echo "tel: 138-0013-8000" | tr -cd '0-9'; echo
13800138000

$ printf 'a\r\nb\r\n' | tr -d '\r' | cat -A
a$
b$
```

`-cd '0-9'` 表示删除所有非数字字符，只留下数字。把 PATH 拆成一行一个目录：

```
$ echo "$PATH" | tr ':' '\n'
/usr/local/sbin
/usr/local/bin
/usr/sbin
/usr/bin
/sbin
/bin
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `tr a-z A-Z readme.txt` 报 `tr: extra operand 'readme.txt'` | tr 不接受文件名 | `tr a-z A-Z < readme.txt` |
| `tr 'abc' 'xyz'` 想把字符串 abc 换成 xyz，结果所有的 a、b、c 都被换了 | tr 按单个字符一一对应替换 | 替换字符串用 `sed 's/abc/xyz/g'` |
| 用 `tr a-z A-Z` 转换中文或带重音的字母没有效果 | 范围只覆盖 ASCII 字母 | 中文没有大小写，不需要转换 |

### 6. 一句话总结

`tr` 按字符替换、`-d` 删除、`-s` 压缩，只认标准输入。

## 157 ★★&nbsp;&nbsp;base64：Base64 编码和解码

> 级别：★★ 中级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`base64` 把任意内容（包括二进制）转换成只由字母、数字、`+`、`/`、`=` 组成的文本，或者反向解码。HTTP 的 Basic 认证头、Kubernetes 的 Secret、邮件附件、JSON 里嵌入的图片和证书，用的都是 Base64。

Base64 **不是加密**，任何人都能解码，不能用它来“保护”密码。

### 2. 基本格式

```bash
echo -n "内容" | base64          # 编码
echo "编码后的内容" | base64 -d   # 解码
base64 文件                       # 编码一个文件
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-d` | 解码 |
| `-w 0` | 编码结果不换行（默认每 76 个字符换一行） |

### 4. 常用示例

#### 4.1 编码和解码

```
$ echo -n "tom:Tom@2026" | base64
dG9tOlRvbUAyMDI2

$ echo "dG9tOlRvbUAyMDI2" | base64 -d; echo
tom:Tom@2026
```

调接口时，`Authorization: Basic dG9tOlRvbUAyMDI2` 里的那串就是“用户名:密码”的 Base64。

#### 4.2 编码文件

```
$ base64 readme.txt
aGVsbG8K
```

要把证书、图片塞进 JSON 或 YAML 里时，用 `base64 -w 0 文件` 得到一整行。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 解码后的密码多了一个换行，认证失败 | 编码时用的是 `echo`，把末尾的换行也编码进去了 | 编码用 `echo -n` 或 `printf '%s'` |
| `base64: error: invalid input` | 输入不是合法的 Base64（多了字符或被截断） | 检查是否复制完整 |

第一条的对比，结尾多出来的 `Cg==` 就是被编码进去的换行符：

```
$ echo "tom:Tom@2026" | base64
dG9tOlRvbUAyMDI2Cg==
```

### 6. 一句话总结

`echo -n 内容 | base64` 编码，`base64 -d` 解码；Base64 不是加密。

## 164 ★★&nbsp;&nbsp;paste：按行合并文件

> 级别：★★ 中级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`paste` 把几个文件的第 1 行拼成输出的第 1 行，第 2 行拼成第 2 行，依此逐行左右拼接。cat 是上下拼接，paste 是左右拼接。加 `-s` 还能把一个文件的所有行合并成一行。

### 2. 基本格式

```bash
paste [参数] 文件1 文件2...
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-d 字符` | 拼接时用的分隔符，默认 Tab |
| `-s` | 把每个文件的所有行合成一行 |

### 4. 常用示例

codes.txt 和 names.txt 分别是 products.csv 的第 1 列和第 2 列：

```
$ paste codes.txt names.txt
code    name
U001    探头A
U002    探头B
U003    主机X
U004    凝胶
U005    探头A

$ paste -d, codes.txt names.txt | head -3
code,name
U001,探头A
U002,探头B

$ paste -s -d, codes.txt
code,U001,U002,U003,U004,U005
```

最后一种常用来拼 SQL 的 IN 条件，或者生成逗号分隔的列表。

### 5. 一句话总结

`paste` 左右拼接文件，`-s -d,` 把多行合成一行。

## 165 ★★&nbsp;&nbsp;join：按关键列连接两个文件

> 级别：★★ 中级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`join` 按两个文件中的同一列（默认第 1 列）进行连接，把匹配的行合并成一行输出，效果相当于 SQL 的 JOIN。两个文件都**必须先按连接列排好序**。

### 2. 基本格式

```bash
join [参数] 文件1 文件2
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-t 字符` | 列分隔符，CSV 用 `-t,` |
| `-1 N` / `-2 N` | 文件 1 / 文件 2 用第几列连接 |
| `-a 1` | 文件 1 中没有匹配的行也输出（左连接） |
| `-e 字符串` | 缺失的字段用什么填充（配合 `-o`） |
| `-o 字段列表` | 指定输出哪些字段，`0` 是连接列，`1.2` 是文件 1 的第 2 列 |

### 4. 常用示例

stock.csv 是库存（编码,数量），只有 U001、U002、U004 三条。先排序：

```bash
tail -n +2 src/products.csv | sort -t, -k1,1 > p.sorted
sort -t, -k1,1 stock.csv > s.sorted
```

内连接：

```
$ join -t, p.sorted s.sorted
U001,探头A,探头,12000,500
U002,探头B,探头,15000,0
U004,凝胶,耗材,35,1200
```

左连接，没有库存的显示“无”：

```
$ join -t, -a1 -e 无 -o 0,1.2,2.2 p.sorted s.sorted
U001,探头A,500
U002,探头B,0
U003,主机X,无
U004,凝胶,1200
U005,探头A,无
```

相当于 `SELECT p.code, p.name, ISNULL(s.qty,'无') FROM p LEFT JOIN s ON p.code = s.code`。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 明明有相同的编码，join 却没有输出，或者报 `is not sorted` | 文件没有按连接列排序 | 先 `sort -t, -k1,1` |
| 表头行也参与了连接 | join 不认识表头 | 先用 `tail -n +2` 去掉表头 |

### 6. 一句话总结

两个文件按某列 JOIN：先 `sort`，再 `join -t,`；左连接加 `-a1`。

## 167 ★★&nbsp;&nbsp;comm：比较两个排好序的文件

> 级别：★★ 中级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`comm` 比较两个**已排序**的文件，把结果分成三列：只在文件 1 中的、只在文件 2 中的、两个文件都有的。用来回答“这次名单比上次多了谁、少了谁”这类问题，相当于集合的差集和交集。

### 2. 基本格式

```bash
comm [参数] 文件1 文件2
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-1` | 不显示第 1 列（只在文件 1 中的） |
| `-2` | 不显示第 2 列（只在文件 2 中的） |
| `-3` | 不显示第 3 列（两边都有的） |

参数可以组合：`-12` 只看共有的，`-13` 只看文件 2 独有的，`-23` 只看文件 1 独有的。

### 4. 常用示例

old.txt 是 alice、bob、carol，new.txt 是 bob、carol、dave：

```
$ comm old.txt new.txt
alice
                bob
                carol
        dave

$ comm -12 old.txt new.txt
bob
carol

$ comm -13 old.txt new.txt
dave

$ comm -23 old.txt new.txt
alice
```

-13 是新增的人（dave），-23 是被移除的人（alice）。核对两次导出的账号清单时很有用。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `comm: file 1 is not in sorted order`，结果不对 | 输入没有排序 | `comm <(sort a) <(sort b)` |

### 6. 一句话总结

`comm -13 旧 新` 看新增，`-23` 看减少，`-12` 看共有，输入要先排序。

## 169 ★★&nbsp;&nbsp;rev：把每行的字符倒过来

> 级别：★★ 中级 · 软件包：`bsdextrautils`

### 1. 作用

`rev` 把每一行的字符顺序反转。单独用的场合不多，主要用于一个技巧：需要“取最后一列”而列数又不固定时，先 rev，用 cut 取第 1 列，再 rev 回来。

### 2. 基本格式

```bash
rev [文件]
```

### 3. 常用示例

```
$ echo "hello 价格" | rev
格价 olleh

$ echo "/var/log/nginx/access.log" | rev | cut -d/ -f1 | rev
access.log
```

第二条从路径里取出了最后一段文件名。同样的需求也可以用 `awk -F/ '{print $NF}'`。

### 4. 一句话总结

`rev` 反转每行，配合 cut 可以取最后一列。

## 170 ★★&nbsp;&nbsp;tac：倒序输出各行

> 级别：★★ 中级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`tac`（cat 倒过来写）从最后一行开始，倒着输出文件的每一行。日志最新的在最后，用 tac 可以让最新的记录排在最前面。

### 2. 基本格式

```bash
tac [文件...]
```

### 3. 常用示例

```
$ tac logs/app.log | head -3
2026-10-28 11:30:45 INFO  连接数据库成功
2026-10-28 11:30:40 ERROR 连接数据库失败
2026-10-28 10:02:15 INFO  订单 A1002 保存成功
```

找“最近一次出错”的记录：

```bash
tac /var/log/app.log | grep -m 1 ERROR
```

`grep -m 1` 找到第一条就停，配合 tac 就是从后往前找到的第一条，即最新的一条。

### 4. 一句话总结

`tac` 倒序输出，配合 `grep -m 1` 找最新的一条记录。

<a id="cmd-printf"></a>

## 171 ★★&nbsp;&nbsp;printf：格式化输出

> 级别：★★ 中级 · 来源：bash 内建命令

### 1. 作用

`printf` 按格式模板输出文本，可以控制宽度、对齐、小数位数、补零。[echo](#cmd-echo) 只能原样输出，需要对齐成报表、输出固定格式的编号时用 printf。

和 echo 的另一个区别：printf 默认**不换行**，要在格式里写 `\n`。

### 2. 基本格式

```bash
printf "格式" 参数...
```

| 格式符 | 含义 | 示例 |
|---|---|---|
| `%s` | 字符串 | `printf "%s\n" tom` |
| `%d` | 整数 | `printf "%d\n" 42` |
| `%f` | 小数，`%.2f` 保留 2 位 | `printf "%.2f\n" 3.14159` |
| `%05d` | 宽度 5，不足补 0 | `00042` |
| `%-8s` | 宽度 8，左对齐 | |
| `%8s` | 宽度 8，右对齐 | |
| `%%` | 输出一个 `%` | |

### 3. 常用示例

```
$ printf "%05d\n" 42
00042

$ printf "%.2f\n" 3.14159
3.14

$ printf "%-8s|%8s|\n" U001 12000
U001    |   12000|

$ printf "100%%\n"
100%
```

参数比格式符多时，格式会重复使用，一次输出多行：

```
$ printf "%s=%s\n" host db01 port 1433
host=db01
port=1433
```

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 含中文的列对不齐 | `%-8s` 按字节计算宽度，一个中文占 3 个字节 | 中文报表改用 `column -t` 对齐 |
| `printf: abc: invalid number`，输出 0 | `%d` 收到的不是数字 | 检查传入的变量 |
| 输出后提示符接在了同一行 | printf 不自动换行 | 格式末尾加 `\n` |

第一条的实测，“编码”“价格”两个中文标题比数据行短了一截：

```
$ printf "%-8s %10s\n" 编码 价格; printf "%-8s %10.2f\n" U001 12000 U004 35
编码       价格
U001       12000.00
U004          35.00
```

### 5. 一句话总结

需要补零、对齐、控制小数位就用 `printf`，记得加 `\n`。

## 174 ★★&nbsp;&nbsp;seq：生成数字序列

> 级别：★★ 中级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`seq` 输出一串连续的数字，每行一个。主要用在脚本的循环里，或者批量生成编号、文件名。

### 2. 基本格式

```bash
seq 结束
seq 开始 结束
seq 开始 步长 结束
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-w` | 补零使宽度一致 |
| `-s 字符` | 数字之间的分隔符，默认换行 |
| `-f 格式` | 按 printf 风格的格式输出 |

### 4. 常用示例

```
$ seq 0 10 50
0
10
20
30
40
50

$ seq -w 1 10 | head -3
01
02
03

$ seq -s, 1 5
1,2,3,4,5

$ seq -f "file%03g.log" 1 3
file001.log
file002.log
file003.log

$ for i in $(seq 1 3); do echo "第 $i 次"; done
第 1 次
第 2 次
第 3 次
```

bash 里也可以写 `{1..3}`，但 `{}` 里不能用变量，`seq 1 $n` 可以。

### 5. 一句话总结

循环要一串数字就用 `seq`，补零加 `-w`，自定义格式用 `-f`。
