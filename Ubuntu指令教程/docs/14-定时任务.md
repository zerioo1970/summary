## 114 ★★&nbsp;&nbsp;crontab：设置周期执行的定时任务

> 级别：★★ 中级 · 软件包：`cron`

### 1. 作用

`crontab` 编辑当前用户的定时任务表，cron 服务会按表里写的时间自动执行命令。每天凌晨备份数据库、每 5 分钟检查一次服务是否正常、每月 1 号清理日志，都靠它。

每个用户有自己的任务表，任务以该用户的身份执行。

### 2. 基本格式

```bash
crontab -e            # 编辑自己的任务表（第一次会让你选择编辑器）
crontab -l            # 查看
crontab -r            # 删除全部任务（不会确认）
sudo crontab -u 用户 -l   # 查看别人的
```

### 3. 时间的写法

每行一个任务：5 个时间字段，加上要执行的命令。

```
分  时  日  月  星期  命令
```

| 字段 | 取值 | 示例 |
|---|---|---|
| 分 | 0–59 | `30` |
| 时 | 0–23 | `2` |
| 日 | 1–31 | `1` |
| 月 | 1–12 | `*` |
| 星期 | 0–7（0 和 7 都是星期日） | `1-5` 周一到周五 |

| 写法 | 含义 |
|---|---|
| `*` | 每一个 |
| `*/5` | 每隔 5 |
| `1,15` | 1 和 15 |
| `1-5` | 1 到 5 |

| 例子 | 含义 |
|---|---|
| `30 2 * * *` | 每天 02:30 |
| `*/5 * * * *` | 每 5 分钟 |
| `0 9 * * 1-5` | 工作日每天 09:00 |
| `0 0 1 * *` | 每月 1 号 00:00 |
| `@reboot` | 每次开机时 |

### 4. 常用示例

以下以 root 身份执行（普通用户用 `crontab -e` 编辑自己的表即可）。

#### 4.1 写入并查看

```
$ crontab -l
no crontab for root

$ crontab -e
（在编辑器里写入以下内容并保存）
# 每天 02:30 备份
30 2 * * * /home/root/backup.sh >> /var/log/backup.log 2>&1
*/5 * * * * /usr/bin/curl -fsS http://127.0.0.1:8080/health > /dev/null

$ crontab -l
# 每天 02:30 备份
30 2 * * * /home/root/backup.sh >> /var/log/backup.log 2>&1
*/5 * * * * /usr/bin/curl -fsS http://127.0.0.1:8080/health > /dev/null
```

> 测试时用 `printf '...' | crontab -` 写入，效果和 `crontab -e` 保存相同。

`>> 日志 2>&1` 把任务的输出和错误都写进日志，出问题时才有据可查。

#### 4.2 时间写错时

```
$ printf '61 * * * * echo bad\n' | crontab -
"-":0: bad minute
errors in crontab file, can't install.
```

crontab 会检查格式，写错了不会保存。

#### 4.3 系统级的定时任务

除了每个用户的任务表，系统还有：

| 位置 | 说明 |
|---|---|
| `/etc/crontab` | 系统任务表，比用户的多一列“以哪个用户执行” |
| `/etc/cron.d/` | 软件包放的任务文件，格式同 /etc/crontab |
| `/etc/cron.daily/` 等 | 放在里面的脚本每天 / 每周 / 每月执行一次 |

```
$ ls /etc/cron.daily
apt-compat
dpkg
logrotate
man-db
plocate
```

日志轮转（logrotate）和 locate 数据库更新就是从这里每天执行的。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 命令在终端里能执行，放进 crontab 就失败 | cron 的环境变量很少，PATH 只有 `/usr/bin:/bin` | 命令写完整路径；或在任务表开头写 `PATH=/usr/local/bin:/usr/bin:/bin` |
| 任务里的 `date +%Y%m%d` 不生效 | `%` 在 crontab 里表示换行 | 写成 `\%`，或把命令放进脚本 |
| 任务执行时间比预期差了 8 小时 | 系统时区是 UTC | `sudo timedatectl set-timezone Asia/Shanghai`，然后 `sudo systemctl restart cron` |
| 想输入 `crontab -e` 却按成了 `crontab -r`，所有任务都没了 | `-r` 直接删除，不确认 | 定期 `crontab -l > ~/crontab.bak` 备份 |
| 不知道任务有没有执行 | 没有记录输出 | 加 `>> 日志 2>&1`；查 `grep CRON /var/log/syslog` 或 `journalctl -u cron` |

### 6. 一句话总结

`crontab -e` 写“分 时 日 月 周 命令”，命令用完整路径，输出写日志。

## 200 ★★&nbsp;&nbsp;at：在指定时间执行一次

> 级别：★★ 中级 · 软件包：`at`（需 `sudo apt install at`）

### 1. 作用

`at` 安排一个命令在将来的某个时间点**执行一次**，执行完就结束。crontab 适合周期性任务，at 适合“今晚 23:30 重启一次服务”“2 小时后把临时开放的权限收回”这类一次性任务。

### 2. 基本格式

```bash
echo "命令" | at 时间
at 时间          # 回车后逐行输入命令，按 Ctrl+D 结束
```

| 时间写法 | 含义 |
|---|---|
| `now + 10 minutes` | 10 分钟后 |
| `now + 2 hours` | 2 小时后 |
| `23:30` | 今天 23:30（已过则为明天） |
| `02:00 tomorrow` | 明天 02:00 |
| `10:00 2026-11-01` | 指定日期 |

### 3. 常用命令

| 命令 | 作用 |
|---|---|
| `atq` 或 `at -l` | 列出等待执行的任务 |
| `atrm 编号` | 删除任务 |
| `at -c 编号` | 查看任务的完整内容 |

### 4. 常用示例

```
$ echo "date > /tmp/at-test.txt" | at now + 1 minute
warning: commands will be executed using /bin/sh
job 1 at Thu Oct 29 08:43:00 2026

$ echo "echo hi" | at 23:30
warning: commands will be executed using /bin/sh
job 2 at Thu Oct 29 23:30:00 2026

$ atq
1	Thu Oct 29 08:43:00 2026 a root
2	Thu Oct 29 23:30:00 2026 a root

$ atrm 1; atq
2	Thu Oct 29 23:30:00 2026 a root

$ echo "tar -czf /tmp/logs.tar.gz /var/log" | at 02:00 tomorrow
warning: commands will be executed using /bin/sh
job 3 at Fri Oct 30 02:00:00 2026
```

`warning: commands will be executed using /bin/sh` 是正常提示：任务用 sh 执行，不是 bash，bash 特有的写法可能不能用。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `Garbled time` | 时间格式写错，如 `25:00` | 按上面的写法 |
| 任务到点没有执行 | atd 服务没有运行 | `sudo systemctl enable --now atd` |
| 任务的输出去哪了 | at 会把输出用本机邮件发给用户，没配置邮件就看不到 | 在命令里重定向到文件 |

### 6. 一句话总结

一次性定时用 `echo "命令" | at 时间`，`atq` 查看，`atrm` 删除。
