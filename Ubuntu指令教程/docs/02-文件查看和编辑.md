## 005 ★★★&nbsp;&nbsp;cat：查看文件内容

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`cat`（concatenate，连接）把文件内容一次性输出到屏幕。它本来的用途是把多个文件首尾相接，日常最多的用法是查看短文件，比如配置文件、几十行的脚本。

长文件不要用 cat，几千行会一下子刷过屏幕。长文件用 [less](#cmd-less)，只看开头结尾用 [head](#cmd-head)、[tail](#cmd-tail)。

### 2. 基本格式

```bash
cat [参数] [文件...]
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-n` | `--number` | 每行前面加行号 |
| `-b` | `--number-nonblank` | 只给非空行加行号 |
| `-A` | `--show-all` | 显示不可见字符：行尾 `$`、Tab 显示为 `^I`、Windows 换行符显示为 `^M` |
| `-s` | `--squeeze-blank` | 连续多个空行压缩成一个 |

### 4. 常用示例

#### 4.1 查看文件

```
$ cat readme.txt
hello
```

#### 4.2 `cat -n`：带行号查看

```
$ cat -n logs/app.log
     1  2026-10-28 09:00:01 INFO  服务启动
     2  2026-10-28 09:00:05 INFO  连接数据库成功
     3  2026-10-28 09:15:22 WARN  价格表缓存过期，重新加载
     4  2026-10-28 10:02:13 ERROR 订单 A1002 保存失败：超时
     5  2026-10-28 10:02:14 INFO  重试订单 A1002
     6  2026-10-28 10:02:15 INFO  订单 A1002 保存成功
     7  2026-10-28 11:30:40 ERROR 连接数据库失败
     8  2026-10-28 11:30:45 INFO  连接数据库成功
```

报错信息里说“第 4 行有问题”时，用 `-n` 很快就能对上号。

#### 4.3 合并多个文件

```
$ cat readme.txt src/products.csv
hello
code,name,category,price
U001,探头A,探头,12000
U002,探头B,探头,15000
U003,主机X,主机,280000
U004,凝胶,耗材,35
U005,探头A,探头,12000

$ cat readme.txt src/products.csv > all.txt
```

`>` 把输出写进 all.txt（覆盖原有内容）。用 `>>` 则追加到文件末尾。每天的 CSV 合并成一个月的汇总，就是这种用法。

#### 4.4 `cat -A`：查出 Windows 换行符

在 Windows 上编辑过的脚本放到 Linux 上运行，经常报莫名其妙的错误。用 `-A` 一看就知道：

```
$ cat -A win.txt
a^M$
b^M$

$ cat -A run.sh
#!/bin/bash$
echo hi$
```

`^M$` 表示行尾是 Windows 的 `\r\n`，正常的 Linux 文件行尾只有 `$`。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 从 Windows 拷来的脚本运行报 `/bin/bash^M: bad interpreter: No such file or directory` | 文件用的是 Windows 换行符 `\r\n`，第一行变成了 `#!/bin/bash\r` | `cat -A` 确认后，用 `sed -i 's/\r$//' 脚本.sh` 去掉 `\r` |
| `cat a.txt > a.txt` 之后 a.txt 变成空文件 | Shell 先清空 a.txt 再让 cat 读取，读到的已经是空文件 | 先写到临时文件再改名：`cat a.txt b.txt > tmp && mv tmp a.txt` |
| `cat: logs: Is a directory` | 对目录用了 cat | 看目录内容用 `ls` |
| cat 一个大日志，屏幕刷了几分钟停不下来 | cat 不分页 | 按 `Ctrl+C` 中断，改用 `less` 或 `tail` |

### 6. 一句话总结

短文件用 `cat` 看，要行号加 `-n`，查换行符加 `-A`，长文件换 `less`。

## 011 ★★★&nbsp;&nbsp;nano：终端里的简易文本编辑器

> 级别：★★★ 初级 · 软件包：`nano`（Ubuntu 26.04 自带 8.7 版）

### 1. 作用

`nano` 是在终端里编辑文本文件的编辑器。服务器没有图形界面，改配置文件时最简单的办法就是 nano。它的快捷键提示一直显示在屏幕底部，不用背。

功能更强的 [vim](#cmd-vim) 学习成本高，日常改几行配置，nano 足够。

### 2. 基本格式

```bash
nano [参数] 文件名
```

文件不存在时，保存后会新建。改系统配置要加 sudo：`sudo nano /etc/hosts`。

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-l` | `--linenumbers` | 左侧显示行号 |
| `-v` | `--view` | 只读模式，防止误改 |
| `-B` | `--backup` | 保存时把旧版本备份成 `文件名~` |
| `-m` | `--mouse` | 启用鼠标，可以点击定位光标 |
| `+行号` | | 打开后直接跳到指定行，如 `nano +25 app.conf` |

### 4. 常用快捷键

屏幕底部的 `^` 表示 Ctrl 键，`M-` 表示 Alt 键。

| 快捷键 | 作用 |
|---|---|
| `Ctrl+O` 再回车 | 保存 |
| `Ctrl+X` | 退出。有未保存的修改时会问 `Save modified buffer?`，按 `Y` 保存、`N` 不保存 |
| `Ctrl+W` | 搜索，输入关键词后回车；按 `Alt+W` 找下一个 |
| `Ctrl+\` | 查找并替换 |
| `Ctrl+K` | 剪切当前行 |
| `Ctrl+U` | 粘贴 |
| `Alt+U` | 撤销 |
| `Ctrl+_` | 跳到指定行号 |
| `Ctrl+G` | 打开帮助 |

> ⚠️ 本节未实机验证：nano 是全屏交互程序，测试环境无法录制界面。参数已对照 nano 8.7 手册核实，快捷键为 nano 长期沿用的默认键位。

### 5. 常用示例

#### 5.1 带行号编辑配置

```bash
sudo nano -l /etc/ssh/sshd_config
```

报错信息说“第 25 行配置有误”时，直接 `sudo nano +25 /etc/ssh/sshd_config` 跳过去。

#### 5.2 只看不改

```bash
nano -v /etc/fstab
```

`/etc/fstab` 写错会导致系统开不了机。只想看内容时用 `-v`，避免误按键盘改动它。

#### 5.3 改之前自动备份

```bash
sudo nano -B /etc/hosts
```

保存后，旧版本留在 `/etc/hosts~`。

### 6. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 保存时提示 `Error writing /etc/hosts: Permission denied` | 打开时没加 sudo | 先 `Ctrl+O` 另存到家目录，退出后 `sudo cp` 回去；以后记得用 `sudo nano` |
| 粘贴进来的长行被自动折成了两行 | 开启了自动断行（`-b`） | 去掉 `-b`。nano 8.x 默认是 `-w`（不断行） |

### 7. 一句话总结

`nano 文件` 打开，`Ctrl+O` 保存，`Ctrl+X` 退出，系统文件记得加 sudo。

## 018 ★★★&nbsp;&nbsp;less：分页查看长文件

> 级别：★★★ 初级 · 软件包：`less`（Ubuntu 26.04 自带 668 版）

### 1. 作用

`less` 一屏一屏地显示文件内容，可以前后翻页、搜索。它不会一次把整个文件读进内存，几个 GB 的日志也能马上打开。看日志、看长配置文件，用 less 比 cat 合适。

`man` 命令的手册、`git log` 的输出，背后用的也是 less，所以学会 less 的按键，这些地方都能用。

### 2. 基本格式

```bash
less [参数] 文件
命令 | less
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-N` | 显示行号 |
| `-S` | 长行不折行，左右方向键横向滚动（看宽表格、CSV 很有用） |
| `-i` | 搜索时忽略大小写（关键词里有大写字母时除外） |
| `+F` | 打开后进入跟踪模式，文件有新内容就自动显示，类似 `tail -f` |
| `+G` | 打开后直接跳到文件末尾 |

### 4. 打开后的按键

| 按键 | 作用 |
|---|---|
| `空格` / `b` | 向下 / 向上翻一页 |
| `↓` `↑` 或 `j` `k` | 向下 / 向上一行 |
| `g` / `G` | 跳到开头 / 结尾 |
| `/关键词` 回车 | 向下搜索 |
| `?关键词` 回车 | 向上搜索 |
| `n` / `N` | 下一个 / 上一个搜索结果 |
| `F` | 进入跟踪模式，按 `Ctrl+C` 退出跟踪 |
| `q` | 退出 |

> ⚠️ 本页未实机验证：less 是全屏交互程序，测试环境无法录制界面。参数和按键为 less 长期稳定的默认行为。

### 5. 常用示例

#### 5.1 查日志里的错误

```bash
less +G /var/log/syslog
```

打开后直接在末尾（最新的日志）。按 `?ERROR` 回车往前找最近的错误，按 `n` 继续往前找。

#### 5.2 看宽表格

```bash
less -S src/products.csv
```

每行不折行，列对得整齐，左右方向键横向滚动。

#### 5.3 带行号

```bash
less -N /etc/ssh/sshd_config
```

#### 5.4 接在其他命令后面

```bash
ps aux | less
```

命令输出太长、屏幕放不下时，在后面接 `| less`。

### 6. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 打开后不知道怎么退出 | less 不响应 `Ctrl+C` 退出 | 按 `q` |
| 在 `+F` 跟踪模式下按键没反应 | 跟踪模式只等新内容 | 先按 `Ctrl+C` 回到普通模式，再按 `q` |
| 打开 .gz 压缩日志看到乱码 | 压缩文件需要先解压 | 用 `zless app.log.gz`；Ubuntu 默认也配置了 less 自动解压，若仍乱码就用 zless |

### 7. 一句话总结

长文件用 `less`，`/` 搜索，`G` 到末尾，`q` 退出。

## 019 ★★★&nbsp;&nbsp;head：查看文件开头

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`head` 只显示文件的前几行，默认 10 行。用来看 CSV 的表头、日志开头、大文件的格式，不用把整个文件打开。

### 2. 基本格式

```bash
head [参数] [文件...]
命令 | head [参数]
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-n 数字` | `--lines` | 显示前 N 行，可以简写成 `-数字`，如 `-3` |
| `-n -数字` | | 显示除了最后 N 行之外的所有行 |
| `-c 数字` | `--bytes` | 显示前 N 个字节 |
| `-q` | `--quiet` | 多个文件时不显示文件名标题 |

### 4. 常用示例

#### 4.1 看前 3 行

```
$ head -n 3 logs/app.log
2026-10-28 09:00:01 INFO  服务启动
2026-10-28 09:00:05 INFO  连接数据库成功
2026-10-28 09:15:22 WARN  价格表缓存过期，重新加载
```

`head -3 logs/app.log` 效果相同。

#### 4.2 去掉最后 6 行

```
$ head -n -6 logs/app.log
2026-10-28 09:00:01 INFO  服务启动
2026-10-28 09:00:05 INFO  连接数据库成功
```

app.log 一共 8 行，去掉最后 6 行剩 2 行。

#### 4.3 同时看多个文件

```
$ head -n 2 src/products.csv logs/app.log
==> src/products.csv <==
code,name,category,price
U001,探头A,探头,12000

==> logs/app.log <==
2026-10-28 09:00:01 INFO  服务启动
2026-10-28 09:00:05 INFO  连接数据库成功
```

导入一批 CSV 之前，用这个办法确认每个文件的表头是否一致。

#### 4.4 接在其他命令后面

```bash
ls -lt | head -5          # 最近修改的 4 个文件（第 1 行是 total）
du -ah | sort -rh | head  # 占空间最大的 10 项
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 想看 CSV 的“前 5 条数据”，结果只看到 4 条 | 第 1 行是表头 | 用 `head -n 6`，或者 `tail -n +2 文件 \| head -5` 跳过表头 |
| `head -c 10` 截出来的中文变成乱码 | `-c` 按字节截，一个中文字（UTF-8）占 3 个字节，可能被截断一半 | 处理中文按行截，用 `-n` |

### 6. 一句话总结

`head -n N` 看前 N 行，`-n -N` 去掉最后 N 行，常接在管道后面取前几条。

## 020 ★★★&nbsp;&nbsp;tail：查看文件末尾，实时跟踪日志

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`tail` 显示文件的最后几行，默认 10 行。日志是不断往末尾追加的，最新的内容在最后，所以查日志最常用的是 tail。

加 `-f` 后 tail 不退出，文件一有新内容就马上显示，用来盯着程序的实时日志。

### 2. 基本格式

```bash
tail [参数] [文件...]
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-n 数字` | `--lines` | 显示最后 N 行，可简写成 `-数字` |
| `-n +数字` | | 从第 N 行开始显示到末尾 |
| `-f` | `--follow` | 持续跟踪文件新增的内容，按 `Ctrl+C` 退出 |
| `-F` | | 和 `-f` 一样，而且文件被删除重建（日志轮转）后会继续跟踪新文件 |
| `-c 数字` | `--bytes` | 显示最后 N 个字节 |

### 4. 常用示例

#### 4.1 看最后 2 行

```
$ tail -n 2 logs/app.log
2026-10-28 11:30:40 ERROR 连接数据库失败
2026-10-28 11:30:45 INFO  连接数据库成功
```

#### 4.2 `-n +7`：从第 7 行开始

```
$ tail -n +7 logs/app.log
2026-10-28 11:30:40 ERROR 连接数据库失败
2026-10-28 11:30:45 INFO  连接数据库成功
```

`tail -n +2 products.csv` 能去掉 CSV 的第一行表头，只留数据。

#### 4.3 `-f`：实时跟踪日志

```
$ tail -f logs/app.log
2026-10-28 09:00:01 INFO  服务启动
2026-10-28 09:00:05 INFO  连接数据库成功
...（先显示最后 10 行，然后停在这里等待）
```

另开一个终端操作程序，新日志一写入，这里马上就会显示出来。按 `Ctrl+C` 退出。

#### 4.4 跟踪时只看错误

```bash
tail -f logs/app.log | grep ERROR
```

#### 4.5 跟踪多个文件

```bash
tail -f /var/log/nginx/access.log /var/log/nginx/error.log
```

tail 会在每段输出前用 `==> 文件名 <==` 标出来自哪个文件。

#### 4.6 `-f` 和 `-F` 的区别

下面模拟日志轮转：1 秒后把 t.log 改名为 t.log.1，再新建一个 t.log 写入 `new`。

```
$ tail -F t.log
old
tail: 't.log' has become inaccessible: No such file or directory
tail: 't.log' has appeared;  following new file
new

$ tail -f u.log
old
```

`-F` 发现文件换了，自动跟上新文件，显示出了 `new`。`-f` 还盯着改名后的旧文件，新内容一直看不到。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `tail -f` 跟踪了一夜，第二天突然不再有新日志 | 日志在半夜被轮转（改名成 app.log.1，再新建 app.log），`-f` 还在跟踪改名后的旧文件 | 改用 `tail -F` |
| `tail -f 文件 \| grep xxx \| 另一个命令` 迟迟没有输出 | grep 的输出接到管道时会攒满一块再输出 | 给 grep 加 `--line-buffered` |
| 用 systemd 管理的服务找不到日志文件 | 很多服务的日志不写文件，而是交给 journald | 用 `journalctl -u 服务名 -f` 跟踪 |

### 6. 一句话总结

`tail -n N` 看最后 N 行，盯实时日志用 `tail -F`。

## 052 ★★★&nbsp;&nbsp;more：简单的分页查看

> 级别：★★★ 初级 · 软件包：`util-linux`

### 1. 作用

`more` 一屏一屏地显示文件，按空格翻到下一页。它比 [less](#cmd-less) 早出现，功能少：主要只能往下翻，看到末尾会自动退出。

现在基本都用 less。了解 more 是因为一些老脚本和文档里还会出现它，而且极简的系统里可能只有 more。

### 2. 基本格式

```bash
more [参数] 文件
命令 | more
```

### 3. 常用参数和按键

| 写法 | 作用 |
|---|---|
| `more +行号 文件` | 从指定行开始显示 |
| `more +/关键词 文件` | 从第一次出现关键词的位置开始显示 |
| `-s` | 连续空行压缩成一行 |

| 按键 | 作用 |
|---|---|
| `空格` | 下一页 |
| `回车` | 下一行 |
| `b` | 上一页（只对文件有效，对管道输入无效） |
| `/关键词` | 搜索 |
| `q` | 退出 |

> ⚠️ 本页未实机验证：more 是交互程序，测试环境只确认了版本（`more from util-linux 2.41.3`）。按键为 more 长期稳定的默认行为。

### 4. 常用示例

```bash
more /etc/services
more +/ssh /etc/services
ps aux | more
```

### 5. more 和 less 怎么选

| | more | less |
|---|---|---|
| 往回翻 | 有限 | 随意 |
| 读到末尾 | 自动退出 | 停在末尾，按 q 才退出 |
| 跟踪实时日志 | 不支持 | `F` 键 |

结论：有 less 就用 less。

### 6. 一句话总结

more 只适合往下翻着看，日常用 less。

## 058 ★★★&nbsp;&nbsp;vim：全功能的终端编辑器

> 级别：★★★ 初级 · 软件包：`vim`（Ubuntu 26.04 为 9.1 版；系统默认只装了精简版 `vim-tiny`）

### 1. 作用

`vim` 是 Linux 上最常见的终端文本编辑器。几乎所有服务器都有它（至少有精简版 `vi`），出故障时 nano 不一定在，vi 一定在。所以即使日常用 nano，也至少要会用 vim 打开、修改、保存、退出。

vim 和 nano 最大的不同是有“模式”：打开后默认在**普通模式**，敲键盘是在下命令，不是输入文字。要先按 `i` 进入**插入模式**才能打字。

### 2. 基本格式

```bash
vim 文件名
```

Ubuntu 默认的 `vi` 指向精简版 vim-tiny：

```
$ ls -l /usr/bin/vi /etc/alternatives/vi
lrwxrwxrwx 1 root root 17 Aug 24 22:11 /etc/alternatives/vi -> /usr/bin/vim.tiny
lrwxrwxrwx 1 root root 20 Aug 24 22:11 /usr/bin/vi -> /etc/alternatives/vi
```

完整版用 `sudo apt install vim` 安装，有语法高亮等功能。

### 3. 三种模式

| 模式 | 怎么进入 | 用来做什么 |
|---|---|---|
| 普通模式 | 打开文件时默认；任何时候按 `Esc` 回到这里 | 移动光标、删除、复制、粘贴 |
| 插入模式 | 普通模式下按 `i` | 输入文字，屏幕底部显示 `-- INSERT --` |
| 命令行模式 | 普通模式下按 `:` | 保存、退出、搜索替换 |

### 4. 最少要会的操作

| 操作 | 按键 |
|---|---|
| 开始输入 | `i` |
| 停止输入 | `Esc` |
| 保存 | `:w` 回车 |
| 保存并退出 | `:wq` 回车 |
| 不保存，强制退出 | `:q!` 回车 |

### 5. 常用命令（普通模式下）

| 按键 | 作用 |
|---|---|
| `gg` / `G` | 跳到文件开头 / 结尾 |
| `:25` 回车 | 跳到第 25 行 |
| `/关键词` 回车 | 搜索，`n` 下一个，`N` 上一个 |
| `dd` | 删除（剪切）当前行 |
| `yy` | 复制当前行 |
| `p` | 粘贴到下一行 |
| `u` | 撤销 |
| `Ctrl+r` | 重做 |
| `:%s/旧/新/g` 回车 | 全文替换 |
| `:set nu` 回车 | 显示行号 |

> ⚠️ 本页按键部分未实机验证：vim 是全屏交互程序，测试环境无法录制界面。版本号已实测（`VIM - Vi IMproved 9.1`）。

### 6. 常用示例

修改 ssh 端口：

```bash
sudo vim /etc/ssh/sshd_config
```

1. 输入 `/Port` 回车，光标跳到 `#Port 22` 那一行；
2. 按 `i` 进入插入模式，删掉 `#`，把 22 改成 2222；
3. 按 `Esc`，输入 `:wq` 回车。

### 7. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 打开后敲字，文件被改得乱七八糟 | 在普通模式下，每个字母都是命令 | 按 `Esc` 再按 `u` 多次撤销；或 `:q!` 不保存退出，重新打开 |
| 不知道怎么退出 | vim 不响应 `Ctrl+C` 退出 | 按 `Esc`，输入 `:q!` 回车 |
| `:wq` 报 `E45: 'readonly' option is set` 或 `can't open file for writing` | 没用 sudo 打开系统文件 | 输入 `:w !sudo tee %` 回车保存，再 `:q!`；以后记得 `sudo vim` |
| 再次打开文件时提示 `Found a swap file` | 上次 vim 异常退出，留下了 `.swp` 交换文件 | 按 `R` 恢复上次的修改，确认后删除 `.文件名.swp` |

### 8. 一句话总结

`i` 输入，`Esc` 停止，`:wq` 保存退出，`:q!` 放弃退出。
