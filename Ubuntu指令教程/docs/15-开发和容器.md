## 128 ★★&nbsp;&nbsp;git：版本控制

> 级别：★★ 中级 · 软件包：`git`（2.53.0）

### 1. 作用

`git` 记录文件的每一次修改：谁、什么时候、改了什么、为什么改。改坏了可以回到任何一个历史版本；多人可以在不同分支上各自开发，再合并到一起；和 GitHub、GitLab 等远程仓库同步，就是代码的备份和协作中心。

除了代码，服务器的配置文件（nginx、应用配置）、运维脚本、文档也适合用 git 管理。

git 的子命令非常多，这里只讲日常最常用的一组。

### 2. 基本概念

| 概念 | 含义 |
|---|---|
| 仓库（repository） | 一个被 git 管理的目录，历史记录保存在其中的 `.git` 子目录里 |
| 工作区 | 你正在编辑的文件 |
| 暂存区（staging） | 用 `git add` 挑出来、准备下一次提交的修改 |
| 提交（commit） | 一次保存的快照，带说明和一个唯一编号 |
| 分支（branch） | 一条独立的修改线，默认分支叫 main |
| 远程（remote） | 另一台机器上的仓库，通常叫 origin |

### 3. 常用子命令

| 子命令 | 作用 |
|---|---|
| `config --global user.name / user.email` | 设置提交者的名字和邮箱（只需设置一次） |
| `init 目录` | 新建仓库 |
| `clone 地址` | 复制一个远程仓库到本地 |
| `status` | 哪些文件改了、哪些已暂存 |
| `add 文件` / `add .` | 加入暂存区 |
| `commit -m "说明"` | 提交 |
| `commit -am "说明"` | 把已跟踪文件的修改直接提交（跳过 add） |
| `diff` | 看还没暂存的修改 |
| `log --oneline` | 简洁的历史 |
| `switch -c 分支` / `switch 分支` | 新建并切换 / 切换分支 |
| `merge 分支` | 合并分支 |
| `restore 文件` | 放弃工作区的修改 |
| `pull` / `push` | 从远程拉取 / 推送到远程 |
| `tag 名称` | 给当前提交打标签（如版本号） |

### 4. 常用示例

#### 4.1 第一次使用

```
$ git config --global user.name "Tom"
$ git config --global user.email "tom@example.com"
$ git config --global init.defaultBranch main
$ git config --global --list
user.name=Tom
user.email=tom@example.com
init.defaultbranch=main
```

#### 4.2 新建仓库并第一次提交

```
$ git init price-app
Initialized empty Git repository in /home/tom/demo/price-app/.git/

$ cd price-app; cp ../src/products.csv .; printf 'logs/\n*.log\n' > .gitignore

$ git status
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
	.gitignore
	products.csv

nothing added to commit but untracked files present (use "git add" to track)

$ git add .; git status --short
A  .gitignore
A  products.csv

$ git commit -m "初始化：产品价格表"
[main (root-commit) 2a27870] 初始化：产品价格表
 2 files changed, 8 insertions(+)
 create mode 100644 .gitignore
 create mode 100644 products.csv
```

`.gitignore` 里写的文件（日志目录、`*.log`）不会被 git 管理。

#### 4.3 修改、查看差异、提交

```
$ sed -i 's/,35$/,38/' products.csv; git status --short
 M products.csv

$ git diff
diff --git a/products.csv b/products.csv
index da7ced1..0c490f0 100644
--- a/products.csv
+++ b/products.csv
@@ -2,5 +2,5 @@ code,name,category,price
 U001,探头A,探头,12000
 U002,探头B,探头,15000
 U003,主机X,主机,280000
-U004,凝胶,耗材,35
+U004,凝胶,耗材,38
 U005,探头A,探头,12000

$ git commit -am "凝胶价格调整为 38"
[main ff1aa75] 凝胶价格调整为 38
 1 file changed, 1 insertion(+), 1 deletion(-)

$ git log --oneline
ff1aa75 凝胶价格调整为 38
2a27870 初始化：产品价格表
```

`git status --short` 里，`M` 是已修改，`A` 是新增，`??` 是未跟踪。

#### 4.4 分支和合并

```
$ git switch -c feature/new-product
Switched to a new branch 'feature/new-product'

$ echo "U006,新品,耗材,99" >> products.csv; git commit -qam "新增 U006"; git branch
* feature/new-product
  main

$ git switch main; git merge feature/new-product
Switched to branch 'main'
Updating ff1aa75..3050125
Fast-forward
 products.csv | 1 +
 1 file changed, 1 insertion(+)

$ git log --oneline --graph
* 3050125 新增 U006
* ff1aa75 凝胶价格调整为 38
* 2a27870 初始化：产品价格表
```

`Fast-forward` 表示 main 在这期间没有新提交，直接把 main 移动到分支的最新位置即可。

#### 4.5 放弃修改

```bash
git restore products.csv            # 放弃工作区里还没 add 的修改
git restore --staged products.csv   # 撤销 add，修改仍保留在工作区
```

#### 4.6 远程仓库

```bash
git clone https://github.com/用户/仓库.git
git remote add origin https://github.com/用户/仓库.git
git push -u origin main
git pull
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 提交时报 `Please tell me who you are` | 没设置 user.name 和 user.email | 按 4.1 设置 |
| push 时报 `could not read Username for 'https://github.com'`，或者输入密码后被拒绝 | GitHub 等平台不再接受账号密码推送 | 用 ssh 地址（`git@github.com:用户/仓库.git`）配合 ssh 密钥，或使用平台生成的访问令牌 |
| 把密码、密钥文件提交进了仓库 | 没写 .gitignore | 立即更换密码；从历史中清除需要专门的工具，提交前养成看 `git status` 的习惯 |
| `git pull` 报 `Your local changes would be overwritten` | 本地有未提交的修改，和远程的修改冲突 | 先 commit，或用 `git stash` 暂存，pull 后再 `git stash pop` |
| `git commit` 后显示 `no changes added to commit` | 修改还没有 add | 先 `git add`，或用 `commit -am` |

### 6. 一句话总结

`git status` 看状态，`add` + `commit -m` 保存，`switch -c` 开分支，`push`/`pull` 同步。

## 129 ★★&nbsp;&nbsp;docker：容器管理

> 级别：★★ 中级 · 软件包：`docker.io`（Ubuntu 软件源）或 Docker 官方的 `docker-ce`

### 1. 作用

`docker` 把应用和它需要的运行环境（系统库、语言运行时、配置）打包成**镜像**，再从镜像启动一个隔离运行的**容器**。同一个镜像在开发机、测试机、生产服务器上运行结果一致，部署时不再需要在每台机器上装一遍 JDK、Node、Python。

| 概念 | 含义 |
|---|---|
| 镜像（image） | 只读的模板，如 `nginx:1.27`、`mysql:8.4` |
| 容器（container） | 从镜像启动的运行实例，可以有多个 |
| 仓库（registry） | 存放镜像的地方，默认是 Docker Hub |
| 卷（volume） | 容器外部的持久存储，容器删除后数据仍在 |

### 2. 安装

```bash
sudo apt install docker.io            # Ubuntu 软件源里的版本
sudo usermod -aG docker $USER         # 加入 docker 组后，不用 sudo 也能执行 docker
# 重新登录后生效
```

也可以按 Docker 官方文档安装 `docker-ce`，版本更新。

### 3. 常用子命令

| 子命令 | 作用 |
|---|---|
| `run [参数] 镜像` | 启动一个新容器 |
| `ps` / `ps -a` | 运行中的容器 / 全部容器 |
| `images` | 本地的镜像 |
| `pull 镜像` | 下载镜像 |
| `logs [-f] 容器` | 查看容器输出 |
| `exec -it 容器 bash` | 进入运行中的容器执行命令 |
| `stop` / `start` / `restart 容器` | 停止 / 启动 / 重启 |
| `rm 容器` / `rmi 镜像` | 删除容器 / 镜像 |
| `build -t 名称 .` | 用当前目录的 Dockerfile 构建镜像 |

`run` 的常用参数：

| 参数 | 作用 |
|---|---|
| `-d` | 后台运行 |
| `--name 名字` | 给容器起名 |
| `-p 主机端口:容器端口` | 端口映射 |
| `-v 主机目录:容器目录` | 挂载目录，数据保存在主机上 |
| `-e 变量=值` | 环境变量 |
| `--restart unless-stopped` | 容器退出或主机重启后自动启动 |

### 4. 常用示例

```bash
docker run -d --name web -p 8080:80 nginx:1.27
docker ps
docker logs -f web
docker exec -it web bash
docker stop web && docker rm web
```

启动一个数据持久化的 MySQL：

```bash
docker run -d --name db \
  -e MYSQL_ROOT_PASSWORD='Db@2026' \
  -v /srv/mysql:/var/lib/mysql \
  -p 127.0.0.1:3306:3306 \
  --restart unless-stopped \
  mysql:8.4
```

`127.0.0.1:3306:3306` 表示只允许本机访问数据库端口。

> ⚠️ 本页未实机验证：测试环境里不能运行 Docker 守护进程。命令写法为 Docker 长期稳定的用法，镜像版本号仅为示例。多容器编排（docker compose）在高级篇讲。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `permission denied while trying to connect to the Docker daemon socket` | 当前用户不在 docker 组 | `sudo usermod -aG docker $USER` 后重新登录 |
| 删掉容器后，数据库数据全没了 | 数据存在容器内部 | 用 `-v` 把数据目录挂载到主机 |
| `-p 3306:3306` 映射的端口，ufw 拦不住，外网能直接访问 | Docker 直接修改 iptables，绕过 ufw | 绑定到 127.0.0.1，或用云安全组控制 |
| 磁盘被 Docker 占满 | 旧镜像、停止的容器、构建缓存越积越多 | `docker system df` 查看，`docker system prune` 清理 |
| 容器里的时间差 8 小时 | 镜像默认用 UTC | `-e TZ=Asia/Shanghai` |

### 6. 一句话总结

`docker run -d --name 名字 -p 端口 -v 目录 镜像` 启动，数据一定挂载到主机。
