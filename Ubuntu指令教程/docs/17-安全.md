## 227 ★&nbsp;&nbsp;openssl：证书和加密工具

> 级别：★ 高级 · 软件包：`openssl`（OpenSSL 3.5.5）

### 1. 作用

`openssl` 是处理 SSL/TLS 证书和加密的通用工具。运维中最常用的几件事：

- 查看证书的有效期、域名、颁发机构；
- 检查一个 HTTPS 网站的证书是否正常、什么时候过期；
- 生成私钥和证书签名请求（CSR），交给证书机构签发；
- 生成内网测试用的自签名证书；
- 生成随机密码、计算哈希、加密单个文件。

### 2. 常用子命令

| 子命令 | 作用 |
|---|---|
| `x509 -in 证书 -noout -subject -issuer -dates` | 查看证书信息 |
| `s_client -connect 主机:443 -servername 主机` | 连接 HTTPS 服务器，查看它返回的证书 |
| `req -new -newkey rsa:2048 -nodes -keyout 私钥 -out CSR` | 生成私钥和 CSR |
| `req -x509 ...` | 直接生成自签名证书 |
| `rand -base64 字节数` | 随机字符串 |
| `dgst -sha256 文件` | 计算哈希 |
| `enc -aes-256-cbc -pbkdf2 ...` | 对称加密文件 |

### 3. 常用示例

#### 3.1 检查网站的证书

```
$ echo | openssl s_client -connect ubuntu.com:443 -servername ubuntu.com 2>/dev/null | openssl x509 -noout -subject -issuer -enddate
subject=CN=ubuntu.com
issuer=C=US, O=Let's Encrypt, CN=YR1
notAfter=Dec 15 04:14:36 2026 GMT
```

`notAfter` 是过期时间。可以写进监控脚本，在证书到期前 30 天报警。`-servername` 不能省，一台服务器上有多个 HTTPS 网站时，靠它选择返回哪个证书。

#### 3.2 生成自签名证书（内网测试用）

```
$ openssl req -x509 -newkey rsa:2048 -nodes -keyout test.key -out test.crt -days 365 -subj "/CN=price.example.com"

$ ls -l test.*
-rw-r--r-- 1 root root 1135 Oct 29 10:11 test.crt
-rw------- 1 root root 1704 Oct 29 10:11 test.key

$ openssl x509 -in test.crt -noout -subject -issuer -dates
subject=CN=price.example.com
issuer=CN=price.example.com
notBefore=Oct 29 10:11:11 2026 GMT
notAfter=Oct 29 10:11:11 2027 GMT
```

subject 和 issuer 相同，就是自签名证书。浏览器会提示“不安全”，只能用于测试或内部。`-nodes` 表示私钥不加密码，否则每次启动 Web 服务都要输密码。

#### 3.3 申请正式证书：生成 CSR

```
$ openssl req -new -newkey rsa:2048 -nodes -keyout site.key -out site.csr -subj "/C=CN/ST=Shanghai/O=Example/CN=www.example.com"

$ openssl req -in site.csr -noout -subject
subject=C=CN, ST=Shanghai, O=Example, CN=www.example.com
```

把 site.csr 提交给证书机构，site.key 自己保管，绝不外发。

#### 3.4 加密一个文件

```
$ openssl enc -aes-256-cbc -pbkdf2 -salt -in salary.txt -out salary.enc -pass pass:'Enc@2026'

$ file salary.enc
salary.enc: openssl enc'd data with salted password

$ openssl enc -d -aes-256-cbc -pbkdf2 -in salary.enc -pass pass:'Enc@2026'
工资表内容

$ openssl enc -d -aes-256-cbc -pbkdf2 -in salary.enc -pass pass:wrong
bad decrypt
```

实际使用时去掉 `-pass`，openssl 会提示输入密码，避免密码留在命令历史里。

#### 3.5 随机密码

```bash
openssl rand -base64 16
```

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 证书装好了，浏览器提示证书链不完整 | 只装了网站证书，没装中间证书 | 把证书机构提供的中间证书和网站证书合并成一个 fullchain 文件 |
| 私钥和证书对不上，nginx 启动报 `key values mismatch` | 用错了私钥 | 比较 `openssl x509 -noout -modulus -in 证书 \| md5sum` 和 `openssl rsa -noout -modulus -in 私钥 \| md5sum` |
| `s_client` 一直不退出 | 它在等你输入 | 前面加 `echo \|`，或加 `< /dev/null` |

> ⚠️ 前两条未实机验证。

### 5. 一句话总结

查网站证书过期时间：`echo | openssl s_client -connect 主机:443 -servername 主机 | openssl x509 -noout -enddate`。

## 228 ★&nbsp;&nbsp;gpg：加密和数字签名

> 级别：★ 高级 · 软件包：`gnupg`（GnuPG 2.4.8）

### 1. 作用

`gpg`（GNU Privacy Guard）用公钥体系加密文件和做数字签名：

- **加密**：用对方的公钥加密，只有对方的私钥能解开；也可以只用一个密码加密（对称加密）。
- **签名**：用自己的私钥签名，别人用你的公钥验证“文件确实是你发的、没有被改过”。

apt 校验软件源、下载的软件包核对签名，背后都是 gpg。

### 2. 常用命令

| 命令 | 作用 |
|---|---|
| `gpg --full-generate-key` | 交互式生成密钥对 |
| `gpg --list-keys` / `--list-secret-keys` | 列出公钥 / 私钥 |
| `gpg --armor --export 邮箱 > pub.asc` | 导出公钥发给别人 |
| `gpg --import 文件` | 导入别人的公钥 |
| `gpg -c 文件` | 用密码加密（对称） |
| `gpg -e -r 对方邮箱 文件` | 用对方的公钥加密 |
| `gpg -d 文件.gpg` | 解密 |
| `gpg --detach-sign 文件` | 生成单独的签名文件 |
| `gpg --verify 签名 文件` | 验证签名 |

### 3. 常用示例

#### 3.1 用密码加密

```
$ gpg -c salary.txt
（提示输入两次密码）

$ ls salary.txt.gpg
salary.txt.gpg

$ gpg -d salary.txt.gpg
工资表内容
```

> 测试时用 `--batch --passphrase` 传入了密码，交互输入未实机录制。

#### 3.2 签名和验证

```
$ gpg --quick-gen-key "Tom <tom@example.com>" ed25519 sign,cert

$ gpg --detach-sign salary.txt

$ gpg --verify salary.txt.sig salary.txt
gpg: Signature made Thu Oct 29 10:11:12 2026 UTC
gpg:                using EDDSA key （指纹）
gpg: Good signature from "Tom <tom@example.com>" [ultimate]
```

文件被改动后：

```
$ echo tampered >> salary.txt; gpg --verify salary.txt.sig salary.txt
...
gpg: BAD signature from "Tom <tom@example.com>" [ultimate]
```

#### 3.3 验证下载的软件

```bash
gpg --import 官方公钥.asc
gpg --verify 软件.tar.gz.sig 软件.tar.gz
```

看到 `Good signature` 才说明文件来自官方且没有被篡改。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 验证时出现 `WARNING: This key is not certified with a trusted signature!` | 公钥导入了，但你没有确认过它的真实性 | 通过官网等可信渠道核对公钥指纹，签名本身仍然是有效的 |
| 私钥丢了，之前用公钥加密的文件都打不开 | 只有私钥能解密 | 用 `gpg --export-secret-keys --armor` 导出私钥，离线妥善备份 |

> ⚠️ 第一条的提示文字未实机验证。

### 5. 一句话总结

文件加密 `gpg -c`，发布文件 `gpg --detach-sign`，收到文件 `gpg --verify`。

## 229 ★&nbsp;&nbsp;certbot：申请免费的 HTTPS 证书

> 级别：★ 高级 · 软件包：`certbot`（4.0），配合 `python3-certbot-nginx` 或 `python3-certbot-apache`

### 1. 作用

`certbot` 从 Let's Encrypt 免费申请 HTTPS 证书，并能自动配置 nginx 或 Apache、自动续期。Let's Encrypt 的证书有效期只有 90 天左右，靠 certbot 的自动续期，基本不用人管。

申请时，Let's Encrypt 要验证你确实控制这个域名：默认方式是访问 `http://你的域名/.well-known/acme-challenge/...`，所以**域名必须解析到这台服务器，80 端口必须能从公网访问**。

### 2. 常用命令

| 命令 | 作用 |
|---|---|
| `certbot --nginx -d 域名` | 申请证书并自动修改 nginx 配置 |
| `certbot certonly --webroot -w 网站目录 -d 域名` | 只申请证书，不改配置 |
| `certbot certonly --standalone -d 域名` | 临时启动自己的 Web 服务来验证（80 端口要空闲） |
| `certbot certificates` | 列出已有的证书和到期时间 |
| `certbot renew --dry-run` | 模拟续期，确认自动续期能成功 |
| `certbot delete --cert-name 名称` | 删除证书 |

### 3. 常用示例

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d www.example.com -d example.com
sudo certbot renew --dry-run
sudo certbot certificates
```

证书文件放在 `/etc/letsencrypt/live/域名/`：`fullchain.pem` 是证书（含中间证书），`privkey.pem` 是私钥。自动续期由 systemd 定时器 `certbot.timer` 负责。

还没有证书时：

```
$ sudo certbot certificates
...
No certificates found.
```

> ⚠️ 申请和续期未实机验证：测试环境没有公网域名。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 申请失败，提示 `Timeout during connect` | 80 端口被防火墙或云安全组拦了 | 放行 80 端口（不只是 443） |
| 内网服务器拿不到证书 | 公网访问不到它 | 用 DNS 验证方式（`--preferred-challenges dns`，配合 DNS 服务商的插件） |
| 测试时反复申请，被 Let's Encrypt 限流 | 同一域名每周的申请次数有限制 | 测试时加 `--staging` 用测试环境 |

### 5. 一句话总结

`sudo certbot --nginx -d 域名` 一步上 HTTPS，`renew --dry-run` 确认能自动续期。

## 230 ★&nbsp;&nbsp;aa-status：查看 AppArmor 状态

> 级别：★ 高级 · 软件包：`apparmor`（`aa-status`）

### 1. 作用

AppArmor 是 Ubuntu 默认启用的强制访问控制（MAC）系统：给每个程序一份“配置文件”（profile），规定它只能读写哪些文件、能使用哪些能力。即使程序被攻破，攻击者也只能在这个范围内活动。和传统的文件权限不同，它即使对 root 运行的程序也有效。

`aa-status`（也可以写成 `apparmor_status`）显示加载了多少 profile、每个 profile 处于什么模式、哪些进程受到了限制。

### 2. 基本格式

```bash
sudo aa-status
```

### 3. 读懂输出

输出分几部分：

| 部分 | 含义 |
|---|---|
| `N profiles are loaded` | 加载了多少个 profile |
| `N profiles are in enforce mode` | 强制模式：违规的操作被**拒绝**并记录 |
| `N profiles are in complain mode` | 告警模式：违规的操作**允许**，只记录日志 |
| `N processes are in enforce mode` | 正在受限制的进程 |

profile 文件放在 `/etc/apparmor.d/`：

```
$ ls /etc/apparmor.d/ | head -8
1password
Discord
MongoDB_Compass
QtWebEngineProcess
Xorg
abi
abstractions
alsamixer
```

> ⚠️ aa-status 的输出未实机验证：测试环境的容器里没有 AppArmor，aa-status 输出 `apparmor not present.`。

### 4. 排查“权限明明够，程序却被拒绝”

```bash
sudo journalctl -k | grep -i apparmor | grep DENIED
```

日志里会写明是哪个 profile、拒绝了对哪个文件的什么操作。例如把 MySQL 的数据目录挪到 /data 后启动失败，就是 AppArmor 不允许 mysqld 访问新目录，需要修改它的 profile，或用 [aa-complain](#cmd-aa-complain) 临时改成告警模式确认问题。

### 5. 一句话总结

`sudo aa-status` 看 AppArmor，程序莫名被拒就搜内核日志里的 `apparmor="DENIED"`。

## 231 ★&nbsp;&nbsp;aa-complain：把 AppArmor 配置切换为告警模式

> 级别：★ 高级 · 软件包：`apparmor-utils`

### 1. 作用

`aa-complain` 把某个程序的 AppArmor profile 从强制模式切换为告警模式：违规的操作不再被拒绝，只记录到日志。用来**确认问题是不是 AppArmor 引起的**，以及收集程序实际需要哪些权限，以便修改 profile。

配套的命令：

| 命令 | 作用 |
|---|---|
| `aa-complain 程序或profile` | 切换为告警模式 |
| `aa-enforce 程序或profile` | 切换回强制模式 |
| `aa-disable 程序或profile` | 完全停用这个 profile |
| `aa-logprof` | 根据日志里的违规记录，交互式地更新 profile |

### 2. 常用示例

```bash
sudo aa-complain /usr/sbin/mysqld
sudo systemctl restart mysql          # 现在能启动了，说明问题出在 AppArmor
sudo journalctl -k | grep ALLOWED     # 看看它需要哪些额外的权限
# 把需要的路径加进 /etc/apparmor.d/local/usr.sbin.mysqld，例如：
#   /data/mysql/ r,
#   /data/mysql/** rwk,
sudo apparmor_parser -r /etc/apparmor.d/usr.sbin.mysqld
sudo aa-enforce /usr/sbin/mysqld      # 改好后恢复强制模式
```

自定义的规则写在 `/etc/apparmor.d/local/` 下的同名文件里，软件包升级时不会被覆盖。

> ⚠️ 本页未实机验证：测试环境的容器里没有 AppArmor。

### 3. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 为了省事把 profile 一直留在 complain 模式甚至直接 disable | 等于关掉了这层保护 | 定位问题后修改 profile，再 `aa-enforce` 恢复 |

### 4. 一句话总结

怀疑 AppArmor 挡了程序就 `aa-complain`，改好 profile 后一定 `aa-enforce` 回去。

## 232 ★&nbsp;&nbsp;auditctl：配置系统审计规则

> 级别：★ 高级 · 软件包：`auditd`（4.1.2）

### 1. 作用

Linux 审计系统（auditd）在内核层面记录指定的事件：谁读写了某个文件、谁执行了某个命令、谁修改了系统时间、谁登录了。记录到 `/var/log/audit/audit.log`，root 也无法悄悄绕过。等保、金融行业的合规检查经常要求开启。`auditctl` 用来添加、查看、删除审计规则，查询记录用 [ausearch](#cmd-ausearch)。

### 2. 常用参数

| 参数 | 作用 |
|---|---|
| `-l` | 列出当前规则 |
| `-w 路径 -p 权限 -k 关键字` | 监视一个文件或目录，权限 `r` 读、`w` 写、`x` 执行、`a` 属性变化 |
| `-a always,exit -F arch=b64 -S 系统调用 -k 关键字` | 按系统调用记录 |
| `-D` | 删除全部规则 |
| `-s` | 审计系统的状态 |

`-k` 给规则起一个关键字，查询时按关键字过滤。

### 3. 常用示例

```bash
sudo auditctl -w /etc/passwd -p wa -k user-change       # 谁改了用户文件
sudo auditctl -w /etc/sudoers -p wa -k sudo-change
sudo auditctl -w /data/finance -p rwa -k finance        # 谁访问了财务目录
sudo auditctl -l
```

用 auditctl 加的规则重启后会丢失，永久规则写进 `/etc/audit/rules.d/` 下的 `.rules` 文件，然后执行 `sudo augenrules --load`。

```
$ auditctl -v
auditctl version 4.1.2
```

> ⚠️ 本页未实机验证：测试环境的容器不能使用内核审计功能，auditctl 报 `There was an error while processing parameters`。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 审计日志增长太快，磁盘吃紧 | 监视了访问很频繁的目录，或者对 `read` 等高频系统调用做了审计 | 只监视关键文件，只记录写操作；在 `/etc/audit/auditd.conf` 里设置日志大小和轮转 |

### 5. 一句话总结

关键文件被谁改了：`sudo auditctl -w 文件 -p wa -k 关键字`，永久规则写进 rules.d。

## 233 ★&nbsp;&nbsp;ausearch：搜索审计日志

> 级别：★ 高级 · 软件包：`auditd`

### 1. 作用

`ausearch` 按条件查询审计日志：关键字、事件类型、用户、时间、成功还是失败。原始的 audit.log 一条记录很长、时间是时间戳、用户是数字，ausearch 加 `-i` 能把它们翻译成人能读的格式。

### 2. 常用参数

| 参数 | 作用 |
|---|---|
| `-k 关键字` | 按 auditctl 设置的关键字查 |
| `-m 类型` | 按事件类型查，如 `USER_LOGIN`、`EXECVE`、`USER_CMD` |
| `-ua 用户` | 按用户查 |
| `--success no` | 只看失败的 |
| `-ts 开始时间` | 如 `-ts today`、`-ts recent`（最近 10 分钟）、`-ts 10/29/26 08:00:00` |
| `-i` | 把数字翻译成用户名、日期等 |
| `-if 文件` | 查询指定的日志文件 |

另一个工具 `aureport` 可以生成汇总报表（如 `aureport -au` 认证报表）。

### 3. 常用示例

下面用一份手工构造的两条登录记录演示（一条成功、一条失败）：

只看失败的登录：

```
$ ausearch -if /tmp/audit.log -m USER_LOGIN --success no
----
time->Thu Oct 29 08:38:20 2026
type=USER_LOGIN msg=audit(1793263100.456:102): pid=1240 uid=0 auid=4294967295 ses=4294967295 msg='op=login acct="root" exe="/usr/sbin/sshd" hostname=? addr=203.0.113.9 terminal=sshd res=failed'
```

`-i` 翻译后更易读：

```
$ ausearch -if /tmp/audit.log -m USER_LOGIN -i
----
type=USER_LOGIN msg=audit(10/29/26 08:36:40.123:101) : pid=1234 uid=root auid=tom ses=3 msg='op=login acct=tom exe=/usr/sbin/sshd hostname=? addr=192.168.1.50 terminal=sshd res=success'
----
type=USER_LOGIN msg=audit(10/29/26 08:38:20.456:102) : pid=1240 uid=root auid=unset ses=unset msg='op=login acct=root exe=/usr/sbin/sshd hostname=? addr=203.0.113.9 terminal=sshd res=failed'
```

`auid` 是“最初登录的用户”：即使后来 sudo 成了 root，auid 仍然记录是谁，审计时靠它追溯到人。

实际使用时不写 `-if`，默认查询 /var/log/audit/：

```bash
sudo ausearch -k user-change -i -ts today
```

### 4. 一句话总结

`sudo ausearch -k 关键字 -i -ts today` 查审计记录，看 auid 找到真正操作的人。

## 234 ★&nbsp;&nbsp;fail2ban-client：防暴力破解

> 级别：★ 高级 · 软件包：`fail2ban`（1.1.0）

### 1. 作用

暴露在公网的 ssh 每天会被扫描、尝试登录成千上万次。fail2ban 盯着日志，一个 IP 在短时间内失败次数过多，就自动用防火墙封禁它一段时间。`fail2ban-client` 用来查看封禁状态、手动封禁或解封。

fail2ban 按“监狱”（jail）组织：每个 jail 对应一个服务（sshd、nginx 等），规定盯哪份日志、失败几次封禁、封多久。

### 2. 常用命令

| 命令 | 作用 |
|---|---|
| `fail2ban-client status` | 启用了哪些 jail |
| `fail2ban-client status sshd` | sshd 的失败次数、当前封禁的 IP |
| `fail2ban-client set sshd unbanip IP` | 解封 |
| `fail2ban-client set sshd banip IP` | 手动封禁 |
| `fail2ban-client reload` | 修改配置后重新加载 |

### 3. 配置

Ubuntu 安装后默认启用了 sshd 的保护：

```
$ cat /etc/fail2ban/jail.d/defaults-debian.conf
[DEFAULT]
banaction = nftables
banaction_allports = nftables[type=allports]

[sshd]
backend = systemd
journalmatch = _SYSTEMD_UNIT=ssh.service + _COMM=sshd
enabled = true

$ grep -E "^(bantime|findtime|maxretry) " /etc/fail2ban/jail.conf
bantime  = 10m
findtime  = 10m
maxretry = 5
```

默认规则：10 分钟内失败 5 次，封禁 10 分钟。要修改，**不要改 jail.conf**（升级时会被覆盖），在 `/etc/fail2ban/jail.local` 里写：

```ini
[sshd]
maxretry = 3
bantime = 1h
ignoreip = 127.0.0.1/8 192.168.1.0/24
```

`ignoreip` 是白名单，公司内网写进去，免得自己人输错几次密码被封。

### 4. 常用示例

```bash
sudo systemctl enable --now fail2ban
sudo fail2ban-client status sshd
sudo fail2ban-client set sshd unbanip 192.168.1.50
```

`status sshd` 的输出里，`Currently failed` 是当前计数中的失败次数，`Banned IP list` 是被封禁的 IP。

> ⚠️ status 和封禁操作未实机验证：测试环境没有运行 fail2ban 服务（`Failed to access socket path: /var/run/fail2ban/fail2ban.sock. Is fail2ban running?`）。配置文件内容为实测。

### 5. 一句话总结

公网 ssh 一定装 fail2ban，`status sshd` 看封禁，自己的网段加进 `ignoreip`。

## 235 ★&nbsp;&nbsp;nmap：端口扫描（仅限自有或已授权的主机）

> 级别：★ 高级 · 软件包：`nmap`（7.98）

### 1. 作用

`nmap` 扫描主机开放了哪些端口、端口上运行的是什么服务和版本。运维用它**检查自己的服务器**：防火墙配置完后，从外面扫一遍，确认只开放了该开放的端口；上线前确认没有遗漏的测试服务暴露在外。

> **只扫描你自己管理的、或者获得书面授权的主机和网络。** 未经授权扫描他人的系统，在多数国家和地区属于违法行为，也违反云服务商的使用条款。

### 2. 常用参数

| 参数 | 作用 |
|---|---|
| （不加） | 扫描最常用的 1000 个 TCP 端口 |
| `-p 端口` | 指定端口，如 `-p 22,80,443`、`-p 1-1024`、`-p-`（全部） |
| `-sV` | 识别服务和版本 |
| `-sn` | 只检测主机是否在线，不扫端口 |
| `-Pn` | 不先 ping，直接扫（对方禁 ping 时用） |
| `-T4` | 加快速度 |

### 3. 常用示例

以下在独立的网络环境里扫描本机（本机运行着 sshd 和一个 8080 端口的网页服务）。

```
$ nmap 127.0.0.1
Starting Nmap 7.98 ( https://nmap.org ) at 2026-10-29 10:14 +0000
Nmap scan report for localhost (127.0.0.1)
Host is up (0.0000010s latency).
Not shown: 998 closed tcp ports (reset)
PORT     STATE SERVICE
22/tcp   open  ssh
8080/tcp open  http-proxy

Nmap done: 1 IP address (1 host up) scanned in 0.23 seconds

$ nmap -p 22,80,443,8080 127.0.0.1
...
PORT     STATE  SERVICE
22/tcp   open   ssh
80/tcp   closed http
443/tcp  closed https
8080/tcp open   http-proxy
```

| STATE | 含义 |
|---|---|
| open | 有服务在监听 |
| closed | 主机可达，端口没有服务 |
| filtered | 被防火墙拦截，不知道有没有服务 |

`SERVICE` 一列只是按端口号猜的名称（8080 被猜成 http-proxy），要知道真实的服务用 `-sV`：

```
$ nmap -sV -p 22,8080 127.0.0.1
PORT     STATE SERVICE VERSION
22/tcp   open  ssh     OpenSSH 10.2p1 Ubuntu 2ubuntu3.8 (Ubuntu Linux; protocol 2.0)
8080/tcp open  http    SimpleHTTPServer 0.6 (Python 3.14.4)
```

检查自己服务器从公网能看到什么，要在**另一台外部机器**上扫描服务器的公网 IP，在服务器本机上扫看到的结果不包括防火墙的效果。

### 4. 一句话总结

防火墙配好后，从外部 `nmap -sV 自己的服务器`，确认只有该开的端口是 open。
