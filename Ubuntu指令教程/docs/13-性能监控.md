## 148 ★★&nbsp;&nbsp;vmstat：内存、CPU、IO 的整体统计

> 级别：★★ 中级 · 软件包：`procps`（procps-ng 4.0.4）

### 1. 作用

`vmstat`（virtual memory statistics）每隔几秒输出一行系统整体的统计：有多少进程在等 CPU、内存和 swap 的使用、磁盘读写量、CPU 时间花在了哪里。和 top 不同，它不看单个进程，而是连续输出数字，适合观察一段时间内的变化趋势，判断瓶颈是在 CPU、内存还是磁盘。

### 2. 基本格式

```bash
vmstat [间隔秒数 [次数]]
```

不加参数只输出一行，是**开机以来的平均值**，意义不大；一般写 `vmstat 1 5`（每秒一行，共 5 行）。

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `间隔 次数` | 每隔几秒输出一次，共几次 |
| `-w` | 宽格式，数字大时列不会挤在一起 |
| `-s` | 输出内存等计数器的汇总 |
| `-S M` | 内存单位用 MB |

### 4. 常用示例

> 以下输出来自测试环境（8 核、32 GB 内存）。

```
$ vmstat 1 3
procs -----------memory---------- ---swap-- -----io---- -system-- -------cpu-------
 r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st gu
 1  0      0 19756704 169588 10026128    0    0   138  1136 4412    8  1  2 96  0  0  0
 0  0      0 19767656 169600 10026536    0    0     0    80 4428 6956  2  3 95  0  0  0
 0  0      0 19767152 169600 10026480    0    0     0     4 3949 6384  1  2 98  0  0  0
```

第一行是开机以来的平均值，从第二行开始才是每秒的实时数据。

| 列 | 含义 | 什么时候需要注意 |
|---|---|---|
| r | 正在运行和等待 CPU 的进程数 | 长期大于 CPU 核数，CPU 不够用 |
| b | 等待 IO 的进程数 | 长期大于 0，磁盘跟不上 |
| swpd / free / buff / cache | swap 已用量、空闲内存、缓冲、缓存（KB） | |
| si / so | 每秒从 swap 换入 / 换出的量 | 持续不为 0，内存不够了 |
| bi / bo | 每秒从磁盘读入 / 写出的块数 | |
| us / sy / id / wa | CPU 时间：用户程序 / 内核 / 空闲 / 等待 IO 的百分比 | wa 高说明瓶颈在磁盘 |

宽格式更容易看清：

```
$ vmstat -w 1 2
--procs-- -----------------------memory---------------------- ---swap-- -----io---- -system-- ----------cpu----------
   r    b         swpd         free         buff        cache   si   so    bi    bo   in   cs  us  sy  id  wa  st  gu
   0    0            0     19767152       169600     10026480    0    0   138  1136 4412    8   1   2  96   0   0   0
   0    0            0     19771996       169600     10026456    0    0     0     0 5850 9350   3   2  96   0   0   0
```

### 5. 一句话总结

`vmstat 1 5` 看趋势：r 高缺 CPU，si/so 不为 0 缺内存，wa 高是磁盘慢。

## 149 ★★&nbsp;&nbsp;iostat：磁盘 IO 统计

> 级别：★★ 中级 · 软件包：`sysstat`（12.7.7，需 `sudo apt install sysstat`）

### 1. 作用

`iostat` 按磁盘统计读写的次数、速度、等待时间和繁忙程度。vmstat 或 top 显示 `wa`（IO 等待）很高时，用 iostat 找出是哪块磁盘忙、忙到什么程度。

### 2. 基本格式

```bash
iostat [参数] [间隔 [次数]]
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-x` | 扩展统计（包含等待时间、繁忙程度） |
| `-d` | 只显示磁盘，不显示 CPU |
| `-h` | 用 K、M、G 显示 |
| `-m` | 以 MB 为单位 |
| `间隔 次数` | 和 vmstat 一样 |

### 4. 常用示例

> 以下输出来自测试环境。

```
$ iostat
Linux 6.1.188-233.393.amzn2023.x86_64 (ubuntu) 	10/29/26 	_x86_64_	(8 CPU)

avg-cpu:  %user   %nice %system %iowait  %steal   %idle
           1.28    0.00    2.10    0.22    0.01   96.39

Device             tps    kB_read/s    kB_wrtn/s    kB_dscd/s    kB_read    kB_wrtn    kB_dscd
loop0             0.01         0.20         0.18         0.00       2194       2067          0
loop1             7.96         0.29       244.98         0.00       3298    2746113          0
nvme0n1           5.02        76.30       591.41         0.00     855271    6629508          0
nvme1n1           8.99        61.97       299.89         0.00     694709    3361708          0
```

和 vmstat 一样，不带间隔时显示的是开机以来的平均值。排查问题用 `iostat -x 1 5`，在扩展统计里重点看：

| 列 | 含义 | 什么时候需要注意 |
|---|---|---|
| r/s、w/s | 每秒读、写次数（IOPS） | |
| rkB/s、wkB/s | 每秒读、写的数据量 | |
| r_await、w_await | 每次读、写平均等待多少毫秒 | 机械硬盘超过 20 ms、SSD 超过 5 ms 说明很慢 |
| aqu-sz | 平均排队的请求数 | 持续大于 1 说明有排队 |
| %util | 磁盘忙的时间占比 | 接近 100% 说明磁盘满负荷 |

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `iostat: command not found` | 没装 sysstat | `sudo apt install sysstat` |
| NVMe 固态硬盘的 %util 到了 100%，但延迟仍然很低 | SSD 能同时处理很多请求，%util 只表示“一直有请求”，不代表达到上限 | SSD 主要看 await 和 aqu-sz |

### 6. 一句话总结

IO 等待高时 `iostat -x 1 5`，看 await 和 %util 找出慢的那块盘。

## 197 ★★&nbsp;&nbsp;iotop：按进程查看磁盘读写

> 级别：★★ 中级 · 软件包：`iotop`（需 `sudo apt install iotop`）

### 1. 作用

`iotop` 和 top 类似，只不过排序依据是**磁盘读写速度**：哪个进程正在大量读写磁盘，一眼就能看出来。iostat 告诉你“哪块盘忙”，iotop 告诉你“是谁让它忙的”。

需要 sudo。

### 2. 基本格式

```bash
sudo iotop [参数]
```

### 3. 常用参数和按键

| 参数 | 作用 |
|---|---|
| `-o` | 只显示正在读写的进程 |
| `-P` | 按进程显示（默认按线程） |
| `-a` | 显示累计的读写量，而不是速度 |
| `-b -n 次数` | 批处理模式，输出几次就退出 |

| 按键 | 作用 |
|---|---|
| `o` | 切换是否只显示正在读写的 |
| `a` | 切换速度 / 累计量 |
| `←` `→` | 选择排序列 |
| `q` | 退出 |

### 4. 常用示例

```bash
sudo iotop -o -P
```

批处理模式的输出（测试环境，几乎没有读写）：

```
$ sudo iotop -b -n 1 | head -3
Total DISK READ:         0.00 B/s | Total DISK WRITE:         0.00 B/s
Current DISK READ:       0.00 B/s | Current DISK WRITE:       0.00 B/s
    TID  PRIO  USER     DISK READ  DISK WRITE  SWAPIN      IO    COMMAND
```

| 列 | 含义 |
|---|---|
| DISK READ / DISK WRITE | 这个进程的读、写速度 |
| IO | 这个进程等待 IO 的时间占比 |
| PRIO | IO 优先级，可以用 `ionice` 调整 |

> ⚠️ 全屏界面未实机验证。

### 5. 一句话总结

磁盘忙找元凶用 `sudo iotop -o -P`。
