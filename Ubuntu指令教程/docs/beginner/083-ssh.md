# 083 ssh：远程登录服务器

> 级别：初级 · 软件包：`openssh-client`（Ubuntu 26.04 为 OpenSSH 10.2）

## 1. 作用

`ssh`（Secure Shell）通过加密连接登录到远程 Linux 服务器，在本机终端里操作远程机器，就像坐在它面前一样。也可以不登录，直接在远程机器上执行一条命令并把结果拿回来。

管理服务器的日常工作几乎都从 ssh 开始。

## 2. 基本格式

```bash
ssh [参数] 用户名@主机 [要执行的命令]
```

不写命令时进入远程的交互式终端，输入 `exit` 退出。

## 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-p 端口` | 指定端口，默认 22 |
| `-i 私钥文件` | 指定用哪个私钥登录 |
| `-o 选项=值` | 临时设置一个配置项，如 `-o ConnectTimeout=5` |
| `-L 本地端口:目标:目标端口` | 本地端口转发（把远程的数据库端口映射到本机） |
| `-J 跳板机` | 通过跳板机连接 |
| `-v` | 显示详细的连接过程，排查连不上的问题 |

## 4. 常用示例

测试环境在本机 2222 端口运行了一个 sshd 来演示，真实场景里把 `127.0.0.1 -p 2222` 换成服务器的 IP 即可。

### 4.1 第一次连接

第一次连接某台服务器时，ssh 会显示对方的主机密钥指纹，问你是否信任：

```
The authenticity of host '[127.0.0.1]:2222 ([127.0.0.1]:2222)' can't be established.
ED25519 key fingerprint is SHA256:...
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

输入 `yes` 后，指纹被记进 `~/.ssh/known_hosts`，以后不再询问。

> ⚠️ 上面这段提示未实机录制（需要真实终端交互），为 OpenSSH 的标准提示。

不想交互确认时，可以让 ssh 自动接受新主机：

```
$ ssh -p 2222 -o StrictHostKeyChecking=accept-new tom@127.0.0.1 "hostname; whoami; uptime -p"
Warning: Permanently added '[127.0.0.1]:2222' (ED25519) to the list of known hosts.
ubuntu
tom
up 1 hour, 34 minutes
```

### 4.2 远程执行一条命令

```
$ ssh -p 2222 tom@127.0.0.1 "df -h /home | tail -1"
tmpfs            16G  2.5M   16G   1% /home
```

命令用引号括起来，管道 `|` 就会在远程执行。巡检多台服务器的磁盘时，写个循环逐台执行即可。

### 4.3 免密码登录：密钥

```bash
ssh-keygen -t ed25519          # 在本机生成密钥对，一路回车
ssh-copy-id tom@192.168.1.10   # 把公钥装到服务器上，这一次需要输入密码
ssh tom@192.168.1.10           # 以后不再需要密码
```

生成的文件：

```
$ ls -l ~/.ssh
total 12
-rw------- 1 tom tom  92 Oct 29 07:09 authorized_keys
-rw------- 1 tom tom 399 Oct 29 07:09 id_ed25519
-rw-r--r-- 1 tom tom  92 Oct 29 07:09 id_ed25519.pub
```

| 文件 | 内容 | 能不能给别人 |
|---|---|---|
| `id_ed25519` | 私钥 | **绝对不能**，权限必须是 600 |
| `id_ed25519.pub` | 公钥 | 可以，装到要登录的服务器上 |
| `authorized_keys` | 服务器上：允许哪些公钥登录 | |
| `known_hosts` | 本机：信任过哪些服务器 | |

### 4.4 `~/.ssh/config`：给服务器起简称

```
Host db01
    HostName 127.0.0.1
    Port 2222
    User tom
```

写进 `~/.ssh/config` 后：

```
$ ssh db01 hostname
ubuntu
```

服务器多、端口不统一时，config 文件能省很多事。scp 也认这个简称。

### 4.5 把远程数据库端口映射到本机

```bash
ssh -L 15432:127.0.0.1:5432 tom@db01
```

保持这个连接，本机的数据库客户端连 `127.0.0.1:15432`，就相当于连到了 db01 上只监听本地的 5432 端口。数据库不用对外开放端口。

## 5. 常见报错

```
$ ssh -p 2222 -o ConnectTimeout=3 tom@10.255.255.1
ssh: connect to host 10.255.255.1 port 2222: Connection timed out

$ ssh -p 2223 tom@127.0.0.1
ssh: connect to host 127.0.0.1 port 2223: Connection refused

$ ssh -p 2222 -o BatchMode=yes nobody@127.0.0.1
nobody@127.0.0.1: Permission denied (publickey).
```

| 报错 | 含义 | 排查方向 |
|---|---|---|
| `Connection timed out` | 网络不通，或被防火墙丢弃 | IP 是否正确；云服务器安全组是否放行该端口 |
| `Connection refused` | 主机在线，但这个端口上没有 ssh 服务 | 端口号是否正确；服务器上 ssh 是否在运行 |
| `Permission denied (publickey)` | 认证失败，服务器只接受密钥 | 用户名、私钥是否正确；用 `ssh -v` 看尝试了哪些密钥 |

## 6. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 出现一大块 `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!`，拒绝连接 | 服务器的主机密钥变了：重装了系统、换了机器，**也可能是被中间人攻击** | 确认服务器确实重装过之后，执行提示里给出的 `ssh-keygen -R 主机` 删除旧记录，再重新连接 |
| 私钥被拒绝，提示 `UNPROTECTED PRIVATE KEY FILE!` | 私钥文件权限太宽 | `chmod 600 ~/.ssh/id_ed25519` |
| ssh 连上后一段时间不操作就断开 | 中间的防火墙或路由器断开了空闲连接 | 在 `~/.ssh/config` 里加 `ServerAliveInterval 60` |
| 修改服务器的 ssh 端口后，新端口连不上 | Ubuntu 26.04 的 ssh 默认由 ssh.socket 监听端口，只改 sshd_config 不够 | 见 [systemctl](066-systemctl.md) 4.4 |

## 7. 一句话总结

`ssh 用户@主机` 登录，用密钥免密，常用服务器写进 `~/.ssh/config`。
