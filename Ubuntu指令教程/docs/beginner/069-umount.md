# 069 umount：卸载磁盘和分区

> 级别：初级 · 软件包：`mount`

## 1. 作用

`umount`（注意没有 n，不是 unmount）把挂载的设备从目录树上卸下来。拔 U 盘、移除硬盘、对分区做检查或调整大小之前，都要先卸载，否则可能丢数据。

## 2. 基本格式

```bash
sudo umount 挂载点或设备
```

写挂载点（`/data`）或设备名（`/dev/sdb1`）都可以。

## 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-l` | 懒卸载：先从目录树上摘下来，等没人使用了再真正卸载 |
| `-f` | 强制卸载（主要用于连不上的网络共享） |
| `-R` | 递归卸载这个目录及其下面的所有挂载 |

## 4. 常用示例

```bash
sudo umount /data
sudo umount /dev/sdc1
```

卸载成功不会有任何输出。用 `df -h` 或 `lsblk` 确认它已经不在了。

> ⚠️ 本页未实机验证：测试环境的容器不允许挂载和卸载设备。命令写法为长期稳定的标准用法。

## 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `umount: /data: target is busy.` | 有进程正在使用里面的文件，或者某个终端的当前目录就在里面 | 先 `cd ~` 离开；用 `sudo lsof +D /data` 或 `sudo fuser -vm /data` 找出占用的进程 |
| 拔掉 U 盘后，拷进去的文件不完整 | 写入的数据还在内存缓存里，没写进 U 盘 | 一定先 `umount`，它会把缓存写完再卸载 |
| 普通用户执行报 `umount: /home: must be superuser to unmount.` | 卸载需要 root | 加 `sudo` |
| 网络共享断了，umount 一直卡住 | 系统在等待服务器响应 | `sudo umount -f` 或 `-l` |

## 6. 一句话总结

拔盘之前先 `sudo umount 挂载点`，提示 busy 就先离开目录、找出占用的进程。
