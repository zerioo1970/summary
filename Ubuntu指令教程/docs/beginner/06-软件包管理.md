## 012 apt：安装、升级、卸载软件

> 级别：初级 · 软件包：`apt`（Ubuntu 26.04 自带 3.2 版）

### 1. 作用

`apt` 是 Ubuntu 的软件包管理工具。它从 Ubuntu 官方软件源下载软件，自动处理依赖关系（装 A 需要先装 B、C，apt 会一起装好）。装软件、打补丁、卸载软件，都用 apt。

软件源的地址写在 `/etc/apt/sources.list.d/ubuntu.sources` 里。apt 本地保存了一份“软件源里有哪些包、什么版本”的清单，`apt update` 就是刷新这份清单。

### 2. 基本格式

```bash
sudo apt 子命令 [包名...]
```

除了 `search`、`show`、`list` 这类只读查询，其他子命令都要加 sudo。

### 3. 常用子命令

| 子命令 | 作用 |
|---|---|
| `update` | 刷新软件包清单（不安装任何东西） |
| `upgrade` | 把已安装的软件升级到最新版本 |
| `install 包名` | 安装软件 |
| `remove 包名` | 卸载软件，保留配置文件 |
| `purge 包名` | 卸载软件，连配置文件一起删除 |
| `autoremove` | 删除当初作为依赖装进来、现在已经没用的包 |
| `search 关键词` | 搜索软件包 |
| `show 包名` | 查看包的详细信息 |
| `list --installed` | 列出已安装的包 |
| `list --upgradable` | 列出可以升级的包 |

常用参数：

| 参数 | 作用 |
|---|---|
| `-y` | 自动回答“是”，不再询问 |
| `--names-only` | 和 search 一起用，只在包名里搜索 |
| `-s` | 模拟执行，只显示会做什么，不真的执行 |

### 4. 常用示例

> 以下输出在 Ubuntu 26.04.1 实测，软件包版本号和数量会随软件源更新而变化。

#### 4.1 `apt update`：刷新清单

```
$ sudo apt update
Hit:1 http://security.ubuntu.com/ubuntu resolute-security InRelease
Hit:2 http://archive.ubuntu.com/ubuntu resolute InRelease
Hit:3 http://archive.ubuntu.com/ubuntu resolute-updates InRelease
Hit:4 http://archive.ubuntu.com/ubuntu resolute-backports InRelease
Reading package lists...
Building dependency tree...
Reading state information...
20 packages can be upgraded. Run 'apt list --upgradable' to see them.
```

`resolute` 是 Ubuntu 26.04 的代号（Resolute Raccoon）。装软件、升级之前，先执行一次 update。

#### 4.2 `apt list --upgradable`：看哪些可以升级

```
$ apt list --upgradable
Listing...
gnu-coreutils/resolute-updates,resolute-security 9.7-3ubuntu2.1 amd64 [upgradable from: 9.7-3ubuntu2]
gpgv/resolute-updates,resolute-security 2.4.8-4ubuntu3.1 amd64 [upgradable from: 2.4.8-4ubuntu3]
...（共 20 行，此处只列前两行）
```

#### 4.3 `apt install`：安装软件

```
$ sudo apt install cowsay
Solving dependencies...
Upgrading:
  perl-base

Installing:
  cowsay

Installing dependencies:
  libgdbm-compat4t64  libtext-charwidth-perl  perl-modules-5.40
  libperl5.40         perl

Suggested packages:
  filters     libterm-readline-gnu-perl     libtap-harness-archive-perl
  cowsay-off  | libterm-readline-perl-perl
  perl-doc    make

Summary:
  Upgrading: 1, Installing: 6, Removing: 0, Not Upgrading: 19
  Download size: 10.2 MB
  Space needed: 51.5 MB / 91.9 GB available

Continue? [Y/n]
```

apt 3.x 的输出按“升级 / 安装 / 依赖 / 建议”分块显示，最后的 Summary 告诉你一共改动多少包、要下载多少。按回车（默认 Y）开始安装。加 `-y` 就不会停下来询问。

软件已经装过时：

```
$ sudo apt install tree
tree is already the newest version (2.3.1-1).
Solving dependencies...
Summary:
  Upgrading: 0, Installing: 0, Removing: 0, Not Upgrading: 20
```

#### 4.4 `apt search` 和 `apt show`：先查再装

```
$ apt search --names-only "^htop"
Sorting...
Full Text Search...
htop/resolute,now 3.4.1-5build2 amd64 [installed]
  interactive processes viewer

$ apt show tree
Package: tree
Version: 2.3.1-1
Priority: optional
Section: universe/utils
Origin: Ubuntu
...
```

不加 `--names-only` 时，apt 会在包的描述里搜索，结果往往有几百条。

#### 4.5 `remove`、`purge`、`autoremove`：卸载

```
$ sudo apt remove cowsay
Solving dependencies...
The following package was automatically installed and is no longer required:
  libtext-charwidth-perl
Use 'apt autoremove' to remove it.

REMOVING:
  cowsay

Summary:
  Upgrading: 0, Installing: 0, Removing: 1, Not Upgrading: 19
  Freed space: 89.1 kB

$ sudo apt autoremove
REMOVING:
  libtext-charwidth-perl

Summary:
  Upgrading: 0, Installing: 0, Removing: 1, Not Upgrading: 19
  Freed space: 43.0 kB
```

remove 只删程序，`/etc` 下的配置文件还在，重装后配置不丢。要彻底清除用 `sudo apt purge 包名`。

#### 4.6 日常打补丁

```bash
sudo apt update && sudo apt upgrade
```

`&&` 表示前一条成功了才执行后一条。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `Error: Unable to locate package xxx` | 包名写错，或者还没执行过 `apt update` | 先 `sudo apt update`，再用 `apt search` 查准包名 |
| 在脚本里用 apt，输出多了一行 `WARNING: apt does not have a stable CLI interface. Use with caution in scripts.` | apt 的输出格式面向人，可能随版本变化 | 脚本里改用 [apt-get](#cmd-apt-get)，例如 `sudo apt-get install -y 包名` |
| 报 `Could not get lock /var/lib/dpkg/lock-frontend` | 另一个 apt 进程（常见的是开机后的自动更新）正在运行 | 等几分钟再试。不要删除锁文件 |
| 卸载后重装，软件还是用旧配置 | `remove` 保留了配置文件 | 想恢复默认配置，用 `purge` 卸载后再装 |
| `Error: Unable to acquire the dpkg frontend lock (/var/lib/dpkg/lock-frontend), are you root?` | 安装、卸载需要管理员权限，普通用户打不开锁文件 | 加 `sudo` |

### 6. 一句话总结

先 `update` 再 `install`；`remove` 留配置、`purge` 全删；脚本里用 `apt-get`。

## 063 apt-get：脚本里用的软件包管理命令

> 级别：初级 · 软件包：`apt`

### 1. 作用

`apt-get` 和 [apt](#cmd-apt) 做的是同一件事：安装、升级、卸载软件。区别在于用途：

| | apt | apt-get |
|---|---|---|
| 面向 | 人在终端里操作 | 脚本、自动化部署、Dockerfile |
| 输出 | 有颜色、进度条，格式可能随版本调整 | 格式稳定，多年不变 |
| 在脚本里用 | 会提示 `WARNING: apt does not have a stable CLI interface` | 不会提示 |

日常手动操作用 apt，写进脚本的一律用 apt-get。

### 2. 基本格式

```bash
sudo apt-get [参数] 子命令 [包名...]
```

### 3. 常用子命令和参数

| 子命令 | 作用 |
|---|---|
| `update` | 刷新软件包清单 |
| `upgrade` | 升级已安装的包 |
| `install 包名` | 安装 |
| `remove 包名` | 卸载，保留配置 |
| `purge 包名` | 卸载，删除配置 |
| `autoremove` | 删除不再需要的依赖 |
| `clean` | 清空已下载的安装包缓存（/var/cache/apt/archives） |
| `download 包名` | 只下载 .deb 文件到当前目录，不安装 |

| 参数 | 作用 |
|---|---|
| `-y` | 自动回答“是” |
| `-q` / `-qq` | 减少输出 / 几乎不输出 |
| `--no-install-recommends` | 不安装“推荐”的附加包，只装必需的依赖 |
| `-s` | 模拟执行 |

### 4. 常用示例

以下以 root 身份执行（普通用户加 sudo）。

#### 4.1 脚本里的标准写法

```bash
sudo apt-get update
sudo DEBIAN_FRONTEND=noninteractive apt-get install -y -q nginx
```

`DEBIAN_FRONTEND=noninteractive` 让安装过程中不弹出任何配置问答，全部用默认值。自动化脚本里不加它，遇到需要回答问题的包就会卡住。

#### 4.2 `--no-install-recommends`：装得更少

```
$ apt-get install -y --no-install-recommends -q fortune-mod
...
The following additional packages will be installed:
  librecode3
Recommended packages:
  fortunes-min | fortune-cookie-db
The following NEW packages will be installed:
  fortune-mod librecode3
```

“推荐”的包（Recommended）没有装。做 Docker 镜像、精简服务器时常用这个参数控制体积。

#### 4.3 `download`：只下载安装包

```
$ apt-get download tree
Get:1 http://archive.ubuntu.com/ubuntu resolute/universe amd64 tree amd64 2.3.1-1 [53.5 kB]
Fetched 53.5 kB in 0s (166 kB/s)

$ ls *.deb
tree_2.3.1-1_amd64.deb
```

给不能上网的内网服务器装软件时，先在能上网的机器上下载，再拷过去用 [dpkg](#cmd-dpkg) 安装。

#### 4.4 `clean`：释放缓存空间

```
$ apt-get clean; ls /var/cache/apt/archives
lock
partial
```

下载过的 .deb 文件都被删除了。/var 分区紧张时可以清一下。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 脚本执行到 apt-get install 就停住不动 | 等待输入 `Y`，或者弹出了配置问答 | 加 `-y`，并设置 `DEBIAN_FRONTEND=noninteractive` |
| Dockerfile 里 `apt-get install` 报找不到包 | 镜像里的软件包清单是空的 | 在同一个 RUN 里先 `apt-get update`：`RUN apt-get update && apt-get install -y 包名` |
| 自动化安装时输出一大段 `debconf: unable to initialize frontend: Dialog` | 没有终端，debconf 尝试几种问答界面都失败，最后改用默认值 | 这些是提示不是错误；加 `DEBIAN_FRONTEND=noninteractive` 就不会出现 |

### 6. 一句话总结

脚本里用 `apt-get install -y`，配上 `DEBIAN_FRONTEND=noninteractive`。

## 064 dpkg：安装和查询 .deb 包

> 级别：初级 · 软件包：`dpkg`

### 1. 作用

`dpkg` 是 Ubuntu 最底层的软件包工具，apt 在下载完安装包之后，实际就是调用 dpkg 来安装的。日常用 dpkg 做两类事：

- 安装从网上下载的单个 `.deb` 文件（比如某些厂商提供的客户端）；
- 查询：装了哪些包、某个包装了哪些文件、某个文件属于哪个包。

dpkg 不会自动下载依赖，这是它和 apt 最大的区别。

### 2. 基本格式

```bash
sudo dpkg -i 文件.deb       # 安装
dpkg -l [包名]              # 查询
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-i 文件.deb` | 安装 |
| `-r 包名` | 卸载，保留配置 |
| `-P 包名` | 卸载并删除配置 |
| `-l [模式]` | 列出已安装的包 |
| `-s 包名` | 查看包的状态和详情 |
| `-L 包名` | 列出这个包装了哪些文件 |
| `-S 文件路径` | 查这个文件属于哪个包 |
| `-c 文件.deb` | 查看 .deb 文件里有什么（不安装） |

### 4. 常用示例

以下以 root 身份执行；只查询的命令普通用户也能执行。

#### 4.1 `-l`：查是否装了某个包

```
$ dpkg -l tree htop
+-- Desired=Unknown/Install/Remove/Purge/Hold
|+- Status=Not/Inst/Conf-files/Unpacked/halF-conf/Half-inst/trig-aWait/Trig-pend
||+ Err?=(none)/Reinst-required (Status,Err: uppercase=bad)
||| Name           Version       Architecture Description
+++-==============-=============-============-=============================================
ii  htop           3.4.1-5build2 amd64        interactive processes viewer
ii  tree           2.3.1-1       amd64        displays an indented directory tree, in color
```

第一列的 `ii` 表示“期望安装，已经安装”，是正常状态。`rc` 表示已卸载但配置文件还在。

#### 4.2 `-l` 加通配符

```
$ dpkg -l "*coreutils*"
...
||| Name                  Version                     Architecture Description
+++-=====================-===========================-============-==========================================
ii  coreutils             9.5-1ubuntu2+0.0.0~ubuntu25 all          coreutils meta package
un  coreutils-from        <none>                      <none>       (no description available)
un  coreutils-from-gnu    <none>                      <none>       (no description available)
ii  coreutils-from-uutils 0.0.0~ubuntu25              all          coreutils from the uutils project
ii  gnu-coreutils         9.7-3ubuntu2.1              amd64        GNU core utilities
ii  rust-coreutils        0.10.0-1ubuntu2~26.04.1     amd64        Universal coreutils utils, written in Rust
```

从这里可以看出：Ubuntu 26.04 的基础命令默认来自 Rust 版（`coreutils-from-uutils`、`rust-coreutils`），GNU 版（`gnu-coreutils`）也装着。

#### 4.3 `-S`：这个文件是哪个包装的

```
$ dpkg -S /usr/bin/tree
tree: /usr/bin/tree

$ dpkg -S /usr/bin/ls
coreutils-from-uutils: /usr/bin/ls
```

#### 4.4 `-L`：这个包装了哪些文件

```
$ dpkg -L tree | head -6
/.
/usr
/usr/bin
/usr/bin/tree
/usr/share
/usr/share/doc
```

装完一个软件不知道配置文件在哪，用 `dpkg -L 包名 | grep etc`。

#### 4.5 `-i`：安装 .deb 文件

```
$ dpkg -i tree_2.3.1-1_amd64.deb
(Reading database ... 16848 files and directories currently installed.)
Preparing to unpack tree_2.3.1-1_amd64.deb ...
Unpacking tree (2.3.1-1) over (2.3.1-1) ...
Setting up tree (2.3.1-1) ...
Processing triggers for man-db (2.13.1-1build1) ...
```

#### 4.6 `-r`：卸载

```
$ dpkg -r tree
(Reading database ... 16848 files and directories currently installed.)
Removing tree (2.3.1-1) ...
Processing triggers for man-db (2.13.1-1build1) ...

$ dpkg -l tree
dpkg-query: no packages found matching tree
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `dpkg -i` 报 `dependency problems`，软件装了一半 | dpkg 不会自动安装依赖 | 执行 `sudo apt-get install -f` 自动补齐依赖；或者一开始就用 `sudo apt install ./文件.deb`（注意 `./`），apt 会处理依赖 |
| `apt install 文件.deb` 报找不到包 | 没写 `./`，apt 把它当成了包名 | 写成 `sudo apt install ./文件.deb` |
| `dpkg -l` 里有很多 `rc` 状态的包 | 卸载时用了 remove，配置文件留着 | 不需要的话 `sudo apt purge 包名` 清掉 |

### 6. 一句话总结

装 .deb 用 `sudo apt install ./文件.deb`；查询用 `dpkg -l`、`-L`、`-S`。

## 065 snap：管理 Snap 软件包

> 级别：初级 · 软件包：`snapd`（Ubuntu 桌面版和服务器版默认安装）

### 1. 作用

`snap` 管理 Snap 格式的软件包。Snap 是 Canonical（Ubuntu 的开发公司）推出的软件分发格式：每个 snap 自带运行所需的依赖库，在沙箱里运行，并且会**自动更新**。

Ubuntu 上有些软件只提供或优先提供 snap 版，例如 Firefox、Thunderbird、LXD、MicroK8s。Ubuntu 桌面版的“应用中心”装的软件也大多是 snap。

| | apt（.deb） | snap |
|---|---|---|
| 依赖 | 和系统共用库 | 每个软件自带 |
| 更新 | 手动 `apt upgrade` | 后台自动更新 |
| 体积 | 小 | 大 |
| 启动速度 | 快 | 第一次启动较慢 |

### 2. 基本格式

```bash
snap 子命令 [参数] [软件名]
```

修改类的子命令（install、remove、refresh）要加 sudo。

### 3. 常用子命令

| 子命令 | 作用 |
|---|---|
| `find 关键词` | 在 Snap 商店里搜索 |
| `info 软件名` | 查看详情和可用的版本通道 |
| `install 软件名` | 安装 |
| `list` | 列出已安装的 snap |
| `refresh [软件名]` | 立即更新 |
| `remove 软件名` | 卸载 |
| `services` | 查看 snap 提供的后台服务 |

常用参数：

| 参数 | 作用 |
|---|---|
| `--classic` | 以“经典模式”安装，不受沙箱限制。开发工具（如 VS Code、各种 SDK）通常需要 |
| `--channel=通道` | 指定版本通道，如 `--channel=1.30/stable` |

### 4. 常用示例

> ⚠️ 本页未实机验证：snapd 需要 systemd 作为系统的第一个进程才能运行，测试环境不满足。命令写法为 snap 长期稳定的用法。

```bash
snap find postman                  # 搜索
snap info code                     # 看详情和通道
sudo snap install code --classic   # 安装 VS Code（需要经典模式）
snap list                          # 已安装列表
sudo snap refresh                  # 立即更新所有 snap
sudo snap remove code              # 卸载
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 安装时报错，提示需要 `--classic` | 这个软件需要访问沙箱外的文件 | 加 `--classic` |
| `df -h` 里出现一大堆 `/dev/loop` 设备 | 每个 snap 都以只读镜像的方式挂载 | 这是正常的。`df -h -x squashfs` 可以不显示它们 |
| 磁盘被 snap 占了好几个 GB | snap 默认保留每个软件的旧版本 | `sudo snap set system refresh.retain=2` 只保留 2 个版本 |
| snap 软件读不到 `/mnt` 或其他目录下的文件 | 沙箱限制了文件访问范围 | 用 `snap connections 软件名` 查看权限，必要时改用 apt 版本 |

### 6. 一句话总结

apt 找不到或官方推荐 snap 时用 `sudo snap install`，开发工具加 `--classic`。
