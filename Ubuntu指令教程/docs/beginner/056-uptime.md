# 056 uptime：查看运行时长和负载

> 级别：初级 · 软件包：`procps`

## 1. 作用

`uptime` 用一行显示：现在几点、系统已经连续运行了多久、有几个用户登录、最近 1/5/15 分钟的平均负载。确认服务器有没有偷偷重启过、负载是不是在升高，用它最快。

## 2. 基本格式

```bash
uptime [参数]
```

## 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-p` | `--pretty` | 用易读的方式显示运行时长 |
| `-s` | `--since` | 显示开机时间 |

## 4. 常用示例

> 以下输出来自测试环境。

```
$ uptime
 07:00:08 up  1:25,  0 users,  load average: 0.33, 0.50, 0.52

$ uptime -p
up 1 hour, 25 minutes

$ uptime -s
2026-10-29 05:34:28
```

| 内容 | 含义 |
|---|---|
| `07:00:08` | 当前时间 |
| `up 1:25` | 已运行 1 小时 25 分。运行超过一天时显示为 `up 12 days, 3:20` |
| `0 users` | 当前登录的终端会话数 |
| `load average: 0.33, 0.50, 0.52` | 最近 1、5、15 分钟的平均负载 |

## 5. 怎么看负载

负载大致表示“正在运行和排队等待 CPU 的进程数”。要和 CPU 核数比较，核数用 `nproc` 查：

```
$ nproc
8
```

| 负载（8 核机器） | 状态 |
|---|---|
| 低于 8 | CPU 还有余力 |
| 约等于 8 | 刚好满负荷 |
| 长期高于 8 | 有进程在排队，系统会变慢 |

三个数字一起看趋势：1 分钟的值远高于 15 分钟的值，说明负载正在升高。

## 6. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 负载很高，CPU 使用率却不高 | 负载也计入了在等待磁盘 IO 的进程 | 用 `top` 看 `wa` 值，或用 `iostat` 查磁盘 |
| `up` 时间只有几分钟，但没人重启过 | 可能断过电、内核崩溃或被云平台迁移 | 用 `journalctl --list-boots` 查历次开机记录，用 `journalctl -b -1 -e` 看上次运行最后的日志 |

## 7. 一句话总结

`uptime` 看开机多久和负载，负载要和 `nproc` 的核数比较。
