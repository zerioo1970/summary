## 028 top：实时查看系统负载和进程

> 级别：初级 · 软件包：`procps`

### 1. 作用

`top` 实时显示系统的整体负载、CPU 和内存使用情况，以及按资源占用排序的进程列表，默认每 3 秒刷新一次。服务器“突然很卡”，第一件事就是打开 top，看是哪个进程在占 CPU 或内存。

界面更友好的替代品是 [htop](#cmd-htop)。

### 2. 基本格式

```bash
top [参数]
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-u 用户` | 只显示某个用户的进程 |
| `-p PID` | 只盯某几个进程，如 `-p 1234,5678` |
| `-o 字段` | 按指定字段排序，如 `-o %MEM` |
| `-d 秒` | 刷新间隔 |
| `-b -n 1` | 批处理模式，输出一次就退出（可以存到文件或接管道） |

### 4. 运行中的按键

| 按键 | 作用 |
|---|---|
| `P` | 按 CPU 排序（默认） |
| `M` | 按内存排序 |
| `1` | 展开显示每个 CPU 核心 |
| `c` | 显示完整命令行 |
| `k` | 输入 PID 结束进程 |
| `q` | 退出 |

### 5. 读懂 top 的输出

下面用一个死循环的 python 进程模拟 CPU 被占满（输出来自测试环境，省略了一行测试环境自身的进程）：

```
$ top -b -n 1 | head -12
top - 06:52:01 up  1:17,  0 users,  load average: 0.57, 0.57, 0.50
Tasks:   6 total,   2 running,   4 sleeping,   0 stopped,   0 zombie
%Cpu(s): 12.1 us,  1.1 sy,  0.0 ni, 75.8 id,  0.0 wa,  0.0 hi, 11.0 si,  0.0 st
MiB Mem :  31560.2 total,  21436.9 free,   2284.8 used,   8338.3 buff/cache
MiB Swap:   2048.0 total,   2048.0 free,      0.0 used.  29275.4 avail Mem

    PID USER      PR  NI    VIRT    RES    SHR S  %CPU  %MEM     TIME+ COMMAND
     35 tom       20   0   16036   8692   6004 R 100.0   0.0   0:02.19 python3
      2 root      20   0    7208   4032   3708 S   0.0   0.0   0:00.00 runuser
     29 tom       20   0    4940   4104   3784 S   0.0   0.0   0:00.00 bash
     37 tom       20   0    8156   5184   3380 R   0.0   0.0   0:00.00 top
```

头部五行：

| 行 | 关注点 |
|---|---|
| 第 1 行 | `up 1:17` 已运行 1 小时 17 分；`load average` 是最近 1、5、15 分钟的平均负载。负载长期超过 CPU 核数，说明 CPU 忙不过来 |
| 第 2 行 | 进程总数；`zombie`（僵尸进程）不为 0 时值得留意 |
| 第 3 行 | `us` 用户程序占用，`sy` 内核占用，`id` 空闲，`wa` 等待磁盘 IO。`wa` 高说明瓶颈在磁盘 |
| 第 4、5 行 | 内存和 swap，含义同 [free](11-系统信息和硬件.md#cmd-free) |

进程列表的关键列：

| 列 | 含义 |
|---|---|
| PID | 进程号，结束进程时要用 |
| %CPU | CPU 占用。单个进程占满一个核显示 100%，多核机器上可以超过 100% |
| RES | 实际占用的物理内存（KB） |
| S | 状态：`R` 运行中，`S` 休眠，`D` 等待 IO（不可中断），`Z` 僵尸 |
| TIME+ | 累计使用的 CPU 时间 |

python3 的 %CPU 是 100.0，排在第一位，它就是“罪魁祸首”。

### 6. 常用示例

```bash
top -o %MEM                # 打开时直接按内存排序
top -u www-data            # 只看网站进程
top -b -n 1 > top.txt      # 把当前状态存成文件，发给同事分析
```

### 7. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 进程 %CPU 显示 400%，以为出了 bug | 多核机器上按单核 100% 计算，4 个核都占满就是 400% | 按 `1` 看每个核的情况 |
| load average 很高，但 CPU 的 `id` 也很高 | 负载里也算了在等磁盘的进程（状态 D） | 看 `wa` 列，用 `iostat` 查磁盘 |
| 在 top 里按 `k` 结束进程没反应 | 进程属于其他用户，普通用户没权限 | 用 `sudo top`，或退出后 `sudo kill PID` |

### 8. 一句话总结

卡了就开 `top`，`P` 按 CPU、`M` 按内存排，找到 PID 再处理。

## 029 ps：查看进程列表

> 级别：初级 · 软件包：`procps`

### 1. 作用

`ps`（process status）列出当前正在运行的进程。和 top 不同，ps 只输出一次快照，适合配合 grep 查找某个程序是否在运行、它的 PID 是多少、是谁启动的。

### 2. 基本格式

```bash
ps [参数]
```

ps 的参数有两种风格并存，最常见的是这两种组合：

| 写法 | 风格 | 说明 |
|---|---|---|
| `ps aux` | BSD 风格（不带 `-`） | 所有用户的所有进程，带 CPU、内存占用 |
| `ps -ef` | 标准风格（带 `-`） | 所有进程，带父进程号 PPID |

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `aux` | 所有进程，用户导向的格式（含 %CPU、%MEM） |
| `-ef` | 所有进程，完整格式（含 PPID） |
| `-u 用户` | 只看某个用户的进程 |
| `-p PID` | 只看指定 PID 的进程 |
| `-o 字段,...` | 自定义显示哪些列 |
| `--sort=-字段` | 按字段排序，`-` 表示从大到小 |

### 4. 常用示例

下面先在后台启动一个 `sleep 600` 和一个占 50 MB 内存的 python 进程，用来演示（测试环境里进程很少，真实服务器会有几百个）。

#### 4.1 `ps`：只看当前终端的进程

```
$ ps
    PID TTY          TIME CMD
     29 ?        00:00:00 bash
     35 ?        00:00:00 sleep
     36 ?        00:00:00 python3
     38 ?        00:00:00 ps
```

#### 4.2 `ps aux`：用户、CPU、内存

```
$ ps u -u tom
USER         PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
tom           29  0.0  0.0   4940  4124 ?        S    06:51   0:00 bash -ic cd ~
tom           35  0.0  0.0  17648  7136 ?        S    06:51   0:00 sleep 600
tom           36  3.9  0.1  64868 57868 ?        S    06:51   0:00 python3 -c im
tom           39  0.0  0.0   7152  4444 ?        R    06:51   0:00 ps u -u tom
```

这里用 `ps u -u tom` 只列出 tom 的进程，列的格式和 `ps aux` 完全一样。

| 列 | 含义 |
|---|---|
| %CPU / %MEM | CPU、内存占用百分比 |
| VSZ / RSS | 虚拟内存 / 实际占用的物理内存（KB）。看内存占用以 RSS 为准 |
| STAT | 状态，含义同 [top](#cmd-top) 的 S 列 |
| START | 启动时间 |

#### 4.3 `ps -ef`：看父进程

```
$ ps -f -u tom
UID          PID    PPID  C STIME TTY          TIME CMD
tom           29       2  0 06:51 ?        00:00:00 bash -ic cd ~/demo; while IF
tom           35      29  0 06:51 ?        00:00:00 sleep 600
tom           36      29  3 06:51 ?        00:00:00 python3 -c import time; x=by
tom           40      29  0 06:51 ?        00:00:00 ps -f -u tom
```

sleep 和 python3 的 PPID 都是 29，说明它们是由 PID 29 的 bash 启动的。排查“这个进程是谁拉起来的”时看 PPID。

#### 4.4 `-o` 和 `--sort`：按内存排序

```
$ ps -u tom -o pid,ppid,%cpu,%mem,etime,cmd --sort=-%mem
    PID    PPID %CPU %MEM     ELAPSED CMD
     36      29  3.8  0.1       00:00 python3 -c import time; x=bytearray(50_000
     35      29  0.0  0.0       00:00 sleep 600
     41      29  0.0  0.0       00:00 ps -u tom -o pid,ppid,%cpu,%mem,etime,cmd
     29       2  0.0  0.0       00:00 bash -ic cd ~/demo; while IFS= read -r lin
```

全机器内存占用前 10 名：`ps aux --sort=-%mem | head -11`。

#### 4.5 查某个程序在不在运行

```
$ ps aux | grep "[s]leep"
tom           35  0.0  0.0  17648  7136 ?        S    06:51   0:00 sleep 600

$ pgrep -a sleep
35 sleep 600
```

`[s]leep` 这个写法能避免 grep 把自己也匹配出来。只想要 PID 时，`pgrep` 更简单。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `ps aux \| grep nginx` 总有一行 `grep --color=auto nginx` | grep 自己也是一个进程 | 用 `grep "[n]ginx"` 或 `pgrep -a nginx` |
| 命令行被截断，看不全启动参数 | ps 按终端宽度截断 | 加 `ww`：`ps auxww` |
| 只用 `ps` 找不到后台服务 | 不带参数的 ps 只显示当前终端的进程 | 用 `ps aux` 或 `ps -ef` |

### 6. 一句话总结

`ps aux | grep 名字` 查进程，`--sort=-%mem` 找内存大户，只要 PID 用 `pgrep`。

## 030 kill：结束进程

> 级别：初级 · 来源：bash 内建命令（另有同名程序 `/usr/bin/kill`，用法相同）

### 1. 作用

`kill` 向进程发送信号（signal，系统通知进程的一种方式）。最常见的用途是结束进程：程序卡死、端口被旧进程占用、要停掉一个手动启动的后台任务时用它。

kill 默认发送的是 TERM（15 号）信号，意思是“请你退出”，程序可以先保存数据、关闭连接再退出。只有程序不理会时，才用 KILL（9 号）信号强制结束。

### 2. 基本格式

```bash
kill [-信号] PID...
kill %作业号            # 结束当前终端的后台作业
```

PID 用 [ps](#cmd-ps) 或 `pgrep` 查。

### 3. 常用信号

| 信号 | 编号 | 写法 | 作用 |
|---|---|---|---|
| TERM | 15 | `kill PID` | 默认信号，请求进程正常退出 |
| KILL | 9 | `kill -9 PID` | 强制结束，进程无法拒绝，也来不及做清理 |
| HUP | 1 | `kill -HUP PID` | 很多服务（如 nginx）收到后会重新读取配置 |
| INT | 2 | `kill -INT PID` | 等同于在终端里按 `Ctrl+C` |

```
$ kill -l 9 15
KILL
TERM
```

`kill -l` 列出所有信号，后面跟编号则显示对应的名字。

### 4. 常用示例

#### 4.1 结束后台作业

```
$ sleep 600 &
[1] 197

$ jobs
[1]+  Running                    sleep 600 &

$ kill %1

$ jobs
[1]+  Terminated                 sleep 600
```

#### 4.2 按 PID 结束

```
$ pgrep -a sleep
199 sleep 601

$ kill 199
```

也可以写成一行：`kill $(pgrep -x sleep)`。

#### 4.3 正常结束不了，再用 `-9`

下面模拟一个忽略 TERM 信号的进程：

```
$ bash -c 'trap "" TERM; sleep 602' &
[2] 203

$ kill 203; sleep 0.5; ps -p 203 -o pid,stat,cmd
    PID STAT CMD
    203 S    sleep 602

$ kill -9 203; sleep 0.3; ps -p 203 -o pid,cmd
    PID CMD
```

第一次 kill 后进程还在；`kill -9` 之后，ps 已经查不到它了。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `bash: kill: (99999) - No such process` | PID 写错，或进程已经退出 | 重新用 `pgrep` 查 |
| `bash: kill: (1) - Operation not permitted` | 不能结束其他用户（包括 root）的进程 | 确认确实要结束后，用 `sudo kill PID` |
| 一上来就 `kill -9` 数据库，重启后数据损坏或要长时间恢复 | `-9` 不给程序保存数据的机会 | 先 `kill PID` 等几秒，不行再 `-9`；systemd 管理的服务用 `sudo systemctl stop 服务名` |
| kill 掉进程，几秒后它又出现了 | 进程由 systemd 或其他守护程序管理，退出后会被自动拉起 | 用 `systemctl stop` 停止服务 |
| 想按名字结束进程 | kill 只认 PID | 用 `pkill 名字` 或 [killall](#cmd-killall) |

### 6. 一句话总结

先 `kill PID` 礼貌请求，没反应再 `kill -9`；服务要用 `systemctl stop`。

## 085 htop：更好用的进程监控

> 级别：初级 · 软件包：`htop`（Ubuntu 26.04 为 3.4.1 版；没有就 `sudo apt install htop`）

### 1. 作用

`htop` 和 [top](#cmd-top) 做同样的事：实时显示 CPU、内存和进程。它的改进是：

- 每个 CPU 核心、内存、swap 用彩色条形图显示，一眼看出忙不忙；
- 可以用方向键、鼠标选中进程，直接结束或调整优先级；
- 底部一直显示功能键提示，不用记快捷键；
- 可以按树形显示父子进程。

### 2. 基本格式

```bash
htop [参数]
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-u 用户` | 只显示某个用户的进程 |
| `-p PID,PID` | 只显示指定的进程 |
| `-t` | 树形显示 |
| `-d 数字` | 刷新间隔，单位是 0.1 秒（`-d 10` 为 1 秒） |

### 4. 运行中的按键

| 按键 | 作用 |
|---|---|
| `F3` 或 `/` | 搜索进程 |
| `F4` 或 `\` | 过滤：只显示名字里含关键词的进程 |
| `F5` 或 `t` | 切换树形显示 |
| `F6` 或 `>` | 选择排序列 |
| `P` / `M` | 按 CPU / 内存排序 |
| `F9` 或 `k` | 给选中的进程发信号（默认 15 TERM） |
| `空格` | 标记进程，可以一次处理多个 |
| `F10` 或 `q` | 退出 |

> ⚠️ 本页未实机验证：htop 是全屏交互程序，测试环境只确认了版本（`htop 3.4.1`）。按键为 htop 的默认键位。

### 5. 常用示例

```bash
htop                 # 打开
htop -u www-data     # 只看网站进程
htop -t              # 树形显示，看哪个进程拉起了哪些子进程
```

排查“某个 Java 程序占了多少内存”：打开 htop，按 `F4` 输入 `java`，列表里只剩 java 进程，看 RES 列。

### 6. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 同一个程序在列表里出现了几十行 | htop 默认把每个线程也单独列出来 | 按 `H` 隐藏用户线程 |
| 在 SSH 终端里按 F 键没反应 | 终端软件截获了功能键 | 用括号里的替代按键，如 `/` 搜索、`q` 退出 |

### 7. 一句话总结

日常看负载用 `htop`，`F4` 过滤、`F9` 结束进程、`q` 退出。

## 087 sleep：暂停一段时间

> 级别：初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`sleep` 什么也不做，只是等待指定的时间后退出。在脚本里，它用来让两个步骤之间隔开一段时间，比如启动服务后等几秒再检查状态，或者每隔一分钟轮询一次。

### 2. 基本格式

```bash
sleep 时长[单位]
```

| 单位 | 含义 | 例子 |
|---|---|---|
| 不写或 `s` | 秒 | `sleep 5`、`sleep 0.5` |
| `m` | 分钟 | `sleep 2m` |
| `h` | 小时 | `sleep 1h` |
| `d` | 天 | `sleep 1d` |

可以用小数。

### 3. 常用示例

#### 3.1 等待后再执行

```
$ sleep 0.5; echo done
done
```

#### 3.2 启动服务后等它就绪

```bash
sudo systemctl restart myapp
sleep 5
curl -fsS http://localhost:8080/health && echo "启动成功"
```

#### 3.3 简单的轮询

```bash
while ! curl -fsS http://localhost:8080/health >/dev/null; do
    echo "还没好，3 秒后重试"
    sleep 3
done
echo "服务已就绪"
```

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 用 `sleep 3600` 加死循环做定时任务，脚本被意外结束后就再也不执行了 | sleep 循环没有人看管 | 定时任务用 crontab 或 systemd 定时器（中级篇讲） |
| 固定 `sleep 5` 等服务启动，机器忙的时候 5 秒不够 | 启动时间不固定 | 改成 3.3 的轮询写法，并设置最大重试次数 |

### 5. 一句话总结

`sleep 秒数` 在脚本里等一会儿；等服务就绪用轮询，定时任务用 cron。

## 088 watch：定时重复执行一条命令

> 级别：初级 · 软件包：`procps`

### 1. 作用

`watch` 每隔一段时间（默认 2 秒）执行一次指定的命令，并全屏显示最新的结果。想盯着某个数字变化时用它：磁盘空间在不在涨、文件有没有传完、某个进程还在不在。

### 2. 基本格式

```bash
watch [参数] 命令
```

按 `Ctrl+C` 退出。

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-n 秒` | `--interval` | 刷新间隔 |
| `-d` | `--differences` | 高亮显示和上一次相比变化的部分 |
| `-t` | `--no-title` | 不显示顶部的标题行 |
| `-g` | `--chgexit` | 输出发生变化时自动退出 |

### 4. 常用示例

#### 4.1 每秒刷新一次

```bash
watch -n 1 date
```

屏幕顶部显示标题行，下面是命令的输出，每秒更新：

```
Every 1.0s: date                                   ubuntu: Thu Oct 29 07:08:42 2026

Thu Oct 29 07:08:42 UTC 2026
```

标题行依次是：刷新间隔和命令、主机名、当前时间。

#### 4.2 盯着上传进度

```bash
watch -n 2 -d "ls -l /data/upload/"
```

`-d` 会把变化的数字（文件大小）高亮显示。

#### 4.3 盯着磁盘和内存

```bash
watch -n 5 "df -h / && free -h"
```

命令里有管道、`&&` 这类符号时，整条命令要加引号。

#### 4.4 等到变化时退出

```bash
watch -g "ls /data/done.flag" && echo "处理完成"
```

> ⚠️ 本页只验证了 4.1：watch 是全屏程序，测试环境只截取到了第一屏的标题和内容。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `watch ls \| grep log` 结果不对 | 管道被当前 Shell 先处理了，watch 只拿到了 `ls` | 整条命令加引号：`watch "ls \| grep log"` |
| 别名在 watch 里用不了 | watch 用 `sh -c` 执行命令，不认识 bash 的别名 | 写完整命令，如 `watch "ls -alF"` |

### 6. 一句话总结

`watch -n 秒 -d "命令"` 定时刷新并高亮变化，`Ctrl+C` 退出。

<a id="cmd-time"></a>

## 089 time：统计命令的执行时间

> 级别：初级 · 来源：bash 关键字（另有程序版 `/usr/bin/time`，需要单独安装）

### 1. 作用

`time` 放在任何命令前面，命令执行完后报告它花了多长时间。对比两种写法哪个更快、确认一个备份脚本要跑多久，都用它。

### 2. 基本格式

```bash
time 命令
```

### 3. 读懂输出

```
$ time sleep 1

real    0m1.002s
user    0m0.002s
sys     0m0.000s
```

| 行 | 含义 |
|---|---|
| real | 从开始到结束实际经过的时间（墙上时钟） |
| user | 程序自身代码占用 CPU 的时间 |
| sys | 程序请求系统内核做事（读写文件、网络）占用 CPU 的时间 |

sleep 1 的 real 是 1 秒，但 user 和 sys 几乎为 0：它一直在等待，没有使用 CPU。

### 4. 常用示例

#### 4.1 统计一组命令的时间

```
$ time (find / -name "*.conf" 2>/dev/null | wc -l)
131

real    0m0.075s
user    0m0.010s
sys     0m0.067s
```

多条命令或带管道时，用括号括起来，统计的是整组命令。

#### 4.2 根据结果判断瓶颈

| 现象 | 说明 |
|---|---|
| real 远大于 user + sys | 大部分时间在等待：等磁盘、等网络、等数据库 |
| user 接近 real | 程序在密集计算 |
| sys 偏高 | 大量读写文件或系统调用 |

导出报表的脚本跑了 10 分钟，`time` 一看 user 只有 5 秒，说明问题出在等数据库查询，而不是脚本本身。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `time` 的输出没法用 `> 文件` 重定向保存 | bash 的 time 把结果写到 Shell 的错误输出，不属于被测命令 | `{ time 命令 ; } 2> time.txt` |
| 网上教程里的 `time -v` 报错 | `-v` 是程序版 `/usr/bin/time` 的参数，bash 的 time 不支持 | `sudo apt install time`，然后用 `/usr/bin/time -v 命令` |

### 6. 一句话总结

`time 命令` 看耗时；real 远大于 user+sys，说明时间花在了等待上。

## 099 killall：按程序名结束进程

> 级别：初级 · 软件包：`psmisc`

### 1. 作用

`killall` 按程序名结束进程，同名的进程会被**全部**结束。用 [kill](#cmd-kill) 需要先查 PID，同一个程序开了很多个进程时，killall 一次就能处理完。

### 2. 基本格式

```bash
killall [参数] 程序名
```

程序名要和进程名完全一致（`ps` 的 CMD 列或 `pgrep -a` 看到的名字）。

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-信号` | 指定信号，如 `-9`、`-HUP`，默认 15（TERM） |
| `-i` | 每个进程都先询问 |
| `-v` | 显示结束了哪些进程 |
| `-u 用户` | 只结束某个用户的进程 |
| `-w` | 等进程真正退出后再返回 |

### 4. 常用示例

#### 4.1 结束所有同名进程

```
$ sleep 600 & sleep 601 &

$ pgrep -a sleep
48 sleep 600
49 sleep 601

$ killall sleep

$ pgrep -a sleep; echo "剩余=$?"
剩余=1
```

两个 sleep 都被结束了。pgrep 找不到进程时退出码为 1。

#### 4.2 `-v`：看结束了谁

```
$ killall -v sleep
Killed sleep(56) with signal 15
```

#### 4.3 只结束某个用户的进程

```bash
sudo killall -u zhang python3
```

#### 4.4 进程名不存在

```
$ killall nothere
nothere: no process found
```

### 5. killall 和 pkill 的区别

| | killall | pkill |
|---|---|---|
| 匹配方式 | 进程名必须完全一致 | 进程名包含关键词即可 |
| 按完整命令行匹配 | 不支持 | `pkill -f "关键词"` |

例如要结束 `java -jar price-service.jar`，killall 只能写 `killall java`（会把所有 Java 程序都结束），而 `pkill -f price-service` 可以精确地只结束这一个。

### 6. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `killall java` 把服务器上所有的 Java 服务都停了 | killall 会结束所有同名进程 | 先 `pgrep -a java` 看清楚有哪些，再用 `pkill -f 关键词` 或 `kill PID` |
| 在其他 Unix 系统（如 Solaris）上执行 killall，结束的是所有进程 | 不同系统上 killall 的含义不同 | 只在 Linux 上用 killall |

### 7. 一句话总结

`killall 程序名` 一次结束所有同名进程，执行前先 `pgrep -a` 确认范围。
