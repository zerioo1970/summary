## 035 tar：打包和解包

> 级别：初级 · 软件包：`tar`（GNU 版）

### 1. 作用

`tar` 把多个文件和目录打包成一个文件，通常同时用 gzip 或 xz 压缩，得到 `.tar.gz` 或 `.tar.xz`。Linux 上的软件源码、备份、日志归档基本都是这种格式。

tar 会保留文件的权限、所有者和时间，所以 Linux 之间传文件、做备份时优先用 tar，不用 zip。

### 2. 基本格式

```bash
tar -czf 包名.tar.gz 文件或目录...     # 打包并压缩
tar -xzf 包名.tar.gz [-C 目标目录]      # 解包
tar -tzf 包名.tar.gz                    # 只看包里有什么
```

### 3. 常用参数

参数通常组合在一起写，记住前三个动作参数，其他的按需加：

| 参数 | 作用 |
|---|---|
| `-c` | create，创建新包 |
| `-x` | extract，解包 |
| `-t` | list，列出包里的内容 |
| `-f 文件` | 指定包的文件名，**必须放在参数最后**，紧跟文件名 |
| `-z` | 用 gzip 压缩/解压（`.tar.gz`、`.tgz`） |
| `-J` | 用 xz 压缩/解压（`.tar.xz`），压缩率更高、更慢 |
| `-v` | 显示处理了哪些文件 |
| `-C 目录` | 解包到指定目录 |
| `--exclude="模式"` | 打包时排除某些文件 |

### 4. 常用示例

#### 4.1 打包压缩一个目录

```
$ tar -czf logs.tar.gz logs

$ ls -l logs.tar.gz
-rw-r--r-- 1 tom tom 374 Oct 29 06:55 logs.tar.gz
```

#### 4.2 `-t`：解包前先看内容

```
$ tar -tzf logs.tar.gz
logs/
logs/app.log

$ tar -tvzf src.tar.gz
drwxr-xr-x tom/tom           0 2026-10-29 06:55 src/
-rw-r--r-- tom/tom         152 2026-10-29 06:55 src/products.csv
-rw-r--r-- tom/tom           6 2026-10-01 09:00 readme.txt
```

先看看包里是不是带了一层目录，免得解开后文件散落一地。

#### 4.3 `-v`：打包多个对象，并显示过程

```
$ tar -czvf src.tar.gz src readme.txt
src/
src/products.csv
readme.txt
```

#### 4.4 `-x -C`：解包到指定目录

```
$ mkdir restore; tar -xzf src.tar.gz -C restore; ls -R restore
restore:
readme.txt
src

restore/src:
products.csv
```

不加 `-C` 时解到当前目录。

#### 4.5 只解出其中一个文件

```bash
tar -xzf src.tar.gz -C restore src/products.csv
```

文件路径要和 `tar -t` 列出来的完全一致。

#### 4.6 `-J`：xz 格式

```
$ tar -cJf logs.tar.xz logs

$ tar -xf logs.tar.xz -C /tmp && ls /tmp/logs
app.log
```

解包时可以不写 `-z`、`-J`，`tar -xf` 会自动识别压缩格式。

#### 4.7 `--exclude`：备份时跳过某些文件

```bash
tar -czf ../demo.tar.gz --exclude="*.iso" .
```

备份网站时常用 `--exclude="*.log" --exclude="cache"` 跳过日志和缓存。

#### 4.8 带日期的备份文件名

```
$ tar -czf backup-$(date +%Y%m%d).tar.gz logs; ls backup-*
backup-20261029.tar.gz
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 写成 `tar -cfz x.tar.gz logs`，生成了一个叫 `z` 的文件 | `-f` 后面紧跟的就是文件名，这里是 `z` | `-f` 放在最后：`-czf` |
| 打包当前目录报 `tar: .: file changed as we read it`，包里还包含了它自己 | 包文件就生成在被打包的目录里 | 把包写到别的目录：`tar -czf ../x.tar.gz .` |
| 用绝对路径打包，提示 `Removing leading '/' from member names` | tar 自动去掉开头的 `/`，防止解包时覆盖系统文件 | 这是保护机制。想要相对路径，用 `-C`：`tar -czf x.tar.gz -C /home/tom/demo logs` |
| `tar -cJf` 报 `xz: not found` | 系统没装 xz（最小化镜像里常见） | `sudo apt install xz-utils` |
| 解包覆盖了同名文件 | tar 解包时直接覆盖 | 先 `-t` 看内容，再用 `-C` 解到一个新目录 |

第二条的实测（包名 all.tar.gz 出现在了自己的内容里）：

```
$ tar -czf all.tar.gz --exclude="*.iso" .
tar: .: file changed as we read it
```

第三条的实测：

```
$ tar -czf logs2.tar.gz /home/tom/demo/logs
tar: Removing leading `/' from member names

$ tar -tzf logs2.tar.gz
home/tom/demo/logs/
home/tom/demo/logs/app.log
```

### 6. 一句话总结

打包 `tar -czf 包 目录`，看内容 `-tzf`，解包 `-xzf 包 -C 目录`，`-f` 永远放最后。

## 036 zip：压缩成 zip 格式

> 级别：初级 · 软件包：`zip`

### 1. 作用

`zip` 把文件和目录压缩成 `.zip` 文件。Linux 内部传文件用 tar 更合适，但要发给 Windows 用户、上传到只认 zip 的系统时，用 zip。

解压用 [unzip](#cmd-unzip)。

### 2. 基本格式

```bash
zip [参数] 压缩包.zip 文件或目录...
```

压缩包名在前，要压缩的内容在后，和 tar 的顺序一样。

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-r` | 递归压缩目录（压缩目录必须加） |
| `-q` | 不显示过程 |
| `-e` | 加密码，执行后会提示输入 |
| `-9` | 最高压缩率（`-1` 最快，默认 `-6`） |
| `-u` | 更新：只加入新增或有改动的文件 |
| `-d` | 从压缩包里删除指定文件 |
| `-x "模式"` | 排除某些文件 |

### 4. 常用示例

#### 4.1 压缩单个文件

```
$ zip readme.zip readme.txt
  adding: readme.txt (stored 0%)
```

`stored 0%` 表示文件太小，直接存储，没有压缩。

#### 4.2 `-r`：压缩目录

```
$ zip -r logs.zip logs
  adding: logs/ (stored 0%)
  adding: logs/app.log (deflated 49%)
```

`deflated 49%` 表示这个文件压缩后小了 49%。

#### 4.3 看压缩包里有什么

```
$ unzip -l logs.zip
Archive:  logs.zip
  Length      Date    Time    Name
---------  ---------- -----   ----
        0  2026-10-29 06:55   logs/
      404  2026-10-28 11:30   logs/app.log
---------                     -------
      404                     2 files
```

#### 4.4 `-e`：加密码

```bash
zip -r -e salary.zip 工资表/
```

执行后会两次提示输入密码，输入时屏幕不显示。

> ⚠️ 4.4 未实机验证：输入密码需要真实终端，测试环境里 zip 报错 `Invalid command arguments (stderr is not a tty)`。

#### 4.5 `-x`：排除文件

```bash
zip -r project.zip project -x "*.log" -x "*/node_modules/*"
```

#### 4.6 `-d`：从包里删掉一个文件

```
$ zip -d logs.zip logs/app.log
deleting: logs/app.log
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `zip logs.zip logs` 之后，压缩包里只有一个空目录 | 没加 `-r`，只压了目录本身 | 加 `-r` |
| `zip error: Nothing to do!` | 只写了压缩包名，没写要压缩什么；或者文件名写错 | 检查命令末尾的文件列表 |
| 解压后文件权限、所有者全变了 | zip 格式不完整保存 Linux 的所有者等信息 | Linux 之间备份用 tar |
| 把 `-e` 加密当成安全措施 | zip 传统加密强度很弱 | 敏感数据用 `gpg` 加密，或用 `7z` 的 AES 加密 |

### 6. 一句话总结

压目录用 `zip -r 包.zip 目录`，给 Windows 用户用 zip，Linux 之间用 tar。

## 037 unzip：解压 zip 文件

> 级别：初级 · 软件包：`unzip`

### 1. 作用

`unzip` 解压 `.zip` 文件，也可以只查看或测试压缩包的内容。从 Windows 同事那里收到的压缩包、从网上下载的 zip 软件包，都用它解。

### 2. 基本格式

```bash
unzip [参数] 压缩包.zip [要解出的文件...] [-d 目标目录]
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-d 目录` | 解压到指定目录（不存在会自动创建） |
| `-l` | 只列出内容，不解压 |
| `-o` | 遇到同名文件直接覆盖，不询问 |
| `-n` | 遇到同名文件一律跳过 |
| `-q` | 不显示过程 |
| `-t` | 测试压缩包是否完整 |
| `-O 编码` | 指定文件名的编码，解决中文文件名乱码，如 `-O GBK` |

### 4. 常用示例

#### 4.1 `-l`：先看内容

```
$ unzip -l pkg.zip
Archive:  pkg.zip
  Length      Date    Time    Name
---------  ---------- -----   ----
        0  2026-10-29 06:55   logs/
      404  2026-10-28 11:30   logs/app.log
        0  2026-10-29 06:55   src/
      152  2026-10-29 06:55   src/products.csv
        6  2026-10-01 09:00   readme.txt
---------                     -------
      562                     5 files
```

#### 4.2 `-d`：解压到指定目录

```
$ unzip pkg.zip -d out
Archive:  pkg.zip
   creating: out/logs/
  inflating: out/logs/app.log
   creating: out/src/
  inflating: out/src/products.csv
 extracting: out/readme.txt
```

#### 4.3 遇到同名文件

再解压一次到同一个目录，unzip 会逐个询问：

```
replace out/logs/app.log? [y]es, [n]o, [A]ll, [N]one, [r]ename:
```

| 输入 | 效果 |
|---|---|
| `y` / `n` | 覆盖 / 跳过这一个 |
| `A` | 后面全部覆盖 |
| `N` | 后面全部跳过 |
| `r` | 改个名字保存 |

不想被询问：覆盖用 `unzip -o`，跳过用 `unzip -n`。

#### 4.4 只解出一个文件

```
$ unzip pkg.zip readme.txt -d one
Archive:  pkg.zip
 extracting: one/readme.txt
```

#### 4.5 `-t`：检查压缩包是否损坏

```
$ unzip -t pkg.zip
Archive:  pkg.zip
    testing: logs/                    OK
    testing: logs/app.log             OK
    testing: src/                     OK
    testing: src/products.csv         OK
    testing: readme.txt               OK
No errors detected in compressed data of pkg.zip.
```

下载的大文件解压报错时，先用 `-t` 确认是不是下载不完整。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| Windows 上打包的 zip，解压后中文文件名是乱码 | Windows 中文版的 zip 工具用 GBK 编码保存文件名，Linux 默认按 UTF-8 解读 | `unzip -O GBK 文件.zip` |
| 解压后当前目录多了一堆散乱的文件 | 压缩包里没有外层目录 | 先 `unzip -l` 看结构，再用 `-d 新目录` 解压 |
| `unzip: cannot find or open nothere.zip, nothere.zip.zip or nothere.zip.ZIP.` | 文件名或路径写错 | 用 `ls` 确认文件名，输入时按 Tab 补全 |
| `unzip: command not found` | 部分最小化安装没有 unzip | `sudo apt install unzip` |

> ⚠️ 第一条未实机验证：测试环境没有 Windows 生成的压缩包。`-O` 参数已在 Ubuntu 26.04 的 `unzip -h` 中确认存在。

### 6. 一句话总结

先 `unzip -l` 看结构，再 `unzip 包 -d 目录`；中文乱码加 `-O GBK`。

## 081 gzip：压缩单个文件

> 级别：初级 · 软件包：`gzip`

### 1. 作用

`gzip` 把一个文件压缩成 `.gz` 格式。日志轮转后的旧日志（`syslog.2.gz`）、`.tar.gz` 里的压缩层，用的都是 gzip。文本类文件（日志、CSV、SQL 导出）通常能压到原来的 10%–50%。

gzip 只压缩**单个文件**，并且默认会**用压缩后的文件替换原文件**。要把多个文件或目录打成一个包，用 [tar](#cmd-tar)。

### 2. 基本格式

```bash
gzip [参数] 文件...
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-k` | `--keep` | 保留原文件 |
| `-d` | `--decompress` | 解压，等同 gunzip |
| `-l` | `--list` | 查看压缩率 |
| `-c` | `--stdout` | 输出到屏幕（标准输出），原文件不动 |
| `-r` | `--recursive` | 把目录里的每个文件分别压缩 |
| `-v` | `--verbose` | 显示压缩率 |
| `-1` … `-9` | | 压缩级别：1 最快，9 压得最小，默认 6 |

### 4. 常用示例

#### 4.1 压缩

```
$ gzip app.log; ls -l app.log*
-rw-r--r-- 1 tom tom 234 Oct 29 07:08 app.log.gz
```

原来的 app.log 不见了，只剩 app.log.gz。

#### 4.2 `-l`：看压缩率

```
$ gzip -l app.log.gz
         compressed        uncompressed  ratio uncompressed_name
                234                 404  48.5% app.log
```

#### 4.3 `-k`：保留原文件

```
$ gzip -k app.log; ls app.log*
app.log  app.log.gz
```

#### 4.4 `-9 -v`：最大压缩并显示结果

```
$ gzip -9 -v app.log
app.log:         48.5% -- replaced with app.log.gz
```

#### 4.5 不解压直接查看

```
$ zcat app.log.gz | head -2
2026-10-28 09:00:01 INFO  服务启动
2026-10-28 09:00:05 INFO  连接数据库成功
```

`zcat`、`zless`、`zgrep` 可以直接读 .gz 文件，查旧日志时不用先解压。

#### 4.6 `-r`：逐个压缩目录里的文件

```
$ gzip -r logs; ls logs
app.log.gz
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 压缩后原文件没了 | gzip 默认替换原文件 | 需要保留就加 `-k` |
| `gzip: app.log.gz already exists;        not overwritten` | 同名的 .gz 已经存在 | 删掉旧的 .gz，或加 `-f` 强制覆盖 |
| `gzip: logs is a directory -- ignored` | gzip 不能把目录压成一个文件 | 用 `tar -czf logs.tar.gz logs` |
| 压缩正在写入的日志，程序继续写的内容丢了 | 程序仍往原来那个（已被删除的）文件里写 | 先让程序切换日志文件（logrotate 会处理），再压缩旧文件 |

### 6. 一句话总结

`gzip 文件` 压缩并替换，`-k` 保留原文件，查看 .gz 用 `zcat`、`zgrep`。

## 082 gunzip：解压 .gz 文件

> 级别：初级 · 软件包：`gzip`

### 1. 作用

`gunzip` 解压 `.gz` 文件，还原出原文件，并删除 .gz 文件。它等同于 `gzip -d`。

`.tar.gz` 文件不要用 gunzip，用 `tar -xzf` 一步解开。

### 2. 基本格式

```bash
gunzip [参数] 文件.gz...
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-k` | `--keep` | 保留 .gz 文件 |
| `-c` | `--stdout` | 解压到屏幕（标准输出），.gz 文件不动 |
| `-r` | `--recursive` | 解压目录里所有的 .gz |
| `-f` | `--force` | 目标文件已存在时强制覆盖 |

### 4. 常用示例

#### 4.1 解压

```
$ gunzip app.log.gz; ls -l app.log*
-rw-r--r-- 1 tom tom 404 Oct 29 07:08 app.log
```

#### 4.2 `-c`：解压成另一个文件，保留 .gz

```
$ gunzip -c app.log.gz > copy.log; ls app.log* copy.log
app.log.gz  copy.log
```

#### 4.3 `gzip -d`：效果相同

```
$ gzip -d app.log.gz; ls app.log*
app.log
```

#### 4.4 `-r`：解压整个目录

```
$ gunzip -r logs; ls logs
app.log
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `gzip: nothere.gz: No such file or directory` | 文件名写错 | 用 ls 确认，输入时按 Tab 补全 |
| 对 .tar.gz 用了 gunzip，得到一个 .tar 文件 | gunzip 只去掉 gzip 那一层 | 继续 `tar -xf 文件.tar`；以后直接 `tar -xzf 文件.tar.gz` |
| 只是想查一下旧日志，解压后占满了磁盘 | 大日志解压后体积会变成好几倍 | 用 `zgrep 关键词 文件.gz` 或 `zless` 直接查 |

### 6. 一句话总结

`gunzip 文件.gz` 解压，`-k` 保留压缩包，只是查看就用 `zcat`。
