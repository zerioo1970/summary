# 054 su：切换到其他用户

> 级别：初级 · 软件包：`util-linux`

## 1. 作用

`su`（switch user）切换成另一个用户，打开一个以那个用户身份运行的 Shell。要以某个服务账号（比如 postgres）的身份操作时用它。

su 要求输入**目标用户**的密码，而 sudo 要求输入**你自己**的密码。Ubuntu 默认锁定了 root 的密码，所以普通用户 `su -` 切换 root 会失败，应该用 `sudo -i`。

## 2. 基本格式

```bash
su [参数] [用户名]
```

不写用户名时，默认切换到 root。

## 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-` 或 `-l` | `--login` | 以登录方式切换：进入目标用户的家目录，加载它的环境变量 |
| `-c "命令"` | `--command` | 只以目标用户身份执行一条命令，然后返回 |
| `-s Shell` | `--shell` | 指定使用的 Shell |

## 4. 常用示例

以下以 root 身份执行。root 切换到任何用户都不需要密码；普通用户可以在前面加 sudo，如 `sudo su - postgres`。

### 4.1 `-` 和不加 `-` 的区别

```
$ su - tom -c "whoami; pwd"
tom
/home/tom

$ su tom -c "pwd"
/root
```

加了 `-`，切换后进入 tom 的家目录，环境变量也是 tom 的；不加 `-`，还停在原来的目录（/root），很多环境变量也保留原来的。日常一律加 `-`。

### 4.2 以服务账号身份执行一条命令

```bash
sudo su - postgres -c "psql -c 'select version();'"
```

也可以写成 `sudo -u postgres psql`，效果类似，更简洁。

### 4.3 退回原来的用户

```bash
exit
```

## 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 普通用户执行 `su -`，输入密码后报 `su: Authentication failure` | Ubuntu 默认锁定了 root 密码（`passwd -S root` 显示 `L`） | 用 `sudo -i` |
| 切换后命令找不到、PATH 不对 | 没加 `-`，环境变量还是原用户的 | 用 `su - 用户名` |
| `su: user nothere does not exist or the user entry does not contain all the required fields` | 用户名写错 | 用 `getent passwd 用户名` 确认 |
| 切到服务账号报 `This account is currently not available.` | 服务账号的 Shell 被设成了 nologin，禁止登录 | 用 `sudo -u 账号 命令` 执行单条命令，或 `su -s /bin/bash - 账号` |

第一条的实测：

```
$ su -c whoami root
Password: su: Authentication failure
```

## 6. 一句话总结

Ubuntu 上切 root 用 `sudo -i`；切其他用户用 `sudo su - 用户` 或 `sudo -u 用户 命令`。
