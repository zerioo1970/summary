# 028 top：实时查看系统负载和进程

> 级别：初级 · 软件包：`procps`

## 1. 作用

`top` 实时显示系统的整体负载、CPU 和内存使用情况，以及按资源占用排序的进程列表，默认每 3 秒刷新一次。服务器“突然很卡”，第一件事就是打开 top，看是哪个进程在占 CPU 或内存。

界面更友好的替代品是 [htop](085-htop.md)。

## 2. 基本格式

```bash
top [参数]
```

## 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-u 用户` | 只显示某个用户的进程 |
| `-p PID` | 只盯某几个进程，如 `-p 1234,5678` |
| `-o 字段` | 按指定字段排序，如 `-o %MEM` |
| `-d 秒` | 刷新间隔 |
| `-b -n 1` | 批处理模式，输出一次就退出（可以存到文件或接管道） |

## 4. 运行中的按键

| 按键 | 作用 |
|---|---|
| `P` | 按 CPU 排序（默认） |
| `M` | 按内存排序 |
| `1` | 展开显示每个 CPU 核心 |
| `c` | 显示完整命令行 |
| `k` | 输入 PID 结束进程 |
| `q` | 退出 |

## 5. 读懂 top 的输出

下面用一个死循环的 python 进程模拟 CPU 被占满（输出来自测试环境，省略了一行测试环境自身的进程）：

```
$ top -b -n 1 | head -12
top - 06:52:01 up  1:17,  0 users,  load average: 0.57, 0.57, 0.50
Tasks:   6 total,   2 running,   4 sleeping,   0 stopped,   0 zombie
%Cpu(s): 12.1 us,  1.1 sy,  0.0 ni, 75.8 id,  0.0 wa,  0.0 hi, 11.0 si,  0.0 st
MiB Mem :  31560.2 total,  21436.9 free,   2284.8 used,   8338.3 buff/cache
MiB Swap:   2048.0 total,   2048.0 free,      0.0 used.  29275.4 avail Mem

    PID USER      PR  NI    VIRT    RES    SHR S  %CPU  %MEM     TIME+ COMMAND
     35 tom       20   0   16036   8692   6004 R 100.0   0.0   0:02.19 python3
      2 root      20   0    7208   4032   3708 S   0.0   0.0   0:00.00 runuser
     29 tom       20   0    4940   4104   3784 S   0.0   0.0   0:00.00 bash
     37 tom       20   0    8156   5184   3380 R   0.0   0.0   0:00.00 top
```

头部五行：

| 行 | 关注点 |
|---|---|
| 第 1 行 | `up 1:17` 已运行 1 小时 17 分；`load average` 是最近 1、5、15 分钟的平均负载。负载长期超过 CPU 核数，说明 CPU 忙不过来 |
| 第 2 行 | 进程总数；`zombie`（僵尸进程）不为 0 时值得留意 |
| 第 3 行 | `us` 用户程序占用，`sy` 内核占用，`id` 空闲，`wa` 等待磁盘 IO。`wa` 高说明瓶颈在磁盘 |
| 第 4、5 行 | 内存和 swap，含义同 [free](027-free.md) |

进程列表的关键列：

| 列 | 含义 |
|---|---|
| PID | 进程号，结束进程时要用 |
| %CPU | CPU 占用。单个进程占满一个核显示 100%，多核机器上可以超过 100% |
| RES | 实际占用的物理内存（KB） |
| S | 状态：`R` 运行中，`S` 休眠，`D` 等待 IO（不可中断），`Z` 僵尸 |
| TIME+ | 累计使用的 CPU 时间 |

python3 的 %CPU 是 100.0，排在第一位，它就是“罪魁祸首”。

## 6. 常用示例

```bash
top -o %MEM                # 打开时直接按内存排序
top -u www-data            # 只看网站进程
top -b -n 1 > top.txt      # 把当前状态存成文件，发给同事分析
```

## 7. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 进程 %CPU 显示 400%，以为出了 bug | 多核机器上按单核 100% 计算，4 个核都占满就是 400% | 按 `1` 看每个核的情况 |
| load average 很高，但 CPU 的 `id` 也很高 | 负载里也算了在等磁盘的进程（状态 D） | 看 `wa` 列，用 `iostat` 查磁盘 |
| 在 top 里按 `k` 结束进程没反应 | 进程属于其他用户，普通用户没权限 | 用 `sudo top`，或退出后 `sudo kill PID` |

## 8. 一句话总结

卡了就开 `top`，`P` 按 CPU、`M` 按内存排，找到 PID 再处理。
