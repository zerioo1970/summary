## 025 ★★★&nbsp;&nbsp;df：查看磁盘空间

> 级别：★★★ 初级 · 软件包：`gnu-coreutils`（Ubuntu 26.04 的 df 仍由 GNU 版提供）

### 1. 作用

`df`（disk free）显示每个已挂载的文件系统总共多大、用了多少、还剩多少。程序报 `No space left on device`，或者服务器监控报警“磁盘使用率 90%”时，先用 df 看是哪个分区满了。

df 看的是整个分区；要知道分区里**哪个目录**占得多，用 [du](#cmd-du)。

### 2. 基本格式

```bash
df [参数] [目录或设备...]
```

指定目录时，只显示该目录所在的分区。

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-h` | `--human-readable` | 用 K、M、G 显示大小 |
| `-T` | `--print-type` | 显示文件系统类型（ext4、xfs、tmpfs 等） |
| `-i` | `--inodes` | 显示 inode（文件个数）的使用情况 |
| `-x 类型` | `--exclude-type` | 不显示某类文件系统，如 `-x tmpfs` |

### 4. 常用示例

> 以下输出来自测试环境，设备名和容量与真实服务器不同。在普通 Ubuntu 机器上，根目录一般显示为 `/dev/sda2`、`/dev/nvme0n1p2` 或 `/dev/mapper/ubuntu--vg-ubuntu--lv`，类型为 ext4。

#### 4.1 `df -h`：看全部分区

```
$ df -h
Filesystem      Size  Used Avail Use% Mounted on
/dev/loop1       87G  1.3G   86G   2% /
tmpfs            16G     0   16G   0% /dev
tmpfs            64M     0   64M   0% /dev/tty
tmpfs            16G     0   16G   0% /run
tmpfs            16G  2.5M   16G   1% /home
tmpfs            16G     0   16G   0% /tmp
```

| 列 | 含义 |
|---|---|
| Filesystem | 设备或文件系统名 |
| Size / Used / Avail | 总大小 / 已用 / 可用 |
| Use% | 使用率，超过 90% 就该清理了 |
| Mounted on | 挂载点，也就是它对应哪个目录 |

`tmpfs` 是内存里的临时文件系统，重启后内容会清空，一般不用关心。

#### 4.2 只看某个目录所在的分区

```
$ df -h /home
Filesystem      Size  Used Avail Use% Mounted on
tmpfs            16G  2.5M   16G   1% /home
```

不确定 `/var/lib/mysql` 在哪个分区，就 `df -h /var/lib/mysql`。

#### 4.3 `-T`：显示文件系统类型

```
$ df -hT /home
Filesystem     Type   Size  Used Avail Use% Mounted on
tmpfs          tmpfs   16G  2.5M   16G   1% /home
```

#### 4.4 `-i`：空间够但还是写不进去

```
$ df -i /home
Filesystem      Inodes IUsed   IFree IUse% Mounted on
tmpfs          4039707    15 4039692    1% /home
```

每个文件占用一个 inode。如果程序产生了几百万个小文件（比如没清理的会话文件），inode 会先用完，这时 `df -h` 还显示有空间，写文件却报 `No space left on device`。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 删了一个大日志，df 显示的可用空间没变 | 文件还被某个进程打开着，空间要等进程关闭文件才释放 | `sudo lsof +L1` 找出占用的进程并重启它；清空日志用 `: > 文件` 而不是删除 |
| `df -h` 有空间，仍然 `No space left on device` | inode 用完了 | `df -i` 确认，找出并清理大量小文件 |
| df 的 Used + Avail 小于 Size | ext4 默认给 root 保留 5% 空间，防止磁盘写满后系统无法维护 | 这是正常现象 |

### 6. 一句话总结

磁盘满了先 `df -h` 定位分区，再用 `du` 找大目录；写不进去还要看 `df -i`。

<a id="cmd-du"></a>

## 026 ★★★&nbsp;&nbsp;du：查看目录和文件占用的空间

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`du`（disk usage）统计目录或文件实际占用了多少磁盘空间。`df` 告诉你哪个分区满了，`du` 帮你找到是哪个目录把它占满的。

### 2. 基本格式

```bash
du [参数] [目录或文件...]
```

不加参数时，du 会列出每一个子目录的大小，输出很长。日常基本都配合 `-sh` 使用。

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-h` | `--human-readable` | 用 K、M、G 显示 |
| `-s` | `--summarize` | 每个参数只显示一个总数 |
| `-a` | `--all` | 文件也列出来（默认只列目录） |
| `-d N` | `--max-depth=N` | 只统计到第 N 层子目录 |
| `-c` | `--total` | 最后加一行总计 |

### 4. 常用示例

#### 4.1 `-sh`：看一个目录总共多大

```
$ du -sh .
2.5M	.
```

#### 4.2 `du -sh *`：当前目录下谁最大

```
$ du -sh *
2.4M	big.iso
0	link.txt
4.0K	logs
4.0K	readme.txt
4.0K	run.sh
4.0K	src
```

readme.txt 只有 6 字节，du 却显示 4.0K，因为磁盘按 4K 一块分配空间，du 统计的是实际占用的块。

#### 4.3 包括隐藏文件

```
$ du -sh .[!.]* *
4.0K	.env
2.4M	big.iso
0	link.txt
4.0K	logs
4.0K	readme.txt
4.0K	run.sh
4.0K	src
```

`*` 不匹配以 `.` 开头的名字，`.[!.]*` 专门匹配隐藏文件。家目录里的 `.cache`、`.local` 经常占几个 GB，不加这个就看不到。

#### 4.4 `--max-depth=1`：只看一层

```
$ du -h --max-depth=1
4.0K	./src
4.0K	./logs
2.5M	.
```

#### 4.5 排序：找出最大的几项

```
$ du -ah | sort -rh | head -3
2.5M	.
2.4M	./big.iso
4.0K	./src/products.csv
```

`sort -rh` 按带单位的大小倒序排列。服务器磁盘满了，常用这一条：

```bash
sudo du -h --max-depth=1 /var | sort -rh | head
```

先找到 /var 下最大的子目录，再进去重复同样的步骤，一层层缩小范围。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| du 统计的总数比 df 显示的已用空间小很多 | 已删除但仍被进程占用的文件，du 看不到 | 见 [df](#cmd-df) 踩坑表第一条 |
| 统计 `/` 时刷出大量 `Permission denied` | 普通用户读不了某些目录 | 加 `sudo`，或在命令末尾加 `2>/dev/null` |
| 统计根目录时，把挂载的网络盘也算进去，非常慢 | du 默认会进入其他文件系统 | 加 `-x`，只统计同一个文件系统 |
| `du -sh *` 漏掉了 `.cache` 等大目录 | `*` 不匹配隐藏文件 | 用 4.3 的写法 |

### 6. 一句话总结

`du -sh *` 看谁最大，`du -h --max-depth=1 | sort -rh` 一层层找出占空间的目录。

## 067 ★★★&nbsp;&nbsp;lsblk：列出磁盘和分区

> 级别：★★★ 初级 · 软件包：`util-linux`

### 1. 作用

`lsblk`（list block devices）用树形列出所有磁盘（块设备）、磁盘上的分区，以及它们挂载在哪个目录。新加了一块硬盘、插了一个 U 盘，想知道它叫什么名字（/dev/sdb 还是 /dev/nvme1n1），就用 lsblk。

### 2. 基本格式

```bash
lsblk [参数] [设备]
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-f` | 显示文件系统类型、卷标、UUID、可用空间 |
| `-d` | 只显示磁盘，不显示分区 |
| `-o 列,...` | 自定义显示的列 |
| `-p` | 显示设备的完整路径（/dev/...） |

### 4. 常用示例

> 以下输出来自测试环境（云服务器）。

#### 4.1 `lsblk`

```
$ lsblk
NAME          MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
loop0           7:0    0 86.9G  0 loop
loop1           7:1    0 86.9G  0 loop /
nvme0n1       259:0    0   30G  0 disk
├─nvme0n1p1   259:1    0   30G  0 part
├─nvme0n1p127 259:2    0    1M  0 part
└─nvme0n1p128 259:3    0   10M  0 part
nvme1n1       259:4    0  128G  0 disk /etc/resolv.conf
```

| 列 | 含义 |
|---|---|
| NAME | 设备名，完整路径是 `/dev/` 加上它 |
| SIZE | 容量 |
| TYPE | `disk` 整块磁盘，`part` 分区，`loop` 回环设备（snap、镜像文件），`lvm` 逻辑卷 |
| MOUNTPOINTS | 挂载到的目录，空白表示没有挂载 |

磁盘命名规律：

| 名字 | 是什么 |
|---|---|
| `sda`、`sdb` | SATA/SAS 硬盘、U 盘，依次编号 |
| `nvme0n1`、`nvme1n1` | NVMe 固态硬盘 |
| `sda1`、`nvme0n1p1` | 上面那块盘的第 1 个分区 |
| `vda` | 虚拟机里的虚拟磁盘 |

#### 4.2 `-d`：只看磁盘

```
$ lsblk -d
NAME    MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
loop0     7:0    0 86.9G  0 loop
loop1     7:1    0 86.9G  0 loop /
nvme0n1 259:0    0   30G  0 disk
nvme1n1 259:4    0  128G  0 disk /etc/resolv.conf
```

#### 4.3 `-o`：只看关心的列

```
$ lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS
NAME           SIZE TYPE FSTYPE MOUNTPOINTS
loop0         86.9G loop
loop1         86.9G loop        /
nvme0n1         30G disk
├─nvme0n1p1     30G part
├─nvme0n1p127    1M part
└─nvme0n1p128   10M part
nvme1n1        128G disk        /etc/resolv.conf
```

#### 4.4 `-f`：看文件系统和 UUID

```bash
lsblk -f
```

在普通 Ubuntu 机器上，FSTYPE 一列会显示 ext4、vfat（EFI 分区）、swap 等，UUID 一列是写进 `/etc/fstab` 时用的唯一编号。测试环境的容器读不到这些信息，所以这两列是空的。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 新插的硬盘在 lsblk 里只有 disk，没有 part | 新硬盘还没分区 | 用 `fdisk` 或 `parted` 分区后格式化（中级篇讲） |
| 云服务器扩容了磁盘，lsblk 显示的磁盘变大了，`df -h` 里的分区没变 | 扩容的是磁盘，分区和文件系统还要单独扩展 | 用 `growpart` 扩分区，再用 `resize2fs` 扩文件系统（高级篇讲） |
| 每次开机 sdb、sdc 的顺序可能不一样 | 设备名按识别顺序分配 | 在 /etc/fstab 里用 UUID，不用 /dev/sdb1 这样的名字 |

### 6. 一句话总结

`lsblk` 看有哪些盘和分区，`lsblk -f` 看文件系统和 UUID。

## 068 ★★★&nbsp;&nbsp;mount：挂载磁盘和分区

> 级别：★★★ 初级 · 软件包：`mount`

### 1. 作用

Linux 里所有文件都在一棵从 `/` 开始的目录树上。一块新硬盘、一个 U 盘、一个网络共享目录，要先**挂载**（mount）到树上的某个空目录，才能通过这个目录访问里面的文件。这个目录叫**挂载点**。

`mount` 不带参数时，列出当前所有的挂载。

### 2. 基本格式

```bash
mount                                # 查看所有挂载
sudo mount [参数] 设备 挂载点          # 挂载
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-t 类型` | 指定文件系统类型，如 `ext4`、`vfat`、`ntfs3`、`cifs`（Windows 共享） |
| `-o 选项` | 挂载选项，多个用逗号分隔：`ro` 只读，`rw` 读写，`noexec` 禁止执行程序 |
| `-a` | 挂载 /etc/fstab 里所有还没挂载的条目 |

### 4. 常用示例

#### 4.1 查看当前挂载

```
$ findmnt /home
TARGET SOURCE FSTYPE OPTIONS
/home  tmpfs  tmpfs  rw,nosuid,nodev,relatime,seclabel,mode=755
```

`mount` 的完整输出很长，查某个目录用 `mount | grep " /home "` 或 `findmnt 目录` 更清楚（findmnt 在中级篇讲）。

#### 4.2 挂载一块新硬盘

```bash
lsblk -f                          # 确认分区名和文件系统，假设是 /dev/sdb1，ext4
sudo mkdir -p /data               # 挂载点必须先存在
sudo mount /dev/sdb1 /data
df -h /data                       # 确认挂载成功
```

#### 4.3 挂载 U 盘（只读）

```bash
sudo mount -o ro /dev/sdc1 /mnt
```

#### 4.4 开机自动挂载：/etc/fstab

用 mount 挂载的内容重启后就没了。要永久挂载，在 `/etc/fstab` 里加一行：

```
UUID=1234abcd-...  /data  ext4  defaults  0  2
```

UUID 从 `lsblk -f` 或 `blkid` 获得。加完后先执行 `sudo mount -a` 测试，没有报错再重启。

> ⚠️ 4.2–4.4 未实机验证：测试环境的容器不允许挂载设备。命令写法为长期稳定的标准用法。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 挂载后，挂载点里原来的文件“不见了” | 挂载会把原目录的内容盖住，卸载后会重新出现 | 挂载点用空目录 |
| /etc/fstab 写错一个字，重启后系统进入紧急模式 | 开机时挂载失败 | 改完一定先 `sudo mount -a` 测试；不重要的盘在选项里加 `nofail` |
| `mount: wrong fs type, bad option, bad superblock` | 文件系统类型不对，或者分区还没格式化 | 用 `lsblk -f` 确认 FSTYPE |
| 普通用户执行 mount 报 `mount: /mnt: must be superuser to use mount.` | 挂载需要 root | 加 `sudo` |

### 6. 一句话总结

`sudo mount 设备 目录` 临时挂载，永久挂载写 /etc/fstab，写完先 `mount -a` 测试。

## 069 ★★★&nbsp;&nbsp;umount：卸载磁盘和分区

> 级别：★★★ 初级 · 软件包：`mount`

### 1. 作用

`umount`（注意没有 n，不是 unmount）把挂载的设备从目录树上卸下来。拔 U 盘、移除硬盘、对分区做检查或调整大小之前，都要先卸载，否则可能丢数据。

### 2. 基本格式

```bash
sudo umount 挂载点或设备
```

写挂载点（`/data`）或设备名（`/dev/sdb1`）都可以。

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-l` | 懒卸载：先从目录树上摘下来，等没人使用了再真正卸载 |
| `-f` | 强制卸载（主要用于连不上的网络共享） |
| `-R` | 递归卸载这个目录及其下面的所有挂载 |

### 4. 常用示例

```bash
sudo umount /data
sudo umount /dev/sdc1
```

卸载成功不会有任何输出。用 `df -h` 或 `lsblk` 确认它已经不在了。

> ⚠️ 本页未实机验证：测试环境的容器不允许挂载和卸载设备。命令写法为长期稳定的标准用法。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `umount: /data: target is busy.` | 有进程正在使用里面的文件，或者某个终端的当前目录就在里面 | 先 `cd ~` 离开；用 `sudo lsof +D /data` 或 `sudo fuser -vm /data` 找出占用的进程 |
| 拔掉 U 盘后，拷进去的文件不完整 | 写入的数据还在内存缓存里，没写进 U 盘 | 一定先 `umount`，它会把缓存写完再卸载 |
| 普通用户执行报 `umount: /home: must be superuser to unmount.` | 卸载需要 root | 加 `sudo` |
| 网络共享断了，umount 一直卡住 | 系统在等待服务器响应 | `sudo umount -f` 或 `-l` |

### 6. 一句话总结

拔盘之前先 `sudo umount 挂载点`，提示 busy 就先离开目录、找出占用的进程。

<a id="cmd-fdisk"></a>

## 142 ★★&nbsp;&nbsp;fdisk：给磁盘分区

> 级别：★★ 中级 · 软件包：`fdisk`（util-linux 2.41）

### 1. 作用

`fdisk` 查看磁盘的分区表，并以交互方式新建、删除、修改分区。新加一块硬盘后的标准流程是：**fdisk 分区 → mkfs 格式化 → mount 挂载 → 写进 /etc/fstab**。

fdisk 支持 GPT 和 MBR（DOS）两种分区表。2 TB 以上的磁盘必须用 GPT；新磁盘一律建议用 GPT。

### 2. 基本格式

```bash
sudo fdisk -l [磁盘]      # 查看分区表
sudo fdisk 磁盘           # 进入交互式分区，如 sudo fdisk /dev/sdb
```

### 3. 交互命令

进入 fdisk 后输入单个字母执行操作。所有修改在按 `w` 之前**都只在内存里**，按 `q` 可以放弃全部修改。

| 命令 | 作用 |
|---|---|
| `p` | 显示当前分区表 |
| `g` | 新建一个空的 GPT 分区表（清除原有分区） |
| `o` | 新建一个空的 MBR 分区表 |
| `n` | 新建分区 |
| `d` | 删除分区 |
| `t` | 修改分区类型（如改成 Linux swap、EFI System） |
| `w` | 写入磁盘并退出 |
| `q` | 不保存，退出 |
| `m` | 帮助 |

### 4. 常用示例

为了安全，下面用一个 1 GB 的镜像文件 `disk.img` 代替真实磁盘演示（以 root 身份执行）。对真实磁盘，把 `disk.img` 换成 `/dev/sdb` 这样的设备名即可。

#### 4.1 查看分区表

```
$ fdisk -l disk.img
Disk disk.img: 1 GiB, 1073741824 bytes, 2097152 sectors
Units: sectors of 1 * 512 = 512 bytes
Sector size (logical/physical): 512 bytes / 512 bytes
I/O size (minimum/optimal): 512 bytes / 512 bytes
```

新磁盘没有分区表，只显示磁盘本身的信息。

#### 4.2 建 GPT 分区表和两个分区

交互过程中依次输入：

| 输入 | 含义 |
|---|---|
| `g` | 新建 GPT 分区表 |
| `n` → `1` → 回车 → `+200M` | 第 1 个分区，从默认位置开始，大小 200 MB |
| `n` → `2` → 回车 → 回车 | 第 2 个分区，用掉剩下的全部空间 |
| `w` | 写入 |

完成后：

```
$ fdisk -l disk.img
...
Device      Start     End Sectors  Size Type
disk.img1    2048  411647  409600  200M Linux filesystem
disk.img2  411648 2095103 1683456  822M Linux filesystem
```

第 1 个分区从第 2048 扇区（1 MiB 处）开始，这是为了对齐，默认值即可，不要改。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 对系统盘执行了 `g`、`w`，原来的分区全没了 | 选错了磁盘 | 执行前用 `lsblk` 核对磁盘名和容量；按 `w` 前先按 `p` 确认 |
| 分区后 `lsblk` 里看不到新分区 | 磁盘正在被使用，内核没有重新读取分区表 | 执行 `sudo partprobe 磁盘`，或重启 |
| 想把一块 4 TB 的盘分区，只能用到 2 TB | 用了 MBR 分区表（`o`） | 用 GPT（`g`） |
| 脚本里需要自动分区 | fdisk 是交互式的 | 用 `parted -s` 或 `sfdisk` |

### 6. 一句话总结

`fdisk -l` 看分区，`fdisk 磁盘` 交互分区，按 `w` 之前一切可反悔。

## 143 ★★&nbsp;&nbsp;parted：分区（适合脚本和大磁盘）

> 级别：★★ 中级 · 软件包：`parted`

### 1. 作用

`parted` 和 fdisk 做同样的事，区别是它可以用**一条命令**完成分区（加 `-s` 不询问），适合写进脚本；并且可以直接用百分比、MiB、GB 指定分区的位置。

注意：parted 的每条命令是**立即生效**的，没有 fdisk 那样“按 w 才写入”的缓冲。

### 2. 基本格式

```bash
sudo parted 磁盘 print                       # 查看
sudo parted -s 磁盘 命令 [命令...]            # 非交互执行
```

### 3. 常用命令

| 命令 | 作用 |
|---|---|
| `print` | 显示分区表 |
| `print free` | 同时显示未分配的空间 |
| `mklabel gpt` | 新建 GPT 分区表（清除原有分区） |
| `mkpart 名称 类型 起点 终点` | 新建分区，如 `mkpart data ext4 1MiB 100%` |
| `rm 编号` | 删除分区 |
| `resizepart 编号 终点` | 调整分区的终点（扩容） |
| `unit MiB` | 后续显示和输入都用 MiB 为单位 |

### 4. 常用示例

以 1 GB 的镜像文件代替真实磁盘（root 身份）：

```
$ parted -s disk2.img mklabel gpt mkpart data ext4 1MiB 100%

$ parted -s disk2.img print
Model:  (file)
Disk /root/disk2.img: 1074MB
Sector size (logical/physical): 512B/512B
Partition Table: gpt
Disk Flags:

Number  Start   End     Size    File system  Name  Flags
 1      1049kB  1073MB  1072MB               data
```

一条命令完成：建 GPT 表，建一个从 1 MiB 到磁盘末尾的分区。`mkpart` 里的 `ext4` 只是标记，**不会格式化**，格式化还要用 mkfs。File system 一列为空，就是因为还没格式化。

查看未分配空间：

```
$ parted -s disk2.img unit MiB print free
...
        0.02MiB  1.00MiB  0.98MiB  Free Space
 1      1.00MiB  1023MiB  1022MiB               data
        1023MiB  1024MiB  0.98MiB  Free Space
```

云服务器扩容磁盘后，用 `print free` 能看到末尾多出来的空闲空间。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 在 parted 交互模式里试着 `mklabel`，原有分区立即没了 | parted 的命令立即生效 | 操作前先 `print`，确认磁盘无误 |
| 以为 `mkpart ... ext4` 已经格式化了，mount 报 `wrong fs type` | mkpart 只建分区 | 再执行 `mkfs.ext4 分区` |
| 用 GB 指定起点，提示分区没有对齐 | 1 GB = 1000 MB，不是 1024 的整数倍 | 用 MiB、GiB 或百分比 |

### 6. 一句话总结

脚本里分区用 `parted -s 磁盘 mklabel gpt mkpart 名称 ext4 1MiB 100%`。

<a id="cmd-mkfs"></a>

## 144 ★★&nbsp;&nbsp;mkfs：格式化分区

> 级别：★★ 中级 · 软件包：`e2fsprogs`（ext4）、`dosfstools`（FAT）

### 1. 作用

`mkfs`（make filesystem）在分区上创建文件系统，也就是“格式化”。分区之后、挂载之前必须做这一步。格式化会**清空分区上的全部数据**。

mkfs 实际上是一组命令，按文件系统类型区分：

| 命令 | 文件系统 | 用途 |
|---|---|---|
| `mkfs.ext4` | ext4 | Linux 默认，绝大多数场景 |
| `mkfs.xfs` | XFS | 大文件、高并发写入（需 `xfsprogs` 包） |
| `mkfs.vfat` | FAT32 | U 盘，和 Windows、相机通用 |
| `mkfs.exfat` | exFAT | 大于 4 GB 文件的 U 盘（需 `exfatprogs` 包） |

### 2. 基本格式

```bash
sudo mkfs.ext4 [参数] 分区
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-L 卷标` | 设置卷标（ext4、FAT 都支持；FAT 用 `-n`） |
| `-F` | 强制执行（目标是普通文件或已有文件系统时） |
| `-q` | 安静模式 |
| `-m 百分比` | ext4 给 root 保留的空间，默认 5%，数据盘可以设成 1 或 0 |

### 4. 常用示例

以镜像文件代替真实分区（root 身份）：

```
$ mkfs.ext4 part.img
mke2fs 1.47.2 (1-Jan-2025)
Discarding device blocks: done
Creating filesystem with 76800 4k blocks and 76800 inodes
Filesystem UUID: 207239f5-07da-4aa3-9f6d-9aa26b343d04
Superblock backups stored on blocks:
	32768

Allocating group tables: done
Writing inode tables: done
Creating journal (4096 blocks): done
Writing superblocks and filesystem accounting information: done
```

输出里的 UUID 是这个文件系统的唯一编号，写 /etc/fstab 时用。

格式化成 FAT32 的 U 盘：

```
$ mkfs.vfat -n USB fat.img
mkfs.fat 4.2 (2021-01-31)
```

对真实设备的写法：`sudo mkfs.ext4 -L data /dev/sdb1`。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 格式化了 `/dev/sdb`（整盘）而不是 `/dev/sdb1`（分区） | 设备名写错 | 用 `lsblk` 确认；分区名带数字 |
| `mkfs.xfs: command not found` | 默认没装 XFS 工具 | `sudo apt install xfsprogs` |
| 2 TB 的数据盘格式化后少了 100 GB | ext4 默认给 root 保留 5% | 数据盘用 `-m 1`，已格式化的用 `sudo tune2fs -m 1 分区` 调整 |

### 6. 一句话总结

`sudo mkfs.ext4 -L 卷标 分区` 格式化，执行前用 lsblk 再确认一次。

## 145 ★★&nbsp;&nbsp;blkid：查看分区的 UUID 和类型

> 级别：★★ 中级 · 软件包：`util-linux`

### 1. 作用

`blkid` 显示块设备（分区、磁盘、镜像）的文件系统类型、卷标和 UUID。写 /etc/fstab 时要用 UUID 而不是 /dev/sdb1 这样的设备名，因为设备名在增减硬盘后可能会变，UUID 不会。

### 2. 基本格式

```bash
sudo blkid [参数] [设备...]
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-s 标签` | 只显示某个字段，如 `-s UUID` |
| `-o value` | 只输出值，不输出 `UUID=` 这样的字段名 |

### 4. 常用示例

```
$ sudo blkid part.img fat.img
part.img: LABEL="data" UUID="87feca15-9d6f-46e6-a3df-1dc4b4a0b5dc" BLOCK_SIZE="4096" TYPE="ext4"
fat.img: SEC_TYPE="msdos" LABEL_FATBOOT="USB" LABEL="USB" UUID="6012-FC31" BLOCK_SIZE="512" TYPE="vfat"

$ sudo blkid -s UUID -o value part.img
87feca15-9d6f-46e6-a3df-1dc4b4a0b5dc
```

脚本里生成 fstab 条目：

```bash
UUID=$(sudo blkid -s UUID -o value /dev/sdb1)
echo "UUID=$UUID  /data  ext4  defaults  0  2" | sudo tee -a /etc/fstab
```

`lsblk -f` 也能看到 UUID，blkid 更适合在脚本里取值。

### 5. 一句话总结

写 fstab 前用 `sudo blkid -s UUID -o value 分区` 取 UUID。

## 146 ★★&nbsp;&nbsp;fsck：检查和修复文件系统

> 级别：★★ 中级 · 软件包：`util-linux`（fsck 前端）、`e2fsprogs`（e2fsck）

### 1. 作用

`fsck`（filesystem check）检查文件系统的一致性，发现问题时修复。异常断电、强制关机、磁盘出现坏道后，可能需要它。fsck 本身只是一个前端，会根据文件系统类型调用 `e2fsck`（ext4）、`fsck.vfat`（FAT）等具体工具。

**分区必须先卸载才能检查和修复**。对已挂载的分区执行修复，可能造成更严重的损坏。

### 2. 基本格式

```bash
sudo umount 分区
sudo fsck [参数] 分区
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-n` | 只检查，不修改（任何问题都回答“否”） |
| `-y` | 自动修复（所有问题都回答“是”） |
| `-f` | 即使文件系统标记为“干净”也强制检查 |

### 4. 常用示例

ext4 用 e2fsck 直接检查：

```
$ sudo e2fsck -f -n part.img
e2fsck 1.47.2 (1-Jan-2025)
Pass 1: Checking inodes, blocks, and sizes
Pass 2: Checking directory structure
Pass 3: Checking directory connectivity
Pass 4: Checking reference counts
Pass 5: Checking group summary information
data: 12/76800 files (0.0% non-contiguous), 9018/76800 blocks
```

5 个阶段都没有报错，最后一行是文件和块的使用情况。

FAT 格式的 U 盘：

```
$ sudo fsck.vfat -n fat.img
fsck.fat 4.2 (2021-01-31)
fat.img: 1 files, 0/51091 clusters
```

根分区无法在运行时卸载。要检查根分区，可以在开机时的 GRUB 菜单里按 `e`，在 `linux` 那一行末尾加上 `fsck.mode=force`，按 `Ctrl+X` 启动，systemd 会在挂载前检查所有文件系统。

> ⚠️ 根分区开机检查未实机验证。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 对挂载中的分区执行修复，数据损坏更严重 | 文件系统在使用中被修改 | 先 umount；根分区用救援模式或开机检查 |
| `fsck -y` 修复后，部分文件出现在 `lost+found` 目录里，文件名变成了数字 | 这些是丢失了目录信息的文件碎片 | 去 lost+found 里按内容找回 |
| 用 `fsck` 检查镜像文件，只输出了版本号 | fsck 前端没识别出类型 | 直接用对应的工具：`e2fsck`、`fsck.vfat` |

### 6. 一句话总结

先 umount，再 `fsck -n` 看问题，确认后 `fsck -y` 修复。

## 193 ★★&nbsp;&nbsp;swapon：启用和查看交换空间

> 级别：★★ 中级 · 软件包：`mount`

### 1. 作用

交换空间（swap）是磁盘上的一块区域，内存不够用时，系统把暂时不用的内存数据挪到这里。它能防止内存耗尽时程序被直接杀掉，代价是速度变慢。`swapon` 启用交换空间，`swapon --show` 查看当前正在用的交换空间。

Ubuntu 默认使用一个交换文件 `/swap.img` 或 `/swapfile`。

### 2. 基本格式

```bash
swapon --show                 # 查看
sudo swapon 文件或分区         # 启用
sudo swapoff 文件或分区        # 停用
```

### 3. 常用示例

```
$ swapon --show
NAME      TYPE SIZE USED PRIO
/swapfile file   2G   0B   -2
```

| 列 | 含义 |
|---|---|
| TYPE | `file` 交换文件，`partition` 交换分区 |
| SIZE / USED | 大小 / 已使用 |
| PRIO | 优先级，有多个交换空间时先用优先级高的 |

USED 持续很高，说明内存长期不够。

给一台 2 GB 内存的小服务器加 4 GB 交换文件的完整步骤：

```bash
sudo fallocate -l 4G /swapfile2
sudo chmod 600 /swapfile2
sudo mkswap /swapfile2
sudo swapon /swapfile2
echo '/swapfile2 none swap sw 0 0' | sudo tee -a /etc/fstab   # 开机自动启用
```

> ⚠️ 启用交换文件的步骤未实机验证（测试环境不允许 swapon），mkswap 部分已实测，见 [mkswap](#cmd-mkswap)。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `swapon: /root/swap.img: skipping - it appears to have holes.` | 交换文件是用 `truncate` 建的稀疏文件，内核不接受 | 用 `fallocate` 或 `dd` 创建 |
| `swapon: insecure permissions 0644, fix with: chmod 0600` | 交换文件里可能有内存中的敏感数据 | `chmod 600` |
| 加了 swap，数据库还是很慢 | swap 在磁盘上，比内存慢得多 | swap 只是兜底，根本办法是加内存或减少占用 |

> ⚠️ 第二条的提示文字未实机验证。

### 5. 一句话总结

`swapon --show` 看交换空间，交换文件用 fallocate 创建、权限 600。

## 194 ★★&nbsp;&nbsp;mkswap：创建交换空间

> 级别：★★ 中级 · 软件包：`util-linux`

### 1. 作用

`mkswap` 把一个文件或分区初始化成交换空间，相当于“交换空间的 mkfs”。初始化之后再用 [swapon](#cmd-swapon) 启用。

### 2. 基本格式

```bash
sudo mkswap 文件或分区
```

### 3. 常用示例

```
$ fallocate -l 64M swap2.img; chmod 600 swap2.img; mkswap swap2.img
Setting up swapspace version 1, size = 64 MiB (67104768 bytes)
no label, UUID=33ab4b3d-6710-4810-af7d-2e45c80e9dcf
```

### 4. ⚠️ 踩坑警告

用 `truncate` 创建的文件是稀疏文件（只记录大小，没有真正分配磁盘空间），mkswap 会给出警告，之后 swapon 也会拒绝：

```
$ truncate -s 64M swap.img; chmod 600 swap.img; mkswap swap.img

mkswap: swap.img contains holes or other unsupported extents.
        This swap file can be rejected by kernel on swap activation!
        Use --verbose for more details.

Setting up swapspace version 1, size = 64 MiB (67104768 bytes)
no label, UUID=97db84d7-339e-4270-982d-e4b290006498
```

创建交换文件用 `fallocate -l 大小 文件` 或 `dd if=/dev/zero of=文件 bs=1M count=大小`。

### 5. 一句话总结

`fallocate` 建文件 → `chmod 600` → `mkswap` → `swapon`。

## 195 ★★&nbsp;&nbsp;findmnt：查看挂载点

> 级别：★★ 中级 · 软件包：`util-linux`

### 1. 作用

`findmnt` 以树形列出当前所有的挂载：哪个设备挂在哪个目录、什么文件系统、什么选项。比 `mount` 的输出清楚，还能按目录、类型筛选。它还有一个重要功能：`findmnt --verify` 检查 /etc/fstab 有没有写错。

### 2. 基本格式

```bash
findmnt [参数] [目录或设备]
```

### 3. 常用参数

| 参数 | 作用 |

### 4. 常用示例

普通 Ubuntu 机器上，`findmnt /` 显示的是根分区设备（如 `/dev/sda2`）和 ext4。

改完 /etc/fstab 后检查：

```
$ sudo findmnt --verify
Success, no errors or warnings detected
```

### 5. 一句话总结

`findmnt 目录` 查挂载，改完 fstab 一定先 `findmnt --verify`。

## 196 ★★&nbsp;&nbsp;ncdu：交互式查看磁盘占用

> 级别：★★ 中级 · 软件包：`ncdu`（1.22，需 `sudo apt install ncdu`）

### 1. 作用

`ncdu`（NCurses Disk Usage）扫描一个目录，然后用全屏界面列出每个子目录和文件的大小，按大小排序。可以用方向键进入子目录、一层层往下找，找到占空间的东西还能直接按 `d` 删除。磁盘满了的时候，它比反复执行 `du -sh *` 方便得多。

### 2. 基本格式

```bash
ncdu [参数] [目录]
```

### 3. 常用参数和按键

| 参数 | 作用 |
|---|---|
| `-x` | 不跨越到其他文件系统（扫描 / 时不进入挂载的网络盘） |
| `-o 文件` | 把扫描结果导出到文件，不打开界面 |
| `-f 文件` | 读取之前导出的结果查看 |

| 按键 | 作用 |
|---|---|
| `↑` `↓` / 回车 | 选择 / 进入目录 |
| `←` | 返回上一级 |
| `d` | 删除选中的文件或目录（会确认） |
| `g` | 切换显示百分比和条形图 |
| `q` | 退出 |

### 4. 常用示例

```bash
sudo ncdu -x /          # 磁盘满了，从根目录开始找
ncdu ~                  # 看家目录里什么最大
```

在服务器上扫描一次，导出结果后慢慢看：

```
$ ncdu -o- /home/tom/demo | head -c 300
[1,2,{"progname":"ncdu","progver":"1.22","timestamp":1793263119},
[{"name":"/home/tom/demo","asize":180,"dev":118},
{"name":"link.txt","asize":10,"notreg":true},
{"name":"run.sh","asize":20,"dsize":4096},
{"name":".env","asize":12,"dsize":4096},
{"name":"big.iso","asize":2500000,"dsize":2502656},
...
```

`-o-` 表示导出到标准输出。导出的是 JSON，`asize` 是文件的实际大小，`dsize` 是占用的磁盘空间。

> ⚠️ 全屏界面部分未实机验证。

### 5. 一句话总结

磁盘满了用 `sudo ncdu -x /` 一层层找，找到了按 `d` 删除。

## 208 ★&nbsp;&nbsp;lvcreate：创建 LVM 逻辑卷

> 级别：★ 高级 · 软件包：`lvm2`（LVM 2.03）

### 1. 作用

LVM（Logical Volume Manager，逻辑卷管理）在物理磁盘和文件系统之间加了一层，让磁盘空间可以像“资金池”一样灵活分配：几块硬盘合成一个大池子，从中划出若干逻辑卷，空间不够时在线扩容。Ubuntu 服务器版安装时默认就用 LVM（根分区是 `/dev/mapper/ubuntu--vg-ubuntu--lv`）。

三层结构：

| 层 | 命令 | 含义 |
|---|---|---|
| PV（物理卷） | [pvcreate](#cmd-pvcreate) | 一块磁盘或分区，交给 LVM 管理 |
| VG（卷组） | [vgcreate](#cmd-vgcreate) | 若干 PV 组成的存储池 |
| LV（逻辑卷） | `lvcreate` | 从卷组里划出来的“虚拟分区”，在上面格式化、挂载 |

`lvcreate` 负责最后一步：从卷组里划出逻辑卷。

### 2. 基本格式

```bash
sudo lvcreate -L 大小 -n 名称 卷组
sudo lvcreate -l 100%FREE -n 名称 卷组
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-L 大小` | 指定大小，如 `-L 50G` |
| `-l 比例` | 按比例，如 `-l 100%FREE`（剩余全部）、`-l 50%VG` |
| `-n 名称` | 逻辑卷名称 |
| `-s` | 创建快照，如 `lvcreate -s -L 5G -n snap /dev/vg0/data` |

查看命令：`lvs`、`vgs`、`pvs`（简要），`lvdisplay`（详细）。

### 4. 常用示例

新加一块硬盘 /dev/sdb，从零建一个 /data：

```bash
sudo pvcreate /dev/sdb
sudo vgcreate vg_data /dev/sdb
sudo lvcreate -l 100%FREE -n lv_data vg_data
sudo mkfs.ext4 /dev/vg_data/lv_data
sudo mkdir /data
sudo mount /dev/vg_data/lv_data /data
sudo lvs
```

逻辑卷的设备路径有两种写法，指向同一个设备：`/dev/vg_data/lv_data` 和 `/dev/mapper/vg_data-lv_data`。

> ⚠️ 本页未实机验证：LVM 需要内核的 device-mapper，测试环境的容器里不可用（`pvcreate` 报 `/dev/mapper/control: open failed: Permission denied`）。命令写法已对照 LVM 2.03 的手册核实。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| Ubuntu 装好后根分区只有 100 GB 左右，但磁盘有 1 TB | 安装程序默认只给根逻辑卷分配一部分空间，其余留在卷组里 | `sudo vgs` 看 VFree，用 [lvextend](#cmd-lvextend) 扩容 |
| 快照放了很久之后失效 | 快照空间写满就会失效 | 快照只用于短期（如升级前），用完 `lvremove` 删除 |

### 6. 一句话总结

LVM 三步：`pvcreate` → `vgcreate` → `lvcreate -l 100%FREE`，再格式化挂载。

## 209 ★&nbsp;&nbsp;pvcreate：把磁盘初始化为 LVM 物理卷

> 级别：★ 高级 · 软件包：`lvm2`

### 1. 作用

`pvcreate` 在磁盘或分区上写入 LVM 标记，把它变成 PV（物理卷），之后才能加入卷组。**会覆盖磁盘上原有的数据。**

### 2. 基本格式

```bash
sudo pvcreate 设备...
sudo pvs                  # 查看所有物理卷
sudo pvdisplay 设备       # 详细信息
```

### 3. 常用示例

```bash
lsblk                         # 确认新磁盘是 /dev/sdb，且没有在使用
sudo pvcreate /dev/sdb
sudo pvs
```

`pvs` 的输出包括 PV（设备）、VG（属于哪个卷组，刚创建时为空）、PSize（大小）、PFree（未分配的空间）。

> ⚠️ 本页未实机验证，原因同 [lvcreate](#cmd-lvcreate)。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `Device /dev/sdb excluded by a filter` | 磁盘上还有旧的分区表或文件系统签名 | 确认数据不要了，用 [wipefs](#cmd-wipefs) `-a` 清除后再 pvcreate |

### 5. 一句话总结

`sudo pvcreate /dev/sdb` 把新盘交给 LVM，执行前用 lsblk 确认。

## 210 ★&nbsp;&nbsp;vgcreate：创建 LVM 卷组

> 级别：★ 高级 · 软件包：`lvm2`

### 1. 作用

`vgcreate` 把一个或多个物理卷合成一个卷组（存储池）。之后可以用 `vgextend` 往池子里继续加磁盘，空间直接变大，上面的逻辑卷随时可以扩容。

### 2. 基本格式

```bash
sudo vgcreate 卷组名 物理卷...
sudo vgextend 卷组名 新物理卷     # 加盘
sudo vgs                         # 查看
```

### 3. 常用示例

```bash
sudo vgcreate vg_data /dev/sdb /dev/sdc   # 两块盘合成一个卷组
sudo vgs
```

`vgs` 的 VSize 是卷组总大小，VFree 是还没分给逻辑卷的空间。

磁盘不够用了，再加一块：

```bash
sudo pvcreate /dev/sdd
sudo vgextend vg_data /dev/sdd
```

> ⚠️ 本页未实机验证，原因同 [lvcreate](#cmd-lvcreate)。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 卷组里的一块盘坏了，整个卷组的数据都受影响 | LVM 本身不做冗余，数据可能分布在所有盘上 | 重要数据在下层用 RAID（[mdadm](#cmd-mdadm) 或硬件 RAID），或做好备份 |

### 5. 一句话总结

`vgcreate 卷组 盘...` 建存储池，空间不够 `vgextend` 加盘。

## 211 ★&nbsp;&nbsp;lvextend：在线扩容逻辑卷

> 级别：★ 高级 · 软件包：`lvm2`

### 1. 作用

`lvextend` 把逻辑卷变大，**不需要卸载、不需要停机**。加上 `-r` 参数，会在扩大逻辑卷之后自动扩展上面的文件系统（ext4 调用 resize2fs，XFS 调用 xfs_growfs）。这是 LVM 最实用的功能：磁盘告警时，几秒钟就能把空间加上。

### 2. 基本格式

```bash
sudo lvextend -r -L +大小 逻辑卷
sudo lvextend -r -l +100%FREE 逻辑卷
```

| 参数 | 作用 |
|---|---|
| `-L +20G` | 增加 20 GB（不写 `+` 则表示扩到 20 GB） |
| `-l +100%FREE` | 用掉卷组里剩余的全部空间 |
| `-r` | 同时扩展文件系统 |

### 3. 常用示例

Ubuntu 服务器默认安装后，把根分区扩到用满整个卷组：

```bash
sudo vgs                                                    # 确认 VFree 还有空间
sudo lvextend -r -l +100%FREE /dev/ubuntu-vg/ubuntu-lv
df -h /                                                     # 确认变大了
```

云服务器把磁盘从 100 GB 扩到 200 GB 后的完整步骤：

```bash
sudo growpart /dev/sda 3          # 1. 扩分区（第 3 个分区是 LVM 的 PV）
sudo pvresize /dev/sda3           # 2. 让 PV 识别新大小
sudo lvextend -r -l +100%FREE /dev/ubuntu-vg/ubuntu-lv   # 3. 扩逻辑卷和文件系统
```

> ⚠️ 本页未实机验证，原因同 [lvcreate](#cmd-lvcreate)。分区号以 `lsblk` 显示的为准。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| lvextend 成功了，`df -h` 显示的大小没变 | 没加 `-r`，只扩了逻辑卷，没扩文件系统 | 补执行 `sudo resize2fs 逻辑卷`（ext4）或 `sudo xfs_growfs 挂载点`（XFS） |
| 想缩小 XFS 的逻辑卷 | XFS 不支持缩小 | 只能备份、重建、恢复；规划空间时宁小勿大，以后再扩 |

### 5. 一句话总结

空间不够：`sudo lvextend -r -l +100%FREE 逻辑卷`，一定带 `-r`。

## 212 ★&nbsp;&nbsp;resize2fs：调整 ext4 文件系统的大小

> 级别：★ 高级 · 软件包：`e2fsprogs`

### 1. 作用

`resize2fs` 调整 ext2/ext3/ext4 文件系统的大小。分区或逻辑卷变大之后，文件系统不会自动跟着变大，要用它扩展。它也能缩小文件系统（必须先卸载）。

### 2. 基本格式

```bash
sudo resize2fs 设备 [新大小]
```

不写大小时，扩展到占满整个分区或逻辑卷。

| 参数 | 作用 |
|---|---|
| `-P` | 估算这个文件系统最小能缩到多大 |
| `-p` | 显示进度 |

### 3. 常用示例

用镜像文件演示（root 身份）。先建一个 300 MB 的 ext4，再把“分区”扩到 600 MB：

```
$ truncate -s 300M e.img; mkfs.ext4 -q -F e.img; dumpe2fs -h e.img 2>/dev/null | grep -E "^(Block count|Block size)"
Block count:              76800
Block size:               4096

$ truncate -s 600M e.img; resize2fs e.img
resize2fs 1.47.2 (1-Jan-2025)
Resizing the filesystem on e.img to 153600 (4k) blocks.
The filesystem on e.img is now 153600 (4k) blocks long.
```

76800 块 × 4 KB = 300 MB，扩展后 153600 块 = 600 MB。

缩小到 200 MB：

```
$ resize2fs e.img 200M
resize2fs 1.47.2 (1-Jan-2025)
Resizing the filesystem on e.img to 51200 (4k) blocks.
The filesystem on e.img is now 51200 (4k) blocks long.

$ resize2fs -P e.img
resize2fs 1.47.2 (1-Jan-2025)
Estimated minimum size of the filesystem: 10672
```

`-P` 估算的最小值单位也是块（10672 × 4 KB ≈ 42 MB）。

已挂载的文件系统只能在线**扩大**；缩小必须先 umount，并且先 `e2fsck -f` 检查。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 先缩小了分区，再缩文件系统，数据损坏 | 顺序错了：分区比文件系统小，尾部数据丢失 | 缩小时：先缩文件系统，再缩分区；扩大时：先扩分区，再扩文件系统 |
| 对 XFS 执行 resize2fs 报错 | resize2fs 只支持 ext 系列 | XFS 用 [xfs_growfs](#cmd-xfs_growfs) |

### 5. 一句话总结

分区扩大后 `sudo resize2fs 设备` 让 ext4 跟着变大；缩小前先卸载。

## 213 ★&nbsp;&nbsp;xfs_growfs：扩容 XFS 文件系统

> 级别：★ 高级 · 软件包：`xfsprogs`（6.18）

### 1. 作用

`xfs_growfs` 扩展 XFS 文件系统，作用和 resize2fs 相同，有两点不同：

- 参数是**挂载点**，不是设备，而且文件系统必须处于挂载状态；
- XFS **只能扩大，不能缩小**。

### 2. 基本格式

```bash
sudo xfs_growfs 挂载点
```

### 3. 常用示例

```bash
sudo lvextend -L +50G /dev/vg_data/lv_data
sudo xfs_growfs /data
df -h /data
```

对没有挂载的镜像文件执行，会直接报错：

```
$ xfs_growfs x.img
xfs_growfs: x.img is not a mounted XFS filesystem
```

查看 XFS 的参数用 `xfs_info`：

```
$ xfs_info x.img | head -2
meta-data=x.img                  isize=512    agcount=4, agsize=25600 blks
         =                       sectsz=512   attr=2, projid32bit=1
```

> ⚠️ 实际扩容未实机验证（测试环境不能挂载）。

### 4. 一句话总结

XFS 扩容用 `sudo xfs_growfs 挂载点`，它只能变大不能变小。

## 214 ★&nbsp;&nbsp;mdadm：管理软件 RAID

> 级别：★ 高级 · 软件包：`mdadm`（4.5）

### 1. 作用

`mdadm` 把多块硬盘组成软件 RAID（由操作系统而不是 RAID 卡实现）。常用的级别：

| 级别 | 最少盘数 | 可用容量 | 能坏几块 | 用途 |
|---|---|---|---|---|
| RAID 1 | 2 | 1 块盘 | 1 块 | 系统盘、小数据量的高可靠 |
| RAID 5 | 3 | N−1 块 | 1 块 | 容量和可靠性折中 |
| RAID 6 | 4 | N−2 块 | 2 块 | 大容量盘 |
| RAID 10 | 4 | N/2 块 | 每组镜像坏 1 块 | 数据库，读写都快 |

RAID 防的是硬盘损坏，不能代替备份（误删、勒索病毒、整机损坏都防不住）。

### 2. 基本格式

```bash
sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb /dev/sdc
cat /proc/mdstat                       # 状态和同步进度
sudo mdadm --detail /dev/md0           # 详细信息
```

### 3. 常用操作

| 命令 | 作用 |
|---|---|
| `mdadm --detail /dev/md0` | 每块盘的状态（active、faulty、spare） |
| `mdadm /dev/md0 --fail /dev/sdb` | 把一块盘标记为故障 |
| `mdadm /dev/md0 --remove /dev/sdb` | 移除故障盘 |
| `mdadm /dev/md0 --add /dev/sdd` | 加入新盘，自动开始重建 |
| `mdadm --detail --scan >> /etc/mdadm/mdadm.conf` | 保存配置，开机自动组装 |

换盘流程：

```bash
sudo mdadm /dev/md0 --fail /dev/sdb --remove /dev/sdb
# 关机换盘（支持热插拔则直接换）
sudo mdadm /dev/md0 --add /dev/sdb
watch cat /proc/mdstat          # 观察重建进度
```

> ⚠️ 本页未实机验证：mdadm 需要真实的块设备，测试环境里用镜像文件创建时报 `mdadm: r1.img is not a block device.`，`/proc/mdstat` 为空。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 重启后 /dev/md0 变成了 /dev/md127 | 没有把阵列写进 mdadm.conf | 执行上表最后一条，再 `sudo update-initramfs -u` |
| 一块盘坏了很久都没人发现，第二块也坏了 | 没有监控 | 配置 `MAILADDR` 让 mdadm 发邮件，或用监控系统检查 /proc/mdstat 里的 `[U_]` |

### 5. 一句话总结

软 RAID 用 mdadm，`cat /proc/mdstat` 常看，RAID 不能代替备份。

## 215 ★&nbsp;&nbsp;cryptsetup：LUKS 磁盘加密

> 级别：★ 高级 · 软件包：`cryptsetup`

### 1. 作用

`cryptsetup` 用 LUKS（Linux Unified Key Setup）格式加密整个分区或磁盘。加密后，硬盘或笔记本丢失，别人拿到也读不出数据。Ubuntu 安装时勾选“加密磁盘”用的就是它。

使用流程：格式化成 LUKS → 用密码打开，得到一个解密后的设备 `/dev/mapper/名称` → 在这个设备上建文件系统、挂载。

### 2. 基本格式

```bash
sudo cryptsetup luksFormat 设备              # 加密（清空原数据）
sudo cryptsetup open 设备 名称               # 解锁，得到 /dev/mapper/名称
sudo cryptsetup close 名称                   # 锁上
sudo cryptsetup luksDump 设备                # 查看加密信息
```

### 3. 常用示例

在镜像文件上演示格式化和查看（root 身份）：

```
$ echo -n 'Luks@2026' | cryptsetup luksFormat --batch-mode --key-file=- c.img; echo rc=$?
rc=0

$ cryptsetup luksDump c.img | head -12
LUKS header information
Version:       	2
Epoch:         	3
Metadata area: 	16384 [bytes]
Keyslots area: 	16744448 [bytes]
UUID:          	26aa2ac0-ceea-4fab-82f8-c69215838a28
Label:         	(no label)
Subsystem:     	(no subsystem)
Flags:       	(no flags)

Data segments:
  0: crypt

$ cryptsetup isLuks c.img && echo 是LUKS
是LUKS
```

真实磁盘上的完整流程：

```bash
sudo cryptsetup luksFormat /dev/sdb1          # 输入 YES 确认，再设置密码
sudo cryptsetup open /dev/sdb1 secret
sudo mkfs.ext4 /dev/mapper/secret
sudo mount /dev/mapper/secret /secure
# 用完后
sudo umount /secure
sudo cryptsetup close secret
```

一个 LUKS 设备可以有多个密码槽：`sudo cryptsetup luksAddKey /dev/sdb1` 再加一个备用密码。

> ⚠️ open 及之后的步骤未实机验证：测试环境没有 device-mapper，`cryptsetup open` 报 `Cannot initialize device-mapper. Is dm_mod kernel module loaded?`。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 忘了密码，数据永远打不开 | 加密的意义就在这里，没有后门 | 用 `luksAddKey` 加一个备用密码妥善保管；备份 LUKS 头：`cryptsetup luksHeaderBackup 设备 --header-backup-file 文件` |
| LUKS 头所在的扇区损坏，有密码也打不开 | 密钥信息存在头部 | 同上，提前备份头部 |

### 5. 一句话总结

`luksFormat` 加密、`open` 解锁、`close` 锁上，务必备份 LUKS 头和备用密码。

<a id="cmd-zfs"></a>

## 216 ★&nbsp;&nbsp;zfs：ZFS 数据集管理

> 级别：★ 高级 · 软件包：`zfsutils-linux`（需 `sudo apt install zfsutils-linux`）

### 1. 作用

ZFS 是集卷管理和文件系统于一体的存储系统，自带校验（能发现并修复静默的数据损坏）、压缩、快照、克隆、配额。Ubuntu 官方支持 ZFS，常用于 NAS、备份服务器、数据库数据盘。

ZFS 分两层：[zpool](#cmd-zpool) 管磁盘组成的存储池，`zfs` 管池里的**数据集**（dataset，相当于一个可以独立设置属性的文件系统）。

### 2. 常用命令

| 命令 | 作用 |
|---|---|
| `zfs list` | 列出数据集和使用量 |
| `zfs create 池/名称` | 新建数据集，自动挂载到 /池/名称 |
| `zfs set compression=lz4 池/名称` | 开启压缩 |
| `zfs set quota=100G 池/名称` | 设置配额 |
| `zfs snapshot 池/名称@快照名` | 创建快照（瞬间完成，几乎不占空间） |
| `zfs list -t snapshot` | 列出快照 |
| `zfs rollback 池/名称@快照名` | 回滚到快照 |
| `zfs send 快照 \| ssh 远程 zfs recv 池/名称` | 把快照复制到另一台机器（备份） |
| `zfs destroy 池/名称@快照名` | 删除快照 |

### 3. 常用示例

```bash
sudo zfs create tank/mysql
sudo zfs set compression=lz4 tank/mysql
sudo zfs snapshot tank/mysql@before-upgrade
# 升级出问题时
sudo zfs rollback tank/mysql@before-upgrade
```

> ⚠️ 本页未实机验证：ZFS 需要内核模块，测试环境不具备。命令写法为 OpenZFS 的标准用法。

### 4. 一句话总结

ZFS 数据集用 `zfs create`，改动前 `zfs snapshot`，出错 `zfs rollback`。

<a id="cmd-zpool"></a>

## 217 ★&nbsp;&nbsp;zpool：ZFS 存储池管理

> 级别：★ 高级 · 软件包：`zfsutils-linux`

### 1. 作用

`zpool` 把磁盘组成 ZFS 存储池，并管理池的冗余方式、状态和数据校验。

| 冗余方式 | 相当于 |
|---|---|
| `mirror` | RAID 1 |
| `raidz` / `raidz2` / `raidz3` | 允许坏 1 / 2 / 3 块盘，类似 RAID 5 / 6 |

### 2. 常用命令

| 命令 | 作用 |
|---|---|
| `zpool create tank mirror /dev/sdb /dev/sdc` | 用两块盘建镜像池 |
| `zpool status` | 每块盘的健康状态、错误计数 |
| `zpool list` | 容量和使用率 |
| `zpool scrub tank` | 读一遍所有数据并校验，发现损坏自动修复 |
| `zpool replace tank 旧盘 新盘` | 换盘 |
| `zpool import` / `export` | 把池迁移到另一台机器 |

### 3. 常用示例

```bash
sudo zpool create tank mirror /dev/disk/by-id/ata-盘1 /dev/disk/by-id/ata-盘2
sudo zpool status
sudo zpool scrub tank           # 建议每月执行一次
```

建池时用 `/dev/disk/by-id/` 下的名字而不是 /dev/sdb，设备名变化时池不会出问题。

> ⚠️ 本页未实机验证，原因同 [zfs](#cmd-zfs)。

### 4. 一句话总结

`zpool create 池 mirror 盘 盘` 建池，`zpool status` 看健康，每月 `scrub`。

## 218 ★&nbsp;&nbsp;btrfs：Btrfs 文件系统管理

> 级别：★ 高级 · 软件包：`btrfs-progs`（6.17）

### 1. 作用

Btrfs 是 Linux 内核自带的现代文件系统，功能和 ZFS 类似：写时复制、子卷（subvolume）、快照、透明压缩、数据校验、多盘。它不需要额外的内核模块。`btrfs` 命令管理这些功能。

### 2. 常用命令

| 命令 | 作用 |
|---|---|
| `mkfs.btrfs -L 卷标 设备` | 格式化 |
| `btrfs filesystem show` | 列出 Btrfs 文件系统 |
| `btrfs filesystem usage 挂载点` | 详细的空间使用情况 |
| `btrfs subvolume create 路径` | 新建子卷 |
| `btrfs subvolume snapshot 源 目标` | 快照（加 `-r` 为只读快照） |
| `btrfs subvolume list 挂载点` | 列出子卷和快照 |
| `btrfs scrub start 挂载点` | 校验数据 |

### 3. 常用示例

格式化和查看（镜像文件演示，root 身份）：

```
$ mkfs.btrfs -L data b.img
btrfs-progs v6.17.1
See https://btrfs.readthedocs.io for more information.

Label:              data
UUID:               7dfbe0a1-49ee-4ff2-9bf3-b2005c07479b
Node size:          16384
Sector size:        4096	(CPU page size: 4096)
Filesystem size:    1.00GiB
Block group profiles:
  Data:             single            8.00MiB
  Metadata:         DUP              51.19MiB
  System:           DUP               8.00MiB
...

$ btrfs filesystem show b.img
Label: 'data'  uuid: 7dfbe0a1-49ee-4ff2-9bf3-b2005c07479b
	Total devices 1 FS bytes used 144.00KiB
	devid    1 size 1.00GiB used 126.38MiB path /root/b.img
```

`Metadata: DUP` 表示元数据存了两份，单盘时也能防止一部分损坏。

挂载后使用快照：

```bash
sudo btrfs subvolume create /data/www
sudo btrfs subvolume snapshot -r /data/www /data/.snap/www-20261029
sudo btrfs subvolume list /data
```

> ⚠️ 挂载后的子卷和快照操作未实机验证（测试环境不能挂载）。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `df -h` 显示还有空间，写入却报 `No space left on device` | Btrfs 的元数据空间单独分配，用完了 | 用 `btrfs filesystem usage` 查看；`btrfs balance start -dusage=50 挂载点` 回收 |
| 把快照当成了备份 | 快照和原数据在同一块盘上，盘坏了一起没 | 用 `btrfs send` 把快照发到另一台机器 |

### 5. 一句话总结

Btrfs 用子卷和快照管理数据，空间问题看 `btrfs filesystem usage`。

## 255 ★&nbsp;&nbsp;smartctl：检查硬盘健康

> 级别：★ 高级 · 软件包：`smartmontools`（7.5）

### 1. 作用

硬盘和 SSD 内部有 S.M.A.R.T. 自检系统，记录坏扇区数量、通电时间、温度、写入总量、剩余寿命等。`smartctl` 读取这些数据，并能启动硬盘自检。硬盘坏之前通常会有征兆，定期看 smartctl 能提前换盘。

需要 sudo；云服务器的虚拟磁盘一般读不到。

### 2. 常用命令

| 命令 | 作用 |
|---|---|
| `smartctl -H 设备` | 只看总体健康结论（PASSED / FAILED） |
| `smartctl -a 设备` | 全部信息 |
| `smartctl -t short 设备` | 启动约 2 分钟的短自检 |
| `smartctl -l selftest 设备` | 查看自检结果 |

### 3. 常用示例

```bash
sudo smartctl -H /dev/sda
sudo smartctl -a /dev/nvme0n1
```

机械硬盘重点看这几项属性：

| 属性 | 含义 |
|---|---|
| Reallocated_Sector_Ct | 已重新映射的坏扇区数，不为 0 且在增长就要换盘 |
| Current_Pending_Sector | 等待重新映射的不稳定扇区 |
| Power_On_Hours | 通电小时数 |

NVMe SSD 看 `Percentage Used`（已用寿命百分比）和 `Media and Data Integrity Errors`。

> ⚠️ 本页未实机验证：测试环境是云服务器上的容器，`smartctl -a /dev/nvme0n1` 报 `No such device`。

### 4. 一句话总结

定期 `sudo smartctl -H 磁盘`，坏扇区在增长就换盘。

## 256 ★&nbsp;&nbsp;hdparm：查看磁盘参数和测速

> 级别：★ 高级 · 软件包：`hdparm`（9.65）

### 1. 作用

`hdparm` 查看和设置 SATA/IDE 硬盘的参数（型号、缓存、省电设置），也常用来粗略测试读取速度。NVMe 固态硬盘的大部分参数要用 [nvme](#cmd-nvme) 工具查看。

### 2. 常用命令

| 命令 | 作用 |
|---|---|
| `hdparm -I 设备` | 硬盘的详细信息 |
| `hdparm -tT 设备` | 测试读取速度：`-T` 缓存读取，`-t` 磁盘实际读取 |
| `hdparm -W 设备` | 查看写缓存是否开启 |

### 3. 常用示例

```bash
sudo hdparm -tT /dev/sda
```

输出会给出两个速度：Timing cached reads（内存缓存的速度，很高）和 Timing buffered disk reads（磁盘实际顺序读取速度，机械硬盘一般 100–250 MB/s，SATA SSD 约 500 MB/s）。

> ⚠️ 本页未实机验证（测试环境没有真实磁盘设备）。

### 4. 一句话总结

粗测磁盘读速用 `sudo hdparm -tT 设备`，NVMe 用 nvme 工具。

## 257 ★&nbsp;&nbsp;nvme：管理 NVMe 固态硬盘

> 级别：★ 高级 · 软件包：`nvme-cli`（2.16）

### 1. 作用

`nvme` 是 NVMe 固态硬盘的管理工具：列出所有 NVMe 设备、读取健康日志（温度、寿命、错误）、查看固件版本、安全擦除。

### 2. 常用命令

| 命令 | 作用 |
|---|---|
| `nvme list` | 列出 NVMe 设备、型号、容量、固件版本 |
| `nvme smart-log 设备` | 健康日志 |
| `nvme id-ctrl 设备` | 控制器的详细信息 |
| `nvme format 设备` | 低级格式化（清空全部数据） |

### 3. 常用示例

```bash
sudo nvme list
sudo nvme smart-log /dev/nvme0
```

smart-log 里重点看：

| 字段 | 含义 |
|---|---|
| temperature | 温度，长期超过 70°C 要注意散热 |
| percentage_used | 已用寿命，到 100% 后厂商不再保证可靠性 |
| media_errors | 介质错误数，不为 0 需要关注 |
| unsafe_shutdowns | 异常断电次数 |

> ⚠️ 本页未实机验证：测试环境的容器打不开 NVMe 设备（`Failed to open ns nvme0n1, errno 2`）。

### 4. 一句话总结

NVMe 看健康：`sudo nvme smart-log /dev/nvme0`，关注 percentage_used 和 media_errors。

## 292 ★&nbsp;&nbsp;losetup：把文件当作磁盘使用

> 级别：★ 高级 · 软件包：`mount`

### 1. 作用

`losetup` 把一个普通文件关联到回环设备（`/dev/loop0`、`/dev/loop1`……），这个文件就可以像一块真的磁盘一样分区、格式化、挂载。用途：挂载 ISO 镜像或虚拟机磁盘镜像查看里面的文件、做文件系统实验、snap 软件包也是这样挂载的。

### 2. 常用命令

| 命令 | 作用 |
|---|---|
| `losetup -f` | 显示下一个空闲的回环设备 |
| `losetup -fP 文件` | 关联到空闲设备，`-P` 同时识别里面的分区 |
| `losetup -a` 或 `losetup -l` | 列出所有已关联的设备 |
| `losetup -d /dev/loopN` | 解除关联 |

### 3. 常用示例

```bash
sudo losetup -fP --show disk.img       # 输出分配到的设备，如 /dev/loop3
lsblk /dev/loop3                       # 能看到 loop3p1、loop3p2 两个分区
sudo mount /dev/loop3p2 /mnt
# 用完后
sudo umount /mnt
sudo losetup -d /dev/loop3
```

挂载 ISO 时 mount 会自动调用 losetup，所以直接 `sudo mount -o loop ubuntu.iso /mnt` 即可。

> ⚠️ 本页未实机验证：测试环境不允许创建回环设备。

### 4. 一句话总结

`sudo losetup -fP --show 镜像` 把镜像变成磁盘，用完 `losetup -d`。

## 293 ★&nbsp;&nbsp;wipefs：清除磁盘上的文件系统签名

> 级别：★ 高级 · 软件包：`util-linux`

### 1. 作用

每种文件系统、分区表、RAID、LVM 都会在磁盘的特定位置写一个“签名”，系统靠它识别磁盘上是什么。`wipefs` 列出或清除这些签名。一块旧盘要重新使用，pvcreate、mkfs、mdadm 因为检测到旧签名而拒绝时，用它先清干净。

它只擦除签名的几个字节，速度很快，但磁盘会因此被识别为“空盘”，**原有数据等于丢失**。

### 2. 基本格式

```bash
sudo wipefs 设备            # 列出签名
sudo wipefs -n -a 设备      # 模拟清除，看会擦掉什么
sudo wipefs -a 设备         # 清除全部签名
```

### 3. 常用示例

镜像文件演示（root 身份），e.img 是 ext4，b.img 是 Btrfs：

```
$ wipefs e.img b.img
DEVICE OFFSET  TYPE  UUID                                 LABEL
e.img  0x438   ext4  b2b1424b-56a0-4454-a532-81ebcf1dae5f
b.img  0x10040 btrfs 7dfbe0a1-49ee-4ff2-9bf3-b2005c07479b data

$ wipefs -a b.img
b.img: 8 bytes were erased at offset 0x00010040 (btrfs): 5f 42 48 52 66 53 5f 4d

$ blkid b.img; echo "blkid退出码=$?"
blkid退出码=2
```

只擦了 8 个字节，blkid 就已经认不出这是 Btrfs 了。

### 4. 一句话总结

旧盘重用前 `sudo wipefs -a 设备` 清签名，先用 `-n` 预览，确认设备名。

## 294 ★&nbsp;&nbsp;sgdisk：用命令行脚本化管理 GPT 分区

> 级别：★ 高级 · 软件包：`gdisk`

### 1. 作用

`sgdisk` 是 gdisk 的非交互版本，用一条命令完成 GPT 分区，还能备份和恢复分区表、清除分区表。适合写进装机脚本、批量给新服务器的数据盘分区。

### 2. 常用参数

| 参数 | 作用 |
|---|---|
| `-p` | 显示分区表 |
| `-n 编号:起点:终点` | 新建分区，`0` 表示默认值，`+100M` 表示大小 |
| `-t 编号:类型码` | 分区类型：`8300` Linux、`ef00` EFI、`8200` swap、`8e00` LVM |
| `-c 编号:名称` | 分区名称 |
| `-Z` | 清除 GPT 和 MBR 分区表 |
| `--backup=文件` / `--load-backup=文件` | 备份 / 恢复分区表 |

### 3. 常用示例

镜像文件演示（root 身份）：建一个 100 MB 的 EFI 分区，剩余空间给 Linux：

```
$ sgdisk -n 1:0:+100M -t 1:ef00 -c 1:EFI -n 2:0:0 -t 2:8300 -c 2:root g.img
Creating new GPT entries in memory.
...
The operation has completed successfully.

$ sgdisk -p g.img
Disk g.img: 2097152 sectors, 1024.0 MiB
Sector size (logical): 512 bytes
...
Number  Start (sector)    End (sector)  Size       Code  Name
   1            2048          206847   100.0 MiB   EF00  EFI
   2          206848         2097118   923.0 MiB   8300  root
```

备份分区表，误操作后可以恢复：

```
$ sgdisk --backup=/root/g.gpt g.img
The operation has completed successfully.
```

### 4. 一句话总结

脚本里给 GPT 分区用 `sgdisk -n -t -c`，动手前 `--backup` 备份分区表。
