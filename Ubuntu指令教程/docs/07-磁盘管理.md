## 025 ★★★&nbsp;&nbsp;df：查看磁盘空间

> 级别：★★★ 初级 · 软件包：`gnu-coreutils`（Ubuntu 26.04 的 df 仍由 GNU 版提供）

### 1. 作用

`df`（disk free）显示每个已挂载的文件系统总共多大、用了多少、还剩多少。程序报 `No space left on device`，或者服务器监控报警“磁盘使用率 90%”时，先用 df 看是哪个分区满了。

df 看的是整个分区；要知道分区里**哪个目录**占得多，用 [du](#cmd-du)。

### 2. 基本格式

```bash
df [参数] [目录或设备...]
```

指定目录时，只显示该目录所在的分区。

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-h` | `--human-readable` | 用 K、M、G 显示大小 |
| `-T` | `--print-type` | 显示文件系统类型（ext4、xfs、tmpfs 等） |
| `-i` | `--inodes` | 显示 inode（文件个数）的使用情况 |
| `-x 类型` | `--exclude-type` | 不显示某类文件系统，如 `-x tmpfs` |

### 4. 常用示例

> 以下输出来自测试环境，设备名和容量与真实服务器不同。在普通 Ubuntu 机器上，根目录一般显示为 `/dev/sda2`、`/dev/nvme0n1p2` 或 `/dev/mapper/ubuntu--vg-ubuntu--lv`，类型为 ext4。

#### 4.1 `df -h`：看全部分区

```
$ df -h
Filesystem      Size  Used Avail Use% Mounted on
/dev/loop1       87G  1.3G   86G   2% /
tmpfs            16G     0   16G   0% /dev
tmpfs            64M     0   64M   0% /dev/tty
tmpfs            16G     0   16G   0% /run
tmpfs            16G  2.5M   16G   1% /home
tmpfs            16G     0   16G   0% /tmp
```

| 列 | 含义 |
|---|---|
| Filesystem | 设备或文件系统名 |
| Size / Used / Avail | 总大小 / 已用 / 可用 |
| Use% | 使用率，超过 90% 就该清理了 |
| Mounted on | 挂载点，也就是它对应哪个目录 |

`tmpfs` 是内存里的临时文件系统，重启后内容会清空，一般不用关心。

#### 4.2 只看某个目录所在的分区

```
$ df -h /home
Filesystem      Size  Used Avail Use% Mounted on
tmpfs            16G  2.5M   16G   1% /home
```

不确定 `/var/lib/mysql` 在哪个分区，就 `df -h /var/lib/mysql`。

#### 4.3 `-T`：显示文件系统类型

```
$ df -hT /home
Filesystem     Type   Size  Used Avail Use% Mounted on
tmpfs          tmpfs   16G  2.5M   16G   1% /home
```

#### 4.4 `-i`：空间够但还是写不进去

```
$ df -i /home
Filesystem      Inodes IUsed   IFree IUse% Mounted on
tmpfs          4039707    15 4039692    1% /home
```

每个文件占用一个 inode。如果程序产生了几百万个小文件（比如没清理的会话文件），inode 会先用完，这时 `df -h` 还显示有空间，写文件却报 `No space left on device`。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 删了一个大日志，df 显示的可用空间没变 | 文件还被某个进程打开着，空间要等进程关闭文件才释放 | `sudo lsof +L1` 找出占用的进程并重启它；清空日志用 `: > 文件` 而不是删除 |
| `df -h` 有空间，仍然 `No space left on device` | inode 用完了 | `df -i` 确认，找出并清理大量小文件 |
| df 的 Used + Avail 小于 Size | ext4 默认给 root 保留 5% 空间，防止磁盘写满后系统无法维护 | 这是正常现象 |

### 6. 一句话总结

磁盘满了先 `df -h` 定位分区，再用 `du` 找大目录；写不进去还要看 `df -i`。

## 026 ★★★&nbsp;&nbsp;du：查看目录和文件占用的空间

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`du`（disk usage）统计目录或文件实际占用了多少磁盘空间。`df` 告诉你哪个分区满了，`du` 帮你找到是哪个目录把它占满的。

### 2. 基本格式

```bash
du [参数] [目录或文件...]
```

不加参数时，du 会列出每一个子目录的大小，输出很长。日常基本都配合 `-sh` 使用。

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-h` | `--human-readable` | 用 K、M、G 显示 |
| `-s` | `--summarize` | 每个参数只显示一个总数 |
| `-a` | `--all` | 文件也列出来（默认只列目录） |
| `-d N` | `--max-depth=N` | 只统计到第 N 层子目录 |
| `-c` | `--total` | 最后加一行总计 |

### 4. 常用示例

#### 4.1 `-sh`：看一个目录总共多大

```
$ du -sh .
2.5M	.
```

#### 4.2 `du -sh *`：当前目录下谁最大

```
$ du -sh *
2.4M	big.iso
0	link.txt
4.0K	logs
4.0K	readme.txt
4.0K	run.sh
4.0K	src
```

readme.txt 只有 6 字节，du 却显示 4.0K，因为磁盘按 4K 一块分配空间，du 统计的是实际占用的块。

#### 4.3 包括隐藏文件

```
$ du -sh .[!.]* *
4.0K	.env
2.4M	big.iso
0	link.txt
4.0K	logs
4.0K	readme.txt
4.0K	run.sh
4.0K	src
```

`*` 不匹配以 `.` 开头的名字，`.[!.]*` 专门匹配隐藏文件。家目录里的 `.cache`、`.local` 经常占几个 GB，不加这个就看不到。

#### 4.4 `--max-depth=1`：只看一层

```
$ du -h --max-depth=1
4.0K	./src
4.0K	./logs
2.5M	.
```

#### 4.5 排序：找出最大的几项

```
$ du -ah | sort -rh | head -3
2.5M	.
2.4M	./big.iso
4.0K	./src/products.csv
```

`sort -rh` 按带单位的大小倒序排列。服务器磁盘满了，常用这一条：

```bash
sudo du -h --max-depth=1 /var | sort -rh | head
```

先找到 /var 下最大的子目录，再进去重复同样的步骤，一层层缩小范围。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| du 统计的总数比 df 显示的已用空间小很多 | 已删除但仍被进程占用的文件，du 看不到 | 见 [df](#cmd-df) 踩坑表第一条 |
| 统计 `/` 时刷出大量 `Permission denied` | 普通用户读不了某些目录 | 加 `sudo`，或在命令末尾加 `2>/dev/null` |
| 统计根目录时，把挂载的网络盘也算进去，非常慢 | du 默认会进入其他文件系统 | 加 `-x`，只统计同一个文件系统 |
| `du -sh *` 漏掉了 `.cache` 等大目录 | `*` 不匹配隐藏文件 | 用 4.3 的写法 |

### 6. 一句话总结

`du -sh *` 看谁最大，`du -h --max-depth=1 | sort -rh` 一层层找出占空间的目录。

## 067 ★★★&nbsp;&nbsp;lsblk：列出磁盘和分区

> 级别：★★★ 初级 · 软件包：`util-linux`

### 1. 作用

`lsblk`（list block devices）用树形列出所有磁盘（块设备）、磁盘上的分区，以及它们挂载在哪个目录。新加了一块硬盘、插了一个 U 盘，想知道它叫什么名字（/dev/sdb 还是 /dev/nvme1n1），就用 lsblk。

### 2. 基本格式

```bash
lsblk [参数] [设备]
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-f` | 显示文件系统类型、卷标、UUID、可用空间 |
| `-d` | 只显示磁盘，不显示分区 |
| `-o 列,...` | 自定义显示的列 |
| `-p` | 显示设备的完整路径（/dev/...） |

### 4. 常用示例

> 以下输出来自测试环境（云服务器）。

#### 4.1 `lsblk`

```
$ lsblk
NAME          MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
loop0           7:0    0 86.9G  0 loop
loop1           7:1    0 86.9G  0 loop /
nvme0n1       259:0    0   30G  0 disk
├─nvme0n1p1   259:1    0   30G  0 part
├─nvme0n1p127 259:2    0    1M  0 part
└─nvme0n1p128 259:3    0   10M  0 part
nvme1n1       259:4    0  128G  0 disk /etc/resolv.conf
```

| 列 | 含义 |
|---|---|
| NAME | 设备名，完整路径是 `/dev/` 加上它 |
| SIZE | 容量 |
| TYPE | `disk` 整块磁盘，`part` 分区，`loop` 回环设备（snap、镜像文件），`lvm` 逻辑卷 |
| MOUNTPOINTS | 挂载到的目录，空白表示没有挂载 |

磁盘命名规律：

| 名字 | 是什么 |
|---|---|
| `sda`、`sdb` | SATA/SAS 硬盘、U 盘，依次编号 |
| `nvme0n1`、`nvme1n1` | NVMe 固态硬盘 |
| `sda1`、`nvme0n1p1` | 上面那块盘的第 1 个分区 |
| `vda` | 虚拟机里的虚拟磁盘 |

#### 4.2 `-d`：只看磁盘

```
$ lsblk -d
NAME    MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
loop0     7:0    0 86.9G  0 loop
loop1     7:1    0 86.9G  0 loop /
nvme0n1 259:0    0   30G  0 disk
nvme1n1 259:4    0  128G  0 disk /etc/resolv.conf
```

#### 4.3 `-o`：只看关心的列

```
$ lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS
NAME           SIZE TYPE FSTYPE MOUNTPOINTS
loop0         86.9G loop
loop1         86.9G loop        /
nvme0n1         30G disk
├─nvme0n1p1     30G part
├─nvme0n1p127    1M part
└─nvme0n1p128   10M part
nvme1n1        128G disk        /etc/resolv.conf
```

#### 4.4 `-f`：看文件系统和 UUID

```bash
lsblk -f
```

在普通 Ubuntu 机器上，FSTYPE 一列会显示 ext4、vfat（EFI 分区）、swap 等，UUID 一列是写进 `/etc/fstab` 时用的唯一编号。测试环境的容器读不到这些信息，所以这两列是空的。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 新插的硬盘在 lsblk 里只有 disk，没有 part | 新硬盘还没分区 | 用 `fdisk` 或 `parted` 分区后格式化（中级篇讲） |
| 云服务器扩容了磁盘，lsblk 显示的磁盘变大了，`df -h` 里的分区没变 | 扩容的是磁盘，分区和文件系统还要单独扩展 | 用 `growpart` 扩分区，再用 `resize2fs` 扩文件系统（高级篇讲） |
| 每次开机 sdb、sdc 的顺序可能不一样 | 设备名按识别顺序分配 | 在 /etc/fstab 里用 UUID，不用 /dev/sdb1 这样的名字 |

### 6. 一句话总结

`lsblk` 看有哪些盘和分区，`lsblk -f` 看文件系统和 UUID。

## 068 ★★★&nbsp;&nbsp;mount：挂载磁盘和分区

> 级别：★★★ 初级 · 软件包：`mount`

### 1. 作用

Linux 里所有文件都在一棵从 `/` 开始的目录树上。一块新硬盘、一个 U 盘、一个网络共享目录，要先**挂载**（mount）到树上的某个空目录，才能通过这个目录访问里面的文件。这个目录叫**挂载点**。

`mount` 不带参数时，列出当前所有的挂载。

### 2. 基本格式

```bash
mount                                # 查看所有挂载
sudo mount [参数] 设备 挂载点          # 挂载
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-t 类型` | 指定文件系统类型，如 `ext4`、`vfat`、`ntfs3`、`cifs`（Windows 共享） |
| `-o 选项` | 挂载选项，多个用逗号分隔：`ro` 只读，`rw` 读写，`noexec` 禁止执行程序 |
| `-a` | 挂载 /etc/fstab 里所有还没挂载的条目 |

### 4. 常用示例

#### 4.1 查看当前挂载

```
$ findmnt /home
TARGET SOURCE FSTYPE OPTIONS
/home  tmpfs  tmpfs  rw,nosuid,nodev,relatime,seclabel,mode=755
```

`mount` 的完整输出很长，查某个目录用 `mount | grep " /home "` 或 `findmnt 目录` 更清楚（findmnt 在中级篇讲）。

#### 4.2 挂载一块新硬盘

```bash
lsblk -f                          # 确认分区名和文件系统，假设是 /dev/sdb1，ext4
sudo mkdir -p /data               # 挂载点必须先存在
sudo mount /dev/sdb1 /data
df -h /data                       # 确认挂载成功
```

#### 4.3 挂载 U 盘（只读）

```bash
sudo mount -o ro /dev/sdc1 /mnt
```

#### 4.4 开机自动挂载：/etc/fstab

用 mount 挂载的内容重启后就没了。要永久挂载，在 `/etc/fstab` 里加一行：

```
UUID=1234abcd-...  /data  ext4  defaults  0  2
```

UUID 从 `lsblk -f` 或 `blkid` 获得。加完后先执行 `sudo mount -a` 测试，没有报错再重启。

> ⚠️ 4.2–4.4 未实机验证：测试环境的容器不允许挂载设备。命令写法为长期稳定的标准用法。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 挂载后，挂载点里原来的文件“不见了” | 挂载会把原目录的内容盖住，卸载后会重新出现 | 挂载点用空目录 |
| /etc/fstab 写错一个字，重启后系统进入紧急模式 | 开机时挂载失败 | 改完一定先 `sudo mount -a` 测试；不重要的盘在选项里加 `nofail` |
| `mount: wrong fs type, bad option, bad superblock` | 文件系统类型不对，或者分区还没格式化 | 用 `lsblk -f` 确认 FSTYPE |
| 普通用户执行 mount 报 `mount: /mnt: must be superuser to use mount.` | 挂载需要 root | 加 `sudo` |

### 6. 一句话总结

`sudo mount 设备 目录` 临时挂载，永久挂载写 /etc/fstab，写完先 `mount -a` 测试。

## 069 ★★★&nbsp;&nbsp;umount：卸载磁盘和分区

> 级别：★★★ 初级 · 软件包：`mount`

### 1. 作用

`umount`（注意没有 n，不是 unmount）把挂载的设备从目录树上卸下来。拔 U 盘、移除硬盘、对分区做检查或调整大小之前，都要先卸载，否则可能丢数据。

### 2. 基本格式

```bash
sudo umount 挂载点或设备
```

写挂载点（`/data`）或设备名（`/dev/sdb1`）都可以。

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-l` | 懒卸载：先从目录树上摘下来，等没人使用了再真正卸载 |
| `-f` | 强制卸载（主要用于连不上的网络共享） |
| `-R` | 递归卸载这个目录及其下面的所有挂载 |

### 4. 常用示例

```bash
sudo umount /data
sudo umount /dev/sdc1
```

卸载成功不会有任何输出。用 `df -h` 或 `lsblk` 确认它已经不在了。

> ⚠️ 本页未实机验证：测试环境的容器不允许挂载和卸载设备。命令写法为长期稳定的标准用法。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `umount: /data: target is busy.` | 有进程正在使用里面的文件，或者某个终端的当前目录就在里面 | 先 `cd ~` 离开；用 `sudo lsof +D /data` 或 `sudo fuser -vm /data` 找出占用的进程 |
| 拔掉 U 盘后，拷进去的文件不完整 | 写入的数据还在内存缓存里，没写进 U 盘 | 一定先 `umount`，它会把缓存写完再卸载 |
| 普通用户执行报 `umount: /home: must be superuser to unmount.` | 卸载需要 root | 加 `sudo` |
| 网络共享断了，umount 一直卡住 | 系统在等待服务器响应 | `sudo umount -f` 或 `-l` |

### 6. 一句话总结

拔盘之前先 `sudo umount 挂载点`，提示 busy 就先离开目录、找出占用的进程。

## 142 ★★&nbsp;&nbsp;fdisk：给磁盘分区

> 级别：★★ 中级 · 软件包：`fdisk`（util-linux 2.41）

### 1. 作用

`fdisk` 查看磁盘的分区表，并以交互方式新建、删除、修改分区。新加一块硬盘后的标准流程是：**fdisk 分区 → mkfs 格式化 → mount 挂载 → 写进 /etc/fstab**。

fdisk 支持 GPT 和 MBR（DOS）两种分区表。2 TB 以上的磁盘必须用 GPT；新磁盘一律建议用 GPT。

### 2. 基本格式

```bash
sudo fdisk -l [磁盘]      # 查看分区表
sudo fdisk 磁盘           # 进入交互式分区，如 sudo fdisk /dev/sdb
```

### 3. 交互命令

进入 fdisk 后输入单个字母执行操作。所有修改在按 `w` 之前**都只在内存里**，按 `q` 可以放弃全部修改。

| 命令 | 作用 |
|---|---|
| `p` | 显示当前分区表 |
| `g` | 新建一个空的 GPT 分区表（清除原有分区） |
| `o` | 新建一个空的 MBR 分区表 |
| `n` | 新建分区 |
| `d` | 删除分区 |
| `t` | 修改分区类型（如改成 Linux swap、EFI System） |
| `w` | 写入磁盘并退出 |
| `q` | 不保存，退出 |
| `m` | 帮助 |

### 4. 常用示例

为了安全，下面用一个 1 GB 的镜像文件 `disk.img` 代替真实磁盘演示（以 root 身份执行）。对真实磁盘，把 `disk.img` 换成 `/dev/sdb` 这样的设备名即可。

#### 4.1 查看分区表

```
$ fdisk -l disk.img
Disk disk.img: 1 GiB, 1073741824 bytes, 2097152 sectors
Units: sectors of 1 * 512 = 512 bytes
Sector size (logical/physical): 512 bytes / 512 bytes
I/O size (minimum/optimal): 512 bytes / 512 bytes
```

新磁盘没有分区表，只显示磁盘本身的信息。

#### 4.2 建 GPT 分区表和两个分区

交互过程中依次输入：

| 输入 | 含义 |
|---|---|
| `g` | 新建 GPT 分区表 |
| `n` → `1` → 回车 → `+200M` | 第 1 个分区，从默认位置开始，大小 200 MB |
| `n` → `2` → 回车 → 回车 | 第 2 个分区，用掉剩下的全部空间 |
| `w` | 写入 |

完成后：

```
$ fdisk -l disk.img
...
Device      Start     End Sectors  Size Type
disk.img1    2048  411647  409600  200M Linux filesystem
disk.img2  411648 2095103 1683456  822M Linux filesystem
```

第 1 个分区从第 2048 扇区（1 MiB 处）开始，这是为了对齐，默认值即可，不要改。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 对系统盘执行了 `g`、`w`，原来的分区全没了 | 选错了磁盘 | 执行前用 `lsblk` 核对磁盘名和容量；按 `w` 前先按 `p` 确认 |
| 分区后 `lsblk` 里看不到新分区 | 磁盘正在被使用，内核没有重新读取分区表 | 执行 `sudo partprobe 磁盘`，或重启 |
| 想把一块 4 TB 的盘分区，只能用到 2 TB | 用了 MBR 分区表（`o`） | 用 GPT（`g`） |
| 脚本里需要自动分区 | fdisk 是交互式的 | 用 `parted -s` 或 `sfdisk` |

### 6. 一句话总结

`fdisk -l` 看分区，`fdisk 磁盘` 交互分区，按 `w` 之前一切可反悔。

## 143 ★★&nbsp;&nbsp;parted：分区（适合脚本和大磁盘）

> 级别：★★ 中级 · 软件包：`parted`

### 1. 作用

`parted` 和 fdisk 做同样的事，区别是它可以用**一条命令**完成分区（加 `-s` 不询问），适合写进脚本；并且可以直接用百分比、MiB、GB 指定分区的位置。

注意：parted 的每条命令是**立即生效**的，没有 fdisk 那样“按 w 才写入”的缓冲。

### 2. 基本格式

```bash
sudo parted 磁盘 print                       # 查看
sudo parted -s 磁盘 命令 [命令...]            # 非交互执行
```

### 3. 常用命令

| 命令 | 作用 |
|---|---|
| `print` | 显示分区表 |
| `print free` | 同时显示未分配的空间 |
| `mklabel gpt` | 新建 GPT 分区表（清除原有分区） |
| `mkpart 名称 类型 起点 终点` | 新建分区，如 `mkpart data ext4 1MiB 100%` |
| `rm 编号` | 删除分区 |
| `resizepart 编号 终点` | 调整分区的终点（扩容） |
| `unit MiB` | 后续显示和输入都用 MiB 为单位 |

### 4. 常用示例

以 1 GB 的镜像文件代替真实磁盘（root 身份）：

```
$ parted -s disk2.img mklabel gpt mkpart data ext4 1MiB 100%

$ parted -s disk2.img print
Model:  (file)
Disk /root/disk2.img: 1074MB
Sector size (logical/physical): 512B/512B
Partition Table: gpt
Disk Flags:

Number  Start   End     Size    File system  Name  Flags
 1      1049kB  1073MB  1072MB               data
```

一条命令完成：建 GPT 表，建一个从 1 MiB 到磁盘末尾的分区。`mkpart` 里的 `ext4` 只是标记，**不会格式化**，格式化还要用 mkfs。File system 一列为空，就是因为还没格式化。

查看未分配空间：

```
$ parted -s disk2.img unit MiB print free
...
        0.02MiB  1.00MiB  0.98MiB  Free Space
 1      1.00MiB  1023MiB  1022MiB               data
        1023MiB  1024MiB  0.98MiB  Free Space
```

云服务器扩容磁盘后，用 `print free` 能看到末尾多出来的空闲空间。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 在 parted 交互模式里试着 `mklabel`，原有分区立即没了 | parted 的命令立即生效 | 操作前先 `print`，确认磁盘无误 |
| 以为 `mkpart ... ext4` 已经格式化了，mount 报 `wrong fs type` | mkpart 只建分区 | 再执行 `mkfs.ext4 分区` |
| 用 GB 指定起点，提示分区没有对齐 | 1 GB = 1000 MB，不是 1024 的整数倍 | 用 MiB、GiB 或百分比 |

### 6. 一句话总结

脚本里分区用 `parted -s 磁盘 mklabel gpt mkpart 名称 ext4 1MiB 100%`。

<a id="cmd-mkfs"></a>

## 144 ★★&nbsp;&nbsp;mkfs：格式化分区

> 级别：★★ 中级 · 软件包：`e2fsprogs`（ext4）、`dosfstools`（FAT）

### 1. 作用

`mkfs`（make filesystem）在分区上创建文件系统，也就是“格式化”。分区之后、挂载之前必须做这一步。格式化会**清空分区上的全部数据**。

mkfs 实际上是一组命令，按文件系统类型区分：

| 命令 | 文件系统 | 用途 |
|---|---|---|
| `mkfs.ext4` | ext4 | Linux 默认，绝大多数场景 |
| `mkfs.xfs` | XFS | 大文件、高并发写入（需 `xfsprogs` 包） |
| `mkfs.vfat` | FAT32 | U 盘，和 Windows、相机通用 |
| `mkfs.exfat` | exFAT | 大于 4 GB 文件的 U 盘（需 `exfatprogs` 包） |

### 2. 基本格式

```bash
sudo mkfs.ext4 [参数] 分区
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-L 卷标` | 设置卷标（ext4、FAT 都支持；FAT 用 `-n`） |
| `-F` | 强制执行（目标是普通文件或已有文件系统时） |
| `-q` | 安静模式 |
| `-m 百分比` | ext4 给 root 保留的空间，默认 5%，数据盘可以设成 1 或 0 |

### 4. 常用示例

以镜像文件代替真实分区（root 身份）：

```
$ mkfs.ext4 part.img
mke2fs 1.47.2 (1-Jan-2025)
Discarding device blocks: done
Creating filesystem with 76800 4k blocks and 76800 inodes
Filesystem UUID: 207239f5-07da-4aa3-9f6d-9aa26b343d04
Superblock backups stored on blocks:
	32768

Allocating group tables: done
Writing inode tables: done
Creating journal (4096 blocks): done
Writing superblocks and filesystem accounting information: done
```

输出里的 UUID 是这个文件系统的唯一编号，写 /etc/fstab 时用。

格式化成 FAT32 的 U 盘：

```
$ mkfs.vfat -n USB fat.img
mkfs.fat 4.2 (2021-01-31)
```

对真实设备的写法：`sudo mkfs.ext4 -L data /dev/sdb1`。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 格式化了 `/dev/sdb`（整盘）而不是 `/dev/sdb1`（分区） | 设备名写错 | 用 `lsblk` 确认；分区名带数字 |
| `mkfs.xfs: command not found` | 默认没装 XFS 工具 | `sudo apt install xfsprogs` |
| 2 TB 的数据盘格式化后少了 100 GB | ext4 默认给 root 保留 5% | 数据盘用 `-m 1`，已格式化的用 `sudo tune2fs -m 1 分区` 调整 |

### 6. 一句话总结

`sudo mkfs.ext4 -L 卷标 分区` 格式化，执行前用 lsblk 再确认一次。

## 145 ★★&nbsp;&nbsp;blkid：查看分区的 UUID 和类型

> 级别：★★ 中级 · 软件包：`util-linux`

### 1. 作用

`blkid` 显示块设备（分区、磁盘、镜像）的文件系统类型、卷标和 UUID。写 /etc/fstab 时要用 UUID 而不是 /dev/sdb1 这样的设备名，因为设备名在增减硬盘后可能会变，UUID 不会。

### 2. 基本格式

```bash
sudo blkid [参数] [设备...]
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-s 标签` | 只显示某个字段，如 `-s UUID` |
| `-o value` | 只输出值，不输出 `UUID=` 这样的字段名 |

### 4. 常用示例

```
$ sudo blkid part.img fat.img
part.img: LABEL="data" UUID="87feca15-9d6f-46e6-a3df-1dc4b4a0b5dc" BLOCK_SIZE="4096" TYPE="ext4"
fat.img: SEC_TYPE="msdos" LABEL_FATBOOT="USB" LABEL="USB" UUID="6012-FC31" BLOCK_SIZE="512" TYPE="vfat"

$ sudo blkid -s UUID -o value part.img
87feca15-9d6f-46e6-a3df-1dc4b4a0b5dc
```

脚本里生成 fstab 条目：

```bash
UUID=$(sudo blkid -s UUID -o value /dev/sdb1)
echo "UUID=$UUID  /data  ext4  defaults  0  2" | sudo tee -a /etc/fstab
```

`lsblk -f` 也能看到 UUID，blkid 更适合在脚本里取值。

### 5. 一句话总结

写 fstab 前用 `sudo blkid -s UUID -o value 分区` 取 UUID。

## 146 ★★&nbsp;&nbsp;fsck：检查和修复文件系统

> 级别：★★ 中级 · 软件包：`util-linux`（fsck 前端）、`e2fsprogs`（e2fsck）

### 1. 作用

`fsck`（filesystem check）检查文件系统的一致性，发现问题时修复。异常断电、强制关机、磁盘出现坏道后，可能需要它。fsck 本身只是一个前端，会根据文件系统类型调用 `e2fsck`（ext4）、`fsck.vfat`（FAT）等具体工具。

**分区必须先卸载才能检查和修复**。对已挂载的分区执行修复，可能造成更严重的损坏。

### 2. 基本格式

```bash
sudo umount 分区
sudo fsck [参数] 分区
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-n` | 只检查，不修改（任何问题都回答“否”） |
| `-y` | 自动修复（所有问题都回答“是”） |
| `-f` | 即使文件系统标记为“干净”也强制检查 |

### 4. 常用示例

ext4 用 e2fsck 直接检查：

```
$ sudo e2fsck -f -n part.img
e2fsck 1.47.2 (1-Jan-2025)
Pass 1: Checking inodes, blocks, and sizes
Pass 2: Checking directory structure
Pass 3: Checking directory connectivity
Pass 4: Checking reference counts
Pass 5: Checking group summary information
data: 12/76800 files (0.0% non-contiguous), 9018/76800 blocks
```

5 个阶段都没有报错，最后一行是文件和块的使用情况。

FAT 格式的 U 盘：

```
$ sudo fsck.vfat -n fat.img
fsck.fat 4.2 (2021-01-31)
fat.img: 1 files, 0/51091 clusters
```

根分区无法在运行时卸载。要检查根分区，可以在开机时的 GRUB 菜单里按 `e`，在 `linux` 那一行末尾加上 `fsck.mode=force`，按 `Ctrl+X` 启动，systemd 会在挂载前检查所有文件系统。

> ⚠️ 根分区开机检查未实机验证。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 对挂载中的分区执行修复，数据损坏更严重 | 文件系统在使用中被修改 | 先 umount；根分区用救援模式或开机检查 |
| `fsck -y` 修复后，部分文件出现在 `lost+found` 目录里，文件名变成了数字 | 这些是丢失了目录信息的文件碎片 | 去 lost+found 里按内容找回 |
| 用 `fsck` 检查镜像文件，只输出了版本号 | fsck 前端没识别出类型 | 直接用对应的工具：`e2fsck`、`fsck.vfat` |

### 6. 一句话总结

先 umount，再 `fsck -n` 看问题，确认后 `fsck -y` 修复。

## 193 ★★&nbsp;&nbsp;swapon：启用和查看交换空间

> 级别：★★ 中级 · 软件包：`mount`

### 1. 作用

交换空间（swap）是磁盘上的一块区域，内存不够用时，系统把暂时不用的内存数据挪到这里。它能防止内存耗尽时程序被直接杀掉，代价是速度变慢。`swapon` 启用交换空间，`swapon --show` 查看当前正在用的交换空间。

Ubuntu 默认使用一个交换文件 `/swap.img` 或 `/swapfile`。

### 2. 基本格式

```bash
swapon --show                 # 查看
sudo swapon 文件或分区         # 启用
sudo swapoff 文件或分区        # 停用
```

### 3. 常用示例

```
$ swapon --show
NAME      TYPE SIZE USED PRIO
/swapfile file   2G   0B   -2
```

| 列 | 含义 |
|---|---|
| TYPE | `file` 交换文件，`partition` 交换分区 |
| SIZE / USED | 大小 / 已使用 |
| PRIO | 优先级，有多个交换空间时先用优先级高的 |

USED 持续很高，说明内存长期不够。

给一台 2 GB 内存的小服务器加 4 GB 交换文件的完整步骤：

```bash
sudo fallocate -l 4G /swapfile2
sudo chmod 600 /swapfile2
sudo mkswap /swapfile2
sudo swapon /swapfile2
echo '/swapfile2 none swap sw 0 0' | sudo tee -a /etc/fstab   # 开机自动启用
```

> ⚠️ 启用交换文件的步骤未实机验证（测试环境不允许 swapon），mkswap 部分已实测，见 [mkswap](#cmd-mkswap)。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `swapon: /root/swap.img: skipping - it appears to have holes.` | 交换文件是用 `truncate` 建的稀疏文件，内核不接受 | 用 `fallocate` 或 `dd` 创建 |
| `swapon: insecure permissions 0644, fix with: chmod 0600` | 交换文件里可能有内存中的敏感数据 | `chmod 600` |
| 加了 swap，数据库还是很慢 | swap 在磁盘上，比内存慢得多 | swap 只是兜底，根本办法是加内存或减少占用 |

> ⚠️ 第二条的提示文字未实机验证。

### 5. 一句话总结

`swapon --show` 看交换空间，交换文件用 fallocate 创建、权限 600。

## 194 ★★&nbsp;&nbsp;mkswap：创建交换空间

> 级别：★★ 中级 · 软件包：`util-linux`

### 1. 作用

`mkswap` 把一个文件或分区初始化成交换空间，相当于“交换空间的 mkfs”。初始化之后再用 [swapon](#cmd-swapon) 启用。

### 2. 基本格式

```bash
sudo mkswap 文件或分区
```

### 3. 常用示例

```
$ fallocate -l 64M swap2.img; chmod 600 swap2.img; mkswap swap2.img
Setting up swapspace version 1, size = 64 MiB (67104768 bytes)
no label, UUID=33ab4b3d-6710-4810-af7d-2e45c80e9dcf
```

### 4. ⚠️ 踩坑警告

用 `truncate` 创建的文件是稀疏文件（只记录大小，没有真正分配磁盘空间），mkswap 会给出警告，之后 swapon 也会拒绝：

```
$ truncate -s 64M swap.img; chmod 600 swap.img; mkswap swap.img

mkswap: swap.img contains holes or other unsupported extents.
        This swap file can be rejected by kernel on swap activation!
        Use --verbose for more details.

Setting up swapspace version 1, size = 64 MiB (67104768 bytes)
no label, UUID=97db84d7-339e-4270-982d-e4b290006498
```

创建交换文件用 `fallocate -l 大小 文件` 或 `dd if=/dev/zero of=文件 bs=1M count=大小`。

### 5. 一句话总结

`fallocate` 建文件 → `chmod 600` → `mkswap` → `swapon`。

## 195 ★★&nbsp;&nbsp;findmnt：查看挂载点

> 级别：★★ 中级 · 软件包：`util-linux`

### 1. 作用

`findmnt` 以树形列出当前所有的挂载：哪个设备挂在哪个目录、什么文件系统、什么选项。比 `mount` 的输出清楚，还能按目录、类型筛选。它还有一个重要功能：`findmnt --verify` 检查 /etc/fstab 有没有写错。

### 2. 基本格式


### 3. 常用参数

| 参数 | 作用 |

| `-o 列` | 自定义列，如 `-o TARGET,SOURCE,FSTYPE` |

| `--verify` | 检查 /etc/fstab 的语法和设备是否存在 |

### 4. 常用示例

```
/dev/loop1[/.tools/u2604] xfs
```

普通 Ubuntu 机器上，`findmnt /` 显示的是根分区设备（如 `/dev/sda2`）和 ext4。

```
$ sudo findmnt --verify
Success, no errors or warnings detected
```

### 5. 一句话总结

`findmnt 目录` 查挂载，改完 fstab 一定先 `findmnt --verify`。

## 196 ★★&nbsp;&nbsp;ncdu：交互式查看磁盘占用

> 级别：★★ 中级 · 软件包：`ncdu`（1.22，需 `sudo apt install ncdu`）

### 1. 作用

`ncdu`（NCurses Disk Usage）扫描一个目录，然后用全屏界面列出每个子目录和文件的大小，按大小排序。可以用方向键进入子目录、一层层往下找，找到占空间的东西还能直接按 `d` 删除。磁盘满了的时候，它比反复执行 `du -sh *` 方便得多。

### 2. 基本格式

```bash
ncdu [参数] [目录]
```

### 3. 常用参数和按键

| 参数 | 作用 |
|---|---|
| `-x` | 不跨越到其他文件系统（扫描 / 时不进入挂载的网络盘） |
| `-o 文件` | 把扫描结果导出到文件，不打开界面 |
| `-f 文件` | 读取之前导出的结果查看 |

| 按键 | 作用 |
|---|---|
| `↑` `↓` / 回车 | 选择 / 进入目录 |
| `←` | 返回上一级 |
| `d` | 删除选中的文件或目录（会确认） |
| `g` | 切换显示百分比和条形图 |
| `q` | 退出 |

### 4. 常用示例

```bash
sudo ncdu -x /          # 磁盘满了，从根目录开始找
ncdu ~                  # 看家目录里什么最大
```

在服务器上扫描一次，导出结果后慢慢看：

```
$ ncdu -o- /home/tom/demo | head -c 300
[1,2,{"progname":"ncdu","progver":"1.22","timestamp":1793263119},
[{"name":"/home/tom/demo","asize":180,"dev":118},
{"name":"link.txt","asize":10,"notreg":true},
{"name":"run.sh","asize":20,"dsize":4096},
{"name":".env","asize":12,"dsize":4096},
{"name":"big.iso","asize":2500000,"dsize":2502656},
...
```

`-o-` 表示导出到标准输出。导出的是 JSON，`asize` 是文件的实际大小，`dsize` 是占用的磁盘空间。

> ⚠️ 全屏界面部分未实机验证。

### 5. 一句话总结

磁盘满了用 `sudo ncdu -x /` 一层层找，找到了按 `d` 删除。
