## 001 ★★★&nbsp;&nbsp;ls：列出目录内容

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`ls`（list）用来列出一个目录里有哪些文件和子目录，也可以查看单个文件的权限、大小、修改时间。它只读不改，可以放心执行。这是 Linux 里使用最频繁的指令。

### 2. 基本格式

```bash
ls [参数] [目录或文件...]
```

| 写法 | 含义 |
|---|---|
| `ls` | 列出当前目录 |
| `ls /var/log` | 列出指定目录 |
| `ls a.txt b.txt` | 只显示这几个文件 |
| `ls *.log` | 列出当前目录下所有 .log 文件（`*` 由 Shell 展开） |
| `ls -l /etc` | 带参数，以详细格式列出 /etc |

多个短参数可以合写：`ls -l -a -h` 和 `ls -lah` 效果相同。

### 3. 读懂 `ls -l` 的输出

```
-rwxr-xr-x 1 tom tom 20 Oct 29 06:39 run.sh
```

| 位置 | 示例值 | 含义 |
|---|---|---|
| 第 1 个字符 | `-` | 文件类型：`-` 普通文件，`d` 目录，`l` 符号链接 |
| 第 2–10 个字符 | `rwxr-xr-x` | 权限，每 3 位一组，依次是所有者、所属组、其他人。`r` 读，`w` 写，`x` 执行，`-` 没有该权限 |
| 第 2 列 | `1` | 硬链接数 |
| 第 3 列 | `tom` | 所有者 |
| 第 4 列 | `tom` | 所属组 |
| 第 5 列 | `20` | 大小（字节） |
| 第 6–8 列 | `Oct 29 06:39` | 最后修改时间。超过半年的文件显示年份，不显示时分 |
| 最后一列 | `run.sh` | 文件名。符号链接显示成 `link.txt -> readme.txt` |

输出第一行的 `total 2452` 是这些文件占用的磁盘块总数（单位 KB），不是文件个数。

### 4. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-l` | | 详细格式，一行一个文件 |
| `-a` | `--all` | 显示所有文件，包括以 `.` 开头的隐藏文件，以及 `.` 和 `..` |
| `-A` | `--almost-all` | 显示隐藏文件，但不显示 `.` 和 `..` |
| `-h` | `--human-readable` | 大小显示成 K、M、G，和 `-l` 一起用 |
| `-t` | | 按修改时间排序，最新的在前 |
| `-S` | | 按文件大小排序，最大的在前 |
| `-r` | `--reverse` | 倒序，和 `-t`、`-S` 配合 |
| `-R` | `--recursive` | 递归列出所有子目录 |
| `-d` | `--directory` | 显示目录本身的信息，不列出目录里的内容 |
| `-F` | `--classify` | 名字后加类型标记：`/` 目录，`*` 可执行文件，`@` 链接 |
| `-1` | | 每行只显示一个文件名（数字 1） |
| `-i` | `--inode` | 显示 inode 编号 |
| | `--color=auto` | 按类型上色（Ubuntu 默认已开启） |
| | `--group-directories-first` | 目录排在文件前面 |
| | `--time-style=long-iso` | 时间显示为 `2026-10-01 09:00` |

### 5. 常用参数组合

#### 5.1 `ls`：只看名字

```
$ ls
big.iso  link.txt  logs  readme.txt  run.sh  src
```

#### 5.2 `ls -l`：详细信息

```
$ ls -l
total 2452
-rw-r--r-- 1 tom tom 2500000 Oct 20 14:30 big.iso
lrwxrwxrwx 1 tom tom      10 Oct 29 06:39 link.txt -> readme.txt
drwxr-xr-x 2 tom tom    4096 Oct 29 06:39 logs
-rw-r--r-- 1 tom tom       6 Oct  1 09:00 readme.txt
-rwxr-xr-x 1 tom tom      20 Oct 29 06:39 run.sh
drwxr-xr-x 2 tom tom    4096 Oct 29 06:39 src
```

#### 5.3 `ls -la`：包括隐藏文件

```
$ ls -la
total 2456
drwxr-xr-x 4 tom tom    4096 Oct 29 06:39 .
drwxr-x--- 3 tom tom    4096 Oct 29 06:39 ..
-rw-r--r-- 1 tom tom      12 Oct 29 06:39 .env
-rw-r--r-- 1 tom tom 2500000 Oct 20 14:30 big.iso
lrwxrwxrwx 1 tom tom      10 Oct 29 06:39 link.txt -> readme.txt
drwxr-xr-x 2 tom tom    4096 Oct 29 06:39 logs
-rw-r--r-- 1 tom tom       6 Oct  1 09:00 readme.txt
-rwxr-xr-x 1 tom tom      20 Oct 29 06:39 run.sh
drwxr-xr-x 2 tom tom    4096 Oct 29 06:39 src
```

`.env` 出现了。`.` 代表当前目录，`..` 代表上一级目录。配置文件（`.bashrc`、`.env`、`.git`）通常都是隐藏文件。

#### 5.4 `ls -lh`：大小换成易读单位

```
$ ls -lh
total 2.4M
-rw-r--r-- 1 tom tom 2.4M Oct 20 14:30 big.iso
lrwxrwxrwx 1 tom tom   10 Oct 29 06:39 link.txt -> readme.txt
drwxr-xr-x 2 tom tom 4.0K Oct 29 06:39 logs
-rw-r--r-- 1 tom tom    6 Oct  1 09:00 readme.txt
-rwxr-xr-x 1 tom tom   20 Oct 29 06:39 run.sh
drwxr-xr-x 2 tom tom 4.0K Oct 29 06:39 src
```

`2500000` 变成了 `2.4M`，换算按 1024 进位（2500000 ÷ 1024 ÷ 1024 ≈ 2.4）。

#### 5.5 `ls -lt`：最新修改的在前

```
$ ls -lt
total 2452
lrwxrwxrwx 1 tom tom      10 Oct 29 06:39 link.txt -> readme.txt
-rwxr-xr-x 1 tom tom      20 Oct 29 06:39 run.sh
drwxr-xr-x 2 tom tom    4096 Oct 29 06:39 src
drwxr-xr-x 2 tom tom    4096 Oct 29 06:39 logs
-rw-r--r-- 1 tom tom 2500000 Oct 20 14:30 big.iso
-rw-r--r-- 1 tom tom       6 Oct  1 09:00 readme.txt
```

适合用来找“刚才哪个日志被写过”。只看最新的几个：`ls -lt | head -5`（第一行是 total）。

#### 5.6 `ls -lhrS`：按大小从小到大

```
$ ls -lhrS
total 2.4M
-rw-r--r-- 1 tom tom    6 Oct  1 09:00 readme.txt
lrwxrwxrwx 1 tom tom   10 Oct 29 06:39 link.txt -> readme.txt
-rwxr-xr-x 1 tom tom   20 Oct 29 06:39 run.sh
drwxr-xr-x 2 tom tom 4.0K Oct 29 06:39 src
drwxr-xr-x 2 tom tom 4.0K Oct 29 06:39 logs
-rw-r--r-- 1 tom tom 2.4M Oct 20 14:30 big.iso
```

`-S` 是从大到小，加 `-r` 反过来，最大的文件落在最后一行，留在屏幕上不会被滚走。

#### 5.7 `ls -F`：一眼分出类型

```
$ ls -F
big.iso  link.txt@  logs/  readme.txt  run.sh*  src/
```

#### 5.8 `ls -ld logs`：看目录本身

```
$ ls -l logs
total 4
-rw-r--r-- 1 tom tom 404 Oct 28 11:30 app.log

$ ls -ld logs
drwxr-xr-x 2 tom tom 4096 Oct 29 06:39 logs
```

不加 `-d`，看到的是 logs 里面的 app.log；加了 `-d`，看到的才是 logs 这个目录的权限。

#### 5.9 `ls -R`：递归列出

```
$ ls -R
.:
big.iso  link.txt  logs  readme.txt  run.sh  src

./logs:
app.log

./src:
products.csv
```

目录层级多时输出很长。看结构用 [tree](#cmd-tree)，找文件用 [find](#cmd-find)。

#### 5.10 时间显示成年月日

```
$ ls -l --time-style=long-iso readme.txt
-rw-r--r-- 1 tom tom 6 2026-10-01 09:00 readme.txt
```

### 6. Ubuntu 自带的 ls 别名

Ubuntu 默认的 `~/.bashrc` 定义了这几个别名，可以直接用：

| 别名 | 实际执行 | 效果 |
|---|---|---|
| `ls` | `ls --color=auto` | 带颜色 |
| `ll` | `ls -alF` | 详细列表，含隐藏文件和类型标记 |
| `la` | `ls -A` | 含隐藏文件 |
| `l` | `ls -CF` | 多列显示，带类型标记 |

```
$ ll
total 2456
drwxr-xr-x 4 tom tom    4096 Oct 29 06:39 ./
drwxr-x--- 3 tom tom    4096 Oct 29 06:39 ../
-rw-r--r-- 1 tom tom      12 Oct 29 06:39 .env
-rw-r--r-- 1 tom tom 2500000 Oct 20 14:30 big.iso
lrwxrwxrwx 1 tom tom      10 Oct 29 06:39 link.txt -> readme.txt
drwxr-xr-x 2 tom tom    4096 Oct 29 06:39 logs/
-rw-r--r-- 1 tom tom       6 Oct  1 09:00 readme.txt
-rwxr-xr-x 1 tom tom      20 Oct 29 06:39 run.sh*
drwxr-xr-x 2 tom tom    4096 Oct 29 06:39 src/
```

### 7. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 目录大小总是 `4096` 或 `4.0K` | `ls -l` 显示的是目录条目本身的大小，不含目录里的文件 | 看目录总大小用 `du -sh logs`（见 [du](07-磁盘管理.md#cmd-du)） |
| `ls -l logs` 看不到 logs 目录的权限 | 参数是目录时，默认列出目录里的内容 | 加 `-d`：`ls -ld logs` |
| `ls *.log` 报 `Argument list too long` | `*.log` 被 Shell 展开成几十万个文件名，超过参数长度上限 | 改用 `find . -name "*.log"` |
| 脚本里 `for f in $(ls)` 遇到带空格的文件名出错 | ls 的输出按空格拆分，`My Docs` 被拆成两个词 | 改成 `for f in *; do ...; done` |
| 脚本里调用 `ll` 报 `command not found` | 别名只在交互式终端里生效 | 脚本里写完整命令 `ls -alF` |

```
$ ls nothere
ls: cannot access 'nothere': No such file or directory
```

文件不存在时 ls 返回退出码 2。脚本里判断文件是否存在用 `[ -e 文件 ]`，不要用 ls。

### 8. 一句话总结

`ls -lah` 看详情，`-t` 按时间排，`-S` 按大小排，`-d` 看目录本身。

## 002 ★★★&nbsp;&nbsp;cd：切换目录

> 级别：★★★ 初级 · 来源：bash 内建命令

### 1. 作用

`cd`（change directory）把当前工作目录切换到另一个目录。之后执行的命令，凡是写相对路径的，都以新目录为起点。

### 2. 基本格式

```bash
cd [目录]
```

| 写法 | 含义 |
|---|---|
| `cd /var/log` | 绝对路径：从根目录 `/` 开始写 |
| `cd logs` | 相对路径：从当前目录往下找 |
| `cd ..` | 回到上一级目录 |
| `cd ../logs` | 先回上一级，再进入 logs |
| `cd ~` 或 `cd` | 回到自己的家目录（如 `/home/tom`） |
| `cd -` | 回到上一次所在的目录 |

### 3. 常用参数

cd 的用法主要靠路径写法（上表），参数很少用：

| 参数 | 作用 |
|---|---|
| `-` | 回到上一次所在的目录，并打印它 |
| `-P` | 进入符号链接指向的真实目录 |
| `-L` | 按符号链接的路径进入（默认行为） |

### 4. 常用示例

#### 4.1 进入、返回、查看位置

```
$ cd logs

$ pwd
/home/tom/demo/logs

$ cd ..

$ pwd
/home/tom/demo
```

#### 4.2 `cd -`：在两个目录之间来回切

```
$ cd /var/log

$ pwd
/var/log

$ cd -
/home/tom/demo
```

查日志时在项目目录和 `/var/log` 之间来回跳，用 `cd -` 最省事。

#### 4.3 回家目录

```
$ cd ~

$ pwd
/home/tom

$ cd

$ pwd
/home/tom
```

不带任何参数的 `cd` 和 `cd ~` 效果相同。`~` 也可以拼在路径里，比如 `cd ~/demo/src`。

#### 4.4 目录名带空格

```
$ cd My Docs
bash: cd: too many arguments

$ cd "My Docs"

$ pwd
/home/tom/demo/My Docs
```

带空格的名字要加引号，或者用反斜杠转义：`cd My\ Docs`。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `bash: cd: nothere: No such file or directory` | 目录不存在，或者大小写写错（Linux 区分大小写，`Logs` 和 `logs` 是两个目录） | 先 `ls` 看准名字。输入时按 Tab 键自动补全，能避免拼错 |
| `bash: cd: readme.txt: Not a directory` | cd 后面跟的是文件 | 文件要用 `cat`、`less` 查看 |
| `bash: cd: /root: Permission denied` | 没有该目录的执行（x）权限 | 确实需要时用 `sudo -i` 切到 root 再进入 |
| `bash: cd: too many arguments` | 目录名有空格，被当成了两个参数 | 加引号 `cd "My Docs"` |
| 脚本里执行了 `cd`，脚本结束后终端还在原目录 | 脚本在子 Shell 里运行，cd 只影响子 Shell | 要改当前终端的目录，用 `source 脚本` 执行 |

### 6. 一句话总结

`cd 目录` 进入，`cd ..` 回上级，`cd` 回家，`cd -` 回上一个位置。

## 003 ★★★&nbsp;&nbsp;pwd：显示当前所在目录

> 级别：★★★ 初级 · 来源：bash 内建命令

### 1. 作用

`pwd`（print working directory）打印你当前所在目录的完整路径。切换了几次目录之后不确定自己在哪，或者要把当前路径复制到配置文件里，就用它。

### 2. 基本格式

```bash
pwd [参数]
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-L` | 显示逻辑路径，保留符号链接的名字（默认行为） |
| `-P` | 显示物理路径，把符号链接换成它指向的真实目录 |

### 4. 常用示例

#### 4.1 查看当前位置

```
$ pwd
/home/tom/demo
```

#### 4.2 `-P`：看穿符号链接

先建一个指向 logs 的链接 mylogs，再进入它：

```
$ ln -s logs mylogs

$ cd mylogs

$ pwd
/home/tom/demo/mylogs

$ pwd -P
/home/tom/demo/logs
```

部署目录常用链接切换版本（比如 `current -> release-20261028`），这时 `pwd -P` 能告诉你实际在哪个版本目录里。

#### 4.3 在脚本里用 `$PWD`

```
$ echo $PWD
/home/tom/demo/mylogs
```

Shell 会把当前目录存在环境变量 `PWD` 里，脚本里拼路径时用 `"$PWD/out.txt"` 比再调用一次 pwd 方便。

### 5. 一句话总结

不知道自己在哪就 `pwd`，要看链接背后的真实目录加 `-P`。

## 006 ★★★&nbsp;&nbsp;cp：复制文件和目录

> 级别：★★★ 初级 · 软件包：`gnu-coreutils`（Ubuntu 26.04 的 cp 仍由 GNU 版提供）

### 1. 作用

`cp`（copy）把文件或目录复制到另一个位置。改配置前先备份一份、把程序包拷到部署目录，都用它。

### 2. 基本格式

```bash
cp [参数] 源文件 目标文件          # 复制并命名为目标文件
cp [参数] 源文件... 目标目录       # 把一个或多个文件复制到目录里
```

最后一个参数是目标。目标是已存在的目录时，文件被复制到目录里面。

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-r` | `--recursive` | 复制目录及其中所有内容（复制目录必须加） |
| `-i` | `--interactive` | 目标已存在时先询问是否覆盖 |
| `-v` | `--verbose` | 显示复制了哪些文件 |
| `-p` | | 保留原文件的修改时间、权限、所有者 |
| `-a` | `--archive` | 归档模式，相当于 `-r` 加上保留所有属性和符号链接，适合做备份 |
| `-u` | `--update` | 只在源文件比目标新，或目标不存在时才复制 |
| | `--update=none` | 目标已存在就跳过，不覆盖 |

### 4. 常用示例

#### 4.1 复制一份备份

```
$ cp readme.txt readme.bak
```

改 `/etc/nginx/nginx.conf` 这类配置之前，先 `sudo cp nginx.conf nginx.conf.bak`，改坏了可以马上恢复。

#### 4.2 `-v`：复制到目录，并显示过程

```
$ cp -v readme.txt src/
'readme.txt' -> 'src/readme.txt'
```

一次复制多个文件到同一目录：`cp readme.txt run.sh src/`。

#### 4.3 `-r`：复制目录

```
$ cp logs logs2
cp: -r not specified; omitting directory 'logs'

$ cp -r logs logs2

$ ls logs2
app.log
```

#### 4.4 `-p`：保留修改时间

```
$ cp big.iso big2.iso

$ cp -p big.iso big3.iso

$ ls -l big.iso big2.iso big3.iso
-rw-r--r-- 1 tom tom 2500000 Oct 20 14:30 big.iso
-rw-r--r-- 1 tom tom 2500000 Oct 29 06:41 big2.iso
-rw-r--r-- 1 tom tom 2500000 Oct 20 14:30 big3.iso
```

不加 `-p`，副本的时间变成复制那一刻（big2.iso）；加了 `-p`，保留原来的 Oct 20（big3.iso）。备份时要保留时间，否则以后分不清哪个是原始版本。

#### 4.5 `-a`：完整备份一个目录

```
$ cp -a logs logs3
```

`-a` 会保留权限、所有者、时间、符号链接。备份网站目录、数据目录时用 `-a`，比 `-r` 更稳妥。

#### 4.6 `-i`：覆盖前询问

```
$ cp -i readme.txt readme.bak
cp: overwrite 'readme.bak'? 
```

输入 `y` 回车覆盖，输入其他内容则取消。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 目标文件被直接覆盖，没有任何提示 | cp 默认不询问 | 重要文件加 `-i`，或先备份 |
| 同一条 `cp -r logs/ logs4` 执行两次，第二次多出了 `logs4/logs/` | 第一次 logs4 不存在，cp 把 logs 复制成 logs4；第二次 logs4 已存在，cp 把 logs 复制到 logs4 里面 | 复制前先确认目标是否存在。要复制“目录里的内容”，写成 `cp -r logs/. logs4/` |
| `cp -n` 提示 `warning: behavior of -n is non-portable and may change in future` | GNU cp 9.x 对 `-n` 的行为做了调整，会给出提醒 | 改用 `--update=none` |
| `cp: cannot stat '*.csv': No such file or directory` | 当前目录没有匹配的文件，`*.csv` 没有被展开，原样传给了 cp | 先 `ls *.csv` 确认文件在哪 |
| 复制到 `/etc`、`/opt` 报 `Permission denied` | 普通用户没有这些目录的写权限 | 加 `sudo` |

上表第二条的实测过程：

```
$ cp -r logs/ logs4

$ ls logs4
app.log

$ cp -r logs/ logs4

$ ls logs4
app.log  logs
```

### 6. 一句话总结

复制目录加 `-r`，做备份用 `-a`，怕覆盖加 `-i`。

<a id="cmd-mv"></a>

## 007 ★★★&nbsp;&nbsp;mv：移动或重命名

> 级别：★★★ 初级 · 软件包：`gnu-coreutils`（Ubuntu 26.04 的 mv 仍由 GNU 版提供）

### 1. 作用

`mv`（move）有两个用途：把文件或目录移动到别的位置；在同一位置换个名字，也就是重命名。Linux 没有单独的“重命名”指令，重命名就用 mv。

和 cp 不同，mv 移动目录不需要 `-r`。

### 2. 基本格式

```bash
mv [参数] 旧名 新名            # 重命名
mv [参数] 源... 目标目录        # 移动到目录里
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-i` | `--interactive` | 目标已存在时先询问 |
| `-v` | `--verbose` | 显示移动了哪些文件 |
| `-n` | `--no-clobber` | 目标已存在就不覆盖 |
| `-u` | `--update` | 只在源比目标新时才移动 |
| `-b` | `--backup` | 覆盖前把目标文件备份成 `文件名~` |

### 4. 常用示例

#### 4.1 重命名

```
$ mv readme.txt readme.md
```

#### 4.2 `-v`：移动到目录

```
$ mv -v readme.md src/
renamed 'readme.md' -> 'src/readme.md'

$ mv src/readme.md .
```

`.` 代表当前目录，第二条命令把文件移回来。

#### 4.3 一次移动多个文件

```
$ mkdir bak

$ mv -v big.iso run.sh bak/
renamed 'big.iso' -> 'bak/big.iso'
renamed 'run.sh' -> 'bak/run.sh'
```

整理日志目录时，常用 `mv *.log.1 archive/` 把旧日志归档。

#### 4.4 `-i`：防止覆盖

```
$ mv -i readme.md a.md
mv: overwrite 'a.md'? 
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 想把 logs 移到 nothere 目录里，结果 logs 被改名成了 nothere | 目标目录不存在时，mv 把它当成新名字 | 先 `mkdir nothere`，再移动 |
| 同名文件被直接覆盖，没有提示 | mv 默认不询问 | 加 `-i` 或 `-n` |
| 跨分区移动大目录特别慢 | 同一分区内 mv 只改目录记录，瞬间完成；跨分区（比如移到另一块硬盘）实际是复制再删除 | 跨分区移动大量数据改用 `rsync -a --remove-source-files`，可以断点续传 |

第一条踩坑的实测过程，执行后 logs 不见了，多了一个 nothere：

```
$ mv logs nothere/

$ ls
a.md  bak  link.txt  nothere  readme.md  src
```

### 6. 一句话总结

同目录里 `mv` 是改名，跨目录是移动；目标目录要先建好，怕覆盖加 `-i`。

<a id="cmd-rm"></a>

## 008 ★★★&nbsp;&nbsp;rm：删除文件和目录

> 级别：★★★ 初级 · 软件包：`gnu-coreutils`（Ubuntu 26.04 的 rm 仍由 GNU 版提供）

### 1. 作用

`rm`（remove）删除文件或目录。在终端里删除的文件**不进回收站**，删了就找不回来，执行前要看清楚。

### 2. 基本格式

```bash
rm [参数] 文件或目录...
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-r` | `--recursive` | 删除目录及其中的所有内容 |
| `-f` | `--force` | 强制删除，不询问，文件不存在也不报错 |
| `-i` | | 每删一个文件都询问 |
| `-I` | | 删除超过 3 个文件或递归删除时，只询问一次 |
| `-v` | `--verbose` | 显示删除了哪些文件 |
| `-d` | `--dir` | 删除空目录 |

### 4. 常用示例

#### 4.1 删除文件

```
$ rm big.iso

$ rm -v readme.txt
removed 'readme.txt'
```

#### 4.2 `-r`：删除目录

```
$ rm src
rm: cannot remove 'src': Is a directory

$ rm -r src
```

#### 4.3 `-rv`：看清楚删了什么

```
$ rm -rv x
removed 'x/y/z.txt'
removed directory 'x/y'
removed directory 'x'
```

#### 4.4 `-i` 和 `-I`：删除前确认

```
$ rm -i run.sh
rm: remove regular file 'run.sh'? 

$ rm -I run.sh link.txt .env logs/app.log
rm: remove 4 arguments? 
```

`-i` 每个文件问一次，`-I` 只问一次，批量删除时用 `-I` 更实用。

#### 4.5 `-f`：文件不存在也不报错

```
$ rm nothere
rm: cannot remove 'nothere': No such file or directory

$ rm -f nothere
```

脚本里清理临时文件常用 `rm -f`，文件不存在时脚本不会因为报错而中断。

#### 4.6 删除以 `-` 开头的文件

```
$ rm -bad.txt
rm: invalid option -- 'b'
Try 'rm ./-bad.txt' to remove the file '-bad.txt'.
Try 'rm --help' for more information.

$ rm -- -bad.txt
```

`--` 告诉 rm “后面的都是文件名，不是参数”。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `rm -rf $DIR/*` 在变量为空时变成 `rm -rf /*`，删掉整个系统 | 变量没赋值，展开后只剩 `/*` | 脚本里写 `rm -rf "${DIR:?}"/*`，变量为空时 bash 直接报错退出 |
| `rm -rf / tmp` 多打了一个空格 | 删除对象变成了 `/` 和 `tmp` 两个 | 执行前先用 `ls` 看要删的路径。rm 对 `/` 有保护（见下方），但对 `/*`、`/home` 没有 |
| 删错文件想恢复 | rm 不经过回收站 | 重要数据提前备份。删除前用 `ls 同样的参数` 预览，确认无误再把 ls 换成 rm |
| `rm: cannot remove 'src': Is a directory` | 删除目录要加 `-r` | `rm -r src` |

rm 对根目录的保护：

```
$ rm -rf /
rm: it is dangerous to operate recursively on '/'
rm: use --no-preserve-root to override this failsafe
```

### 6. 一句话总结

`rm` 删了不进回收站；删目录加 `-r`，批量删除加 `-I`，脚本里变量要防空。

<a id="cmd-mkdir"></a>

## 009 ★★★&nbsp;&nbsp;mkdir：新建目录

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`mkdir`（make directory）新建目录。部署程序前建好 `logs`、`data`、`backup` 这些目录，用的就是它。

### 2. 基本格式

```bash
mkdir [参数] 目录名...
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-p` | `--parents` | 自动创建缺少的上级目录；目录已存在也不报错 |
| `-v` | `--verbose` | 显示创建了哪些目录 |
| `-m` | `--mode` | 创建时直接指定权限，如 `-m 700` |

### 4. 常用示例

#### 4.1 新建一个目录

```
$ mkdir backup

$ mkdir backup
mkdir: backup: File exists
```

#### 4.2 `-p`：一次建多层

```
$ mkdir a/b/c
mkdir: No such file or directory

$ mkdir -p a/b/c

$ mkdir -p a/b/c
```

不加 `-p`，上级目录 a/b 不存在就报错。加了 `-p`，目录已存在时再执行也不报错，所以部署脚本里一律写 `mkdir -p`。

#### 4.3 `-pv` 加花括号：批量建目录

```
$ mkdir -pv 2026/{01,02,03}
mkdir: created directory '2026'
mkdir: created directory '2026/01'
mkdir: created directory '2026/02'
mkdir: created directory '2026/03'
```

`{01,02,03}` 由 bash 展开成三个名字。按月归档报表时很方便，`{01..12}` 一次建出 12 个月。

#### 4.4 `-m`：创建时指定权限

```
$ mkdir -m 700 secret

$ ls -ld secret
drwx------ 2 tom tom 4096 Oct 29 06:41 secret
```

700 表示只有自己能进入。存放密钥、证书的目录适合这样建。权限数字的含义见 [chmod](05-用户和权限.md#cmd-chmod)。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `mkdir My Docs` 建出了 `My` 和 `Docs` 两个目录 | 空格把名字拆成了两个参数 | 加引号：`mkdir "My Docs"`。Linux 下的目录名最好不用空格 |
| 在 `/opt` 下建目录报 `mkdir: Permission denied` | 普通用户没有 /opt 的写权限 | `sudo mkdir /opt/app`，再用 `sudo chown tom:tom /opt/app` 把目录交给自己 |
| 脚本第二次运行时在 mkdir 处报 `File exists` | 目录在第一次运行时已经建好了 | 改用 `mkdir -p` |

Ubuntu 26.04 的 mkdir 由 Rust 版 coreutils 提供，报错信息比较简短，例如 `mkdir: No such file or directory` 不会写出是哪个路径。看到这类报错，回头检查命令里的路径即可。

### 6. 一句话总结

建目录一律用 `mkdir -p`，批量建配合 `{}`，私密目录加 `-m 700`。

<a id="cmd-touch"></a>

## 010 ★★★&nbsp;&nbsp;touch：新建空文件或修改文件时间

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`touch` 有两个用途：

- 文件不存在时，新建一个空文件；
- 文件已存在时，把它的修改时间改成现在（或你指定的时间），内容不变。

第二种用法常用于测试：比如让某个按时间清理旧文件的脚本，误以为一个文件是很久以前的。

### 2. 基本格式

```bash
touch [参数] 文件...
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-d` | `--date` | 指定时间，写法如 `"2026-01-01 08:00"` |
| `-t` | | 指定时间，格式为 `[[CC]YY]MMDDhhmm[.ss]`，如 `202605011230` |
| `-c` | `--no-create` | 文件不存在时不新建 |
| `-r` | `--reference` | 使用另一个文件的时间 |

### 4. 常用示例

#### 4.1 新建空文件

```
$ touch new.txt

$ ls -l new.txt readme.txt
-rw-r--r-- 1 tom tom 0 Oct 29 06:41 new.txt
-rw-r--r-- 1 tom tom 6 Oct  1 09:00 readme.txt
```

#### 4.2 把修改时间改成现在

```
$ touch readme.txt

$ ls -l readme.txt
-rw-r--r-- 1 tom tom 6 Oct 29 06:41 readme.txt
```

时间从 Oct 1 变成了现在，内容没变（大小还是 6）。

#### 4.3 `-d` 和 `-t`：改成指定时间

```
$ touch -d "2026-01-01 08:00" readme.txt

$ ls -l readme.txt
-rw-r--r-- 1 tom tom 6 Jan  1  2026 readme.txt

$ touch -t 202605011230 readme.txt

$ ls -l --time-style=long-iso readme.txt
-rw-r--r-- 1 tom tom 6 2026-05-01 12:30 readme.txt
```

`-d` 的写法更直观，推荐用 `-d`。

#### 4.4 批量新建

```
$ touch file{1..3}.log

$ ls
big.iso    file2.log  link.txt  new.txt     run.sh
file1.log  file3.log  logs      readme.txt  src
```

#### 4.5 `-r`：照搬另一个文件的时间

```
$ touch -r big.iso new.txt

$ ls -l big.iso new.txt
-rw-r--r-- 1 tom tom 2500000 Oct 20 14:30 big.iso
-rw-r--r-- 1 tom tom       0 Oct 20 14:30 new.txt
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 想测试“文件不存在”的情况，touch 反而把文件建出来了 | touch 默认会新建 | 加 `-c` |
| `touch: cannot touch '/etc/x': Permission denied` | 没有目录的写权限 | 加 `sudo` |
| 用 touch 清空文件，文件内容还在 | touch 只改时间，不动内容 | 清空文件用 `: > 文件名` 或 `truncate -s 0 文件名` |

### 6. 一句话总结

`touch` 建空文件或刷新时间，指定时间用 `-d`，不想新建加 `-c`。

<a id="cmd-find"></a>

## 022 ★★★&nbsp;&nbsp;find：按条件查找文件

> 级别：★★★ 初级 · 软件包：`findutils`（GNU 版）

### 1. 作用

`find` 从指定目录开始，逐层往下找出符合条件的文件和目录。条件可以是文件名、类型、大小、修改时间、所有者，还可以组合使用。找到之后还能直接对它们执行操作，比如删除 30 天前的日志。

grep 是在文件**内容**里找，find 是按文件**名字和属性**找。

### 2. 基本格式

```bash
find [起始目录] [条件...] [动作]
```

不写起始目录时从当前目录开始。不写动作时，默认打印找到的路径。

### 3. 常用参数

| 条件 / 动作 | 作用 |
|---|---|
| `-name "模式"` | 按文件名匹配，区分大小写，可用 `*` `?` 通配符 |
| `-iname "模式"` | 按文件名匹配，不区分大小写 |
| `-type f` / `-type d` | 只找普通文件 / 只找目录 |
| `-size +1M` | 大于 1 MB（`-1M` 小于，单位可用 `k` `M` `G`） |
| `-mtime -1` | 1 天内修改过（`+7` 表示 7 天以前修改的） |
| `-mmin -30` | 30 分钟内修改过 |
| `-newer 文件` | 比某个文件更新 |
| `-user 用户` | 属于某个用户 |
| `-empty` | 空文件或空目录 |
| `-maxdepth N` | 最多往下找 N 层 |
| `-exec 命令 {} \;` | 对每个结果执行命令，`{}` 代表找到的文件 |
| `-delete` | 删除找到的文件 |

### 4. 常用示例

#### 4.1 按名字找

```
$ find . -name "*.log"
./logs/app.log

$ find . -name "*.LOG"

$ find . -iname "*.LOG"
./logs/app.log
```

#### 4.2 按类型找

```
$ find . -type d
.
./src
./logs

$ find . -type f -name "*.csv"
./src/products.csv
```

#### 4.3 按大小找：磁盘满了，找大文件

```
$ find . -size +1M
./big.iso
```

整台机器上找大于 1 GB 的文件：`sudo find / -type f -size +1G 2>/dev/null`。

#### 4.4 按时间找

```
$ find . -mtime +7
./big.iso
./readme.txt
```

big.iso（Oct 20）和 readme.txt（Oct 1）都是 7 天前修改的。`-mtime -1` 找 24 小时内改过的文件，排查“昨天谁动了配置”时用。

#### 4.5 限制深度

```
$ find . -maxdepth 1 -type f
./run.sh
./.env
./big.iso
./readme.txt
```

只看当前这一层，不进子目录。

#### 4.6 `-exec`：对结果执行命令

```
$ find . -name "*.log" -exec ls -l {} \;
-rw-r--r-- 1 tom tom 404 Oct 28 11:30 ./logs/app.log
```

`{}` 会被替换成每个找到的文件，`\;` 表示命令到此结束（分号前的反斜杠不能省）。

#### 4.7 清理旧日志

```bash
find /var/log/app -name "*.log" -mtime +30 -print     # 先看看会删哪些
find /var/log/app -name "*.log" -mtime +30 -delete    # 确认无误再删
```

#### 4.8 屏蔽权限报错

```
$ find /etc -name "hosts"
/etc/hosts
find: ‘/etc/ssl/private’: Permission denied

$ find /etc -name "hosts" 2>/dev/null
/etc/hosts
```

`2>/dev/null` 把错误信息丢掉，只留结果。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `find: paths must precede expression` | `-name *.txt` 没加引号，`*.txt` 被 Shell 先展开成了多个文件名 | 模式一律加引号：`-name "*.txt"` |
| `-delete` 写在前面，把所有文件都删了 | find 按顺序处理，`find . -delete -name "*.tmp"` 会先删再判断名字 | `-delete` 必须放在最后；先用 `-print` 预览 |
| 搜索整个系统非常慢，还刷出一堆 `Permission denied` | 从 `/` 开始会遍历所有目录，包括 `/proc` | 缩小起始目录；加 `2>/dev/null`；只按文件名找可以用更快的 [locate](#cmd-locate) |
| `-mtime +1` 没找到昨天的文件 | `-mtime` 按“整 24 小时”计算，`+1` 表示超过 48 小时 | 按分钟算更直观：`-mmin +1440` |

第一条的实测：

```
$ find . -name *.txt
find: paths must precede expression: `readme.txt'
find: possible unquoted pattern after predicate `-name'?
```

### 6. 一句话总结

`find 目录 -name "模式" -type f` 按名字找；删除前先 `-print` 预览，`-delete` 放最后。

<a id="cmd-file"></a>

## 046 ★★★&nbsp;&nbsp;file：判断文件类型

> 级别：★★★ 初级 · 软件包：`file`

### 1. 作用

`file` 读取文件开头的内容，判断它实际上是什么类型：文本、脚本、压缩包、图片、可执行程序等。Linux 不靠扩展名决定文件类型，一个叫 `data.txt` 的文件完全可能是个压缩包。拿到来历不明的文件，先用 file 看一眼。

### 2. 基本格式

```bash
file [参数] 文件...
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-i` | `--mime` | 输出 MIME 类型和字符编码 |
| `-b` | `--brief` | 不显示文件名，只显示类型 |
| `-L` | `--dereference` | 对符号链接，判断它指向的文件 |

### 4. 常用示例

#### 4.1 判断多个文件

```
$ file run.sh big.iso logs link.txt
run.sh:   Bourne-Again shell script, ASCII text executable
big.iso:  data
logs:     directory
link.txt: symbolic link to readme.txt
```

`data` 表示 file 认不出具体格式（演示用的 big.iso 只是一堆 0）。

#### 4.2 文本文件和编码

```
$ file src/products.csv
src/products.csv: CSV Unicode text, UTF-8 text

$ file -i readme.txt
readme.txt: text/plain; charset=us-ascii
```

从 Windows 导出的 CSV 在 Linux 上显示乱码时，先用 `file` 看编码。下面是一个 GBK 编码的文件：

```
$ file gbk.csv
gbk.csv: ISO-8859 text

$ iconv -f GBK -t UTF-8 gbk.csv
探头,主机
```

file 不认识 GBK，会显示成 `ISO-8859` 或 `Non-ISO extended-ASCII`。看到这两种，多半就是 GBK，用 `iconv -f GBK -t UTF-8 原文件 > 新文件` 转换。

#### 4.3 扩展名会骗人

```
$ cp a.tgz a.txt; file a.txt
a.txt: gzip compressed data, from Unix, original size modulo 2^32 10240
```

文件叫 a.txt，实际是 gzip 压缩包。

#### 4.4 可执行程序

```
$ file /usr/bin/grep
/usr/bin/grep: ELF 64-bit LSB pie executable, x86-64, version 1 (SYSV), dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2, BuildID[sha1]=9601f9b5d319a231b14e6c6289e998da074aa543, for GNU/Linux 3.2.0, stripped
```

`x86-64` 说明是给 Intel/AMD 64 位 CPU 编译的程序。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| CSV 是 GBK 编码，file 却显示成别的编码 | 文件里中文很少时，file 的判断依据不足 | 用 `iconv -f GBK -t UTF-8` 试着转换，看结果是否正常 |
| 对链接只显示 `symbolic link to ...` | file 默认不跟随链接 | 加 `-L` |

### 6. 一句话总结

不确定文件是什么就 `file` 一下，查编码加 `-i`。

## 050 ★★★&nbsp;&nbsp;rmdir：删除空目录

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`rmdir`（remove directory）只删除**空**目录。目录里还有任何文件时它会拒绝执行，所以比 `rm -r` 安全：清理目录结构时用它，不用担心误删里面的文件。

### 2. 基本格式

```bash
rmdir [参数] 目录...
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-p` | `--parents` | 连同上级目录一起删除（上级也必须变成空的） |
| `-v` | `--verbose` | 显示处理过程 |

### 4. 常用示例

#### 4.1 删除空目录

```
$ mkdir empty; rmdir empty
```

#### 4.2 目录不空时拒绝删除

```
$ rmdir logs
rmdir: failed to remove 'logs': Directory not empty
```

确认里面的东西都不要了，才改用 `rm -r logs`。

#### 4.3 `-p`：一次删掉多层空目录

```
$ mkdir -p a/b/c; rmdir -p a/b/c; ls
big.iso  link.txt  logs  n.txt  readme.txt  run.sh  src
```

依次删除 a/b/c、a/b、a。

#### 4.4 批量清理空目录

```bash
find . -type d -empty -delete
```

rmdir 只处理你点名的目录。要把整个目录树里所有空目录都清掉，用 find。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 目录看起来是空的，rmdir 仍报 `Directory not empty` | 里面有隐藏文件 | `ls -A 目录` 查看 |

### 6. 一句话总结

只删空目录用 `rmdir`，删不掉就说明里面还有东西。

<a id="cmd-ln"></a>

## 051 ★★★&nbsp;&nbsp;ln：创建链接

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`ln`（link）给文件或目录创建链接。日常用的几乎都是**符号链接**（symbolic link，也叫软链接）：一个指向另一个路径的“快捷方式”。

常见用途：

- 部署多个版本时，用 `current -> release-20261028` 指向当前版本，切换版本只需改链接；
- 把一个很深的目录链接到家目录，少敲几层路径；
- 程序要求配置文件在某个固定位置，用链接指过去，实际文件放在别处统一管理。

### 2. 基本格式

```bash
ln -s 目标 链接名
```

顺序是“先写已经存在的目标，再写要新建的链接名”，和 `cp 源 目标` 的顺序一致。

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-s` | `--symbolic` | 创建符号链接（不加则创建硬链接） |
| `-f` | `--force` | 链接名已存在时先删除再创建 |
| `-n` | `--no-dereference` | 链接名是指向目录的链接时，把它当普通文件处理（和 `-f` 配合替换目录链接） |
| `-v` | `--verbose` | 显示创建了什么 |

### 4. 常用示例

#### 4.1 链接到文件

```
$ ln -s readme.txt r.lnk; ls -l r.lnk
lrwxrwxrwx 1 tom tom 10 Oct 29 07:00 r.lnk -> readme.txt
```

#### 4.2 链接到目录

```
$ ln -s /var/log syslogs; ls -l syslogs
lrwxrwxrwx 1 tom tom 8 Oct 29 07:00 syslogs -> /var/log

$ ls syslogs | head -3
alternatives.log
apt
bootstrap.log
```

#### 4.3 `-sfn`：切换版本

```
$ ln -sf src current; ls -l current
lrwxrwxrwx 1 tom tom 3 Oct 29 07:00 current -> src

$ mkdir v2; ln -sfn v2 current; ls -l current
lrwxrwxrwx 1 tom tom 2 Oct 29 07:00 current -> v2
```

`current` 已经指向一个目录时，必须加 `-n`。不加的话，ln 会进入 current 指向的目录，在里面新建一个链接，current 本身不会改变。

### 5. 符号链接和硬链接

| | 符号链接（`ln -s`） | 硬链接（`ln`） |
|---|---|---|
| 本质 | 一个记录着路径的小文件 | 同一份数据的另一个名字 |
| 删除原文件后 | 链接失效 | 数据还在，另一个名字照样能用 |
| 能否链接目录 | 能 | 不能 |
| 能否跨分区 | 能 | 不能 |

硬链接的实测，两个名字的 inode 编号相同（都是 9），链接数是 2：

```
$ ln readme.txt hard.txt; ls -li readme.txt hard.txt
9 -rw-r--r-- 2 tom tom 6 Oct  1 09:00 hard.txt
9 -rw-r--r-- 2 tom tom 6 Oct  1 09:00 readme.txt

$ echo more >> hard.txt; cat readme.txt
hello
more

$ rm readme.txt; cat hard.txt; cat r.lnk
hello
more
cat: r.lnk: No such file or directory
```

删除 readme.txt 后，硬链接 hard.txt 照常可读，符号链接 r.lnk 失效了。日常用符号链接即可。

### 6. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `ln -s logs/app.log logs/app2.log` 建出来的链接打不开 | 符号链接里的相对路径，是相对**链接所在的目录**计算的，这里实际指向 `logs/logs/app.log` | 写成 `ln -s app.log logs/app2.log`，或者目标用绝对路径 |
| `ls -l` 显示链接存在，访问时报 `No such file or directory` | 目标已经被删除或改名（失效链接） | 用 `ls -l` 看它指向哪里，重新创建 |
| 参数顺序写反，报 `failed to create symbolic link ... Already exists` | 把已存在的文件写在了链接名的位置 | 记住顺序：`ln -s 已有的目标 新链接名` |

第一条的实测：

```
$ ln -s logs/app.log logs/app2.log; cat logs/app2.log
cat: logs/app2.log: No such file or directory
```

### 7. 一句话总结

`ln -s 目标 链接名` 建快捷方式，切换目录链接用 `-sfn`，相对路径从链接所在目录算起。

## 059 ★★★&nbsp;&nbsp;tree：树状显示目录结构

> 级别：★★★ 初级 · 软件包：`tree`（不是所有安装方式都自带，没有就 `sudo apt install tree`）

### 1. 作用

`tree` 用树形图显示目录下的所有子目录和文件，层级关系一目了然。接手一个新项目、写文档说明目录结构、确认部署包里的文件齐不齐，都用它。

### 2. 基本格式

```bash
tree [参数] [目录]
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-L 层数` | 只显示到第几层 |
| `-d` | 只显示目录 |
| `-a` | 包括隐藏文件 |
| `-h` | 显示文件大小 |
| `-P "模式"` | 只显示匹配的文件 |
| `-I "模式"` | 排除匹配的文件或目录 |
| `--prune` | 不显示空目录（和 `-P` 配合） |

### 4. 常用示例

#### 4.1 显示全部

```
$ tree
.
├── big.iso
├── link.txt -> readme.txt
├── logs
│   └── app.log
├── readme.txt
├── run.sh
└── src
    └── products.csv

3 directories, 6 files
```

#### 4.2 `-L`：只看一层

```
$ tree -L 1
.
├── big.iso
├── link.txt -> readme.txt
├── logs
├── readme.txt
├── run.sh
└── src

3 directories, 4 files
```

大项目的目录有几千个文件，先用 `-L 2` 看个大概。

#### 4.3 `-d`：只看目录

```
$ tree -d
.
├── logs
└── src

3 directories
```

#### 4.4 `-h`：带大小

```
$ tree -h
[4.0K]  .
├── [2.4M]  big.iso
├── [  10]  link.txt -> readme.txt
├── [4.0K]  logs
│   └── [ 404]  app.log
├── [   6]  readme.txt
├── [  20]  run.sh
└── [4.0K]  src
    └── [ 152]  products.csv

3 directories, 6 files
```

#### 4.5 `-P` 和 `-I`：筛选

```
$ tree -P "*.csv" --prune
.
└── src
    └── products.csv

2 directories, 1 file

$ tree -I "logs"
.
├── big.iso
├── link.txt -> readme.txt
├── readme.txt
├── run.sh
└── src
    └── products.csv

2 directories, 5 files
```

前端项目里常用 `tree -I "node_modules|dist"` 跳过依赖和构建产物，`|` 分隔多个模式。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `tree: command not found` | 系统没装 | `sudo apt install tree` |
| 在大目录下执行，刷屏几分钟 | 文件太多 | 加 `-L 2`，或用 `-I` 排除大目录 |
| 把输出贴到 Windows 记事本里，线条变成乱码 | 树形线条是 UTF-8 字符 | 加 `--charset=ascii`，线条改用 `|--` 显示 |

### 6. 一句话总结

`tree -L 2` 看项目结构，`-I` 排除大目录，`-d` 只看目录。

## 090 ★★★&nbsp;&nbsp;basename：从路径里取文件名

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`basename` 去掉路径中的目录部分，只留下最后的文件名；还可以顺便去掉扩展名。主要在脚本里用：批量处理文件时，拼出新的文件名。

和它对应的是 [dirname](#cmd-dirname)，只取目录部分。

### 2. 基本格式

```bash
basename 路径 [要去掉的后缀]
basename -s 后缀 路径...
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-s 后缀` | `--suffix` | 去掉指定后缀 |
| `-a` | `--multiple` | 一次处理多个路径 |

### 4. 常用示例

#### 4.1 取文件名

```
$ basename /home/tom/demo/logs/app.log
app.log
```

#### 4.2 顺便去掉扩展名

```
$ basename /home/tom/demo/logs/app.log .log
app

$ basename -s .csv src/products.csv
products
```

#### 4.3 脚本里批量改名备份

```
$ for f in logs/*.log; do cp "$f" "/tmp/$(basename "$f" .log)-$(date +%Y%m%d).log"; done; ls /tmp
app-20261029.log
```

logs/app.log 被复制成了 /tmp/app-20261029.log。

#### 4.4 bash 自带的写法

```
$ f=/var/log/nginx/access.log; echo "${f##*/} ${f%/*}"
access.log /var/log/nginx
```

`${f##*/}` 等于 basename，`${f%/*}` 等于 dirname。在循环里处理大量文件时，这种写法不用启动新进程，速度更快。

### 5. 一句话总结

`basename 路径 .扩展名` 取不带扩展名的文件名，批量改名时常用。

## 091 ★★★&nbsp;&nbsp;dirname：从路径里取目录

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`dirname` 去掉路径中最后一部分，只留下所在的目录。它只做字符串处理，不检查目录是否真的存在。

### 2. 基本格式

```bash
dirname 路径...
```

### 3. 常用示例

#### 3.1 取目录

```
$ dirname /home/tom/demo/logs/app.log
/home/tom/demo/logs

$ dirname app.log
.
```

路径里没有目录部分时，返回 `.`（当前目录）。

#### 3.2 和 basename 一起拆路径

```
$ f=/var/log/nginx/access.log; echo "目录=$(dirname $f) 文件=$(basename $f)"
目录=/var/log/nginx 文件=access.log
```

#### 3.3 脚本里找到“脚本自己所在的目录”

```bash
#!/bin/bash
SCRIPT_DIR=$(cd "$(dirname "$0")" && pwd)
cat "$SCRIPT_DIR/config.ini"
```

`$0` 是脚本自己的路径。这样写，无论从哪个目录调用这个脚本，都能找到和它放在一起的 config.ini。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 路径里有空格，dirname 结果被拆开了 | `$f` 没加引号，被 Shell 按空格拆分 | 写成 `dirname "$f"` |

### 5. 一句话总结

`dirname 路径` 取所在目录；脚本里用 `$(dirname "$0")` 定位脚本自身的目录。

## 092 ★★★&nbsp;&nbsp;stat：查看文件的详细属性

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`stat` 显示文件的全部元数据：精确大小、占用的块数、inode 号、权限（同时给出数字和字母两种写法）、所有者，以及四个时间。`ls -l` 只显示一个修改时间，排查“这个文件到底什么时候被动过”时要用 stat。

### 2. 基本格式

```bash
stat [参数] 文件...
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-c 格式` | `--format` | 只输出指定的字段 |
| `-L` | `--dereference` | 对符号链接，显示它指向的文件 |

`-c` 常用的格式符：

| 格式符 | 含义 |
|---|---|
| `%n` | 文件名 |
| `%s` | 大小（字节） |
| `%U` / `%G` | 所有者 / 所属组 |
| `%a` | 权限的数字写法，如 644 |
| `%y` | 修改时间 |

### 4. 常用示例

#### 4.1 完整信息

```
$ stat readme.txt
  File: readme.txt
  Size: 6               Blocks: 8          IO Block: 4096   regular file
Device: 0,118   Inode: 9           Links: 1
Access: (0644/-rw-r--r--)  Uid: ( 1000/     tom)   Gid: ( 1000/     tom)
Access: 2026-10-01 09:00:00.000000000 +0000
Modify: 2026-10-01 09:00:00.000000000 +0000
Change: 2026-10-29 07:08:33.509863663 +0000
 Birth: 2026-10-29 07:08:33.489863744 +0000
```

四个时间的含义：

| 时间 | 什么时候会变 |
|---|---|
| Access | 文件内容被读取 |
| Modify | 文件**内容**被修改，`ls -l` 显示的就是它 |
| Change | 文件**属性**被修改（权限、所有者、改名），内容修改也会更新它 |
| Birth | 文件创建的时间 |

演示文件的 Modify 被 touch 改成了 Oct 1，但 Change 记录了真实的操作时间（Oct 29）。touch 可以伪造 Modify，伪造不了 Change。

#### 4.2 `-c`：只取需要的字段

```
$ stat -c "%n %s %U %a %y" readme.txt
readme.txt 6 tom 644 2026-10-01 09:00:00.000000000 +0000

$ stat -c %s big.iso
2500000
```

脚本里判断文件大小，`stat -c %s` 比解析 `ls -l` 的输出可靠。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| Access 时间一直不怎么变 | Ubuntu 默认用 relatime 方式挂载，读取时不是每次都更新 Access | 不要用 Access 时间判断文件是否被读过 |
| `stat: cannot statx 'nothere': No such file or directory` | 文件不存在 | 检查文件名 |

### 6. 一句话总结

`stat` 看四个时间和数字权限，脚本里取大小用 `stat -c %s`。

<a id="cmd-locate"></a>

## 093 ★★★&nbsp;&nbsp;locate：按文件名快速查找

> 级别：★★★ 初级 · 软件包：`plocate`（`locate` 是指向 plocate 的链接）

### 1. 作用

`locate` 按文件名在整个系统里查找，几乎瞬间出结果。它快的原因是：并不现场搜索磁盘，而是查一个事先建好的文件名数据库（`/var/lib/plocate/plocate.db`）。这个数据库每天自动更新一次。

| | locate | [find](#cmd-find) |
|---|---|---|
| 速度 | 很快 | 目录多时很慢 |
| 结果是否最新 | 只到上次更新数据库为止 | 实时 |
| 能按大小、时间等条件找 | 不能，只按名字 | 能 |

### 2. 基本格式

```bash
locate [参数] 模式
```

模式里不带通配符时，会匹配路径中任何位置包含这段文字的文件。

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-i` | 忽略大小写 |
| `-c` | 只输出匹配的数量 |
| `-n 数量` | 最多输出 N 条 |
| `-e` | 只显示现在仍然存在的文件 |
| `-b` | 只匹配文件名部分，不匹配目录名 |

### 4. 常用示例

以下以 root 身份执行（测试环境限制，普通用户在真实系统上同样可以使用）。

#### 4.1 找配置文件在哪

```
$ locate sshd_config
/etc/ssh/sshd_config
/etc/ssh/sshd_config.d
/usr/share/man/man5/sshd_config.5.gz
/usr/share/openssh/sshd_config
/usr/share/openssh/sshd_config.md5sum
/var/lib/ucf/cache/:etc:ssh:sshd_config
```

#### 4.2 `-i`、`-c`、`-n`

```
$ locate -i "SSHD_CONFIG" | head -2
/etc/ssh/sshd_config
/etc/ssh/sshd_config.d

$ locate -c "*.conf"
131
```

#### 4.3 新文件找不到，删掉的还在

```
$ touch /opt/new-report.xlsx; locate new-report.xlsx; echo "退出码=$?"
退出码=1

$ sudo updatedb; locate new-report.xlsx
/opt/new-report.xlsx

$ rm /opt/new-report.xlsx; locate new-report.xlsx
/opt/new-report.xlsx

$ locate -e new-report.xlsx; echo "退出码=$?"
退出码=1
```

刚创建的文件要等 [updatedb](#cmd-updatedb) 更新数据库后才能找到；删掉的文件在下次更新前还会出现，加 `-e` 可以过滤掉。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 刚下载的文件 locate 找不到 | 数据库还没更新 | `sudo updatedb` 后再找，或用 find |
| `/tmp`、U 盘里的文件永远找不到 | 这些位置在 `/etc/updatedb.conf` 里被设为不收录 | 用 find |
| `locate: command not found` | 没装 plocate | `sudo apt install plocate` |

### 6. 一句话总结

按名字找文件先用 `locate`，找不到再 `sudo updatedb` 或改用 find。

<a id="cmd-updatedb"></a>

## 094 ★★★&nbsp;&nbsp;updatedb：更新 locate 的数据库

> 级别：★★★ 初级 · 软件包：`plocate`

### 1. 作用

`updatedb` 扫描整个文件系统，重建 [locate](#cmd-locate) 使用的文件名数据库。系统每天会自动执行一次，平时只有在“刚放进去的文件 locate 找不到”时才需要手动执行。

### 2. 基本格式

```bash
sudo updatedb
```

需要 root 权限，因为它要读取所有目录。执行成功不会有输出。

### 3. 自动更新的时间

Ubuntu 26.04 用 systemd 定时器 `plocate-updatedb.timer` 每天执行一次，单元文件里的设置是：

```
OnCalendar=daily
RandomizedDelaySec=1h
```

即每天零点之后的 1 小时内随机执行。

### 4. 哪些位置不收录

设置在 `/etc/updatedb.conf` 里：

```
$ grep -E "^PRUNEPATHS" /etc/updatedb.conf
PRUNEPATHS="/tmp /var/spool /media /var/lib/os-prober /var/lib/ceph /home/.ecryptfs /var/lib/schroot"
```

| 设置项 | 作用 |
|---|---|
| `PRUNEPATHS` | 不收录的目录，如 /tmp、/media（U 盘挂载的位置） |
| `PRUNEFS` | 不收录的文件系统类型，如 nfs、cifs（网络共享）、tmpfs |
| `PRUNE_BIND_MOUNTS` | 不重复收录绑定挂载的目录 |

不收录网络共享，是为了避免每天扫描一遍远程的海量文件。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 普通用户执行报 `/var/lib/plocate/: Permission denied` | 数据库目录只有 root 能写 | 加 `sudo` |
| 执行了 updatedb，NAS 共享目录里的文件还是找不到 | 网络文件系统在 PRUNEFS 里被排除 | 在共享目录里用 find |

### 6. 一句话总结

locate 找不到新文件时 `sudo updatedb`，平时系统每天自动更新。

<a id="cmd-md5sum"></a>

## 155 ★★&nbsp;&nbsp;md5sum：计算 MD5 校验值

> 级别：★★ 中级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`md5sum` 为文件计算一个 32 位十六进制的“指纹”。文件内容哪怕只改了一个字节，指纹就完全不同。用途是确认文件在复制、传输、下载之后是否完整，或者判断两个文件内容是否相同。

MD5 已经可以被人为构造出碰撞，只适合检查“传输有没有出错”，不能用来防篡改。安全相关的校验用 [sha256sum](#cmd-sha256sum)。

### 2. 基本格式

```bash
md5sum 文件...                  # 计算
md5sum 文件... > 清单.md5        # 保存成校验清单
md5sum -c 清单.md5               # 按清单校验
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-c` | 读取校验清单，逐个核对 |
| `--quiet` | 和 `-c` 一起用，只显示校验失败的文件 |

### 4. 常用示例

```
$ md5sum readme.txt big.iso
b1946ac92492d2347c6235b4d2611184  readme.txt
d278b9a1a5957ce0af8086018ae106b0  big.iso
```

把一批文件的校验值存下来，拷到另一台机器后核对：

```
$ md5sum src/*.csv logs/*.log > files.md5

$ md5sum -c --quiet files.md5; echo "退出码=$?"
退出码=0
```

全部一致时 `--quiet` 不输出任何内容，退出码为 0，适合写进脚本。

### 5. 一句话总结

`md5sum` 查传输是否完整，防篡改用 sha256sum。

<a id="cmd-sha256sum"></a>

## 156 ★★&nbsp;&nbsp;sha256sum：计算 SHA-256 校验值

> 级别：★★ 中级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`sha256sum` 计算文件的 SHA-256 指纹（64 位十六进制）。用法和 [md5sum](#cmd-md5sum) 完全相同，但安全性高得多。Ubuntu 镜像、各种软件的下载页都会给出 SHA256 值，下载后用它核对，确认文件没有损坏、没有被替换。

### 2. 基本格式

```bash
sha256sum 文件...
sha256sum -c 清单文件
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-c` | 按清单校验 |
| `--ignore-missing` | 和 `-c` 一起用，清单里有、本地没有的文件跳过 |
| `--quiet` | 只显示失败的 |

### 4. 常用示例

#### 4.1 计算并保存

```
$ sha256sum readme.txt big.iso
5891b5b522d5df086d0ff0b110fbd9d21bb4fc7163af34d08286a2e846f6be03  readme.txt
382ec408afd51de29f84bd9d5b43cdfebe2f89532950e0259fdfb2271894b6de  big.iso

$ sha256sum big.iso > big.iso.sha256
```

#### 4.2 校验

```
$ sha256sum -c big.iso.sha256
big.iso: OK

$ echo x >> big.iso; sha256sum -c big.iso.sha256
big.iso: FAILED
sha256sum: WARNING: 1 computed checksum did NOT match
```

文件末尾多了一个字节，校验就失败了。

#### 4.3 核对下载的 Ubuntu 镜像

```bash
wget https://releases.ubuntu.com/26.04/SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
```

SHA256SUMS 里列了所有镜像的校验值，`--ignore-missing` 只校验你实际下载了的那一个。

> ⚠️ 4.3 未实机验证（没有下载完整镜像）。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 网页上的校验值和计算结果对不上，文件其实没问题 | 网页给的是 SHA-1 或 SHA-512，算错了算法 | 看清楚校验值的长度：MD5 32 位、SHA-256 64 位、SHA-512 128 位 |
| `-c` 报 `no properly formatted checksum lines found` | 清单格式不对（例如是 Windows 工具生成的大写或带 `*`） | 清单每行格式是“校验值 + 两个空格 + 文件名” |

### 6. 一句话总结

下载重要文件后用 `sha256sum -c 清单` 核对，结果是 OK 才能用。

## 166 ★★&nbsp;&nbsp;split：把大文件拆成小文件

> 级别：★★ 中级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`split` 按大小或行数把一个大文件拆成多个小文件。用途：邮件或上传接口有大小限制、要把百万行的 CSV 分批导入数据库、要把大日志分给几个进程并行处理。拆开的文件用 `cat` 按顺序拼回去，和原文件完全一样。

### 2. 基本格式

```bash
split [参数] 文件 [输出文件名前缀]
```

不写前缀时，默认是 `x`，生成 xaa、xab、xac……

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-b 大小` | 按大小拆，如 `-b 100M` |
| `-l 行数` | 按行数拆 |
| `-n 份数` | 平均拆成 N 份 |
| `-d` | 后缀用数字（00、01……）而不是字母 |
| `--additional-suffix=.csv` | 给每个文件加上扩展名 |

### 4. 常用示例

#### 4.1 按大小拆，再拼回去

```
$ split -b 1M big.iso part_; ls -l part_*
-rw-r--r-- 1 tom tom 1048576 Oct 29 08:41 part_aa
-rw-r--r-- 1 tom tom 1048576 Oct 29 08:41 part_ab
-rw-r--r-- 1 tom tom  402850 Oct 29 08:41 part_ac

$ cat part_* > big2.iso; cmp big.iso big2.iso && echo 完全一致
完全一致
```

`cmp` 逐字节比较两个文件，没有输出就是相同。

#### 4.2 按行数拆 CSV

```
$ split -l 2 -d --additional-suffix=.csv src/products.csv p_; ls p_*
p_00.csv
p_01.csv
p_02.csv

$ cat p_01.csv
U002,探头B,探头,15000
U003,主机X,主机,280000
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 拆开的 CSV 只有第一个文件有表头，后面的导入失败 | split 只按行切，不知道表头 | 先 `tail -n +2` 去掉表头再拆，导入时统一指定列名 |
| `split -n 3` 拆日志，第二个文件开头是半行，中文变成乱码 | `-n 3` 按字节平均切，会把一行甚至一个汉字切成两半 | 文本文件用 `-n l/3`，按整行平均分成 3 份 |

第二条的实测：

```
$ split -n 3 logs/app.log c_; head -1 c_ab
��重新加载

$ split -n l/3 logs/app.log d_; head -1 d_ab
2026-10-28 10:02:13 ERROR 订单 A1002 保存失败：超时
```

### 6. 一句话总结

`split -b 大小` 或 `-l 行数` 拆文件，`cat 前缀*` 拼回去。

<a id="cmd-dd"></a>

## 177 ★★&nbsp;&nbsp;dd：按块复制数据

> 级别：★★ 中级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`dd` 按指定的块大小，从一个地方原样复制数据到另一个地方。它不关心文件系统，直接读写字节，所以能做 cp 做不到的事：

- 把 ISO 镜像写进 U 盘做启动盘；
- 生成指定大小的测试文件；
- 粗略测试磁盘写入速度；
- 备份或擦除整块磁盘。

dd 写设备时不会做任何确认，写错盘符会直接抹掉那块盘的数据，所以它也被戏称为“disk destroyer”。

### 2. 基本格式

```bash
dd if=输入 of=输出 bs=块大小 count=块数
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `if=` | 输入文件或设备（input file） |
| `of=` | 输出文件或设备（output file） |
| `bs=` | 每次读写的块大小，如 `4M` |
| `count=` | 复制多少块 |
| `status=progress` | 显示进度 |
| `status=none` | 不显示统计信息 |
| `conv=fsync` | 写完后确保数据真正落盘 |

### 4. 常用示例

#### 4.1 生成一个 50 MB 的测试文件

```
$ dd if=/dev/zero of=test.img bs=1M count=50
50+0 records in
50+0 records out
52428800 bytes (52 MB, 50 MiB) copied, 0.012102 s, 4.4 GB/s
```

`/dev/zero` 是一个可以无限读出 0 的特殊设备。

#### 4.2 只取文件的开头部分

```
$ dd if=big.iso of=head.bin bs=1k count=4 status=none; ls -l head.bin
-rw-r--r-- 1 tom tom 4096 Oct 29 08:41 head.bin
```

#### 4.3 写 U 盘启动盘

```bash
lsblk                                                  # 先确认 U 盘是哪个设备，例如 /dev/sdb
sudo dd if=ubuntu-26.04-desktop-amd64.iso of=/dev/sdb bs=4M status=progress conv=fsync
```

`of=` 写整块盘（/dev/sdb），不是分区（/dev/sdb1）。

> ⚠️ 4.3 未实机验证（测试环境没有 U 盘）。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 写启动盘时把 `of=` 写成了系统盘，系统被毁 | dd 不做任何确认 | 执行前用 `lsblk` 反复核对容量和型号；拔掉 U 盘再看一次，消失的那个才是 U 盘 |
| 测出的写入速度高得离谱（几 GB/s） | 数据只写进了内存缓存，没写到磁盘 | 加 `conv=fsync`，或改用专门的测速工具 |
| dd 执行很久没有任何输出 | 默认只在结束时显示统计 | 加 `status=progress` |

### 6. 一句话总结

`dd if=源 of=目标 bs=4M status=progress`；写设备前用 `lsblk` 再三确认。

<a id="cmd-sync"></a>

## 178 ★★&nbsp;&nbsp;sync：把缓存数据写入磁盘

> 级别：★★ 中级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

Linux 写文件时，数据先放在内存缓存里，过一会儿才真正写到磁盘，这样速度更快。`sync` 让系统立即把缓存中所有待写的数据写到磁盘。

需要它的场合：拔 U 盘前、断电维护前、用 dd 写完镜像后、对磁盘做快照前。

### 2. 基本格式

```bash
sync [参数] [文件...]
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| （不加） | 同步所有文件系统 |
| `-f 路径` | 只同步这个路径所在的文件系统 |
| `文件` | 只同步指定的文件 |

### 4. 常用示例

```
$ sync; echo synced
synced
```

sync 执行完不输出任何内容，返回时数据已经写完。缓存的数据量大时（比如刚拷了几 GB 到 U 盘），sync 会等一段时间才返回。

正常卸载（`umount`）时系统会自动同步，所以拔 U 盘的正确做法仍然是先 umount。

### 5. 一句话总结

拔盘、断电、做快照之前先 `sync`，让缓存里的数据落盘。
