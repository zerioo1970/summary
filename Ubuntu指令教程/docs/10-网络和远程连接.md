## 031 ★★★&nbsp;&nbsp;ping：测试网络是否连通

> 级别：★★★ 初级 · 软件包：`iputils-ping`

### 1. 作用

`ping` 向目标主机发送 ICMP 回显请求（一种很小的探测包），看对方是否回应、往返花了多长时间。网络出问题时，用它判断“到底是不通，还是慢，还是域名解析不了”。

### 2. 基本格式

```bash
ping [参数] 主机名或IP
```

Linux 上的 ping 默认会一直发下去，按 `Ctrl+C` 停止。

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-c 次数` | 发送指定次数后自动停止 |
| `-i 秒` | 每次发送的间隔，默认 1 秒 |
| `-W 秒` | 等待每个回应的超时时间 |
| `-q` | 只显示最后的统计结果 |
| `-4` / `-6` | 强制使用 IPv4 / IPv6 |

### 4. 常用示例

#### 4.1 `-c`：发 4 次

```
$ ping -c 4 127.0.0.1
PING 127.0.0.1 (127.0.0.1) 56(84) bytes of data.
64 bytes from 127.0.0.1: icmp_seq=1 ttl=127 time=0.036 ms
64 bytes from 127.0.0.1: icmp_seq=2 ttl=127 time=0.044 ms
64 bytes from 127.0.0.1: icmp_seq=3 ttl=127 time=0.042 ms
64 bytes from 127.0.0.1: icmp_seq=4 ttl=127 time=0.034 ms

--- 127.0.0.1 ping statistics ---
4 packets transmitted, 4 received, 0% packet loss, time 3146ms
rtt min/avg/max/mdev = 0.034/0.039/0.044/0.004 ms
```

| 内容 | 含义 |
|---|---|
| `icmp_seq` | 第几个包。序号不连续说明中间丢了包 |
| `time=0.036 ms` | 往返时间。局域网一般小于 1 ms，国内跨城几十 ms |
| `0% packet loss` | 丢包率。偶尔丢 1% 可以接受，持续丢包说明线路有问题 |
| `rtt min/avg/max/mdev` | 往返时间的最小 / 平均 / 最大 / 波动 |

#### 4.2 不通的样子

```
$ ping -c 2 -W 1 10.255.255.1
PING 10.255.255.1 (10.255.255.1) 56(84) bytes of data.

--- 10.255.255.1 ping statistics ---
2 packets transmitted, 0 received, 100% packet loss, time 1039ms
```

没有任何回应，丢包 100%。

#### 4.3 域名解析失败

```
$ ping -c 1 nothere.invalid
ping: nothere.invalid: Name or service not known
```

连第一行的 `PING ...` 都没有出现，说明问题在 DNS（域名解析），还没开始发包。这时可以直接 ping IP，如果 IP 能通，就去查 DNS 设置。

#### 4.4 `-q`：只看统计

```
$ ping -c 3 -i 0.5 -q 127.0.0.1
PING 127.0.0.1 (127.0.0.1) 56(84) bytes of data.

--- 127.0.0.1 ping statistics ---
3 packets transmitted, 3 received, 0% packet loss, time 1033ms
rtt min/avg/max/mdev = 0.018/0.030/0.038/0.008 ms
```

### 5. 排查思路

按从近到远的顺序 ping，哪一步不通，问题就在哪一段：

| 顺序 | 命令 | 不通说明 |
|---|---|---|
| 1 | `ping -c 2 127.0.0.1` | 本机网络协议栈有问题（极少见） |
| 2 | `ping -c 2 网关IP`（用 `ip route` 查） | 网线、Wi-Fi 或本机网卡配置有问题 |
| 3 | `ping -c 2 223.5.5.5`（公共 DNS 的 IP） | 出不了外网 |
| 4 | `ping -c 2 www.baidu.com` | 外网通但域名解析有问题 |

### 6. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| ping 一个网站 100% 丢包，但浏览器能打开 | 很多服务器和云防火墙禁止 ICMP，ping 不通不代表服务不可用 | 用 `curl -I https://网站` 测试 HTTP 是否通 |
| 在脚本里 ping 一直不结束 | 没加 `-c` | 脚本里一定写 `-c 次数` 和 `-W 超时` |
| 能 ping 通数据库服务器，程序还是连不上 | ping 只说明主机在线，不代表端口开放 | 用 `nc -zv 主机 端口` 测端口 |

本教程测试环境就禁止了出外网的 ICMP，下面这个结果就是第一条的实例（archive.ubuntu.com 的网站本身可以正常访问）：

```
$ ping -c 2 archive.ubuntu.com
PING archive.ubuntu.com (91.189.91.82) 56(84) bytes of data.

--- archive.ubuntu.com ping statistics ---
2 packets transmitted, 0 received, 100% packet loss, time 1087ms
```

### 7. 一句话总结

`ping -c 4 主机` 测连通；ping 不通不等于服务不可用，测端口用 `nc`。

## 032 ★★★&nbsp;&nbsp;ip：查看 IP 地址、网卡和路由

> 级别：★★★ 初级 · 软件包：`iproute2`

### 1. 作用

`ip` 用来查看和配置网卡、IP 地址、路由表。最常用的是 `ip a` 查本机 IP。它取代了老的 `ifconfig` 和 `route`，Ubuntu 默认已经不再安装 ifconfig。

用 ip 命令改的配置重启后就会丢失。要永久修改 IP，Ubuntu 用的是 netplan 配置文件（中级篇讲）。

### 2. 基本格式

```bash
ip [参数] 对象 [子命令]
```

| 对象 | 简写 | 管什么 |
|---|---|---|
| `address` | `a` | IP 地址 |
| `link` | `l` | 网卡本身（启用、停用、MAC 地址） |
| `route` | `r` | 路由表 |
| `neigh` | `n` | 邻居表（同网段机器的 MAC 地址，即 ARP 表） |

### 3. 常用参数

| 写法 | 作用 |
|---|---|
| `ip a` | 所有网卡的 IP 地址 |
| `ip -br a` | 简洁格式，一个网卡一行 |
| `ip -4 a` | 只显示 IPv4 |
| `ip a show 网卡名` | 只看某个网卡 |
| `ip r` | 路由表，`default via` 那一行是默认网关 |
| `ip r get 目标IP` | 访问这个 IP 会走哪个网卡、哪个网关 |
| `ip -s link` | 网卡收发流量和错误统计 |

### 4. 常用示例

> 以下输出来自测试环境（省略了一个 docker0 网卡）。普通 Ubuntu 机器上的网卡名一般是 `enp0s3`、`ens33`、`eth0` 或 `wlp2s0`（无线），地址通常是 `192.168.x.x`。

#### 4.1 `ip a`：查本机 IP

```
$ ip a
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN group default qlen 1000
    link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00
    inet 127.0.0.1/8 scope host lo
       valid_lft forever preferred_lft forever
11: eth0@if12: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc noqueue state UP group default
    link/ether 02:42:a9:fe:ff:c2 brd ff:ff:ff:ff:ff:ff link-netnsid 0
    inet 169.254.255.194/26 brd 169.254.255.255 scope global eth0
       valid_lft forever preferred_lft forever
```

| 内容 | 含义 |
|---|---|
| `lo` | 回环网卡，地址固定是 127.0.0.1，只用于本机内部通信 |
| `eth0` | 真实网卡 |
| `UP,LOWER_UP` | 网卡已启用，并且网线/链路是通的 |
| `inet 169.254.255.194/26` | IPv4 地址；`/26` 是子网掩码位数（`/24` 等于 255.255.255.0） |
| `link/ether` | MAC 地址 |

#### 4.2 `ip -br a`：一眼看清

```
$ ip -br a
lo               UNKNOWN        127.0.0.1/8
eth0@if12        UP             169.254.255.194/26
```

#### 4.3 `ip r`：看默认网关

```
$ ip route
default via 169.254.255.193 dev eth0
169.254.255.192/26 dev eth0 proto kernel scope link src 169.254.255.194
```

`default via 169.254.255.193` 表示：去其他网段的数据，都交给 169.254.255.193 这台网关转发。

#### 4.4 `ip r get`：去某个地址走哪条路

```
$ ip r get 8.8.8.8
8.8.8.8 via 169.254.255.193 dev eth0 src 169.254.255.194 uid 1000
    cache
```

机器有多块网卡（比如一块连内网、一块连外网）时，用它确认流量从哪块网卡出去。

#### 4.5 `ip -s link`：看收发流量和错误

```
$ ip -s link show lo
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN mode DEFAULT group default qlen 1000
    link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00
    RX:  bytes packets errors dropped  missed   mcast
        350047    2257      0       0       0       0
    TX:  bytes packets errors dropped carrier collsns
        350047    2257      0       0       0       0
```

RX 是接收，TX 是发送。errors、dropped 持续增长，说明网线、网卡或驱动有问题。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `ifconfig: command not found` | Ubuntu 默认不再安装 net-tools | 用 `ip a`；确实需要可以 `sudo apt install net-tools` |
| 用 `sudo ip addr add` 配好了 IP，重启后没了 | ip 命令只改运行时的配置 | 永久修改写进 `/etc/netplan/*.yaml`，再执行 `sudo netplan apply` |
| 网卡状态显示 `DOWN` 或 `NO-CARRIER` | 网卡被停用，或者网线没插好 | `sudo ip link set 网卡名 up`；检查物理连接 |
| 找不到 192.168 开头的地址，只有 10.x 或 172.x | 云服务器、公司网络常用其他私有网段 | 看 `scope global` 的那个 inet 地址即可 |

### 6. 一句话总结

查 IP 用 `ip -br a`，查网关用 `ip r`，永久改 IP 要改 netplan。

## 033 ★★★&nbsp;&nbsp;wget：从网上下载文件

> 级别：★★★ 初级 · 软件包：`wget`（Ubuntu 26.04 自带 1.25 版）

### 1. 作用

`wget` 通过 HTTP、HTTPS、FTP 下载文件，保存到当前目录。服务器上没有浏览器，下载安装包、数据文件、脚本都靠它。它支持断点续传，网络断了可以接着下。

和 [curl](#cmd-curl) 的分工：wget 专注“把文件下载下来”，用法简单；curl 更适合调试接口、发 POST 请求。

### 2. 基本格式

```bash
wget [参数] 网址
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-O 文件名` | `--output-document` | 保存成指定的文件名（大写字母 O） |
| `-P 目录` | `--directory-prefix` | 保存到指定目录 |
| `-c` | `--continue` | 断点续传 |
| `-q` | `--quiet` | 不输出任何信息 |
| `-nv` | `--no-verbose` | 只输出一行结果 |
| `-b` | `--background` | 后台下载，日志写入 wget-log |
| `-i 文件` | `--input-file` | 从文件里读取一批网址逐个下载 |
| | `--limit-rate=1m` | 限速，避免占满带宽 |

### 4. 常用示例

#### 4.1 直接下载

```
$ wget https://cdimage.ubuntu.com/ubuntu-base/releases/26.04.1/release/SHA256SUMS
...
     0K .                                                     100% 76.5M=0s

2026-10-29 06:55:38 (76.5 MB/s) - ‘SHA256SUMS’ saved [1244/1244]
```

下载大文件时，这里会显示进度条、速度和剩余时间。

#### 4.2 `-O`：换个名字保存

```
$ wget -nv -O sums.txt https://cdimage.ubuntu.com/ubuntu-base/releases/26.04.1/release/SHA256SUMS
2026-10-29 06:55:37 URL:https://cdimage.ubuntu.com/ubuntu-base/releases/26.04.1/release/SHA256SUMS [1244/1244] -> "sums.txt" [1]
```

#### 4.3 `-P`：保存到指定目录

```
$ wget -nv -P downloads https://cdimage.ubuntu.com/ubuntu-base/releases/26.04.1/release/SHA256SUMS
2026-10-29 06:55:38 URL:https://cdimage.ubuntu.com/ubuntu-base/releases/26.04.1/release/SHA256SUMS [1244/1244] -> "downloads/SHA256SUMS" [1]
```

目录不存在时 wget 会自动创建。

#### 4.4 `-c`：断点续传

```bash
wget -c https://releases.ubuntu.com/26.04/ubuntu-26.04-live-server-amd64.iso
```

下载几 GB 的镜像中途断了，再执行同一条命令加 `-c`，会从断开的地方继续。文件已经完整时，`-c` 什么也不做。

#### 4.5 下载失败的样子

```
$ wget -nv https://cdimage.ubuntu.com/nothere.txt
https://cdimage.ubuntu.com/nothere.txt:
2026-10-29 06:55:38 ERROR 404: Not Found.
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 同一个文件下载两次，第二次保存成了 `SHA256SUMS.1` | 文件已存在时，wget 不覆盖，而是加编号 | 用 `-O 文件名` 指定名字会直接覆盖；续传用 `-c` |
| 网址里带 `&`，下载的东西不对，终端还多出一个后台任务 | `&` 被 Shell 当成“放到后台运行” | 网址加引号：`wget "https://a.com/x?a=1&b=2"` |
| 下载的文件打不开，内容其实是一个网页 | 下载链接需要登录，或者会跳转到下载页 | 换成直链；需要带登录凭据时改用 curl |

第一条的实测：

```
$ ls
SHA256SUMS    big.iso   logs        run.sh  sums.txt
SHA256SUMS.1  link.txt  readme.txt  src
```

### 6. 一句话总结

`wget 网址` 下载，`-O` 改名，`-P` 指定目录，大文件加 `-c` 续传。

## 034 ★★★&nbsp;&nbsp;curl：发送 HTTP 请求

> 级别：★★★ 初级 · 软件包：`curl`（Ubuntu 26.04 自带 8.18 版）

### 1. 作用

`curl` 向网址发送请求，并把服务器返回的内容输出到屏幕。它可以发 GET、POST 等各种请求，带请求头、带 JSON 数据，所以是测试 Web 接口最常用的工具。它也能下载文件。

后端写好一个 REST 接口，在服务器上用 curl 调一下，就能确认“接口本身是好的”，再去排查前端或网络。

### 2. 基本格式

```bash
curl [参数] 网址
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-o 文件名` | `--output` | 把返回内容保存到文件 |
| `-O` | `--remote-name` | 按网址里的文件名保存 |
| `-L` | `--location` | 自动跟随跳转（301、302） |
| `-I` | `--head` | 只看响应头 |
| `-s` | `--silent` | 不显示进度信息 |
| `-S` | `--show-error` | 和 `-s` 一起用，出错时仍显示错误 |
| `-f` | `--fail` | HTTP 状态码 ≥ 400 时返回非 0 退出码 |
| `-X 方法` | `--request` | 指定请求方法：POST、PUT、DELETE |
| `-H "头: 值"` | `--header` | 添加请求头 |
| `-d '数据'` | `--data` | 发送请求体（默认用 POST） |
| `-m 秒` | `--max-time` | 整个请求的超时时间 |
| `-w "格式"` | `--write-out` | 请求完成后输出指定信息，如状态码、耗时 |

### 4. 常用示例

#### 4.1 获取网页内容

```
$ curl -s https://example.com | grep -o "<title>.*</title>"
<title>Example Domain</title>
```

curl 把内容输出到屏幕，可以直接接 grep 处理。

#### 4.2 `-I`：只看响应头

```
$ curl -sI https://example.com
HTTP/2 200
date: Thu, 29 Oct 2026 06:55:39 GMT
content-type: text/html; charset=utf-8
server: cloudflare
last-modified: Sat, 24 Oct 2026 11:34:40 GMT
...
```

第一行的 `200` 是状态码。检查网站是否在线、证书是否正常、走没走 CDN，用 `-I` 就够了。

#### 4.3 `-w`：只要状态码和耗时

```
$ curl -s -o /dev/null -w "%{http_code} %{time_total}s\n" https://example.com
200 0.029388s
```

`-o /dev/null` 丢掉网页内容，只输出状态码和总耗时。写健康检查脚本常用。

#### 4.4 带参数的 GET 请求

```
$ curl -s "https://httpbin.org/get?item=U001"
{
  "args": {
    "item": "U001"
  },
  "headers": {
    "Accept": "*/*",
    "Host": "httpbin.org",
    "User-Agent": "curl/8.18.0"
  },
  "method": "GET",
  "origin": "（你的公网 IP）",
  "url": "https://httpbin.org/get?item=U001"
}
```

httpbin.org 是一个把收到的请求原样返回的测试网站，适合练习。

#### 4.5 POST 一段 JSON

```
$ curl -s -X POST -H "Content-Type: application/json" -d '{"code":"U001","price":12000}' https://httpbin.org/post
{
  "args": {},
  "headers": {
    "Accept": "*/*",
    "Content-Length": "29",
    "Content-Type": "application/json",
    "Host": "httpbin.org",
    "User-Agent": "curl/8.18.0"
  },
  "method": "POST",
  "origin": "（你的公网 IP）",
  "url": "https://httpbin.org/post",
  "data": "{\"code\":\"U001\",\"price\":12000}",
  "files": {},
  "form": {},
  "json": {
    "code": "U001",
    "price": 12000
  }
}
```

测试自己的接口时，把网址换成 `http://localhost:8080/api/products` 这类地址即可。JSON 要用单引号括起来，因为里面有双引号。

#### 4.6 下载文件

```
$ curl -sSLO https://cdimage.ubuntu.com/ubuntu-base/releases/26.04.1/release/SHA256SUMS

$ ls -l SHA256SUMS
-rw-r--r-- 1 tom tom 1244 Oct 29 06:55 SHA256SUMS
```

`-L` 跟随跳转，`-O` 按原文件名保存。

#### 4.7 常见错误

```
$ curl -sS https://nothere.invalid
curl: (6) Could not resolve host: nothere.invalid

$ curl -sS -m 3 http://10.255.255.1
curl: (28) Connection timed out after 3002 milliseconds

$ curl -fsS https://cdimage.ubuntu.com/nothere.txt; echo "退出码=$?"
curl: (22) The requested URL returned error: 404
退出码=22
```

| 错误码 | 含义 |
|---|---|
| 6 | 域名解析失败 |
| 7 | 连接被拒绝：主机在线，但端口上没有服务 |
| 28 | 超时 |
| 22 | 加了 `-f` 时，服务器返回了 4xx/5xx |

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 返回 404 页面，脚本却当成成功了 | 不加 `-f` 时，只要拿到响应，curl 的退出码就是 0 | 脚本里用 `curl -fsS` |
| 输出里夹着一大段 `% Total % Received` 进度表 | 输出接到管道或文件时，curl 会显示进度 | 加 `-s`；想保留错误信息再加 `-S` |
| 下载下来的文件只有几百字节，内容是 `301 Moved` | 网址发生了跳转，curl 默认不跟随 | 加 `-L` |
| 访问内网 https 地址报 `SSL certificate problem` | 证书是自签的，系统不信任 | 把公司的根证书装进系统；只在测试时临时用 `-k` 跳过校验 |
| `-d` 发的 JSON 后端收不到 | 没加 `Content-Type: application/json`，后端按表单解析 | 加 `-H "Content-Type: application/json"`，或用 `--json '数据'`（curl 7.82 起支持） |

### 6. 一句话总结

测接口用 `curl -s`，看状态用 `-I` 或 `-w`，脚本里加 `-fsS`，下载加 `-LO`。

## 055 ★★★&nbsp;&nbsp;hostname：查看主机名和本机 IP

> 级别：★★★ 初级 · 软件包：`hostname`

### 1. 作用

`hostname` 显示本机的主机名，加 `-I` 可以快速列出本机所有 IP 地址。主机名会显示在终端提示符里（`tom@ubuntu:~$` 中的 ubuntu），多台服务器同时操作时，靠它区分自己在哪台机器上。

永久修改主机名用 `hostnamectl`（中级篇讲）。

### 2. 基本格式

```bash
hostname [参数]
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-I` | 列出本机所有 IP 地址（不含 127.0.0.1） |
| `-f` | 完整域名（FQDN），如 `db01.example.com` |
| `-s` | 短主机名（第一个点之前的部分） |

### 4. 常用示例

> 以下输出来自测试环境。

```
$ hostname
ubuntu

$ hostname -I
172.17.0.1 169.254.255.194
```

`hostname -I` 比 `ip a` 简洁，只想知道“这台机器的 IP 是多少”时最快。多个地址用空格分隔，顺序没有固定含义。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `hostname -f` 报 `hostname: Name or service not known` | 主机名没有在 `/etc/hosts` 或 DNS 里登记 | 在 `/etc/hosts` 加一行 `127.0.1.1 主机名.域名 主机名` |
| `sudo hostname 新名字` 改了，重启后又变回去 | 这样只改了运行时的主机名 | 用 `sudo hostnamectl set-hostname 新名字` |
| 改了主机名之后，sudo 每次都很慢，提示 `unable to resolve host` | `/etc/hosts` 里还是旧主机名 | 同步修改 `/etc/hosts` |

第一条的实测：

```
$ hostname -f
hostname: Name or service not known
```

### 6. 一句话总结

`hostname` 看主机名，`hostname -I` 看本机 IP，永久修改用 `hostnamectl`。

## 083 ★★★&nbsp;&nbsp;ssh：远程登录服务器

> 级别：★★★ 初级 · 软件包：`openssh-client`（Ubuntu 26.04 为 OpenSSH 10.2）

### 1. 作用

`ssh`（Secure Shell）通过加密连接登录到远程 Linux 服务器，在本机终端里操作远程机器，就像坐在它面前一样。也可以不登录，直接在远程机器上执行一条命令并把结果拿回来。

管理服务器的日常工作几乎都从 ssh 开始。

### 2. 基本格式

```bash
ssh [参数] 用户名@主机 [要执行的命令]
```

不写命令时进入远程的交互式终端，输入 `exit` 退出。

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-p 端口` | 指定端口，默认 22 |
| `-i 私钥文件` | 指定用哪个私钥登录 |
| `-o 选项=值` | 临时设置一个配置项，如 `-o ConnectTimeout=5` |
| `-L 本地端口:目标:目标端口` | 本地端口转发（把远程的数据库端口映射到本机） |
| `-J 跳板机` | 通过跳板机连接 |
| `-v` | 显示详细的连接过程，排查连不上的问题 |

### 4. 常用示例

测试环境在本机 2222 端口运行了一个 sshd 来演示，真实场景里把 `127.0.0.1 -p 2222` 换成服务器的 IP 即可。

#### 4.1 第一次连接

第一次连接某台服务器时，ssh 会显示对方的主机密钥指纹，问你是否信任：

```
The authenticity of host '[127.0.0.1]:2222 ([127.0.0.1]:2222)' can't be established.
ED25519 key fingerprint is SHA256:...
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

输入 `yes` 后，指纹被记进 `~/.ssh/known_hosts`，以后不再询问。

> ⚠️ 上面这段提示未实机录制（需要真实终端交互），为 OpenSSH 的标准提示。

不想交互确认时，可以让 ssh 自动接受新主机：

```
$ ssh -p 2222 -o StrictHostKeyChecking=accept-new tom@127.0.0.1 "hostname; whoami; uptime -p"
Warning: Permanently added '[127.0.0.1]:2222' (ED25519) to the list of known hosts.
ubuntu
tom
up 1 hour, 34 minutes
```

#### 4.2 远程执行一条命令

```
$ ssh -p 2222 tom@127.0.0.1 "df -h /home | tail -1"
tmpfs            16G  2.5M   16G   1% /home
```

命令用引号括起来，管道 `|` 就会在远程执行。巡检多台服务器的磁盘时，写个循环逐台执行即可。

#### 4.3 免密码登录：密钥

```bash
ssh-keygen -t ed25519          # 在本机生成密钥对，一路回车
ssh-copy-id tom@192.168.1.10   # 把公钥装到服务器上，这一次需要输入密码
ssh tom@192.168.1.10           # 以后不再需要密码
```

生成的文件：

```
$ ls -l ~/.ssh
total 12
-rw------- 1 tom tom  92 Oct 29 07:09 authorized_keys
-rw------- 1 tom tom 399 Oct 29 07:09 id_ed25519
-rw-r--r-- 1 tom tom  92 Oct 29 07:09 id_ed25519.pub
```

| 文件 | 内容 | 能不能给别人 |
|---|---|---|
| `id_ed25519` | 私钥 | **绝对不能**，权限必须是 600 |
| `id_ed25519.pub` | 公钥 | 可以，装到要登录的服务器上 |
| `authorized_keys` | 服务器上：允许哪些公钥登录 | |
| `known_hosts` | 本机：信任过哪些服务器 | |

#### 4.4 `~/.ssh/config`：给服务器起简称

```
Host db01
    HostName 127.0.0.1
    Port 2222
    User tom
```

写进 `~/.ssh/config` 后：

```
$ ssh db01 hostname
ubuntu
```

服务器多、端口不统一时，config 文件能省很多事。scp 也认这个简称。

#### 4.5 把远程数据库端口映射到本机

```bash
ssh -L 15432:127.0.0.1:5432 tom@db01
```

保持这个连接，本机的数据库客户端连 `127.0.0.1:15432`，就相当于连到了 db01 上只监听本地的 5432 端口。数据库不用对外开放端口。

### 5. 常见报错

```
$ ssh -p 2222 -o ConnectTimeout=3 tom@10.255.255.1
ssh: connect to host 10.255.255.1 port 2222: Connection timed out

$ ssh -p 2223 tom@127.0.0.1
ssh: connect to host 127.0.0.1 port 2223: Connection refused

$ ssh -p 2222 -o BatchMode=yes nobody@127.0.0.1
nobody@127.0.0.1: Permission denied (publickey).
```

| 报错 | 含义 | 排查方向 |
|---|---|---|
| `Connection timed out` | 网络不通，或被防火墙丢弃 | IP 是否正确；云服务器安全组是否放行该端口 |
| `Connection refused` | 主机在线，但这个端口上没有 ssh 服务 | 端口号是否正确；服务器上 ssh 是否在运行 |
| `Permission denied (publickey)` | 认证失败，服务器只接受密钥 | 用户名、私钥是否正确；用 `ssh -v` 看尝试了哪些密钥 |

### 6. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 出现一大块 `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!`，拒绝连接 | 服务器的主机密钥变了：重装了系统、换了机器，**也可能是被中间人攻击** | 确认服务器确实重装过之后，执行提示里给出的 `ssh-keygen -R 主机` 删除旧记录，再重新连接 |
| 私钥被拒绝，提示 `UNPROTECTED PRIVATE KEY FILE!` | 私钥文件权限太宽 | `chmod 600 ~/.ssh/id_ed25519` |
| ssh 连上后一段时间不操作就断开 | 中间的防火墙或路由器断开了空闲连接 | 在 `~/.ssh/config` 里加 `ServerAliveInterval 60` |
| 修改服务器的 ssh 端口后，新端口连不上 | Ubuntu 26.04 的 ssh 默认由 ssh.socket 监听端口，只改 sshd_config 不够 | 见 [systemctl](09-系统服务和开关机.md#cmd-systemctl) 4.4 |

第一条的实测（指纹已替换为占位）：

```
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@    WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!     @
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
IT IS POSSIBLE THAT SOMEONE IS DOING SOMETHING NASTY!
...
Offending ED25519 key in /home/tom/.ssh/known_hosts:1
  remove with:
  ssh-keygen -f '/home/tom/.ssh/known_hosts' -R '[127.0.0.1]:2222'
Host key for [127.0.0.1]:2222 has changed and you have requested strict checking.
Host key verification failed.

$ ssh-keygen -R "[127.0.0.1]:2222"
# Host [127.0.0.1]:2222 found: line 1
/home/tom/.ssh/known_hosts updated.
Original contents retained as /home/tom/.ssh/known_hosts.old
```

### 7. 一句话总结

`ssh 用户@主机` 登录，用密钥免密，常用服务器写进 `~/.ssh/config`。

## 084 ★★★&nbsp;&nbsp;scp：在本机和服务器之间复制文件

> 级别：★★★ 初级 · 软件包：`openssh-client`

### 1. 作用

`scp`（secure copy）通过 ssh 连接复制文件：从本机传到服务器，或者从服务器下载到本机。它走 ssh 的认证方式（密码或密钥），ssh 能登录的服务器，scp 就能传文件。

### 2. 基本格式

```bash
scp [参数] 本机文件 用户@主机:远程路径     # 上传
scp [参数] 用户@主机:远程文件 本机路径     # 下载
```

远程路径都写在冒号 `:` 后面。冒号后面不写路径，表示远程用户的家目录。

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-r` | 复制目录 |
| `-P 端口` | 指定端口（注意是**大写** P，ssh 用的是小写 p） |
| `-i 私钥` | 指定私钥 |
| `-p` | 保留修改时间和权限（小写 p） |
| `-C` | 传输时压缩，适合网络慢、文件是文本的情况 |

### 4. 常用示例

演示用的 sshd 在本机 2222 端口。

#### 4.1 上传文件

```
$ scp -P 2222 readme.txt tom@127.0.0.1:/tmp/

$ ssh -p 2222 tom@127.0.0.1 ls -l /tmp/readme.txt
-rw-r--r-- 1 tom tom 6 Oct 29 07:09 /tmp/readme.txt
```

在真实终端里，scp 会显示文件名、进度百分比、速度。

#### 4.2 `-r`：上传目录

```
$ scp -P 2222 -r logs tom@127.0.0.1:/tmp/

$ ssh -p 2222 tom@127.0.0.1 ls -R /tmp/logs
/tmp/logs:
app.log
```

#### 4.3 从服务器下载

```
$ scp -P 2222 tom@127.0.0.1:/etc/hostname dl/

$ ls dl
hostname
```

#### 4.4 配合 `~/.ssh/config` 的简称

```
$ scp readme.txt db01:/tmp/r2.txt && echo copied
copied
```

config 里写好了地址、端口、用户名（见 [ssh](#cmd-ssh) 4.4），scp 命令就短多了。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `scp -p 2222 ...` 连接的还是 22 端口 | scp 的端口参数是大写 `-P`，小写 `-p` 是“保留时间” | 改成 `-P 2222` |
| `scp: dest open "/root/readme.txt": Permission denied` | 远程用户对目标目录没有写权限 | 先传到 `/tmp` 或家目录，再 ssh 上去 `sudo mv` |
| 忘了写冒号，文件被复制成了本机上一个叫 `tom@127.0.0.1` 的文件 | 没有冒号时 scp 把它当成本地文件名 | 远程地址一定带 `:` |
| 传几 GB 的文件中途断了，只能从头再来 | scp 不支持断点续传 | 大文件改用 `rsync -avP`（中级篇讲） |

第二条的实测：

```
$ scp -P 2222 readme.txt tom@127.0.0.1:/root/
scp: dest open "/root/readme.txt": Permission denied
scp: failed to upload file readme.txt to /root/
```

### 6. 一句话总结

上传 `scp 文件 用户@主机:路径`，目录加 `-r`，端口用大写 `-P`，大文件换 rsync。

## 106 ★★&nbsp;&nbsp;ufw：简易防火墙

> 级别：★★ 中级 · 软件包：`ufw`（0.36.2）

### 1. 作用

`ufw`（Uncomplicated Firewall）是 Ubuntu 自带的防火墙管理工具。它在底层的 iptables/nftables 之上包了一层，用接近口语的命令管理规则：允许 22 端口、只允许某个网段访问 1433 端口、拒绝 3306 端口。

Ubuntu 默认安装了 ufw，但**没有启用**。

### 2. 基本格式

```bash
sudo ufw 子命令 [规则]
```

### 3. 常用子命令

| 子命令 | 作用 |
|---|---|
| `status` / `status verbose` / `status numbered` | 查看状态和规则（带编号） |
| `enable` / `disable` | 启用 / 停用（启用后开机自动生效） |
| `default deny incoming` | 默认拒绝所有进入的连接 |
| `default allow outgoing` | 默认允许所有出去的连接 |
| `allow 端口[/协议]` | 允许，如 `allow 80/tcp` |
| `allow from 网段 to any port 端口` | 只允许某个来源访问 |
| `deny 端口` | 拒绝 |
| `limit 端口或应用` | 限速：30 秒内同一 IP 超过 6 次连接就拒绝，防暴力破解 |
| `delete 编号` 或 `delete 规则` | 删除规则 |
| `app list` | 列出已知的应用配置（如 OpenSSH） |
| `reset` | 清空所有规则，恢复初始状态 |

### 4. 常用示例

以下以 root 身份执行。

#### 4.1 新服务器的标准配置

```
$ ufw default deny incoming
Default incoming policy changed to 'deny'
(be sure to update your rules accordingly)

$ ufw default allow outgoing
Default outgoing policy changed to 'allow'
(be sure to update your rules accordingly)

$ ufw allow OpenSSH
Rules updated
Rules updated (v6)

$ ufw allow 80/tcp
Rules updated
Rules updated (v6)

$ ufw allow from 192.168.1.0/24 to any port 1433 proto tcp
Rules updated

$ ufw deny 3306
Rules updated
Rules updated (v6)

$ ufw enable
Firewall is active and enabled on system startup
```

**一定要在 enable 之前放行 ssh**，否则启用的那一刻，远程连接就断了。在真实的 ssh 会话里执行 enable 时，ufw 会先提示 `Command may disrupt existing ssh connections. Proceed with operation (y|n)?`。

> ⚠️ 上面这句提示未实机录制（测试环境不是 ssh 会话）。

#### 4.2 查看规则

```
$ ufw status
Status: active

To                         Action      From
--                         ------      ----
OpenSSH                    ALLOW       Anywhere
80/tcp                     ALLOW       Anywhere
1433/tcp                   ALLOW       192.168.1.0/24
3306                       DENY        Anywhere
OpenSSH (v6)               ALLOW       Anywhere (v6)
80/tcp (v6)                ALLOW       Anywhere (v6)
3306 (v6)                  DENY        Anywhere (v6)

$ ufw status verbose | head -4
Status: active
Logging: on (low)
Default: deny (incoming), allow (outgoing), deny (routed)
New profiles: skip
```

#### 4.3 删除规则

```
$ ufw status numbered
Status: active

     To                         Action      From
     --                         ------      ----
[ 1] OpenSSH                    ALLOW IN    Anywhere
[ 2] 80/tcp                     ALLOW IN    Anywhere
[ 3] 1433/tcp                   ALLOW IN    192.168.1.0/24
[ 4] 3306                       DENY IN     Anywhere
...

$ ufw delete allow 80/tcp
Rule deleted
Rule deleted (v6)
```

按编号删除（`ufw delete 4`）时会要求确认 `Proceed with operation (y|n)?`。删除一条后编号会变，连续删除时每次都先 `status numbered` 看一下。

#### 4.4 限制 ssh 暴力破解

```
$ ufw limit OpenSSH
Rule updated
Rule updated (v6)

$ ufw status | grep -i limit
OpenSSH                    LIMIT       Anywhere
OpenSSH (v6)               LIMIT       Anywhere (v6)
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `ufw enable` 后 ssh 断开，再也连不上 | 启用前没有放行 22 端口 | 通过云控制台的 VNC 或机房 KVM 登录，执行 `ufw allow OpenSSH` |
| 用 Docker 映射的端口，ufw 规则拦不住，外网照样能访问 | Docker 直接修改 iptables，绕过了 ufw 的规则 | 映射时绑定到本机：`-p 127.0.0.1:8080:80`；或用云安全组控制 |
| 云服务器上 ufw 已放行，还是访问不了 | 云平台还有一层安全组 | 同时在云控制台的安全组里放行 |
| 改了 ssh 端口，ufw 里放行的还是 OpenSSH（22） | OpenSSH 应用配置里写的是 22 | 放行新端口：`ufw allow 2222/tcp` |

### 6. 一句话总结

先 `allow OpenSSH`，再 `default deny incoming`，最后 `enable`；查看用 `status numbered`。

## 115 ★★&nbsp;&nbsp;rsync：增量同步文件

> 级别：★★ 中级 · 软件包：`rsync`（3.4.1）

### 1. 作用

`rsync` 在本机两个目录之间、或者本机和远程服务器之间同步文件。和 cp、scp 最大的区别是**增量**：只传输有变化的文件（甚至只传文件中变化的部分），第二次同步几乎瞬间完成。它还能断点续传、保留权限和时间、删除目标端多余的文件。

做备份、部署代码、迁移数据，都首选 rsync。

### 2. 基本格式

```bash
rsync [参数] 源 目标
rsync [参数] 源 用户@主机:目标路径       # 推到远程（走 ssh）
rsync [参数] 用户@主机:源路径 目标       # 从远程拉
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-a` | 归档模式：递归，并保留权限、时间、所有者、符号链接（几乎总是要加） |
| `-v` | 显示传输了哪些文件 |
| `-z` | 传输时压缩（跨网络时有用） |
| `-P` | 显示进度，并支持断点续传 |
| `-n` | 模拟执行（dry run），只显示会做什么 |
| `--delete` | 删除目标端有、源端没有的文件，让两边完全一致 |
| `--exclude="模式"` | 排除 |
| `-e "ssh -p 端口"` | 指定 ssh 端口 |

### 4. 常用示例

#### 4.1 第一次同步和第二次同步

```
$ rsync -av logs src /tmp/backup/
sending incremental file list
created directory /tmp/backup
logs/
logs/app.log
src/
src/products.csv

sent 791 bytes  received 96 bytes  1,774.00 bytes/sec
total size is 556  speedup is 0.63

$ rsync -av logs src /tmp/backup/
sending incremental file list

sent 139 bytes  received 14 bytes  306.00 bytes/sec
total size is 556  speedup is 3.63
```

第二次没有任何文件变化，一个文件都没传。改了一个文件后再同步：

```
$ echo "2026-10-28 12:00:00 INFO  新的一行" >> logs/app.log

$ rsync -av logs src /tmp/backup/
sending incremental file list
logs/app.log

sent 626 bytes  received 37 bytes  1,326.00 bytes/sec
total size is 595  speedup is 0.90
```

只传了改过的 app.log。

#### 4.2 源路径末尾的斜杠

```
$ rsync -av logs/ /tmp/b2/; ls /tmp/b2
...
app.log

$ rsync -av logs /tmp/b3/; ls -R /tmp/b3
...
/tmp/b3:
logs

/tmp/b3/logs:
app.log
```

| 写法 | 结果 |
|---|---|
| `logs/`（带斜杠） | 同步 logs **里面的内容** |
| `logs`（不带斜杠） | 同步 logs **这个目录本身** |

这是 rsync 最容易出错的地方。

#### 4.3 `--delete` 之前先 `-n`

```
$ rsync -avn --delete src/ /tmp/backup/logs/
sending incremental file list
deleting app.log
products.csv

sent 83 bytes  received 37 bytes  240.00 bytes/sec
total size is 152  speedup is 1.27 (DRY RUN)
```

`-n` 显示会删除 app.log，但并没有真的执行（末尾标注 DRY RUN）。确认无误后去掉 `-n`。

#### 4.4 同步到远程服务器

```bash
rsync -avzP --exclude=".git" ./dist/ deploy@192.168.1.20:/var/www/app/
rsync -avz -e "ssh -p 2222" /data/backup/ backup@nas:/volume1/backup/
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 目标里多了一层同名目录 | 源路径没写末尾的 `/` | 同步内容就写 `源/` |
| 用了 `--delete`，目标目录里的重要文件被删了 | 源和目标写反了，或者源路径写错 | 带 `--delete` 时一律先加 `-n` 预览 |
| 远程同步报 `rsync: command not found` | 远程服务器上也必须装 rsync | 在远程执行 `sudo apt install rsync` |
| 同步后文件所有者变成了自己 | 普通用户不能设置文件所有者 | 需要保留所有者时，两端都用 root（`sudo rsync`、远程用 `--rsync-path="sudo rsync"`） |

### 6. 一句话总结

`rsync -avP 源/ 目标/` 增量同步，注意末尾斜杠，`--delete` 前先 `-n`。

<a id="cmd-ss"></a>

## 116 ★★&nbsp;&nbsp;ss：查看端口和网络连接

> 级别：★★ 中级 · 软件包：`iproute2`

### 1. 作用

`ss`（socket statistics）列出本机的网络连接和监听的端口。最常用的问题：“服务启动了吗？在监听哪个端口？是只监听本机还是所有网卡？是哪个进程？”它是老命令 [netstat](#cmd-netstat) 的替代品，速度更快，Ubuntu 默认就有。

### 2. 基本格式

```bash
ss [参数] [过滤条件]
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-t` | TCP |
| `-u` | UDP |
| `-l` | 只看监听中的（listening） |
| `-n` | 端口和地址用数字显示，不解析成名字 |
| `-p` | 显示是哪个进程（看其他用户的进程要 sudo） |
| `-a` | 所有状态 |
| `-s` | 统计汇总 |

最常用的组合是 `sudo ss -tulnp`，记成“tulnp”。

### 4. 常用示例

以下在独立的网络环境里执行，先用 python 在 18080 端口启动了一个网页服务。

#### 4.1 查看监听的端口

```
$ ss -tlnp
State     Recv-Q    Send-Q       Local Address:Port        Peer Address:Port    Process
LISTEN    0         5                  0.0.0.0:18080            0.0.0.0:*        users:(("python3",pid=35,fd=4))
```

| 列 | 含义 |
|---|---|
| Local Address:Port | `0.0.0.0:18080` 监听所有网卡；`127.0.0.1:18080` 只允许本机访问 |
| Process | 进程名和 PID |

服务启动了但别的机器访问不了，先看这里是 0.0.0.0 还是 127.0.0.1。

#### 4.2 查某个端口

```
$ ss -tlnp 'sport = :18080'
State     Recv-Q    Send-Q       Local Address:Port        Peer Address:Port    Process
LISTEN    0         5                  0.0.0.0:18080            0.0.0.0:*        users:(("python3",pid=35,fd=4))
```

也可以简单地 `ss -tlnp | grep 18080`。

#### 4.3 按状态看连接

```
$ ss -tan state time-wait
Recv-Q     Send-Q          Local Address:Port            Peer Address:Port
0          0                   127.0.0.1:18080              127.0.0.1:49470
```

TIME-WAIT 是连接关闭后的等待状态，短时间内大量出现说明有很多短连接。

#### 4.4 统计汇总

```
$ ss -s
Total: 7
TCP:   53 (estab 0, closed 52, orphaned 0, timewait 1)
...
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| Process 列是空的 | 端口属于其他用户（如 root）的进程 | 加 `sudo` |
| 服务监听在 127.0.0.1，别的机器连不上 | 程序配置成只监听本机 | 改程序配置为 `0.0.0.0` 或具体网卡 IP，并在防火墙放行 |

### 6. 一句话总结

`sudo ss -tulnp` 查监听端口和进程，看清是 0.0.0.0 还是 127.0.0.1。

<a id="cmd-dig"></a>

## 118 ★★&nbsp;&nbsp;dig：查询 DNS

> 级别：★★ 中级 · 软件包：`bind9-dnsutils`

### 1. 作用

`dig` 向 DNS 服务器查询域名的解析记录，并显示完整的查询过程和结果。域名改了解析没生效、邮件发不出去（MX 记录）、网站时好时坏（可能有多个 IP），都用 dig 排查。

### 2. 基本格式

```bash
dig [@DNS服务器] 域名 [记录类型] [+选项]
```

| 记录类型 | 含义 |
|---|---|
| `A` | IPv4 地址（默认） |
| `AAAA` | IPv6 地址 |
| `CNAME` | 别名 |
| `MX` | 邮件服务器 |
| `NS` | 负责这个域名的 DNS 服务器 |
| `TXT` | 文本记录（SPF、域名验证等） |

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `+short` | 只显示结果 |
| `@服务器` | 指定向哪个 DNS 服务器查询 |
| `-x IP` | 反向查询：IP 对应的域名 |
| `+trace` | 从根服务器开始逐级查询，看解析过程 |

### 4. 常用示例

#### 4.1 完整输出

```
$ dig ubuntu.com

; <<>> DiG 9.20.24-1ubuntu0.4-Ubuntu <<>> ubuntu.com
;; global options: +cmd
;; Got answer:
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 41233
;; flags: qr rd ra; QUERY: 1, ANSWER: 3, AUTHORITY: 0, ADDITIONAL: 1
...
;; ANSWER SECTION:
ubuntu.com.		24	IN	A	185.125.190.21
ubuntu.com.		24	IN	A	185.125.190.29
ubuntu.com.		24	IN	A	185.125.190.20

;; Query time: 9 msec
;; SERVER: 127.0.0.11#53(127.0.0.11) (UDP)
...
```

| 内容 | 含义 |
|---|---|
| `status: NOERROR` | 查询成功；`NXDOMAIN` 表示域名不存在 |
| ANSWER SECTION | 结果。`24` 是 TTL（秒），过了这么久才会重新查询 |
| SERVER | 这次用的是哪个 DNS 服务器 |

#### 4.2 `+short`：只要结果

```
$ dig +short ubuntu.com
185.125.190.20
185.125.190.29
185.125.190.21

$ dig +short MX gmail.com
10 alt1.gmail-smtp-in.l.google.com.
5 gmail-smtp-in.l.google.com.
20 alt2.gmail-smtp-in.l.google.com.
30 alt3.gmail-smtp-in.l.google.com.
40 alt4.gmail-smtp-in.l.google.com.
```

MX 记录前面的数字是优先级，数字小的优先。

#### 4.3 指定 DNS 服务器

```
$ dig @8.8.8.8 +short ubuntu.com
185.125.190.21
185.125.190.29
185.125.190.20
```

刚改了域名解析，用 `@` 分别向本地 DNS 和公共 DNS 查询，比较结果，就知道是不是本地缓存还没过期。

#### 4.4 反向查询

```
$ dig -x 8.8.8.8 +short
dns.google.
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `dig +short 域名` 没有输出，以为是网络问题 | 域名不存在时 `+short` 不显示任何内容，退出码仍是 0 | 去掉 `+short`，看 status 是不是 `NXDOMAIN` |
| dig 能解析，程序还是连到旧 IP | 程序或系统有自己的 DNS 缓存；也可能 `/etc/hosts` 里写死了 | 检查 /etc/hosts；用 `getent hosts 域名` 看程序实际得到的结果 |

### 6. 一句话总结

`dig +short 域名` 看解析，`@服务器` 对比不同 DNS，看不到结果时去掉 +short 看 status。

## 120 ★★&nbsp;&nbsp;traceroute：追踪到目标经过的路由

> 级别：★★ 中级 · 软件包：`traceroute`（需 `sudo apt install traceroute`）

### 1. 作用

`traceroute` 显示数据包从本机到目标主机，一路经过了哪些路由器（每一跳），以及每一跳的延迟。ping 只能告诉你“通不通、慢不慢”，traceroute 能告诉你“慢在哪一段”。

### 2. 基本格式

```bash
traceroute [参数] 目标
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-n` | 不把 IP 解析成主机名（快很多） |
| `-m 跳数` | 最多追踪几跳，默认 30 |
| `-w 秒` | 每一跳等待回应的时间 |
| `-T -p 端口` | 用 TCP 探测（需要 root），能穿过只放行 TCP 的防火墙 |
| `-I` | 用 ICMP 探测（需要 root） |

### 4. 常用示例

```
$ traceroute -n -m 5 -w 1 archive.ubuntu.com
traceroute to archive.ubuntu.com (185.125.190.82), 5 hops max, 60 byte packets
 1  169.254.255.193  0.031 ms  0.005 ms  0.004 ms
 2  240.64.221.128  1.137 ms  1.194 ms 240.64.221.131  1.139 ms
 3  240.3.184.33  1.206 ms  1.706 ms  2.299 ms
 4  149.112.69.20  2.605 ms  2.638 ms  2.678 ms
 5  184.104.198.33  75.546 ms *  75.504 ms
```

每一行是一跳，后面三个时间是三次探测的往返时间。第 4 跳到第 5 跳延迟从 2.6 ms 跳到 75 ms，说明这一段（通常是跨国或跨运营商的线路）最慢。

用 TCP 443 端口探测：

```
$ sudo traceroute -n -T -p 443 -m 8 -w 1 archive.ubuntu.com
traceroute to archive.ubuntu.com (91.189.91.82), 8 hops max, 60 byte packets
 1  169.254.255.193  0.027 ms  0.006 ms  0.005 ms
 2  * * *
 3  240.7.172.3  0.361 ms 240.7.172.0  0.353 ms  0.344 ms
...
```

`* * *` 表示这一跳的路由器没有回应，通常是它被配置为不回应探测，不一定是故障。只要后面的跳能继续出现，就没有问题。

> 以上输出来自测试环境（云服务器），IP 是云平台内部和运营商的路由器。

### 5. 一句话总结

`traceroute -n 目标` 看慢在哪一跳；中间出现 `* * *` 但后面能继续，就不是问题。

## 121 ★★&nbsp;&nbsp;tracepath：追踪路由（不需要 root）

> 级别：★★ 中级 · 软件包：`iputils-tracepath`

### 1. 作用

`tracepath` 和 traceroute 作用相同，区别是：不需要 root 权限、参数更少，并且会显示路径上的 MTU（最大传输单元）。Ubuntu 默认可能没有 traceroute，但通常有 tracepath。

### 2. 基本格式

```bash
tracepath [-n] [-m 跳数] 目标
```

### 3. 常用示例

```
$ tracepath -n -m 5 archive.ubuntu.com
 1?: [LOCALHOST]                      pmtu 1500
 1:  169.254.255.193                                       0.081ms asymm  2
 1:  169.254.255.193                                       0.025ms asymm  2
 2:  no reply
 3:  240.7.172.2                                           0.899ms
 4:  242.25.170.149                                        1.918ms asymm  7
 5:  99.83.112.142                                         1.541ms asymm  8
     Too many hops: pmtu 1500
     Resume: pmtu 1500
```

`pmtu 1500` 是路径上允许的最大包大小。VPN、隧道环境里这个值会变小，如果比预期小很多，可能导致“小请求正常、大文件传不过去”的问题。`asymm` 表示去程和回程的跳数不一样，很常见。

### 4. 一句话总结

没有 root 或没装 traceroute 时，用 `tracepath -n 目标`。

## 123 ★★&nbsp;&nbsp;netplan：Ubuntu 的网络配置

> 级别：★★ 中级 · 软件包：`netplan.io`

### 1. 作用

Ubuntu 用 netplan 管理网络配置：你在 `/etc/netplan/*.yaml` 里用 YAML 描述想要的网络（IP、网关、DNS），`netplan apply` 把它翻译成 systemd-networkd 或 NetworkManager 的配置并立即生效。服务器要设置**永久的**静态 IP，就是改 netplan 的配置文件。

### 2. 基本格式

```bash
sudo netplan 子命令
```

### 3. 常用子命令

| 子命令 | 作用 |
|---|---|
| `try` | 应用新配置，120 秒内不按回车确认就自动回滚（远程修改时必用） |
| `apply` | 应用配置 |
| `generate` | 只生成后端配置，不应用（用来检查语法） |
| `get [键]` | 查看合并后的配置 |
| `status` | 查看网卡当前状态 |

### 4. 常用示例

#### 4.1 静态 IP 的配置文件

`/etc/netplan/01-static.yaml`：

```yaml
network:
  version: 2
  ethernets:
    enp0s3:
      dhcp4: false
      addresses: [192.168.1.20/24]
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses: [223.5.5.5, 114.114.114.114]
```

| 配置 | 含义 |
|---|---|
| `enp0s3` | 网卡名，用 `ip a` 查 |
| `dhcp4: false` | 不用 DHCP 自动获取 |
| `addresses` | IP/掩码位数 |
| `routes: to: default via` | 默认网关 |
| `nameservers` | DNS |

#### 4.2 查看合并后的配置

```
$ sudo netplan get
network:
  version: 2
  ethernets:
    enp0s3:
      addresses:
      - "192.168.1.20/24"
      nameservers:
        addresses:
        - 223.5.5.5
        - 114.114.114.114
      dhcp4: false
      routes:
      - to: "default"
        via: "192.168.1.1"

$ sudo netplan get ethernets.enp0s3.addresses
- "192.168.1.20/24"
```

/etc/netplan/ 下可以有多个文件，按文件名顺序合并，`get` 显示的是最终结果。

#### 4.3 远程修改：用 try

```bash
sudo netplan try
```

如果新配置导致网络断开，你按不了回车，120 秒后自动恢复成原来的配置，不至于把自己锁在外面。确认网络正常后按回车，配置才会保留。

> ⚠️ 4.3 和 `netplan apply` 的实际效果未实机验证（测试环境没有 systemd，不能真正应用网络配置）。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 执行时提示 `Permissions for /etc/netplan/01-static.yaml are too open. Netplan configuration should NOT be accessible by others.` | 配置文件里可能有 Wi-Fi 密码，netplan 要求权限 600 | `sudo chmod 600 /etc/netplan/*.yaml` |
| apply 后网络断了，ssh 再也连不上 | 配置写错（网卡名、网关） | 远程修改一律用 `netplan try`；保留控制台兜底 |
| YAML 报错 | 缩进必须用空格，不能用 Tab，层级要对齐 | 用 2 个空格缩进；`sudo netplan generate` 检查 |
| 网上教程用 `gateway4: 192.168.1.1` | 这个写法已经废弃 | 改用 `routes: - to: default via: 网关` |
| 改了 /etc/network/interfaces 没有效果 | 那是旧版 Ubuntu 的方式 | 改 /etc/netplan/ 下的文件 |

第一条的实测：

```
$ sudo chmod 644 /etc/netplan/01-static.yaml; sudo netplan get

** (process:54): WARNING **: 08:39:25.040: Permissions for /etc/netplan/01-static.yaml are too open. Netplan configuration should NOT be accessible by others.
```

### 6. 一句话总结

永久改 IP 就改 /etc/netplan/*.yaml，权限 600，远程用 `sudo netplan try`。

<a id="cmd-resolvectl"></a>

## 124 ★★&nbsp;&nbsp;resolvectl：查看和设置 DNS 解析

> 级别：★★ 中级 · 软件包：`systemd-resolved`

### 1. 作用

Ubuntu 的 DNS 解析由 systemd-resolved 服务负责。`/etc/resolv.conf` 里写的是 `nameserver 127.0.0.53`，这是 resolved 在本机提供的一个转发地址，真正用的上游 DNS 服务器要用 `resolvectl` 查看。

### 2. 基本格式

```bash
resolvectl [子命令] [参数]
```

### 3. 常用子命令

| 子命令 | 作用 |
|---|---|
| `status` | 每个网卡用的 DNS 服务器 |
| `query 域名` | 通过 resolved 解析域名 |
| `flush-caches` | 清空 DNS 缓存 |
| `statistics` | 缓存命中等统计 |
| `dns 网卡 服务器...` | 临时设置某个网卡的 DNS（重启后失效） |

### 4. 常用示例

```bash
resolvectl status
resolvectl query ubuntu.com
sudo resolvectl flush-caches
```

`status` 的输出里，每个网卡下的 `DNS Servers:` 就是实际使用的 DNS。永久修改 DNS 要改 netplan 配置里的 `nameservers`。

> ⚠️ 本页未实机验证：测试环境没有运行 systemd-resolved，resolvectl 报 `sd_bus_open_system: No such file or directory`。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 直接改 /etc/resolv.conf，过一会儿又被改回去 | 它是 resolved 自动生成的链接 | 在 netplan 里改 nameservers |
| 刚改了域名解析，本机一直解析到旧地址 | resolved 有缓存 | `sudo resolvectl flush-caches` |

### 6. 一句话总结

看实际用的 DNS 用 `resolvectl status`，清缓存用 `flush-caches`，永久修改改 netplan。

<a id="cmd-ssh-keygen"></a>

## 150 ★★&nbsp;&nbsp;ssh-keygen：生成和管理 SSH 密钥

> 级别：★★ 中级 · 软件包：`openssh-client`（OpenSSH 10.2）

### 1. 作用

`ssh-keygen` 生成 SSH 密钥对：私钥留在本机，公钥放到要登录的服务器上，之后登录就不需要密码。用密钥登录比密码更安全，也方便脚本自动化。它还能查看密钥指纹、修改私钥的保护密码、清理 known_hosts 里的旧记录。

### 2. 基本格式

```bash
ssh-keygen [-t 类型] [-C 备注] [-f 文件名]
```

一路回车就用默认值：类型 ed25519，保存在 `~/.ssh/id_ed25519`。

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-t ed25519` | 密钥类型，推荐 ed25519（短、快、安全） |
| `-t rsa -b 4096` | RSA 类型，只在对方系统太旧不支持 ed25519 时用 |
| `-C "备注"` | 写在公钥末尾，方便识别是谁的密钥 |
| `-f 文件` | 保存的文件名 |
| `-N "密码"` | 私钥的保护密码，`-N ""` 表示不设 |
| `-l -f 文件` | 查看密钥的指纹 |
| `-p -f 文件` | 修改私钥的保护密码 |
| `-R 主机` | 从 known_hosts 里删除某台主机的记录 |

### 4. 常用示例

#### 4.1 生成密钥

```
$ ssh-keygen -t ed25519 -C "tom@ubuntu 2026-10"
Generating public/private ed25519 key pair.
Enter file in which to save the key (/home/tom/.ssh/id_ed25519):
Enter passphrase for "/home/tom/.ssh/id_ed25519" (empty for no passphrase):
Enter same passphrase again:
Your identification has been saved in /home/tom/.ssh/id_ed25519
Your public key has been saved in /home/tom/.ssh/id_ed25519.pub
The key fingerprint is:
...
```

> ⚠️ 中间三行提问未实机录制（测试时用 `-N "" -f` 跳过了提问），其余输出为实测。

生成的文件：

```
$ ls -l ~/.ssh
total 8
-rw------- 1 tom tom 411 Oct 29 08:40 id_ed25519
-rw-r--r-- 1 tom tom 100 Oct 29 08:40 id_ed25519.pub
```

私钥权限是 600，公钥是 644。公钥是一行文本：

```
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIEo+n77Pw7KjudCnVyJshxNI...  tom@ubuntu 2026-10
```

#### 4.2 查看指纹

```
$ ssh-keygen -l -f ~/.ssh/id_ed25519.pub
256 SHA256:（指纹） tom@ubuntu 2026-10 (ED25519)
```

服务器管理员要核对“这把公钥是不是你的”时，比对指纹即可。

#### 4.3 给私钥加保护密码

```
$ ssh-keygen -p -N "newpass" -P "" -f ~/.ssh/id_rsa_old
Key has comment 'tom@ubuntu'
Your identification has been saved with the new passphrase.
```

私钥有密码，即使文件被拷走也不能直接用。配合 [ssh-agent](#cmd-ssh-agent)，每次开机只需输入一次。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 生成新密钥时提示 `/home/tom/.ssh/id_ed25519 already exists.`，选了覆盖，原来能登录的服务器都登不上了 | 旧私钥被覆盖，服务器上装的是旧公钥 | 不要覆盖；新密钥用 `-f` 起别的名字 |
| 把 `id_ed25519`（私钥）发给了管理员 | 搞混了公钥和私钥 | 只发 `.pub` 结尾的文件；私钥泄露后要立即重新生成并更换 |
| 旧服务器不接受 ed25519 密钥 | 系统太旧 | 用 `-t rsa -b 4096` 另生成一把 |

### 6. 一句话总结

`ssh-keygen -t ed25519 -C 备注` 生成密钥，只把 `.pub` 给别人。

<a id="cmd-ssh-copy-id"></a>

## 151 ★★&nbsp;&nbsp;ssh-copy-id：把公钥装到服务器上

> 级别：★★ 中级 · 软件包：`openssh-client`

### 1. 作用

`ssh-copy-id` 把你的公钥追加到远程服务器上该用户的 `~/.ssh/authorized_keys` 里，并自动设置正确的目录和文件权限。执行时需要输入一次远程用户的密码，之后就可以用密钥免密登录了。

### 2. 基本格式

```bash
ssh-copy-id [-i 公钥文件] [-p 端口] 用户@主机
```

不写 `-i` 时，使用 `~/.ssh/` 下的默认公钥。

### 3. 常用示例

演示用的 sshd 在本机 2222 端口，远程用户是 ops：

```
$ ssh-copy-id -p 2222 ops@127.0.0.1
/usr/bin/ssh-copy-id: INFO: Source of key(s) to be installed: "/home/tom/.ssh/id_ed25519.pub"
/usr/bin/ssh-copy-id: INFO: attempting to log in with the new key(s), to filter out any that are already installed
/usr/bin/ssh-copy-id: INFO: 1 key(s) remain to be installed -- if you are prompted now it is to install the new keys

Number of key(s) added: 1

Now try logging into the machine, with: "ssh -p 2222 'ops@127.0.0.1'"
and check to make sure that only the key(s) you wanted were added.
```

> 测试时用 sshpass 自动输入了密码；真实使用时，在第三行之后会提示输入 ops 的密码。

确认结果：

```
$ ssh -p 2222 ops@127.0.0.1 "whoami; ls -ld ~/.ssh ~/.ssh/authorized_keys"
ops
drwx------ 2 ops ops 4096 Oct 29 08:41 /home/ops/.ssh
-rw------- 1 ops ops   92 Oct 29 08:41 /home/ops/.ssh/authorized_keys
```

已经免密登录了，目录权限 700、文件权限 600 也都设置好了。

重复执行时，它会发现公钥已经装过：

```
$ ssh-copy-id -p 2222 ops@127.0.0.1
...
/usr/bin/ssh-copy-id: WARNING: All keys were skipped because they already exist on the remote system.
		(if you think this is a mistake, you may want to use -f option)
```

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 报 `Permission denied (publickey)`，连密码都没让输 | 服务器关闭了密码登录 | 请管理员把你的 .pub 文件手动加到 authorized_keys 里 |
| 手动把公钥追加到 authorized_keys 后，还是要密码 | 目录或文件权限太宽，sshd 拒绝使用 | `chmod 700 ~/.ssh; chmod 600 ~/.ssh/authorized_keys` |

### 5. 一句话总结

`ssh-copy-id 用户@主机` 输一次密码，以后免密登录。

<a id="cmd-sftp"></a>

## 152 ★★&nbsp;&nbsp;sftp：交互式的安全文件传输

> 级别：★★ 中级 · 软件包：`openssh-client`

### 1. 作用

`sftp` 通过 ssh 连接到服务器，进入一个类似 FTP 的交互界面，可以浏览远程目录、上传、下载、建目录、删文件。和 [scp](#cmd-scp) 相比，它适合“先看看远程有什么，再决定传哪些”的场景。很多图形化工具（WinSCP、FileZilla）底层用的也是 SFTP 协议。

### 2. 基本格式

```bash
sftp [-P 端口] 用户@主机
sftp 用户@主机:远程文件 本地目录      # 直接下载一个文件
sftp -b 命令文件 用户@主机            # 批处理
```

和 scp 一样，端口是大写 `-P`。

### 3. 常用的交互命令

| 命令 | 作用 |
|---|---|
| `pwd` / `lpwd` | 远程 / 本地的当前目录 |
| `ls` / `lls` | 列出远程 / 本地的文件 |
| `cd` / `lcd` | 切换远程 / 本地目录 |
| `put 文件` / `put -r 目录` | 上传 |
| `get 文件` / `get -r 目录` | 下载 |
| `mkdir` / `rm` / `rmdir` | 在远程建目录 / 删文件 / 删空目录 |
| `bye` 或 `exit` | 退出 |

带 `l` 前缀的（local）作用于本机。

### 4. 常用示例

用批处理模式执行一组命令（`-b -` 表示从标准输入读取命令）：

```
$ printf "pwd\nls\nput readme.txt\nmkdir upload\ncd upload\nput -r logs\nls\nget /etc/hostname\nbye\n" | sftp -P 2222 -b - ops@127.0.0.1
sftp> pwd
Remote working directory: /home/ops
sftp> ls
sftp> put readme.txt
sftp> mkdir upload
sftp> cd upload
sftp> put -r logs
Entering logs/
sftp> ls
logs
sftp> get /etc/hostname
sftp> bye
```

交互式使用时，输入 `sftp -P 2222 ops@127.0.0.1` 后会出现 `sftp>` 提示符，再逐条输入上面这些命令。

直接下载一个文件：

```
$ sftp -P 2222 ops@127.0.0.1:/etc/os-release /tmp/
Connected to 127.0.0.1.
Fetching /etc/os-release to /tmp/os-release
```

### 5. 一句话总结

要浏览远程目录再传文件用 `sftp`，`put`/`get` 传输，`l` 开头的命令操作本机。

## 198 ★★&nbsp;&nbsp;iftop：按连接查看实时带宽

> 级别：★★ 中级 · 软件包：`iftop`（需 `sudo apt install iftop`）

### 1. 作用

`iftop` 实时显示网卡上每一个连接（本机 IP:端口 ↔ 对方 IP:端口）占用的带宽，按流量排序。服务器带宽突然被占满，用它能马上看出是和谁之间的流量。

它需要抓包，必须用 sudo。

### 2. 基本格式

```bash
sudo iftop [参数]
```

### 3. 常用参数和按键

| 参数 | 作用 |
|---|---|
| `-i 网卡` | 指定网卡 |
| `-n` | 不把 IP 解析成主机名 |
| `-P` | 显示端口 |
| `-t -s 秒` | 文本模式，统计 N 秒后输出一次就退出 |

| 按键 | 作用 |
|---|---|
| `n` | 切换是否解析主机名 |
| `p` | 切换是否显示端口 |
| `t` | 切换显示方式（发送、接收分开或合并） |
| `q` | 退出 |

### 4. 常用示例

```bash
sudo iftop -n -P -i eth0
```

文本模式适合截图发给别人：

```
$ sudo iftop -t -s 1
interface: eth0
IP address is: 169.254.255.194
MAC address is: 02:42:a9:fe:ff:c2
Listening on eth0
   # Host name (port/service if enabled)            last 2s   last 10s   last 40s cumulative
...
```

每行一个连接，`=>` 是发出的流量，`<=` 是收到的流量，后面三列是最近 2 秒、10 秒、40 秒的平均速率。

> ⚠️ 只验证了开头几行（测试环境流量太少），全屏界面未实机验证。

### 5. 一句话总结

带宽被占满了，用 `sudo iftop -n -P` 找出是哪个连接。

<a id="cmd-ssh-agent"></a>

## 199 ★★&nbsp;&nbsp;ssh-agent：保管解锁后的私钥

> 级别：★★ 中级 · 软件包：`openssh-client`

### 1. 作用

私钥设了保护密码后，每次 ssh 都要输入一次密码。`ssh-agent` 是一个在后台运行的程序：你用 `ssh-add` 把私钥交给它，输入一次密码解锁，之后这个会话里的所有 ssh、scp、git 操作都由它代为签名，不用再输密码。

Ubuntu 桌面版登录后已经自动运行了 agent；在服务器的 ssh 会话里需要自己启动。

### 2. 基本格式

```bash
eval "$(ssh-agent -s)"     # 启动 agent，并设置环境变量
ssh-add [私钥文件]         # 添加私钥
ssh-add -l                 # 列出已添加的私钥
ssh-add -D                 # 移除所有私钥
ssh-agent -k               # 结束 agent
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `ssh-add -t 秒` | 私钥在 agent 里只保留这么久 |
| `ssh -A` | 把本机的 agent 转发到远程服务器（谨慎使用） |

### 4. 常用示例

```
$ eval "$(ssh-agent -s)"
Agent pid 303

$ ssh-add -l
The agent has no identities.

$ ssh-add ~/.ssh/id_ed25519
Identity added: /home/tom/.ssh/id_ed25519 (tom@ubuntu)

$ ssh-add -l
256 SHA256:（指纹） tom@ubuntu (ED25519)

$ ssh-add -D
All identities removed.
```

`eval "$(...)"` 这一步不能省：ssh-agent 启动后会输出两条设置环境变量的命令（`SSH_AUTH_SOCK`、`SSH_AGENT_PID`），eval 让它们在当前 Shell 里生效，ssh 才找得到 agent。在 OpenSSH 10 上，agent 的通信文件放在 `~/.ssh/agent/` 目录下。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `ssh-add` 报 `Could not open a connection to your authentication agent.` | agent 没启动，或者没有用 eval 设置环境变量 | 执行 `eval "$(ssh-agent -s)"` |
| 用 `ssh -A` 登录了一台不可信的服务器 | 那台服务器的 root 可以借用你的 agent 去登录你能登录的其他服务器 | 只对可信的跳板机用 `-A`；更好的办法是 `ssh -J 跳板机 目标` |


### 6. 一句话总结

私钥有密码时，`eval "$(ssh-agent -s)"` 后 `ssh-add`，只输一次密码。
