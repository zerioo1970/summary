## 004 ★★★&nbsp;&nbsp;sudo：以管理员身份执行命令

> 级别：★★★ 初级 · 软件包：`sudo-rs`（Ubuntu 26.04 默认的 sudo 实现）

### 1. 作用

`sudo`（superuser do）让普通用户临时以 root（管理员）身份执行一条命令。装软件、改 `/etc` 下的配置、重启服务，都需要在命令前加 sudo。

Ubuntu 默认不给 root 设密码，也不建议直接登录 root。日常用普通账号，需要管理员权限时才加 sudo，这样每一次提权都有记录，误操作的范围也限定在这一条命令里。

从 Ubuntu 25.10 起，`sudo` 由 Rust 重写的 sudo-rs 提供。在 Ubuntu 26.04 上可以这样确认：

```
$ ls -l /usr/bin/sudo /etc/alternatives/sudo
lrwxrwxrwx 1 root root 23 Oct 29 06:36 /etc/alternatives/sudo -> /usr/lib/cargo/bin/sudo
lrwxrwxrwx 1 root root 22 Oct  6 13:13 /usr/bin/sudo -> /etc/alternatives/sudo
```

### 2. 基本格式

```bash
sudo [参数] 命令 [命令的参数]
```

谁能用 sudo，由 `/etc/sudoers` 决定。Ubuntu 默认的规则是 `sudo` 组的成员可以执行任何命令：

```
%sudo	ALL=(ALL:ALL) ALL
```

安装系统时创建的第一个用户自动在 sudo 组里。用 `groups` 可以确认：

```
$ groups
tom sudo
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-i` | `--login` | 切换成 root 的登录 Shell，连续执行多条管理命令 |
| `-u 用户` | `--user` | 以指定用户（不一定是 root）的身份执行 |
| `-l` | `--list` | 列出自己被允许执行哪些命令 |
| `-k` | `--reset-timestamp` | 让密码缓存立即失效，下次 sudo 重新问密码 |
| `-e` | `--edit` | 以 root 权限编辑文件，等同 `sudoedit` |
| `-s` | `--shell` | 以 root 身份启动当前的 Shell（不读取 root 的登录配置） |

### 4. 常用示例

> ⚠️ 本节未实机验证：测试环境的容器禁止提权（见第 5 节最后一条），sudo 无法真正执行。命令写法已对照 sudo-rs 手册核实。

#### 4.1 执行一条管理命令

```bash
sudo apt update
```

第一次执行时要输入**你自己的密码**（不是 root 的密码）。Ubuntu 26.04 的 sudo-rs 默认开启了 `pwfeedback`，输入时每个字符显示一个 `*`。旧版 sudo 输入时屏幕上没有任何显示。

验证通过后，**同一个终端** 15 分钟内再用 sudo 不会再问密码。sudo-rs 按终端分别计时，在另一个终端窗口里还是要输入一次。

#### 4.2 `sudo -i`：连续执行多条管理命令

```bash
sudo -i          # 提示符从 $ 变成 #，表示现在是 root
apt update
apt upgrade
exit             # 退回普通用户
```

需要连着做十几步管理操作时，比每条都加 sudo 方便。做完一定要 `exit`，不要一直停在 root 下干日常的事。

#### 4.3 `sudo -u`：以其他用户身份执行

```bash
sudo -u www-data ls /var/www/html
```

排查“网站进程读不到某个文件”时，用网站运行账号（www-data）的身份试一下，就能确认是不是权限问题。

#### 4.4 忘了加 sudo，补上

```bash
apt install tree        # 报权限错误
sudo !!                 # !! 代表上一条命令，相当于 sudo apt install tree
```

`!!` 是 bash 的历史展开功能，不是 sudo 的参数。

#### 4.5 写入受保护的文件

```bash
echo "192.168.1.10 db01" | sudo tee -a /etc/hosts
```

不能写成 `sudo echo "..." >> /etc/hosts`，原因见下面的踩坑表。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `sudo echo "x" >> /etc/hosts` 报 `Permission denied` | 重定向 `>>` 是当前 Shell（普通用户）做的，sudo 只提升了 echo 的权限 | 用 `echo "x" \| sudo tee -a /etc/hosts` |
| 网上教程里的 `sudo -E` 用不了 | sudo-rs 手册里没有 `-E`（保留全部环境变量），只有 `--preserve-env=变量列表` | 改用 `sudo --preserve-env=HTTP_PROXY 命令`，或在命令前写 `sudo 变量=值 命令` |
| 在 `sudo` 下运行的程序找不到自己装的命令 | sudoers 里的 `secure_path` 会重设 PATH，只包含 `/usr/sbin`、`/usr/bin`、`/snap/bin` 等系统目录 | 写命令的完整路径，例如 `sudo /opt/app/bin/tool` |
| 直接用 `vi /etc/sudoers` 改错一个字符，之后所有 sudo 都失败 | sudoers 语法错误会让 sudo 拒绝工作 | 一律用 `sudo visudo` 编辑，它会在保存前检查语法 |
| 容器里报 `The "no new privileges" flag is set, which prevents sudo from running as root.` | 容器启动时设置了禁止提权的标志 | 在容器里直接以 root 运行命令，或调整容器配置 |

### 6. 一句话总结

管理操作前加 `sudo`，连续操作用 `sudo -i`，写系统文件用 `sudo tee`。

## 023 ★★★&nbsp;&nbsp;chmod：修改文件权限

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`chmod`（change mode）修改文件或目录的权限：谁可以读、谁可以写、谁可以执行。脚本不能运行、网站读不到文件、ssh 密钥被拒绝使用，很多时候都是权限问题。

### 2. 权限的两种写法

`ls -l` 里的 `rwxr-xr-x` 分三组：所有者（u）、所属组（g）、其他人（o）。每组三位，`r` 读、`w` 写、`x` 执行。

**数字写法**：r=4、w=2、x=1，每组相加得到一位数字。

| 数字 | 权限 | 含义 |
|---|---|---|
| 7 | rwx | 4+2+1，读写执行 |
| 6 | rw- | 4+2，读写 |
| 5 | r-x | 4+1，读和执行 |
| 4 | r-- | 只读 |
| 0 | --- | 无权限 |

所以 `755` = `rwxr-xr-x`，`644` = `rw-r--r--`，`600` = `rw-------`。

**符号写法**：`谁 操作 权限`。

| 部分 | 可选值 |
|---|---|
| 谁 | `u` 所有者，`g` 所属组，`o` 其他人，`a` 所有人 |
| 操作 | `+` 增加，`-` 去掉，`=` 设为 |
| 权限 | `r` `w` `x` |

例如 `u+x`（给所有者加执行权限）、`go-w`（去掉组和其他人的写权限）。

### 3. 基本格式和常用参数

```bash
chmod [参数] 权限 文件...
```

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-R` | `--recursive` | 递归修改目录及其中所有内容 |
| `-v` | `--verbose` | 显示每个文件改动前后的权限 |
| `-c` | `--changes` | 只显示真正有改动的文件 |

### 4. 常用示例

#### 4.1 `+x`：让脚本可以执行

```
$ chmod +x readme.txt; ls -l readme.txt
-rwxr-xr-x 1 tom tom 6 Oct  1 09:00 readme.txt

$ chmod -x readme.txt; ls -l readme.txt
-rw-r--r-- 1 tom tom 6 Oct  1 09:00 readme.txt
```

写好的 `deploy.sh` 要先 `chmod +x deploy.sh` 才能用 `./deploy.sh` 运行。

#### 4.2 数字写法：常见的几个组合

```
$ chmod 755 run.sh; ls -l run.sh
-rwxr-xr-x 1 tom tom 20 Oct 29 06:37 run.sh

$ chmod 600 .env; ls -l .env
-rw------- 1 tom tom 12 Oct 29 06:37 .env
```

| 权限 | 用在哪里 |
|---|---|
| `755` | 脚本、程序、目录 |
| `644` | 普通文件、网页文件、大部分配置文件 |
| `600` | 只有自己能读写：密码文件、`.env`、ssh 私钥 |
| `700` | 只有自己能进入的目录：`~/.ssh` |

#### 4.3 符号写法：精确设置

```
$ chmod u=rw,g=r,o= readme.txt; ls -l readme.txt
-rw-r----- 1 tom tom 6 Oct  1 09:00 readme.txt
```

#### 4.4 `-v`：看清楚改了什么

```
$ chmod -v 644 readme.txt
mode of 'readme.txt' changed from 0640 (rw-r-----) to 0644 (rw-r--r--)
```

#### 4.5 `-R`：递归修改

```
$ chmod -R 750 src; ls -ld src src/products.csv
drwxr-x--- 2 tom tom 4096 Oct 29 06:37 src
-rwxr-x--- 1 tom tom  152 Oct 29 06:37 src/products.csv
```

注意 products.csv 也被加上了执行权限，这通常不是你想要的，见下方踩坑表。

### 5. 目录的 x 权限

对目录来说，三个权限的含义和文件不同：

| 权限 | 对目录的含义 |
|---|---|
| `r` | 可以列出目录里有哪些文件（ls） |
| `w` | 可以在目录里新建、删除、改名文件 |
| `x` | 可以进入目录（cd），访问里面的文件 |

目录没有 `x`，即使里面的文件是 644，别人也读不到。

### 6. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `./readme.txt` 报 `Permission denied` | 文件没有执行权限 | `chmod +x 文件` |
| `chmod -R 755` 之后所有文件都变成了可执行 | -R 对文件和目录一视同仁 | 分开设置：`find 目录 -type d -exec chmod 755 {} +` 和 `find 目录 -type f -exec chmod 644 {} +` |
| 网站报 403，文件明明是 644 | 上级某个目录缺少 `x` 权限，网站进程进不去 | 用 `namei -l 文件完整路径` 查看路径上每一级目录的权限 |
| 为了省事 `chmod 777`，问题“解决”了 | 777 让任何用户都能修改，是安全隐患 | 找出真正需要访问的用户，用 chown 改所有者或所属组 |
| ssh 报 `UNPROTECTED PRIVATE KEY FILE!` 并拒绝使用私钥 | 私钥权限太宽 | `chmod 600 ~/.ssh/id_ed25519` |
| `chmod 999 文件` 报 `chmod: invalid digit found in string` | 每一位只能是 0–7 | 按第 2 节的表重新计算 |

### 7. 一句话总结

脚本加 `+x`，普通文件 644，目录 755，私密文件 600，不要用 777。

## 024 ★★★&nbsp;&nbsp;chown：修改文件的所有者和所属组

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`chown`（change owner）修改文件或目录属于哪个用户、哪个组。典型场景：用 sudo 把程序拷到 `/opt/app` 后，文件都属于 root，程序以普通账号运行时写不了日志，这时要用 chown 把目录交给运行账号。

修改所有者需要 root 权限，所以基本都要加 sudo。

### 2. 基本格式

```bash
sudo chown [参数] 用户[:组] 文件...
```

| 写法 | 含义 |
|---|---|
| `chown tom 文件` | 只改所有者 |
| `chown tom:www-data 文件` | 同时改所有者和所属组 |
| `chown :tom 文件` | 只改所属组（等同 `chgrp tom 文件`） |

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-R` | `--recursive` | 递归修改目录及其中所有内容 |
| `-v` | `--verbose` | 显示处理了哪些文件 |
| `-c` | `--changes` | 只显示真正有改动的文件 |
| | `--reference=文件` | 照搬另一个文件的所有者和组 |

### 4. 常用示例

以下以 root 身份执行（相当于普通用户加 sudo）。

#### 4.1 改所有者

```
$ ls -l readme.txt
-rw-r--r-- 1 tom tom 6 Oct  1 09:00 readme.txt

$ sudo chown root readme.txt

$ ls -l readme.txt
-rw-r--r-- 1 root tom 6 Oct  1 09:00 readme.txt
```

#### 4.2 同时改所有者和组

```
$ sudo chown tom:www-data readme.txt

$ ls -l readme.txt
-rw-r--r-- 1 tom www-data 6 Oct  1 09:00 readme.txt
```

网站文件常设成“自己是所有者，www-data 是所属组”，你能编辑，网站进程（www-data）能读。

#### 4.3 `-R`：把整个目录交给某个账号

```
$ sudo chown -R www-data:www-data src

$ ls -l src
total 4
-rw-r--r-- 1 www-data www-data 152 Oct 29 06:50 products.csv
```

部署时常用：`sudo chown -R appuser:appuser /opt/app`。

#### 4.4 `-v`：确认结果

```
$ sudo chown -v tom:tom readme.txt
ownership of 'readme.txt' retained as tom:tom
```

`retained` 表示本来就是这样，没有改动。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `chown: changing ownership of 'readme.txt': Operation not permitted (os error 1)` | 普通用户不能把文件交给别人 | 加 `sudo` |
| `chown: invalid user: 'nobodyx'` | 用户不存在或拼错 | 用 `id 用户名` 确认 |
| 在 Ubuntu 26.04 上 `chown tom: 文件` 没有改所属组 | 传统写法 `用户:`（冒号后留空）表示“组改成该用户的登录组”。26.04 默认的 Rust 版 chown 只改了所有者，组保持不变 | 把组写全：`chown tom:tom 文件`。需要传统行为时可以用 GNU 版 `gnuchown` |
| 对 `/` 或 `/usr` 执行了 `chown -R`，系统多处出错 | 系统文件的所有者被改乱了 | 执行 -R 前再三确认路径；这类事故通常只能重装或从备份恢复 |

第三条的实测（两个文件原来都是 `www-data:www-data`）：

```
$ sudo chown tom: readme.txt; ls -l readme.txt
-rw-r--r-- 1 tom www-data 6 Oct  1 09:00 readme.txt

$ sudo gnuchown tom: run.sh; ls -l run.sh
-rwxr-xr-x 1 tom tom 20 Oct 29 06:50 run.sh
```

### 6. 一句话总结

`sudo chown -R 用户:组 目录` 把目录交给运行账号；在 26.04 上组名要写全。

## 040 ★★★&nbsp;&nbsp;whoami：显示当前用户名

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`whoami` 打印当前是以哪个用户身份在操作。用 `su`、`sudo -i` 切换过身份，或者在脚本里要确认“我现在是不是 root”时用它。

### 2. 基本格式

```bash
whoami
```

没有常用参数。

### 3. 常用示例

#### 3.1 查看当前用户

```
$ whoami
tom
```

`id -un` 输出的结果相同：

```
$ id -un
tom
```

#### 3.2 脚本里要求必须用 root 运行

```bash
#!/bin/bash
if [ "$(whoami)" != "root" ]; then
    echo "请用 sudo 运行本脚本"
    exit 1
fi
```

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `sudo whoami` 输出 root，`whoami` 输出 tom | sudo 让这一条命令以 root 身份执行 | 这是正常的。想知道“是谁用 sudo 提的权”，在 sudo 下的程序里查环境变量 `$SUDO_USER` |
| 用 `whoami` 判断权限，结果被普通用户改了 PATH 绕过 | PATH 里放了一个假的 whoami | 判断是否 root 更可靠的写法是 `[ "$(id -u)" -eq 0 ]`（root 的 UID 固定为 0） |

### 5. 一句话总结

`whoami` 看当前身份，脚本里判断 root 用 `id -u` 等于 0。

## 053 ★★★&nbsp;&nbsp;passwd：修改密码

> 级别：★★★ 初级 · 软件包：`passwd`

### 1. 作用

`passwd` 修改用户的登录密码。普通用户只能改自己的密码，并且要先输入旧密码；root（或加 sudo）可以直接重设任何用户的密码，不需要知道旧密码。

### 2. 基本格式

```bash
passwd                # 改自己的密码
sudo passwd 用户名    # 管理员重设别人的密码
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-S` | 查看密码状态 |
| `-l` | 锁定账号的密码（无法再用密码登录） |
| `-u` | 解锁 |
| `-e` | 让密码立即过期，用户下次登录时必须改密码 |
| `-d` | 删除密码（不推荐） |

### 4. 常用示例

#### 4.1 改自己的密码

```
$ passwd
Changing password for tom.
Current password:
New password:
Retype new password:
passwd: password updated successfully
```

输入密码时屏幕上没有任何显示，输完按回车即可。

> ⚠️ 4.1 只验证了前两行：测试环境无法进行交互输入。后面几行为 Ubuntu 的标准提示。

#### 4.2 `-S`：查看密码状态

以下以 root 身份执行（普通用户加 sudo）：

```
$ sudo passwd -S tom
tom P 2026-10-29 0 99999 7 -1

$ sudo passwd -S root
root L 2026-08-26 0 99999 7 -1
```

| 字段 | 含义 |
|---|---|
| 第 2 列 | `P` 已设密码，`L` 已锁定，`NP` 没有密码 |
| 第 3 列 | 最后一次修改密码的日期 |
| 后面 4 个数字 | 最短使用天数、最长有效天数（99999 表示永不过期）、提前几天提醒、过期后宽限天数 |

Ubuntu 默认 root 是 `L`（锁定），这就是为什么 Ubuntu 上用 sudo 而不用 root 登录。

#### 4.3 新员工入职：重设密码并要求首次登录修改

```bash
sudo passwd zhang          # 设置一个临时密码
sudo passwd -e zhang       # 让它立即过期
```

#### 4.4 员工离职：先锁定账号

```bash
sudo passwd -l zhang
```

锁定只是禁止密码登录。如果对方配置过 ssh 密钥，还要删除 `~/.ssh/authorized_keys` 或用 `sudo usermod -s /usr/sbin/nologin zhang` 禁止登录。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 输密码时屏幕没反应，以为卡住了 | passwd 输入密码时不显示任何字符 | 照常输入，输完回车 |
| 新密码被拒绝：`BAD PASSWORD: The password is shorter than 8 characters` 之类 | 系统的密码强度规则 | 用更长、更复杂的密码 |
| `passwd -l` 锁定后对方还能 ssh 登录 | 对方用的是 ssh 密钥，不走密码 | 同时处理 ssh 密钥，见 4.4 |

> ⚠️ 第二条的提示文字未实机验证，具体内容随密码强度模块而不同。

### 6. 一句话总结

`passwd` 改自己的，`sudo passwd 用户` 重设别人的，`-S` 查状态，`-l` 锁定。

<a id="cmd-su"></a>

## 054 ★★★&nbsp;&nbsp;su：切换到其他用户

> 级别：★★★ 初级 · 软件包：`util-linux`

### 1. 作用

`su`（switch user）切换成另一个用户，打开一个以那个用户身份运行的 Shell。要以某个服务账号（比如 postgres）的身份操作时用它。

su 要求输入**目标用户**的密码，而 sudo 要求输入**你自己**的密码。Ubuntu 默认锁定了 root 的密码，所以普通用户 `su -` 切换 root 会失败，应该用 `sudo -i`。

### 2. 基本格式

```bash
su [参数] [用户名]
```

不写用户名时，默认切换到 root。

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-` 或 `-l` | `--login` | 以登录方式切换：进入目标用户的家目录，加载它的环境变量 |
| `-c "命令"` | `--command` | 只以目标用户身份执行一条命令，然后返回 |
| `-s Shell` | `--shell` | 指定使用的 Shell |

### 4. 常用示例

以下以 root 身份执行。root 切换到任何用户都不需要密码；普通用户可以在前面加 sudo，如 `sudo su - postgres`。

#### 4.1 `-` 和不加 `-` 的区别

```
$ su - tom -c "whoami; pwd"
tom
/home/tom

$ su tom -c "pwd"
/root
```

加了 `-`，切换后进入 tom 的家目录，环境变量也是 tom 的；不加 `-`，还停在原来的目录（/root），很多环境变量也保留原来的。日常一律加 `-`。

#### 4.2 以服务账号身份执行一条命令

```bash
sudo su - postgres -c "psql -c 'select version();'"
```

也可以写成 `sudo -u postgres psql`，效果类似，更简洁。

#### 4.3 退回原来的用户

```bash
exit
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 普通用户执行 `su -`，输入密码后报 `su: Authentication failure` | Ubuntu 默认锁定了 root 密码（`passwd -S root` 显示 `L`） | 用 `sudo -i` |
| 切换后命令找不到、PATH 不对 | 没加 `-`，环境变量还是原用户的 | 用 `su - 用户名` |
| `su: user nothere does not exist or the user entry does not contain all the required fields` | 用户名写错 | 用 `getent passwd 用户名` 确认 |
| 切到服务账号报 `This account is currently not available.` | 服务账号的 Shell 被设成了 nologin，禁止登录 | 用 `sudo -u 账号 命令` 执行单条命令，或 `su -s /bin/bash - 账号` |

第一条的实测：

```
$ su -c whoami root
Password: su: Authentication failure
```

### 6. 一句话总结

Ubuntu 上切 root 用 `sudo -i`；切其他用户用 `sudo su - 用户` 或 `sudo -u 用户 命令`。

## 070 ★★★&nbsp;&nbsp;id：查看用户的 UID 和所属组

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`id` 显示一个用户的用户号（UID）、主组号（GID）和所属的全部组。排查权限问题时经常要回答“这个用户在不在 docker 组 / www-data 组里”，用 id 一查就知道。

### 2. 基本格式

```bash
id [参数] [用户名]
```

不写用户名时，显示当前用户。

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-u` | 只显示 UID |
| `-g` | 只显示主组 GID |
| `-G` | 显示所有组的编号 |
| `-n` | 和上面三个配合，显示名字而不是编号 |

### 4. 常用示例

```
$ id
uid=1000(tom) gid=1000(tom) groups=1000(tom),27(sudo)

$ id root
uid=0(root) gid=0(root) groups=0(root)

$ id -u; id -g; id -Gn
1000
1000
tom sudo
```

| 内容 | 含义 |
|---|---|
| `uid=1000(tom)` | 用户号 1000。Ubuntu 上普通用户从 1000 开始编号，root 固定是 0 |
| `gid=1000(tom)` | 主组。新建用户时默认会建一个同名的组 |
| `groups=...,27(sudo)` | 所属的全部组。在 sudo 组里才能用 sudo |

脚本里判断是否 root：

```bash
if [ "$(id -u)" -ne 0 ]; then
    echo "请用 sudo 运行"
    exit 1
fi
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 刚用 `usermod -aG docker tom` 加了组，`id` 里还是没有 docker | 组信息在登录时读取，当前会话还是旧的 | 退出重新登录；`id tom`（带用户名）能看到最新的结果 |
| 两台服务器上同名用户的 UID 不同，共享目录的文件所有者显示成数字 | 文件按 UID 记录所有者，不是按名字 | 在多台机器上保持同一用户的 UID 一致 |

### 6. 一句话总结

`id 用户名` 查 UID 和所属组，加了组要重新登录才生效。

## 071 ★★★&nbsp;&nbsp;groups：查看用户属于哪些组

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`groups` 列出用户所属的组名。它是 `id -Gn` 的简写，只输出组名，更简洁。

Linux 用组来批量授权：把用户加进 `sudo` 组就能用 sudo，加进 `docker` 组就能直接用 docker 命令，加进 `www-data` 组就能读写网站目录。

### 2. 基本格式

```bash
groups [用户名...]
```

### 3. 常用示例

```
$ groups
tom sudo

$ groups root
root : root
```

带用户名时，输出格式是“用户名 : 组名...”。

Ubuntu 安装时创建的第一个用户，在桌面版上通常属于这些组：

| 组 | 作用 |
|---|---|
| `sudo` | 可以使用 sudo |
| `adm` | 可以读取 /var/log 下的系统日志 |
| `lpadmin` | 可以管理打印机 |

把用户加入组用 `sudo usermod -aG 组名 用户名`（中级篇讲 usermod）。

> ⚠️ 上表“通常属于这些组”未实机验证：测试环境是手工建的用户，只加了 sudo 组。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 加组后 `groups` 还是旧的 | 当前登录会话读的是登录时的组信息 | 重新登录；或用 `groups 用户名` 查看最新配置 |

### 5. 一句话总结

`groups` 看自己在哪些组里，加组之后要重新登录。

## 072 ★★★&nbsp;&nbsp;who：查看谁登录了系统

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`who` 列出当前登录在这台机器上的用户：用户名、终端、登录时间、从哪个 IP 登录。准备重启服务器前，先看看还有没有别人在用。

### 2. 基本格式

```bash
who [参数]
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-b` | 上次开机的时间 |
| `-q` | 只显示用户名和人数 |
| `-H` | 显示列标题 |
| `am i` | 只显示当前这个终端的登录信息（`who am i`） |

### 4. 常用示例

```bash
who
who -H
who -b
```

典型的输出格式：

```
tom      pts/0        2026-10-29 08:12 (192.168.1.50)
zhang    pts/1        2026-10-29 09:03 (192.168.1.61)
```

| 列 | 含义 |
|---|---|
| 第 1 列 | 用户名 |
| 第 2 列 | 终端：`pts/N` 是 ssh 或图形界面里的终端窗口，`tty1` 是本机控制台 |
| 第 3 列 | 登录时间 |
| 括号里 | 来源 IP |

> ⚠️ 上面的输出是格式示意，未实机验证：测试环境不是通过登录进入的，`who` 没有任何输出。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 用 `sudo -i` 切到 root 后，who 显示的还是原来的用户名 | who 显示的是登录时的身份 | 这是正常的；查当前身份用 `whoami` |
| 在容器里执行 who 没有任何输出 | 容器里没有登录记录 | 这是正常的 |

### 6. 一句话总结

重启前先 `who` 看有没有人在线；想看每个人在做什么用 `w`。

## 073 ★★★&nbsp;&nbsp;w：查看谁在线、在做什么

> 级别：★★★ 初级 · 软件包：`procps`

### 1. 作用

`w` 是 `uptime` 和 `who` 的合体，再加上每个用户当前正在运行的命令。第一行是系统时间、运行时长和负载，下面每行一个登录会话。

### 2. 基本格式

```bash

```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-h` | 不显示标题行 |
| `-s` | 简短格式，不显示登录时间和 CPU 时间 |

### 4. 常用示例

```
$ w
 07:03:58 up  1:29,  0 users,  load average: 0.61, 0.57, 0.55

```

在有人登录的服务器上，标题下面每行一个会话，例如：

```
tom      pts/0    192.168.1.50     08:12    0.00s  0.05s  0.00s w
```

> ⚠️ 上面两行会话是格式示意，未实机验证。

| IDLE | 多久没有操作了 |

看到同事正在 `vim /etc/nginx/nginx.conf`，这时重启 nginx 或者也去改同一个文件，就要先打个招呼。

### 5. 一句话总结

`w` 一眼看清系统负载、谁在线、每人在做什么。

## 074 ★★★&nbsp;&nbsp;last：查看登录历史

> 级别：★★★ 初级 · 软件包：`wtmpdb`（Ubuntu 26.04 中 `last` 由 wtmpdb 提供）

### 1. 作用

`last` 列出过去的登录记录：谁、从哪个 IP、什么时候登录、什么时候退出，以及系统的开机和关机记录。服务器出了问题，想知道“出事前谁登录过”，或者怀疑有人非法登录时，用它查。

在 Ubuntu 26.04 上，登录记录由 wtmpdb 保存在 `/var/log/wtmp.db`（一个 SQLite 数据库），`last` 是指向 wtmpdb 的链接：

```
$ ls -l /usr/bin/last
lrwxrwxrwx 1 root root 6 Dec  2  2025 /usr/bin/last -> wtmpdb
```

### 2. 基本格式

```bash
last [参数] [用户名]
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-n 数量` | `--limit` | 只显示最近 N 条 |
| `-x` | `--system` | 同时显示系统关机、开机记录 |
| `-F` | `--fulltimes` | 显示完整的日期时间 |
| `-i` | `--ip` | 来源显示成 IP 地址 |
| `-s 时间` | `--since` | 只看某个时间之后的记录 |
| `-j` | `--json` | 输出 JSON |

以上参数取自 Ubuntu 26.04 上 wtmpdb 的帮助信息。

### 4. 常用示例

```bash
last -n 10           # 最近 10 次登录
last tom             # tom 的登录记录
last -x -n 5         # 包括开机、关机在内的最近 5 条
last -s yesterday    # 昨天以来的记录
```

> ⚠️ 本节未实机验证：测试环境没有登录记录，`last` 报 `Cannot open database (/var/log/wtmp.db) read-only: unable to open database file`。

登录失败的记录 last 不显示。要查有没有人在暴力猜密码，看 ssh 的日志：

```bash
sudo journalctl -u ssh --since today | grep "Failed password"
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `last: command not found` | 精简安装可能没有 wtmpdb 包 | `sudo apt install wtmpdb` |
| 网上教程说读取 `/var/log/wtmp`，Ubuntu 26.04 上没有这个文件 | 26.04 改用了 wtmpdb，记录存在 `/var/log/wtmp.db` | 直接用 `last` 命令，不用管文件位置 |

### 6. 一句话总结

`last -n 10` 查最近谁登录过，加 `-x` 看开关机记录。

## 107 ★★&nbsp;&nbsp;useradd：新建用户（底层命令）

> 级别：★★ 中级 · 软件包：`passwd`

### 1. 作用

`useradd` 在系统里创建一个新用户：在 `/etc/passwd`、`/etc/shadow`、`/etc/group` 里登记，可选地创建家目录。它是底层命令，**什么都不问，不加参数就不建家目录、Shell 是 /bin/sh**。脚本和自动化部署里用它，因为结果完全由参数决定。

手动给同事开账号，用交互式的 [adduser](#cmd-adduser) 更省心。

新用户创建后还没有密码，不能登录，要再用 `sudo passwd 用户名` 设置。

### 2. 基本格式

```bash
sudo useradd [参数] 用户名
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-m` | 创建家目录（并复制 /etc/skel 里的 .bashrc 等文件） |
| `-s Shell` | 登录 Shell，一般用 `/bin/bash` |
| `-c "说明"` | 备注，通常写姓名、部门 |
| `-G 组,组` | 同时加入附加组，如 `-G sudo` |
| `-u UID` | 指定用户号 |
| `-d 目录` | 指定家目录位置 |
| `-r` | 创建系统账号（给服务程序用，UID 小于 1000，默认不建家目录） |

### 4. 常用示例

以下以 root 身份执行（普通用户加 sudo）。

#### 4.1 不加参数的结果

```
$ useradd zhang

$ grep zhang /etc/passwd
zhang:x:1001:1001::/home/zhang:/bin/sh

$ ls -d /home/zhang
ls: cannot access '/home/zhang': No such file or directory
```

账号建了，但家目录不存在，Shell 是 /bin/sh。这样的账号登录后用起来很别扭。

#### 4.2 推荐写法

```
$ useradd -m -s /bin/bash -c "张三,财务部" zhang

$ grep zhang /etc/passwd; ls -ld /home/zhang
zhang:x:1001:1001:张三,财务部:/home/zhang:/bin/bash
drwxr-x--- 2 zhang zhang 4096 Oct 29 08:36 /home/zhang
```

/etc/passwd 每行 7 列：用户名、密码占位 `x`、UID、GID、备注、家目录、Shell。

#### 4.3 建账号的同时加入 sudo 组

```
$ useradd -m -u 1500 -G sudo li; id li
uid=1500(li) gid=1500(li) groups=1500(li),27(sudo)
```

#### 4.4 给服务程序建一个不能登录的系统账号

```
$ useradd -r -s /usr/sbin/nologin -d /opt/priceapp priceapp

$ grep priceapp /etc/passwd
priceapp:x:986:986::/opt/priceapp:/usr/sbin/nologin
```

让 Java、Python 服务以这个账号运行，而不是 root。即使程序被攻破，攻击者也只拿到一个权限很小、不能登录的账号。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 新用户登录后提示符只有 `$`，没有颜色，方向键出乱码 | 没加 `-s /bin/bash`，用的是 /bin/sh | `sudo usermod -s /bin/bash 用户名` |
| 新用户登录后报 `Could not chdir to home directory` | 没加 `-m`，家目录不存在 | 删掉重建，或手动建目录并 chown |
| `useradd: user 'zhang' already exists` | 用户名已被占用 | 用 `id 用户名` 检查 |
| 建好的账号无法登录 | 还没设置密码 | `sudo passwd 用户名` |

### 6. 一句话总结

脚本里用 `useradd -m -s /bin/bash 用户名`，服务账号用 `-r -s /usr/sbin/nologin`。

## 108 ★★&nbsp;&nbsp;adduser：新建用户（交互式）

> 级别：★★ 中级 · 软件包：`adduser`

### 1. 作用

`adduser` 是 Ubuntu/Debian 提供的友好版建用户工具。它自动创建家目录、设置 bash、提示你输入密码和姓名等信息，一条命令就能得到一个可以直接登录的账号。手动开账号时推荐用它。

它还有第二个用法：`adduser 用户 组`，把已有用户加入一个组。

### 2. 基本格式

```bash
sudo adduser 用户名             # 新建用户
sudo adduser 用户名 组名        # 把用户加入组
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `--disabled-password` | 不设密码（只允许 ssh 密钥登录） |
| `--comment "说明"` | 直接给出姓名等备注，不再提问 |
| `--system` | 创建系统账号 |
| `--verbose` | 显示详细过程 |

### 4. 常用示例

#### 4.1 交互式新建

```bash
sudo adduser wang
```

执行后会依次提示输入新密码（两次）、全名、房间号、电话等信息，后面几项可以直接回车跳过，最后确认 `Is the information correct? [Y/n]`。

> ⚠️ 交互过程未实机录制（需要真实终端）。

#### 4.2 非交互式，并显示过程

```
$ sudo adduser --verbose --disabled-password --comment "王五" wang
info: Adding user `wang' ...
info: Selecting UID/GID from range 1000 to 59999 ...
info: Adding new group `wang' (1002) ...
info: Adding new user `wang' (1002) with group `wang (1002)' ...
info: Creating home directory `/home/wang' ...
info: Copying files from `/etc/skel' ...
info: Adding new user `wang' to supplemental / extra groups `users' ...
info: Adding user `wang' to group `users' ...
```

从过程可以看出 adduser 比 useradd 多做的事：建同名组、建家目录、复制 /etc/skel、加入 users 组。

#### 4.3 把用户加入组

```
$ sudo adduser --verbose wang sudo
info: Adding user `wang' to group `sudo' ...
```

效果等同 `sudo usermod -aG sudo wang`，但不会出现忘写 `-a` 的问题。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `fatal: The user 'nothere' does not exist.` | 加组时用户名写错 | 用 `id 用户名` 确认 |
| 用户名带大写字母或中文被拒绝 | adduser 默认只接受小写字母、数字、下划线、连字符 | 用拼音小写，如 `zhangsan` |

### 6. 一句话总结

手动开账号用 `sudo adduser 用户名`，加组用 `sudo adduser 用户名 组名`。

<a id="cmd-usermod"></a>

## 109 ★★&nbsp;&nbsp;usermod：修改用户属性

> 级别：★★ 中级 · 软件包：`passwd`

### 1. 作用

`usermod` 修改已有用户的属性：加入或移出组、改登录 Shell、改用户名、改家目录、锁定或解锁账号。最常用的一条是 `usermod -aG 组 用户`，把用户加入某个组，比如 sudo、docker。

### 2. 基本格式

```bash
sudo usermod [参数] 用户名
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-aG 组,组` | **追加**到附加组，原有的组保留 |
| `-G 组,组` | 把附加组**设置为**这些组，原来不在列表里的组会被移出 |
| `-s Shell` | 改登录 Shell |
| `-c "说明"` | 改备注 |
| `-l 新名` | 改用户名 |
| `-d 目录 -m` | 改家目录，`-m` 同时把旧家目录的内容搬过去 |
| `-L` / `-U` | 锁定 / 解锁密码 |

### 4. 常用示例

以下以 root 身份执行。

#### 4.1 `-aG` 和 `-G` 的区别

```
$ usermod -aG dev zhang; id zhang
uid=1001(zhang) gid=1001(zhang) groups=1001(zhang),1501(dev)

$ usermod -G ops zhang; id zhang
uid=1001(zhang) gid=1001(zhang) groups=1001(zhang),2001(ops)

$ usermod -aG dev,ops zhang; id zhang
uid=1001(zhang) gid=1001(zhang) groups=1001(zhang),1501(dev),2001(ops)
```

第二条用了 `-G` 没有 `-a`，dev 组被移除了。给自己加组时漏掉 `-a`，可能把自己移出 sudo 组。

#### 4.2 禁止登录

```
$ usermod -s /usr/sbin/nologin zhang; getent passwd zhang
zhang:x:1001:1001:张三,财务部:/home/zhang:/usr/sbin/nologin
```

#### 4.3 改用户名和家目录

```
$ usermod -l zhangsan zhang; id zhangsan
uid=1001(zhangsan) gid=1001(zhang) groups=1001(zhang),1501(dev),2001(ops)

$ usermod -d /home/zhangsan -m zhangsan; ls -d /home/zhang*
/home/zhangsan
```

注意改名后，主组仍然叫 zhang，要改组名用 `groupmod -n zhangsan zhang`。

#### 4.4 锁定和解锁

```
$ usermod -L zhang; passwd -S zhang
zhang L 2026-10-29 0 99999 7 -1

$ usermod -U zhang
usermod: unlocking the user's password would result in a passwordless account.
You should set a password with usermod -p to unlock this user's password.
```

这个账号从未设过密码，解锁会变成“无密码账号”，所以 usermod 拒绝了。先用 passwd 设密码。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 加入新组后，原来的 sudo 权限没了 | 用了 `-G` 而不是 `-aG` | 一律写 `-aG`；或者用 `adduser 用户 组` |
| 加入 docker 组后，执行 docker 仍然提示权限不足 | 组信息要重新登录才生效 | 退出重新登录，或执行 `newgrp docker` |
| 改用户名时报 `user zhang is currently used by process 1234` | 该用户还有进程在运行 | 先让该用户退出登录，结束其进程 |

### 6. 一句话总结

加组永远写 `usermod -aG 组 用户`，然后重新登录。

## 110 ★★&nbsp;&nbsp;userdel：删除用户（底层命令）

> 级别：★★ 中级 · 软件包：`passwd`

### 1. 作用

`userdel` 删除一个用户账号。默认**只删账号，保留家目录**；加 `-r` 才同时删除家目录和邮件文件。

### 2. 基本格式

```bash
sudo userdel [参数] 用户名
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-r` | 同时删除家目录和邮件 |
| `-f` | 强制删除，即使用户还在登录 |

### 4. 常用示例

```

/home/li
id: 'li': no such user

$ userdel -r zhangsan; ls -d /home/zhangsan
userdel: zhangsan mail spool (/var/mail/zhangsan) not found
```

### 6. 一句话总结

`userdel -r 用户` 连家目录一起删；离职先锁定、再备份、最后删除。

## 112 ★★&nbsp;&nbsp;groupadd：新建用户组

> 级别：★★ 中级 · 软件包：`passwd`

### 1. 作用

`groupadd` 新建一个组。按部门、按项目建组，再把相关的人加进去，配合目录的组权限，就能实现“开发组的人都能改 /srv/app，其他人只能看”。

### 2. 基本格式

```bash
sudo groupadd [参数] 组名
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-g GID` | 指定组号 |
| `-r` | 创建系统组 |

相关命令：

| 命令 | 作用 |
|---|---|
| `groupdel 组名` | 删除组 |
| `groupmod -n 新名 旧名` | 改组名 |
| `getent group 组名` | 查看组和成员 |

### 4. 常用示例

```
$ sudo groupadd dev; getent group dev
dev:x:1501:

$ sudo groupadd -g 2001 ops; getent group ops
ops:x:2001:
```

/etc/group 每行 4 列：组名、密码占位、GID、成员列表（逗号分隔）。

一个完整的“项目共享目录”配置：

```bash
sudo groupadd dev
sudo usermod -aG dev zhang
sudo usermod -aG dev li
sudo mkdir /srv/app
sudo chgrp dev /srv/app
sudo chmod 2775 /srv/app     # 2 = setgid：目录里新建的文件自动属于 dev 组
```

> ⚠️ 最后一段未实机完整验证（setgid 的效果需要多个用户登录测试）。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `groupadd: group 'dev' already exists` | 组已存在 | `getent group dev` 查看 |
| 组里的人在共享目录里新建的文件，别人改不了 | 新文件的组是创建者自己的主组 | 给目录设置 setgid：`chmod g+s 目录` |

### 6. 一句话总结

`groupadd 组` 建组，配合 `usermod -aG` 和 `chgrp` 做共享目录。

## 113 ★★&nbsp;&nbsp;visudo：安全地编辑 sudo 权限

> 级别：★★ 中级 · 软件包：`sudo-rs`（Ubuntu 26.04 的 visudo 由 sudo-rs 提供）

### 1. 作用

`visudo` 用于编辑 sudo 的权限配置 `/etc/sudoers`。它和直接用编辑器打开的区别是：**保存前会检查语法**，有错就不让保存。sudoers 一旦写错，所有人的 sudo 都会失效，可能连修复的机会都没有，所以只能用 visudo 改。

更推荐的做法是不改主文件，而是在 `/etc/sudoers.d/` 下单独建文件，一个用途一个文件。

### 2. 基本格式

```bash
sudo visudo                         # 编辑 /etc/sudoers
sudo visudo -f /etc/sudoers.d/文件名  # 编辑单独的规则文件
sudo visudo -c                      # 只检查语法
```

### 3. sudoers 规则的写法

```
用户  主机=(以谁的身份)  [NOPASSWD:] 命令
```

| 示例 | 含义 |
|---|---|
| `%sudo ALL=(ALL:ALL) ALL` | sudo 组的成员可以执行任何命令（Ubuntu 默认规则） |
| `tom ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart nginx` | tom 可以免密码重启 nginx，只能执行这一条 |
| `%dev ALL=(www-data) /usr/bin/php` | dev 组可以以 www-data 身份运行 php |

### 4. 常用示例

以下以 root 身份执行。

#### 4.1 检查语法

```
$ visudo -c
/etc/sudoers: parsed OK
```

#### 4.2 给某人只开放一条命令

```
$ printf 'tom ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart nginx\n' > /etc/sudoers.d/tom-nginx
$ chmod 440 /etc/sudoers.d/tom-nginx
$ visudo -c
/etc/sudoers: parsed OK
```

日常推荐用 `sudo visudo -f /etc/sudoers.d/tom-nginx` 直接编辑这个文件，保存时自动检查。

#### 4.3 语法错误时的提示

```
$ visudo -c -f /tmp/bad
/tmp/bad:1:24: syntax error: expecting ':' but found '/'
tom ALL=(ALL) NOPASSWD /usr/bin/systemctl
                       ^
visudo: invalid sudoers file
```

`NOPASSWD` 后面少了冒号，visudo 指出了第 1 行第 24 个字符。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 用 nano 直接改了 /etc/sudoers，之后所有 sudo 都报错 | 绕过了语法检查 | 有控制台或 root 密码时用 root 登录修复；云服务器可用救援模式。以后只用 visudo |
| sudoers.d 里的文件不生效 | 文件名含 `.` 或以 `~` 结尾的会被跳过（如 `tom.conf`） | 文件名只用字母、数字、连字符、下划线，并 `chmod 440` |
| 规则写了 `NOPASSWD: /usr/bin/systemctl`，结果对方能执行 systemctl 的所有操作 | 只写程序名就是允许所有参数 | 把参数写完整，如 `/usr/bin/systemctl restart nginx` |

### 6. 一句话总结

改 sudo 权限只用 `sudo visudo -f /etc/sudoers.d/文件`，改完 `visudo -c` 检查。

<a id="cmd-umask"></a>

## 154 ★★&nbsp;&nbsp;umask：新建文件的默认权限

> 级别：★★ 中级 · 来源：bash 内建命令

### 1. 作用

新建文件和目录时，权限不是随意的，而是由 `umask`（权限掩码）决定：从“最大权限”里**去掉** umask 指定的位。文件的最大权限是 666，目录是 777。

| umask | 新文件 | 新目录 | 含义 |
|---|---|---|---|
| `022`（Ubuntu 默认） | 666 − 022 = 644 | 777 − 022 = 755 | 组和其他人可读，不可写 |
| `027` | 640 | 750 | 其他人完全无权限 |
| `077` | 600 | 700 | 只有自己能访问 |

### 2. 基本格式

```bash
umask           # 查看
umask -S        # 用 rwx 的形式查看
umask 值        # 设置（只对当前 Shell 有效）
```

### 3. 常用示例

```
$ umask
0022

$ umask -S
u=rwx,g=rx,o=rx

$ touch f1; mkdir d1; ls -ld f1 d1
drwxr-xr-x 2 tom tom 4096 Oct 29 08:37 d1
-rw-r--r-- 1 tom tom    0 Oct 29 08:37 f1

$ umask 077; touch f2; mkdir d2; ls -ld f2 d2
drwx------ 2 tom tom 4096 Oct 29 08:37 d2
-rw------- 1 tom tom    0 Oct 29 08:37 f2
```

处理含敏感数据的脚本（如导出工资表），可以在脚本开头写 `umask 077`，脚本生成的所有文件只有自己能读。

要永久修改，写进 `~/.bashrc`。服务程序的 umask 在 systemd 单元文件里用 `UMask=0027` 设置。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 设置了 `umask 000`，新文件也不是 777 | 新文件的最大权限是 666，umask 不会额外加上执行权限 | 需要执行权限时用 chmod +x |
| 在终端里改了 umask，服务生成的文件权限没变 | umask 只影响当前 Shell 及其子进程 | 在服务的启动配置里设置 |

### 5. 一句话总结

umask 决定新文件的默认权限，默认 022 得到 644/755，敏感脚本用 077。

<a id="cmd-chage"></a>

## 187 ★★&nbsp;&nbsp;chage：设置密码有效期

> 级别：★★ 中级 · 软件包：`passwd`

### 1. 作用

`chage`（change age）查看和设置用户密码的有效期策略：多少天必须改一次密码、到期前几天提醒、账号在哪天失效。等保、ISO 27001 这类安全检查经常要求“密码 90 天必须更换”，就靠它设置。

### 2. 基本格式

```bash
sudo chage [参数] 用户名
chage -l 用户名              # 查看（查自己的不用 sudo）
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-l` | 查看当前策略 |
| `-M 天数` | 密码最长有效天数 |
| `-m 天数` | 两次修改密码之间最少间隔几天 |
| `-W 天数` | 到期前几天开始提醒 |
| `-d 0` | 让密码立即过期，下次登录必须改密码 |
| `-E 日期` | 账号在这天之后失效，`-E -1` 取消 |

### 4. 常用示例

以下以 root 身份执行。

#### 4.1 查看

```
$ chage -l tom
Last password change					: Oct 29, 2026
Password expires					: never
Password inactive					: never
Account expires						: never
Minimum number of days between password change		: 0
Maximum number of days between password change		: 99999
Number of days of warning before password expires	: 7
```

99999 天约等于永不过期，这是 Ubuntu 的默认值。

#### 4.2 设置 90 天有效期

```
$ chage -M 90 -W 7 tom; chage -l tom | sed -n 2,6p
Password expires					: Jan 27, 2027
Password inactive					: never
Account expires						: never
Minimum number of days between password change		: 0
Maximum number of days between password change		: 90
```

#### 4.3 下次登录强制改密码

```
$ chage -d 0 tom; chage -l tom | head -2
Last password change					: password must be changed
Password expires					: password must be changed
```

给新员工设了临时密码后用这条。

#### 4.4 外包人员账号到期自动失效

```
$ chage -E 2026-12-31 tom; chage -l tom | grep "Account expires"
Account expires						: Dec 31, 2026
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 设了 `-M 90`，用 ssh 密钥登录的人从来没被要求改密码 | 密码有效期只在用密码登录时检查 | 密钥登录的账号需要另外管理密钥 |
| 给已有账号设 `-M 90` 后，有人立即被要求改密码 | 他的上次改密码时间已经超过 90 天 | 先 `chage -l` 看 Last password change |

### 6. 一句话总结

`chage -l` 查看，`-M 90` 设有效期，`-d 0` 强制下次改密码，`-E` 设账号失效日。

<a id="cmd-getent"></a>

## 188 ★★&nbsp;&nbsp;getent：查询用户、组、主机等系统数据库

> 级别：★★ 中级 · 软件包：`libc-bin`

### 1. 作用

`getent`（get entries）按系统的配置查询用户、组、主机名等信息。和直接 `grep /etc/passwd` 的区别是：如果服务器接入了 LDAP 或 AD 域，域账号不在 /etc/passwd 里，但 getent 能查到。查主机名时，它按 `/etc/hosts` → DNS 的顺序查，结果和程序实际看到的一致。

### 2. 基本格式

```bash
getent 数据库 [键...]
```

| 数据库 | 内容 |
|---|---|
| `passwd` | 用户 |
| `group` | 组 |
| `shadow` | 密码（需要 root） |
| `hosts` | 主机名和 IP |
| `services` | 端口号和服务名 |

### 3. 常用示例

```
$ getent passwd tom
tom:x:1000:1000::/home/tom:/bin/bash

$ getent group sudo
sudo:x:27:tom

$ getent hosts localhost
::1             localhost

$ getent passwd nothere; echo "退出码=$?"
退出码=2
```

找不到时没有输出，退出码为 2，脚本里可以用来判断用户是否存在：

```bash
if ! getent passwd priceapp >/dev/null; then
    sudo useradd -r -s /usr/sbin/nologin priceapp
fi
```

### 4. 一句话总结

查用户、组、主机名用 `getent`，结果和程序实际看到的一致。

## 189 ★★&nbsp;&nbsp;sudoedit：以 root 权限安全地编辑文件

> 级别：★★ 中级 · 软件包：`sudo-rs`

### 1. 作用

`sudoedit`（等同 `sudo -e`）用来编辑普通用户没有权限修改的文件。它和 `sudo nano 文件` 的区别：

| | `sudo nano 文件` | `sudoedit 文件` |
|---|---|---|
| 编辑器以谁的身份运行 | root | 你自己 |
| 编辑器的配置 | root 的 | 你自己的 |
| 安全性 | 编辑器里可以执行命令，等于拿到 root Shell | 编辑器没有 root 权限，只在保存时以 root 身份写回 |

sudoers 里只允许某人编辑某个文件时，也要用 sudoedit。

### 2. 基本格式

```bash
sudoedit 文件...
SUDO_EDITOR=vim sudoedit 文件     # 指定编辑器
```

编辑器的选择顺序：`SUDO_EDITOR` → `VISUAL` → `EDITOR` 环境变量 → 系统默认（Ubuntu 是 nano）。

### 3. 常用示例

```bash
sudoedit /etc/hosts
```

sudoedit 把文件复制到临时位置，用你的身份打开编辑器；你保存退出后，它再以 root 身份把内容写回原文件。

> ⚠️ 本页未实机验证：测试环境禁止提权，sudoedit 报 `The "no new privileges" flag is set`。

### 4. 一句话总结

改系统配置文件用 `sudoedit` 比 `sudo 编辑器` 更安全。
