## 028 ★★★&nbsp;&nbsp;top：实时查看系统负载和进程

> 级别：★★★ 初级 · 软件包：`procps`

### 1. 作用

`top` 实时显示系统的整体负载、CPU 和内存使用情况，以及按资源占用排序的进程列表，默认每 3 秒刷新一次。服务器“突然很卡”，第一件事就是打开 top，看是哪个进程在占 CPU 或内存。

界面更友好的替代品是 [htop](#cmd-htop)。

### 2. 基本格式

```bash
top [参数]
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-u 用户` | 只显示某个用户的进程 |
| `-p PID` | 只盯某几个进程，如 `-p 1234,5678` |
| `-o 字段` | 按指定字段排序，如 `-o %MEM` |
| `-d 秒` | 刷新间隔 |
| `-b -n 1` | 批处理模式，输出一次就退出（可以存到文件或接管道） |

### 4. 运行中的按键

| 按键 | 作用 |
|---|---|
| `P` | 按 CPU 排序（默认） |
| `M` | 按内存排序 |
| `1` | 展开显示每个 CPU 核心 |
| `c` | 显示完整命令行 |
| `k` | 输入 PID 结束进程 |
| `q` | 退出 |

### 5. 读懂 top 的输出

下面用一个死循环的 python 进程模拟 CPU 被占满（输出来自测试环境，省略了一行测试环境自身的进程）：

```
$ top -b -n 1 | head -12
top - 06:52:01 up  1:17,  0 users,  load average: 0.57, 0.57, 0.50
Tasks:   6 total,   2 running,   4 sleeping,   0 stopped,   0 zombie
%Cpu(s): 12.1 us,  1.1 sy,  0.0 ni, 75.8 id,  0.0 wa,  0.0 hi, 11.0 si,  0.0 st
MiB Mem :  31560.2 total,  21436.9 free,   2284.8 used,   8338.3 buff/cache
MiB Swap:   2048.0 total,   2048.0 free,      0.0 used.  29275.4 avail Mem

    PID USER      PR  NI    VIRT    RES    SHR S  %CPU  %MEM     TIME+ COMMAND
     35 tom       20   0   16036   8692   6004 R 100.0   0.0   0:02.19 python3
      2 root      20   0    7208   4032   3708 S   0.0   0.0   0:00.00 runuser
     29 tom       20   0    4940   4104   3784 S   0.0   0.0   0:00.00 bash
     37 tom       20   0    8156   5184   3380 R   0.0   0.0   0:00.00 top
```

头部五行：

| 行 | 关注点 |
|---|---|
| 第 1 行 | `up 1:17` 已运行 1 小时 17 分；`load average` 是最近 1、5、15 分钟的平均负载。负载长期超过 CPU 核数，说明 CPU 忙不过来 |
| 第 2 行 | 进程总数；`zombie`（僵尸进程）不为 0 时值得留意 |
| 第 3 行 | `us` 用户程序占用，`sy` 内核占用，`id` 空闲，`wa` 等待磁盘 IO。`wa` 高说明瓶颈在磁盘 |
| 第 4、5 行 | 内存和 swap，含义同 [free](11-系统信息和硬件.md#cmd-free) |

进程列表的关键列：

| 列 | 含义 |
|---|---|
| PID | 进程号，结束进程时要用 |
| %CPU | CPU 占用。单个进程占满一个核显示 100%，多核机器上可以超过 100% |
| RES | 实际占用的物理内存（KB） |
| S | 状态：`R` 运行中，`S` 休眠，`D` 等待 IO（不可中断），`Z` 僵尸 |
| TIME+ | 累计使用的 CPU 时间 |

python3 的 %CPU 是 100.0，排在第一位，它就是“罪魁祸首”。

### 6. 常用示例

```bash
top -o %MEM                # 打开时直接按内存排序
top -u www-data            # 只看网站进程
top -b -n 1 > top.txt      # 把当前状态存成文件，发给同事分析
```

### 7. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 进程 %CPU 显示 400%，以为出了 bug | 多核机器上按单核 100% 计算，4 个核都占满就是 400% | 按 `1` 看每个核的情况 |
| load average 很高，但 CPU 的 `id` 也很高 | 负载里也算了在等磁盘的进程（状态 D） | 看 `wa` 列，用 `iostat` 查磁盘 |
| 在 top 里按 `k` 结束进程没反应 | 进程属于其他用户，普通用户没权限 | 用 `sudo top`，或退出后 `sudo kill PID` |

### 8. 一句话总结

卡了就开 `top`，`P` 按 CPU、`M` 按内存排，找到 PID 再处理。

## 029 ★★★&nbsp;&nbsp;ps：查看进程列表

> 级别：★★★ 初级 · 软件包：`procps`

### 1. 作用

`ps`（process status）列出当前正在运行的进程。和 top 不同，ps 只输出一次快照，适合配合 grep 查找某个程序是否在运行、它的 PID 是多少、是谁启动的。

### 2. 基本格式

```bash
ps [参数]
```

ps 的参数有两种风格并存，最常见的是这两种组合：

| 写法 | 风格 | 说明 |
|---|---|---|
| `ps aux` | BSD 风格（不带 `-`） | 所有用户的所有进程，带 CPU、内存占用 |
| `ps -ef` | 标准风格（带 `-`） | 所有进程，带父进程号 PPID |

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `aux` | 所有进程，用户导向的格式（含 %CPU、%MEM） |
| `-ef` | 所有进程，完整格式（含 PPID） |
| `-u 用户` | 只看某个用户的进程 |
| `-p PID` | 只看指定 PID 的进程 |
| `-o 字段,...` | 自定义显示哪些列 |
| `--sort=-字段` | 按字段排序，`-` 表示从大到小 |

### 4. 常用示例

下面先在后台启动一个 `sleep 600` 和一个占 50 MB 内存的 python 进程，用来演示（测试环境里进程很少，真实服务器会有几百个）。

#### 4.1 `ps`：只看当前终端的进程

```
$ ps
    PID TTY          TIME CMD
     29 ?        00:00:00 bash
     35 ?        00:00:00 sleep
     36 ?        00:00:00 python3
     38 ?        00:00:00 ps
```

#### 4.2 `ps aux`：用户、CPU、内存

```
$ ps u -u tom
USER         PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
tom           29  0.0  0.0   4940  4124 ?        S    06:51   0:00 bash -ic cd ~
tom           35  0.0  0.0  17648  7136 ?        S    06:51   0:00 sleep 600
tom           36  3.9  0.1  64868 57868 ?        S    06:51   0:00 python3 -c im
tom           39  0.0  0.0   7152  4444 ?        R    06:51   0:00 ps u -u tom
```

这里用 `ps u -u tom` 只列出 tom 的进程，列的格式和 `ps aux` 完全一样。

| 列 | 含义 |
|---|---|
| %CPU / %MEM | CPU、内存占用百分比 |
| VSZ / RSS | 虚拟内存 / 实际占用的物理内存（KB）。看内存占用以 RSS 为准 |
| STAT | 状态，含义同 [top](#cmd-top) 的 S 列 |
| START | 启动时间 |

#### 4.3 `ps -ef`：看父进程

```
$ ps -f -u tom
UID          PID    PPID  C STIME TTY          TIME CMD
tom           29       2  0 06:51 ?        00:00:00 bash -ic cd ~/demo; while IF
tom           35      29  0 06:51 ?        00:00:00 sleep 600
tom           36      29  3 06:51 ?        00:00:00 python3 -c import time; x=by
tom           40      29  0 06:51 ?        00:00:00 ps -f -u tom
```

sleep 和 python3 的 PPID 都是 29，说明它们是由 PID 29 的 bash 启动的。排查“这个进程是谁拉起来的”时看 PPID。

#### 4.4 `-o` 和 `--sort`：按内存排序

```
$ ps -u tom -o pid,ppid,%cpu,%mem,etime,cmd --sort=-%mem
    PID    PPID %CPU %MEM     ELAPSED CMD
     36      29  3.8  0.1       00:00 python3 -c import time; x=bytearray(50_000
     35      29  0.0  0.0       00:00 sleep 600
     41      29  0.0  0.0       00:00 ps -u tom -o pid,ppid,%cpu,%mem,etime,cmd
     29       2  0.0  0.0       00:00 bash -ic cd ~/demo; while IFS= read -r lin
```

全机器内存占用前 10 名：`ps aux --sort=-%mem | head -11`。

#### 4.5 查某个程序在不在运行

```
$ ps aux | grep "[s]leep"
tom           35  0.0  0.0  17648  7136 ?        S    06:51   0:00 sleep 600

$ pgrep -a sleep
35 sleep 600
```

`[s]leep` 这个写法能避免 grep 把自己也匹配出来。只想要 PID 时，`pgrep` 更简单。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `ps aux \| grep nginx` 总有一行 `grep --color=auto nginx` | grep 自己也是一个进程 | 用 `grep "[n]ginx"` 或 `pgrep -a nginx` |
| 命令行被截断，看不全启动参数 | ps 按终端宽度截断 | 加 `ww`：`ps auxww` |
| 只用 `ps` 找不到后台服务 | 不带参数的 ps 只显示当前终端的进程 | 用 `ps aux` 或 `ps -ef` |

### 6. 一句话总结

`ps aux | grep 名字` 查进程，`--sort=-%mem` 找内存大户，只要 PID 用 `pgrep`。

## 030 ★★★&nbsp;&nbsp;kill：结束进程

> 级别：★★★ 初级 · 来源：bash 内建命令（另有同名程序 `/usr/bin/kill`，用法相同）

### 1. 作用

`kill` 向进程发送信号（signal，系统通知进程的一种方式）。最常见的用途是结束进程：程序卡死、端口被旧进程占用、要停掉一个手动启动的后台任务时用它。

kill 默认发送的是 TERM（15 号）信号，意思是“请你退出”，程序可以先保存数据、关闭连接再退出。只有程序不理会时，才用 KILL（9 号）信号强制结束。

### 2. 基本格式

```bash
kill [-信号] PID...
kill %作业号            # 结束当前终端的后台作业
```

PID 用 [ps](#cmd-ps) 或 `pgrep` 查。

### 3. 常用信号

| 信号 | 编号 | 写法 | 作用 |
|---|---|---|---|
| TERM | 15 | `kill PID` | 默认信号，请求进程正常退出 |
| KILL | 9 | `kill -9 PID` | 强制结束，进程无法拒绝，也来不及做清理 |
| HUP | 1 | `kill -HUP PID` | 很多服务（如 nginx）收到后会重新读取配置 |
| INT | 2 | `kill -INT PID` | 等同于在终端里按 `Ctrl+C` |

```
$ kill -l 9 15
KILL
TERM
```

`kill -l` 列出所有信号，后面跟编号则显示对应的名字。

### 4. 常用示例

#### 4.1 结束后台作业

```
$ sleep 600 &
[1] 197

$ jobs
[1]+  Running                    sleep 600 &

$ kill %1

$ jobs
[1]+  Terminated                 sleep 600
```

#### 4.2 按 PID 结束

```
$ pgrep -a sleep
199 sleep 601

$ kill 199
```

也可以写成一行：`kill $(pgrep -x sleep)`。

#### 4.3 正常结束不了，再用 `-9`

下面模拟一个忽略 TERM 信号的进程：

```
$ bash -c 'trap "" TERM; sleep 602' &
[2] 203

$ kill 203; sleep 0.5; ps -p 203 -o pid,stat,cmd
    PID STAT CMD
    203 S    sleep 602

$ kill -9 203; sleep 0.3; ps -p 203 -o pid,cmd
    PID CMD
```

第一次 kill 后进程还在；`kill -9` 之后，ps 已经查不到它了。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `bash: kill: (99999) - No such process` | PID 写错，或进程已经退出 | 重新用 `pgrep` 查 |
| `bash: kill: (1) - Operation not permitted` | 不能结束其他用户（包括 root）的进程 | 确认确实要结束后，用 `sudo kill PID` |
| 一上来就 `kill -9` 数据库，重启后数据损坏或要长时间恢复 | `-9` 不给程序保存数据的机会 | 先 `kill PID` 等几秒，不行再 `-9`；systemd 管理的服务用 `sudo systemctl stop 服务名` |
| kill 掉进程，几秒后它又出现了 | 进程由 systemd 或其他守护程序管理，退出后会被自动拉起 | 用 `systemctl stop` 停止服务 |
| 想按名字结束进程 | kill 只认 PID | 用 `pkill 名字` 或 [killall](#cmd-killall) |

### 6. 一句话总结

先 `kill PID` 礼貌请求，没反应再 `kill -9`；服务要用 `systemctl stop`。

## 085 ★★★&nbsp;&nbsp;htop：更好用的进程监控

> 级别：★★★ 初级 · 软件包：`htop`（Ubuntu 26.04 为 3.4.1 版；没有就 `sudo apt install htop`）

### 1. 作用

`htop` 和 [top](#cmd-top) 做同样的事：实时显示 CPU、内存和进程。它的改进是：

- 每个 CPU 核心、内存、swap 用彩色条形图显示，一眼看出忙不忙；
- 可以用方向键、鼠标选中进程，直接结束或调整优先级；
- 底部一直显示功能键提示，不用记快捷键；
- 可以按树形显示父子进程。

### 2. 基本格式

```bash
htop [参数]
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-u 用户` | 只显示某个用户的进程 |
| `-p PID,PID` | 只显示指定的进程 |
| `-t` | 树形显示 |
| `-d 数字` | 刷新间隔，单位是 0.1 秒（`-d 10` 为 1 秒） |

### 4. 运行中的按键

| 按键 | 作用 |
|---|---|
| `F3` 或 `/` | 搜索进程 |
| `F4` 或 `\` | 过滤：只显示名字里含关键词的进程 |
| `F5` 或 `t` | 切换树形显示 |
| `F6` 或 `>` | 选择排序列 |
| `P` / `M` | 按 CPU / 内存排序 |
| `F9` 或 `k` | 给选中的进程发信号（默认 15 TERM） |
| `空格` | 标记进程，可以一次处理多个 |
| `F10` 或 `q` | 退出 |

> ⚠️ 本页未实机验证：htop 是全屏交互程序，测试环境只确认了版本（`htop 3.4.1`）。按键为 htop 的默认键位。

### 5. 常用示例

```bash
htop                 # 打开
htop -u www-data     # 只看网站进程
htop -t              # 树形显示，看哪个进程拉起了哪些子进程
```

排查“某个 Java 程序占了多少内存”：打开 htop，按 `F4` 输入 `java`，列表里只剩 java 进程，看 RES 列。

### 6. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 同一个程序在列表里出现了几十行 | htop 默认把每个线程也单独列出来 | 按 `H` 隐藏用户线程 |
| 在 SSH 终端里按 F 键没反应 | 终端软件截获了功能键 | 用括号里的替代按键，如 `/` 搜索、`q` 退出 |

### 7. 一句话总结

日常看负载用 `htop`，`F4` 过滤、`F9` 结束进程、`q` 退出。

## 087 ★★★&nbsp;&nbsp;sleep：暂停一段时间

> 级别：★★★ 初级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`sleep` 什么也不做，只是等待指定的时间后退出。在脚本里，它用来让两个步骤之间隔开一段时间，比如启动服务后等几秒再检查状态，或者每隔一分钟轮询一次。

### 2. 基本格式

```bash
sleep 时长[单位]
```

| 单位 | 含义 | 例子 |
|---|---|---|
| 不写或 `s` | 秒 | `sleep 5`、`sleep 0.5` |
| `m` | 分钟 | `sleep 2m` |
| `h` | 小时 | `sleep 1h` |
| `d` | 天 | `sleep 1d` |

可以用小数。

### 3. 常用示例

#### 3.1 等待后再执行

```
$ sleep 0.5; echo done
done
```

#### 3.2 启动服务后等它就绪

```bash
sudo systemctl restart myapp
sleep 5
curl -fsS http://localhost:8080/health && echo "启动成功"
```

#### 3.3 简单的轮询

```bash
while ! curl -fsS http://localhost:8080/health >/dev/null; do
    echo "还没好，3 秒后重试"
    sleep 3
done
echo "服务已就绪"
```

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 用 `sleep 3600` 加死循环做定时任务，脚本被意外结束后就再也不执行了 | sleep 循环没有人看管 | 定时任务用 crontab 或 systemd 定时器（中级篇讲） |
| 固定 `sleep 5` 等服务启动，机器忙的时候 5 秒不够 | 启动时间不固定 | 改成 3.3 的轮询写法，并设置最大重试次数 |

### 5. 一句话总结

`sleep 秒数` 在脚本里等一会儿；等服务就绪用轮询，定时任务用 cron。

## 088 ★★★&nbsp;&nbsp;watch：定时重复执行一条命令

> 级别：★★★ 初级 · 软件包：`procps`

### 1. 作用

`watch` 每隔一段时间（默认 2 秒）执行一次指定的命令，并全屏显示最新的结果。想盯着某个数字变化时用它：磁盘空间在不在涨、文件有没有传完、某个进程还在不在。

### 2. 基本格式

```bash
watch [参数] 命令
```

按 `Ctrl+C` 退出。

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-n 秒` | `--interval` | 刷新间隔 |
| `-d` | `--differences` | 高亮显示和上一次相比变化的部分 |
| `-t` | `--no-title` | 不显示顶部的标题行 |
| `-g` | `--chgexit` | 输出发生变化时自动退出 |

### 4. 常用示例

#### 4.1 每秒刷新一次

```bash
watch -n 1 date
```

屏幕顶部显示标题行，下面是命令的输出，每秒更新：

```
Every 1.0s: date                                   ubuntu: Thu Oct 29 07:08:42 2026

Thu Oct 29 07:08:42 UTC 2026
```

标题行依次是：刷新间隔和命令、主机名、当前时间。

#### 4.2 盯着上传进度

```bash
watch -n 2 -d "ls -l /data/upload/"
```

`-d` 会把变化的数字（文件大小）高亮显示。

#### 4.3 盯着磁盘和内存

```bash
watch -n 5 "df -h / && free -h"
```

命令里有管道、`&&` 这类符号时，整条命令要加引号。

#### 4.4 等到变化时退出

```bash
watch -g "ls /data/done.flag" && echo "处理完成"
```

> ⚠️ 本页只验证了 4.1：watch 是全屏程序，测试环境只截取到了第一屏的标题和内容。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `watch ls \| grep log` 结果不对 | 管道被当前 Shell 先处理了，watch 只拿到了 `ls` | 整条命令加引号：`watch "ls \| grep log"` |
| 别名在 watch 里用不了 | watch 用 `sh -c` 执行命令，不认识 bash 的别名 | 写完整命令，如 `watch "ls -alF"` |

### 6. 一句话总结

`watch -n 秒 -d "命令"` 定时刷新并高亮变化，`Ctrl+C` 退出。

<a id="cmd-time"></a>

## 089 ★★★&nbsp;&nbsp;time：统计命令的执行时间

> 级别：★★★ 初级 · 来源：bash 关键字（另有程序版 `/usr/bin/time`，需要单独安装）

### 1. 作用

`time` 放在任何命令前面，命令执行完后报告它花了多长时间。对比两种写法哪个更快、确认一个备份脚本要跑多久，都用它。

### 2. 基本格式

```bash
time 命令
```

### 3. 读懂输出

```
$ time sleep 1

real    0m1.002s
user    0m0.002s
sys     0m0.000s
```

| 行 | 含义 |
|---|---|
| real | 从开始到结束实际经过的时间（墙上时钟） |
| user | 程序自身代码占用 CPU 的时间 |
| sys | 程序请求系统内核做事（读写文件、网络）占用 CPU 的时间 |

sleep 1 的 real 是 1 秒，但 user 和 sys 几乎为 0：它一直在等待，没有使用 CPU。

### 4. 常用示例

#### 4.1 统计一组命令的时间

```
$ time (find / -name "*.conf" 2>/dev/null | wc -l)
131

real    0m0.075s
user    0m0.010s
sys     0m0.067s
```

多条命令或带管道时，用括号括起来，统计的是整组命令。

#### 4.2 根据结果判断瓶颈

| 现象 | 说明 |
|---|---|
| real 远大于 user + sys | 大部分时间在等待：等磁盘、等网络、等数据库 |
| user 接近 real | 程序在密集计算 |
| sys 偏高 | 大量读写文件或系统调用 |

导出报表的脚本跑了 10 分钟，`time` 一看 user 只有 5 秒，说明问题出在等数据库查询，而不是脚本本身。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `time` 的输出没法用 `> 文件` 重定向保存 | bash 的 time 把结果写到 Shell 的错误输出，不属于被测命令 | `{ time 命令 ; } 2> time.txt` |
| 网上教程里的 `time -v` 报错 | `-v` 是程序版 `/usr/bin/time` 的参数，bash 的 time 不支持 | `sudo apt install time`，然后用 `/usr/bin/time -v 命令` |

### 6. 一句话总结

`time 命令` 看耗时；real 远大于 user+sys，说明时间花在了等待上。

<a id="cmd-killall"></a>

## 099 ★★★&nbsp;&nbsp;killall：按程序名结束进程

> 级别：★★★ 初级 · 软件包：`psmisc`

### 1. 作用

`killall` 按程序名结束进程，同名的进程会被**全部**结束。用 [kill](#cmd-kill) 需要先查 PID，同一个程序开了很多个进程时，killall 一次就能处理完。

### 2. 基本格式

```bash
killall [参数] 程序名
```

程序名要和进程名完全一致（`ps` 的 CMD 列或 `pgrep -a` 看到的名字）。

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-信号` | 指定信号，如 `-9`、`-HUP`，默认 15（TERM） |
| `-i` | 每个进程都先询问 |
| `-v` | 显示结束了哪些进程 |
| `-u 用户` | 只结束某个用户的进程 |
| `-w` | 等进程真正退出后再返回 |

### 4. 常用示例

#### 4.1 结束所有同名进程

```
$ sleep 600 & sleep 601 &

$ pgrep -a sleep
48 sleep 600
49 sleep 601

$ killall sleep

$ pgrep -a sleep; echo "剩余=$?"
剩余=1
```

两个 sleep 都被结束了。pgrep 找不到进程时退出码为 1。

#### 4.2 `-v`：看结束了谁

```
$ killall -v sleep
Killed sleep(56) with signal 15
```

#### 4.3 只结束某个用户的进程

```bash
sudo killall -u zhang python3
```

#### 4.4 进程名不存在

```
$ killall nothere
nothere: no process found
```

### 5. killall 和 pkill 的区别

| | killall | pkill |
|---|---|---|
| 匹配方式 | 进程名必须完全一致 | 进程名包含关键词即可 |
| 按完整命令行匹配 | 不支持 | `pkill -f "关键词"` |

例如要结束 `java -jar price-service.jar`，killall 只能写 `killall java`（会把所有 Java 程序都结束），而 `pkill -f price-service` 可以精确地只结束这一个。

### 6. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `killall java` 把服务器上所有的 Java 服务都停了 | killall 会结束所有同名进程 | 先 `pgrep -a java` 看清楚有哪些，再用 `pkill -f 关键词` 或 `kill PID` |
| 在其他 Unix 系统（如 Solaris）上执行 killall，结束的是所有进程 | 不同系统上 killall 的含义不同 | 只在 Linux 上用 killall |

### 7. 一句话总结

`killall 程序名` 一次结束所有同名进程，执行前先 `pgrep -a` 确认范围。

## 130 ★★&nbsp;&nbsp;pgrep：按名称查找进程号

> 级别：★★ 中级 · 软件包：`procps`

### 1. 作用

`pgrep` 按进程名（或完整命令行）查找进程，输出 PID。它取代了 `ps aux | grep 名字` 这种写法：结果干净，不会把 grep 自己也列出来，在脚本里判断“某个程序是否在运行”最方便。

### 2. 基本格式

```bash
pgrep [参数] 模式
```

模式是正则表达式，默认匹配进程名的一部分。

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-a` | 同时显示完整命令行 |
| `-l` | 同时显示进程名 |
| `-f` | 用完整命令行匹配（不只是进程名） |
| `-x` | 进程名必须完全一致 |
| `-u 用户` | 只找某个用户的进程 |
| `-c` | 只输出匹配的数量 |
| `-n` / `-o` | 只输出最新 / 最早启动的那一个 |

### 4. 常用示例

后台先启动了 `sleep 600`、`sleep 601` 和一个 python3 进程。

```
$ pgrep sleep
35
36

$ pgrep -a sleep
35 sleep 600
36 sleep 601

$ pgrep -l python
37 python3

$ pgrep -u tom -c
4
```

#### 4.1 `-f`：按命令行里的内容找

```
$ pgrep -f "time.sleep"
37
```

Java 程序的进程名都是 java，要找某一个服务只能用 `-f`：`pgrep -f price-service.jar`。

#### 4.2 `-x`：完全匹配

```
$ pgrep -x slee; echo "退出码=$?"
退出码=1
```

找不到时退出码为 1。脚本里的常见用法：

```bash
if ! pgrep -x nginx >/dev/null; then
    echo "nginx 没有运行"
fi
```

### 5. 一句话总结

查进程号用 `pgrep -a 名字`，按命令行找用 `-f`，精确匹配用 `-x`。

<a id="cmd-pkill"></a>

## 131 ★★&nbsp;&nbsp;pkill：按名称结束进程

> 级别：★★ 中级 · 软件包：`procps`

### 1. 作用

`pkill` 用和 [pgrep](#cmd-pgrep) 一样的方式匹配进程，然后给它们发信号（默认 TERM，请求退出）。和 [killall](#cmd-killall) 相比，它支持部分匹配和按完整命令行匹配（`-f`），能精确结束某一个 Java 服务而不影响其他 Java 程序。

### 2. 基本格式

```bash
pkill [参数] 模式
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-f` | 按完整命令行匹配 |
| `-x` | 进程名完全一致 |
| `-u 用户` | 只处理某个用户的进程 |
| `-信号` | 指定信号，如 `-9`、`-HUP` |
| `-e` | 显示结束了哪些进程 |

### 4. 常用示例

```
$ pkill -f "sleep 601"; sleep 0.2; pgrep -a sleep
35 sleep 600

$ pkill -e python3
python3 killed (pid 37)

$ pkill nothere; echo "退出码=$?"
退出码=1
```

只结束了 `sleep 601`，`sleep 600` 还在。

常见用法：

```bash
pkill -f price-service.jar     # 结束某个 Java 服务
pkill -HUP -x nginx            # 让 nginx 重新加载配置
sudo pkill -u zhang            # 结束某个用户的所有进程
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `pkill sh` 把 bash、ssh、sshd 都结束了，ssh 连接断开 | 默认是部分匹配，`sh` 出现在很多进程名里 | 先用 `pgrep -a 模式` 预览，确认后再 pkill；或加 `-x` |
| `pkill -f 关键词` 把自己正在运行的脚本也结束了 | 脚本的命令行里也包含这个关键词 | 关键词写得更具体 |

### 6. 一句话总结

先 `pgrep -a` 预览，再 `pkill -f 关键词` 结束；短名字一定加 `-x`。

## 132 ★★&nbsp;&nbsp;nice：以指定优先级启动程序

> 级别：★★ 中级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`nice` 用指定的优先级启动一个程序。优先级用 nice 值表示，范围 -20 到 19，**数字越大优先级越低**（越“谦让”），默认是 0。

在白天业务繁忙时跑备份、压缩、数据导出这类耗 CPU 的任务，用 `nice -n 19` 启动，它只会用到其他程序剩下的 CPU，不影响业务。

### 2. 基本格式

```bash
nice -n 数值 命令 [参数]
```

### 3. 常用参数

| 写法 | 作用 |
|---|---|
| `nice` | 显示当前 Shell 的 nice 值 |
| `nice -n 10 命令` | 以 nice 值 10 运行 |
| `sudo nice -n -5 命令` | 以更高的优先级运行（负值需要 root） |

### 4. 常用示例

```
$ nice
0

$ nice -n 10 sleep 300 &

$ ps -o pid,ni,cmd -p $!
    PID  NI CMD
     52  10 sleep 300
```

NI 列就是 nice 值。

```bash
nice -n 19 tar -czf /backup/www-$(date +%F).tar.gz /var/www
```

普通用户想提高优先级会失败：

```
$ nice -n -5 true
nice: warning: setpriority: Permission denied
```

命令照样执行了，只是优先级没有提高。

### 5. 一句话总结

后台大任务用 `nice -n 19 命令` 启动，给业务让路。

<a id="cmd-renice"></a>

## 133 ★★&nbsp;&nbsp;renice：调整运行中进程的优先级

> 级别：★★ 中级 · 软件包：`bsdutils`

### 1. 作用

`renice` 修改**已经在运行**的进程的 nice 值。一个备份任务正在拖慢系统，不想结束它，可以用 renice 把它的优先级调低。

### 2. 基本格式

```bash
renice -n 数值 -p PID
renice -n 数值 -u 用户       # 该用户的所有进程
```

### 3. 常用示例

```
$ renice -n 15 -p 52
52 (process ID) old priority 10, new priority 15

$ ps -o pid,ni,cmd -p 52
    PID  NI CMD
     52  15 sleep 300
```

普通用户只能把自己进程的 nice 值调大（降低优先级），不能调回去：

```
$ renice -n 5 -p 52
renice: failed to set priority for 52 (process ID): Permission denied
```

从 15 调回 5 需要 root。

### 4. 一句话总结

进程拖慢系统时 `renice -n 19 -p PID`，普通用户只能往大了调。

<a id="cmd-nohup"></a>

## 134 ★★&nbsp;&nbsp;nohup：退出终端后程序继续运行

> 级别：★★ 中级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

通过 ssh 在终端里启动一个程序，关掉终端或网络断开时，系统会给它发 HUP 信号，程序通常就退出了。`nohup`（no hang up）让程序忽略这个信号，终端关掉后继续运行。它还会把程序的输出写到文件里，因为终端已经不在了。

需要长期运行的服务应该交给 systemd 管理；nohup 适合临时跑一个耗时的任务，比如一次性的数据迁移脚本。

### 2. 基本格式

```bash
nohup 命令 [参数] > 日志文件 2>&1 &
```

| 部分 | 作用 |
|---|---|
| `nohup` | 忽略 HUP 信号 |
| `> 日志文件 2>&1` | 输出和错误都写进日志文件 |
| `&` | 放到后台运行，立即返回提示符 |

### 3. 常用示例

```
$ nohup bash -c 'echo 写日志' > job.log 2>&1 &
[2] 68

$ cat job.log
写日志
```

不写重定向时，在终端里执行 nohup 会把输出写进当前目录的 `nohup.out`，并提示 `nohup: ignoring input and appending output to 'nohup.out'`。

> ⚠️ 上面这句提示未实机录制（只有在真实终端里才会出现）。

一个实际的例子：

```bash
nohup python3 migrate.py > migrate.log 2>&1 &
tail -f migrate.log      # 随时查看进度；断开 ssh 后重新登录，再 tail 即可
```

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 用了 nohup，关掉终端后程序还是没了 | 没加 `&`，程序在前台运行；或者程序本身捕获了其他信号 | 加 `&`；长期运行的程序改用 systemd 服务或 tmux |
| `nohup.out` 越来越大，把磁盘写满了 | 输出一直追加 | 重定向到指定文件，并配置日志轮转 |
| 服务器重启后程序没有自动起来 | nohup 不管开机启动 | 写成 systemd 服务 |

### 5. 一句话总结

临时任务要在断开 ssh 后继续跑：`nohup 命令 > 日志 2>&1 &`。

## 135 ★★&nbsp;&nbsp;bg：让暂停的作业在后台继续运行

> 级别：★★ 中级 · 来源：bash 内建命令

### 1. 作用

在终端里启动一个前台程序后，它会占住终端。这时按 `Ctrl+Z` 可以把它**暂停**，回到提示符；再输入 `bg`，它就在**后台**继续运行，终端可以干别的事。

典型场景：直接执行了一个要跑很久的命令，忘了在末尾加 `&`。不用结束重来，`Ctrl+Z` 再 `bg` 即可。

### 2. 基本格式

```bash
bg [%作业号]
```

不写作业号时，处理最近的那一个。作业号用 [jobs](#cmd-jobs) 查看。

### 3. 常用示例

```bash
tar -czf backup.tar.gz /var/www      # 跑起来后发现要很久
# 按 Ctrl+Z
[1]+  Stopped                 tar -czf backup.tar.gz /var/www
bg
[1]+ tar -czf backup.tar.gz /var/www &
```

> ⚠️ 本页未实机验证：`Ctrl+Z` 需要真实终端，测试环境的 Shell 没有作业控制。上面的提示为 bash 的标准输出格式。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 程序放到后台后，屏幕上还在不停地输出 | 后台程序的输出仍然显示在终端上 | 启动时就重定向输出 |
| 后台运行的程序在关闭终端后也停了 | bg 不能防止 HUP 信号 | 再执行 `disown`，见 [disown](#cmd-disown) |

### 5. 一句话总结

忘了加 `&`：`Ctrl+Z` 暂停，`bg` 转到后台。

<a id="cmd-jobs"></a>

## 137 ★★&nbsp;&nbsp;jobs：查看当前终端的作业

> 级别：★★ 中级 · 来源：bash 内建命令

### 1. 作用

`jobs` 列出当前终端里用 `&` 放到后台、或者用 `Ctrl+Z` 暂停的作业，以及它们的状态。作业号（`%1`、`%2`）可以用在 kill、bg、fg 里。

jobs 只管**当前终端**启动的程序，看不到其他终端或系统服务的进程（那些用 ps 查）。

### 2. 基本格式

```bash
jobs [-l]
```

| 参数 | 作用 |
|---|---|
| `-l` | 同时显示 PID |
| `-p` | 只显示 PID |

### 3. 常用示例

```
$ jobs
[1]   Running                    sleep 600 &
[2]-  Terminated                 sleep 601
[3]+  Terminated                 python3 -c "import time; time.sleep(600)"

$ jobs -l
[1]+    35 Running                    sleep 600 &

$ kill %1; sleep 0.2; jobs
[1]+  Terminated                 sleep 600
```

| 标记 | 含义 |
|---|---|
| `+` | 当前作业，bg、fg 不写编号时处理它 |
| `-` | 上一个作业 |
| Running / Stopped / Terminated / Done | 运行中 / 已暂停 / 已被结束 / 已正常完成 |

已结束的作业只显示一次，再执行 jobs 就不再出现。

### 4. 一句话总结

`jobs -l` 看后台作业，用 `%编号` 去 kill、bg、fg。

<a id="cmd-disown"></a>

## 138 ★★&nbsp;&nbsp;disown：让作业脱离当前终端

> 级别：★★ 中级 · 来源：bash 内建命令

### 1. 作用

`disown` 把一个作业从当前 Shell 的作业表里移除。移除之后，关闭终端时 Shell 不会再给它发 HUP 信号，它就能继续运行。

和 [nohup](#cmd-nohup) 的区别：nohup 要在**启动时**加；disown 用于**已经启动**的程序，事后补救。

### 2. 基本格式

```bash
disown [%作业号]
disown -h %作业号     # 保留在作业表里，但关闭终端时不发 HUP
```

### 3. 常用示例

```
$ sleep 500 &
[3] 71

$ disown %3

$ jobs

$ pgrep -a "^sleep"
71 sleep 500
```

disown 之后，jobs 里已经看不到它，但进程（71）还在运行。

事后补救的完整步骤：

```bash
./long-task.sh        # 跑起来了才想起来没用 nohup
# Ctrl+Z
bg
disown
exit                  # 可以放心退出 ssh
```

> ⚠️ 最后一段的 `Ctrl+Z` 部分未实机验证。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| disown 后程序继续运行，但它往终端写输出时出错退出 | 终端已经关闭，写输出失败 | 启动时就把输出重定向到文件 |

### 5. 一句话总结

已经跑起来的程序要在退出后继续：`bg` 后再 `disown`。

## 141 ★★&nbsp;&nbsp;lsof：查看进程打开了哪些文件和端口

> 级别：★★ 中级 · 软件包：`lsof`

### 1. 作用

`lsof`（list open files）列出进程打开的文件。在 Linux 里，网络连接、管道、设备也都算文件，所以 lsof 能回答这些问题：

- 8080 端口被哪个进程占了？
- 删掉了大日志，磁盘空间为什么没释放？
- U 盘卸载提示 busy，是谁在用？

查看其他用户的进程需要 sudo。

### 2. 基本格式

```bash
sudo lsof [参数]
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-i :端口` | 谁在使用这个端口 |
| `-i -P -n` | 所有网络连接，端口和 IP 用数字显示 |
| `-p PID` | 某个进程打开的所有文件 |
| `-u 用户` | 某个用户打开的文件 |
| `-c 名字` | 某个程序打开的文件 |
| `+D 目录` | 谁在使用这个目录下的文件 |
| `+L1` | 已被删除但仍被占用的文件 |

### 4. 常用示例

#### 4.1 端口被谁占用

先用 python 在 18080 端口启动一个网页服务：

```
$ lsof -i :18080
COMMAND PID USER FD   TYPE   DEVICE SIZE/OFF NODE NAME
python3  35  tom 4u  IPv4 12667263      0t0  TCP *:18080 (LISTEN)
```

程序启动报 `Address already in use`，就用这条找出是谁占了端口。

#### 4.2 删了文件，空间不释放

```
$ sudo lsof +L1
COMMAND PID USER FD   TYPE DEVICE SIZE/OFF NLINK NODE NAME
bash     29  tom 5w   REG  0,118        5     0   16 /home/tom/demo/held.log (deleted)
```

`(deleted)` 表示文件已经删除，但 PID 29 还开着它，所以空间没有释放。重启这个进程，或者让它重新打开日志文件，空间就回来了。

#### 4.3 一个进程打开了什么

```
$ lsof -p 29 | head -5
COMMAND PID USER  FD   TYPE DEVICE SIZE/OFF      NODE NAME
bash     29  tom cwd    DIR  0,118      200         6 /home/tom/demo
bash     29  tom rtd    DIR    7,1     4096 201326726 /
bash     29  tom txt    REG    7,1  1540520 201459519 /usr/bin/bash
bash     29  tom mem    REG    7,1  2186512 201457080 /usr/lib/x86_64-linux-gnu/libc.so.6
```

| FD 列 | 含义 |
|---|---|
| `cwd` | 当前工作目录 |
| `txt` | 程序文件本身 |
| `mem` | 加载的库 |
| `数字+r/w/u` | 打开的文件，r 读、w 写、u 读写 |

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `lsof -i :80` 什么都没输出，但端口确实被占用 | 端口属于 root 的进程，普通用户看不到 | 加 `sudo` |
| lsof 执行很慢 | 默认会把 IP 反查成主机名 | 加 `-n -P` |
| 只想看端口占用 | lsof 功能多但慢 | 用 `ss -tlnp`，见 [ss](10-网络和远程连接.md#cmd-ss) |

### 6. 一句话总结

端口被占 `lsof -i :端口`，空间不释放 `lsof +L1`，卸载 busy `lsof +D 目录`。
