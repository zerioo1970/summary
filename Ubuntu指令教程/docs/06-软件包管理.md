## 012 ★★★&nbsp;&nbsp;apt：安装、升级、卸载软件

> 级别：★★★ 初级 · 软件包：`apt`（Ubuntu 26.04 自带 3.2 版）

### 1. 作用

`apt` 是 Ubuntu 的软件包管理工具。它从 Ubuntu 官方软件源下载软件，自动处理依赖关系（装 A 需要先装 B、C，apt 会一起装好）。装软件、打补丁、卸载软件，都用 apt。

软件源的地址写在 `/etc/apt/sources.list.d/ubuntu.sources` 里。apt 本地保存了一份“软件源里有哪些包、什么版本”的清单，`apt update` 就是刷新这份清单。

### 2. 基本格式

```bash
sudo apt 子命令 [包名...]
```

除了 `search`、`show`、`list` 这类只读查询，其他子命令都要加 sudo。

### 3. 常用子命令

| 子命令 | 作用 |
|---|---|
| `update` | 刷新软件包清单（不安装任何东西） |
| `upgrade` | 把已安装的软件升级到最新版本 |
| `install 包名` | 安装软件 |
| `remove 包名` | 卸载软件，保留配置文件 |
| `purge 包名` | 卸载软件，连配置文件一起删除 |
| `autoremove` | 删除当初作为依赖装进来、现在已经没用的包 |
| `search 关键词` | 搜索软件包 |
| `show 包名` | 查看包的详细信息 |
| `list --installed` | 列出已安装的包 |
| `list --upgradable` | 列出可以升级的包 |

常用参数：

| 参数 | 作用 |
|---|---|
| `-y` | 自动回答“是”，不再询问 |
| `--names-only` | 和 search 一起用，只在包名里搜索 |
| `-s` | 模拟执行，只显示会做什么，不真的执行 |

### 4. 常用示例

> 以下输出在 Ubuntu 26.04.1 实测，软件包版本号和数量会随软件源更新而变化。

#### 4.1 `apt update`：刷新清单

```
$ sudo apt update
Hit:1 http://security.ubuntu.com/ubuntu resolute-security InRelease
Hit:2 http://archive.ubuntu.com/ubuntu resolute InRelease
Hit:3 http://archive.ubuntu.com/ubuntu resolute-updates InRelease
Hit:4 http://archive.ubuntu.com/ubuntu resolute-backports InRelease
Reading package lists...
Building dependency tree...
Reading state information...
20 packages can be upgraded. Run 'apt list --upgradable' to see them.
```

`resolute` 是 Ubuntu 26.04 的代号（Resolute Raccoon）。装软件、升级之前，先执行一次 update。

#### 4.2 `apt list --upgradable`：看哪些可以升级

```
$ apt list --upgradable
Listing...
gnu-coreutils/resolute-updates,resolute-security 9.7-3ubuntu2.1 amd64 [upgradable from: 9.7-3ubuntu2]
gpgv/resolute-updates,resolute-security 2.4.8-4ubuntu3.1 amd64 [upgradable from: 2.4.8-4ubuntu3]
...（共 20 行，此处只列前两行）
```

#### 4.3 `apt install`：安装软件

```
$ sudo apt install cowsay
Solving dependencies...
Upgrading:
  perl-base

Installing:
  cowsay

Installing dependencies:
  libgdbm-compat4t64  libtext-charwidth-perl  perl-modules-5.40
  libperl5.40         perl

Suggested packages:
  filters     libterm-readline-gnu-perl     libtap-harness-archive-perl
  cowsay-off  | libterm-readline-perl-perl
  perl-doc    make

Summary:
  Upgrading: 1, Installing: 6, Removing: 0, Not Upgrading: 19
  Download size: 10.2 MB
  Space needed: 51.5 MB / 91.9 GB available

Continue? [Y/n]
```

apt 3.x 的输出按“升级 / 安装 / 依赖 / 建议”分块显示，最后的 Summary 告诉你一共改动多少包、要下载多少。按回车（默认 Y）开始安装。加 `-y` 就不会停下来询问。

软件已经装过时：

```
$ sudo apt install tree
tree is already the newest version (2.3.1-1).
Solving dependencies...
Summary:
  Upgrading: 0, Installing: 0, Removing: 0, Not Upgrading: 20
```

#### 4.4 `apt search` 和 `apt show`：先查再装

```
$ apt search --names-only "^htop"
Sorting...
Full Text Search...
htop/resolute,now 3.4.1-5build2 amd64 [installed]
  interactive processes viewer

$ apt show tree
Package: tree
Version: 2.3.1-1
Priority: optional
Section: universe/utils
Origin: Ubuntu
...
```

不加 `--names-only` 时，apt 会在包的描述里搜索，结果往往有几百条。

#### 4.5 `remove`、`purge`、`autoremove`：卸载

```
$ sudo apt remove cowsay
Solving dependencies...
The following package was automatically installed and is no longer required:
  libtext-charwidth-perl
Use 'apt autoremove' to remove it.

REMOVING:
  cowsay

Summary:
  Upgrading: 0, Installing: 0, Removing: 1, Not Upgrading: 19
  Freed space: 89.1 kB

$ sudo apt autoremove
REMOVING:
  libtext-charwidth-perl

Summary:
  Upgrading: 0, Installing: 0, Removing: 1, Not Upgrading: 19
  Freed space: 43.0 kB
```

remove 只删程序，`/etc` 下的配置文件还在，重装后配置不丢。要彻底清除用 `sudo apt purge 包名`。

#### 4.6 日常打补丁

```bash
sudo apt update && sudo apt upgrade
```

`&&` 表示前一条成功了才执行后一条。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `Error: Unable to locate package xxx` | 包名写错，或者还没执行过 `apt update` | 先 `sudo apt update`，再用 `apt search` 查准包名 |
| 在脚本里用 apt，输出多了一行 `WARNING: apt does not have a stable CLI interface. Use with caution in scripts.` | apt 的输出格式面向人，可能随版本变化 | 脚本里改用 [apt-get](#cmd-apt-get)，例如 `sudo apt-get install -y 包名` |
| 报 `Could not get lock /var/lib/dpkg/lock-frontend` | 另一个 apt 进程（常见的是开机后的自动更新）正在运行 | 等几分钟再试。不要删除锁文件 |
| 卸载后重装，软件还是用旧配置 | `remove` 保留了配置文件 | 想恢复默认配置，用 `purge` 卸载后再装 |
| `Error: Unable to acquire the dpkg frontend lock (/var/lib/dpkg/lock-frontend), are you root?` | 安装、卸载需要管理员权限，普通用户打不开锁文件 | 加 `sudo` |

### 6. 一句话总结

先 `update` 再 `install`；`remove` 留配置、`purge` 全删；脚本里用 `apt-get`。

## 063 ★★★&nbsp;&nbsp;apt-get：脚本里用的软件包管理命令

> 级别：★★★ 初级 · 软件包：`apt`

### 1. 作用

`apt-get` 和 [apt](#cmd-apt) 做的是同一件事：安装、升级、卸载软件。区别在于用途：

| | apt | apt-get |
|---|---|---|
| 面向 | 人在终端里操作 | 脚本、自动化部署、Dockerfile |
| 输出 | 有颜色、进度条，格式可能随版本调整 | 格式稳定，多年不变 |
| 在脚本里用 | 会提示 `WARNING: apt does not have a stable CLI interface` | 不会提示 |

日常手动操作用 apt，写进脚本的一律用 apt-get。

### 2. 基本格式

```bash
sudo apt-get [参数] 子命令 [包名...]
```

### 3. 常用子命令和参数

| 子命令 | 作用 |
|---|---|
| `update` | 刷新软件包清单 |
| `upgrade` | 升级已安装的包 |
| `install 包名` | 安装 |
| `remove 包名` | 卸载，保留配置 |
| `purge 包名` | 卸载，删除配置 |
| `autoremove` | 删除不再需要的依赖 |
| `clean` | 清空已下载的安装包缓存（/var/cache/apt/archives） |
| `download 包名` | 只下载 .deb 文件到当前目录，不安装 |

| 参数 | 作用 |
|---|---|
| `-y` | 自动回答“是” |
| `-q` / `-qq` | 减少输出 / 几乎不输出 |
| `--no-install-recommends` | 不安装“推荐”的附加包，只装必需的依赖 |
| `-s` | 模拟执行 |

### 4. 常用示例

以下以 root 身份执行（普通用户加 sudo）。

#### 4.1 脚本里的标准写法

```bash
sudo apt-get update
sudo DEBIAN_FRONTEND=noninteractive apt-get install -y -q nginx
```

`DEBIAN_FRONTEND=noninteractive` 让安装过程中不弹出任何配置问答，全部用默认值。自动化脚本里不加它，遇到需要回答问题的包就会卡住。

#### 4.2 `--no-install-recommends`：装得更少

```
$ apt-get install -y --no-install-recommends -q fortune-mod
...
The following additional packages will be installed:
  librecode3
Recommended packages:
  fortunes-min | fortune-cookie-db
The following NEW packages will be installed:
  fortune-mod librecode3
```

“推荐”的包（Recommended）没有装。做 Docker 镜像、精简服务器时常用这个参数控制体积。

#### 4.3 `download`：只下载安装包

```
$ apt-get download tree
Get:1 http://archive.ubuntu.com/ubuntu resolute/universe amd64 tree amd64 2.3.1-1 [53.5 kB]
Fetched 53.5 kB in 0s (166 kB/s)

$ ls *.deb
tree_2.3.1-1_amd64.deb
```

给不能上网的内网服务器装软件时，先在能上网的机器上下载，再拷过去用 [dpkg](#cmd-dpkg) 安装。

#### 4.4 `clean`：释放缓存空间

```
$ apt-get clean; ls /var/cache/apt/archives
lock
partial
```

下载过的 .deb 文件都被删除了。/var 分区紧张时可以清一下。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 脚本执行到 apt-get install 就停住不动 | 等待输入 `Y`，或者弹出了配置问答 | 加 `-y`，并设置 `DEBIAN_FRONTEND=noninteractive` |
| Dockerfile 里 `apt-get install` 报找不到包 | 镜像里的软件包清单是空的 | 在同一个 RUN 里先 `apt-get update`：`RUN apt-get update && apt-get install -y 包名` |
| 自动化安装时输出一大段 `debconf: unable to initialize frontend: Dialog` | 没有终端，debconf 尝试几种问答界面都失败，最后改用默认值 | 这些是提示不是错误；加 `DEBIAN_FRONTEND=noninteractive` 就不会出现 |

### 6. 一句话总结

脚本里用 `apt-get install -y`，配上 `DEBIAN_FRONTEND=noninteractive`。

## 064 ★★★&nbsp;&nbsp;dpkg：安装和查询 .deb 包

> 级别：★★★ 初级 · 软件包：`dpkg`

### 1. 作用

`dpkg` 是 Ubuntu 最底层的软件包工具，apt 在下载完安装包之后，实际就是调用 dpkg 来安装的。日常用 dpkg 做两类事：

- 安装从网上下载的单个 `.deb` 文件（比如某些厂商提供的客户端）；
- 查询：装了哪些包、某个包装了哪些文件、某个文件属于哪个包。

dpkg 不会自动下载依赖，这是它和 apt 最大的区别。

### 2. 基本格式

```bash
sudo dpkg -i 文件.deb       # 安装
dpkg -l [包名]              # 查询
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-i 文件.deb` | 安装 |
| `-r 包名` | 卸载，保留配置 |
| `-P 包名` | 卸载并删除配置 |
| `-l [模式]` | 列出已安装的包 |
| `-s 包名` | 查看包的状态和详情 |
| `-L 包名` | 列出这个包装了哪些文件 |
| `-S 文件路径` | 查这个文件属于哪个包 |
| `-c 文件.deb` | 查看 .deb 文件里有什么（不安装） |

### 4. 常用示例

以下以 root 身份执行；只查询的命令普通用户也能执行。

#### 4.1 `-l`：查是否装了某个包

```
$ dpkg -l tree htop
+-- Desired=Unknown/Install/Remove/Purge/Hold
|+- Status=Not/Inst/Conf-files/Unpacked/halF-conf/Half-inst/trig-aWait/Trig-pend
||+ Err?=(none)/Reinst-required (Status,Err: uppercase=bad)
||| Name           Version       Architecture Description
+++-==============-=============-============-=============================================
ii  htop           3.4.1-5build2 amd64        interactive processes viewer
ii  tree           2.3.1-1       amd64        displays an indented directory tree, in color
```

第一列的 `ii` 表示“期望安装，已经安装”，是正常状态。`rc` 表示已卸载但配置文件还在。

#### 4.2 `-l` 加通配符

```
$ dpkg -l "*coreutils*"
...
||| Name                  Version                     Architecture Description
+++-=====================-===========================-============-==========================================
ii  coreutils             9.5-1ubuntu2+0.0.0~ubuntu25 all          coreutils meta package
un  coreutils-from        <none>                      <none>       (no description available)
un  coreutils-from-gnu    <none>                      <none>       (no description available)
ii  coreutils-from-uutils 0.0.0~ubuntu25              all          coreutils from the uutils project
ii  gnu-coreutils         9.7-3ubuntu2.1              amd64        GNU core utilities
ii  rust-coreutils        0.10.0-1ubuntu2~26.04.1     amd64        Universal coreutils utils, written in Rust
```

从这里可以看出：Ubuntu 26.04 的基础命令默认来自 Rust 版（`coreutils-from-uutils`、`rust-coreutils`），GNU 版（`gnu-coreutils`）也装着。

#### 4.3 `-S`：这个文件是哪个包装的

```
$ dpkg -S /usr/bin/tree
tree: /usr/bin/tree

$ dpkg -S /usr/bin/ls
coreutils-from-uutils: /usr/bin/ls
```

#### 4.4 `-L`：这个包装了哪些文件

```
$ dpkg -L tree | head -6
/.
/usr
/usr/bin
/usr/bin/tree
/usr/share
/usr/share/doc
```

装完一个软件不知道配置文件在哪，用 `dpkg -L 包名 | grep etc`。

#### 4.5 `-i`：安装 .deb 文件

```
$ dpkg -i tree_2.3.1-1_amd64.deb
(Reading database ... 16848 files and directories currently installed.)
Preparing to unpack tree_2.3.1-1_amd64.deb ...
Unpacking tree (2.3.1-1) over (2.3.1-1) ...
Setting up tree (2.3.1-1) ...
Processing triggers for man-db (2.13.1-1build1) ...
```

#### 4.6 `-r`：卸载

```
$ dpkg -r tree
(Reading database ... 16848 files and directories currently installed.)
Removing tree (2.3.1-1) ...
Processing triggers for man-db (2.13.1-1build1) ...

$ dpkg -l tree
dpkg-query: no packages found matching tree
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `dpkg -i` 报 `dependency problems`，软件装了一半 | dpkg 不会自动安装依赖 | 执行 `sudo apt-get install -f` 自动补齐依赖；或者一开始就用 `sudo apt install ./文件.deb`（注意 `./`），apt 会处理依赖 |
| `apt install 文件.deb` 报找不到包 | 没写 `./`，apt 把它当成了包名 | 写成 `sudo apt install ./文件.deb` |
| `dpkg -l` 里有很多 `rc` 状态的包 | 卸载时用了 remove，配置文件留着 | 不需要的话 `sudo apt purge 包名` 清掉 |

### 6. 一句话总结

装 .deb 用 `sudo apt install ./文件.deb`；查询用 `dpkg -l`、`-L`、`-S`。

## 065 ★★★&nbsp;&nbsp;snap：管理 Snap 软件包

> 级别：★★★ 初级 · 软件包：`snapd`（Ubuntu 桌面版和服务器版默认安装）

### 1. 作用

`snap` 管理 Snap 格式的软件包。Snap 是 Canonical（Ubuntu 的开发公司）推出的软件分发格式：每个 snap 自带运行所需的依赖库，在沙箱里运行，并且会**自动更新**。

Ubuntu 上有些软件只提供或优先提供 snap 版，例如 Firefox、Thunderbird、LXD、MicroK8s。Ubuntu 桌面版的“应用中心”装的软件也大多是 snap。

| | apt（.deb） | snap |
|---|---|---|
| 依赖 | 和系统共用库 | 每个软件自带 |
| 更新 | 手动 `apt upgrade` | 后台自动更新 |
| 体积 | 小 | 大 |
| 启动速度 | 快 | 第一次启动较慢 |

### 2. 基本格式

```bash
snap 子命令 [参数] [软件名]
```

修改类的子命令（install、remove、refresh）要加 sudo。

### 3. 常用子命令

| 子命令 | 作用 |
|---|---|
| `find 关键词` | 在 Snap 商店里搜索 |
| `info 软件名` | 查看详情和可用的版本通道 |
| `install 软件名` | 安装 |
| `list` | 列出已安装的 snap |
| `refresh [软件名]` | 立即更新 |
| `remove 软件名` | 卸载 |
| `services` | 查看 snap 提供的后台服务 |

常用参数：

| 参数 | 作用 |
|---|---|
| `--classic` | 以“经典模式”安装，不受沙箱限制。开发工具（如 VS Code、各种 SDK）通常需要 |
| `--channel=通道` | 指定版本通道，如 `--channel=1.30/stable` |

### 4. 常用示例

> ⚠️ 本页未实机验证：snapd 需要 systemd 作为系统的第一个进程才能运行，测试环境不满足。命令写法为 snap 长期稳定的用法。

```bash
snap find postman                  # 搜索
snap info code                     # 看详情和通道
sudo snap install code --classic   # 安装 VS Code（需要经典模式）
snap list                          # 已安装列表
sudo snap refresh                  # 立即更新所有 snap
sudo snap remove code              # 卸载
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 安装时报错，提示需要 `--classic` | 这个软件需要访问沙箱外的文件 | 加 `--classic` |
| `df -h` 里出现一大堆 `/dev/loop` 设备 | 每个 snap 都以只读镜像的方式挂载 | 这是正常的。`df -h -x squashfs` 可以不显示它们 |
| 磁盘被 snap 占了好几个 GB | snap 默认保留每个软件的旧版本 | `sudo snap set system refresh.retain=2` 只保留 2 个版本 |
| snap 软件读不到 `/mnt` 或其他目录下的文件 | 沙箱限制了文件访问范围 | 用 `snap connections 软件名` 查看权限，必要时改用 apt 版本 |

### 6. 一句话总结

apt 找不到或官方推荐 snap 时用 `sudo snap install`，开发工具加 `--classic`。

<a id="cmd-apt-cache"></a>

## 179 ★★&nbsp;&nbsp;apt-cache：查询软件包信息

> 级别：★★ 中级 · 软件包：`apt`

### 1. 作用

`apt-cache` 只查询、不修改：一个软件包在软件源里有哪些版本、当前装的是哪个、它依赖谁、谁依赖它。安装或升级之前先查清楚，避免装错版本或者误删依赖。它不需要 sudo。

### 2. 基本格式

```bash
apt-cache 子命令 包名
```

### 3. 常用子命令

| 子命令 | 作用 |
|---|---|
| `policy 包名` | 已安装版本、候选版本、每个版本来自哪个软件源 |
| `madison 包名` | 简洁地列出所有可用版本 |
| `show 包名` | 详细信息（同 `apt show`） |
| `depends 包名` | 它依赖哪些包 |
| `rdepends 包名` | 哪些包依赖它（加 `--installed` 只看已安装的） |
| `search 关键词` | 搜索（加 `--names-only` 只搜包名） |

### 4. 常用示例

#### 4.1 `policy`：装没装、会装哪个版本

```
$ apt-cache policy nginx
nginx:
  Installed: (none)
  Candidate: 1.28.3-2ubuntu1.12
  Version table:
     1.28.3-2ubuntu1.12 500
        500 http://archive.ubuntu.com/ubuntu resolute-updates/main amd64 Packages
        500 http://security.ubuntu.com/ubuntu resolute-security/main amd64 Packages
     1.28.3-2ubuntu1 500
        500 http://archive.ubuntu.com/ubuntu resolute/main amd64 Packages
```

| 内容 | 含义 |
|---|---|
| Installed | 已安装的版本，`(none)` 表示没装 |
| Candidate | 执行 `apt install` 时会装的版本 |
| Version table | 所有可用版本；`500` 是优先级，`resolute-updates` 是来源 |

加了第三方源（PPA、官方仓库）后，用 policy 确认 Candidate 是不是来自你期望的那个源。

#### 4.2 `madison`：所有可用版本

```
$ apt-cache madison curl
      curl | 8.18.0-1ubuntu2.8 | http://archive.ubuntu.com/ubuntu resolute-updates/main amd64 Packages
      curl | 8.18.0-1ubuntu2.8 | http://security.ubuntu.com/ubuntu resolute-security/main amd64 Packages
      curl | 8.18.0-1ubuntu2 | http://archive.ubuntu.com/ubuntu resolute/main amd64 Packages
```

要装指定版本：`sudo apt install curl=8.18.0-1ubuntu2`。

#### 4.3 依赖关系

```
$ apt-cache depends tree
tree
  Depends: libc6

$ apt-cache rdepends --installed libncurses6
libncurses6
Reverse Depends:
  iftop
  libaa1
```

卸载一个库之前，用 `rdepends --installed` 看会影响哪些已安装的软件。

#### 4.4 搜索

```
$ apt-cache search --names-only "^redis" | head -3
redis - Persistent key-value database with network interface (metapackage)
redis-module-knot - Redis module for Knot DNS
redis-redisearch - Full-text and secondary search index engine module for Redis
```

### 5. 一句话总结

装之前 `apt-cache policy` 看版本和来源，删之前 `rdepends --installed` 看影响。

<a id="cmd-apt-mark"></a>

## 180 ★★&nbsp;&nbsp;apt-mark：锁定版本、标记安装方式

> 级别：★★ 中级 · 软件包：`apt`

### 1. 作用

`apt-mark` 给软件包做标记，主要两个用途：

- **hold（锁定）**：被锁定的包在 `apt upgrade` 时不会升级。生产环境的数据库、Docker、内核等不希望被意外升级时使用。
- **auto / manual**：标记包是“作为依赖自动装的”还是“你手动装的”。`apt autoremove` 只会删除 auto 且不再被依赖的包。

### 2. 基本格式

```bash
sudo apt-mark 子命令 包名...
```

### 3. 常用子命令

| 子命令 | 作用 |
|---|---|
| `hold` / `unhold` | 锁定 / 解锁 |
| `showhold` | 列出被锁定的包 |
| `manual` / `auto` | 标记为手动安装 / 自动安装 |
| `showmanual` / `showauto` | 列出手动 / 自动安装的包 |

### 4. 常用示例

以下以 root 身份执行。

```
$ apt-mark hold tree
tree set on hold.

$ apt-mark showhold
tree

$ apt-mark unhold tree
Canceled hold on tree.
```

锁定期间执行 `apt upgrade`，被锁定的包会出现在 “Not Upgrading” 里。

```
$ apt-mark auto tree
tree set to automatically installed.

$ apt-mark manual tree
tree set to manually installed.
```

`apt autoremove` 提示要删除一个你还在用的软件时，用 `apt-mark manual` 把它标记为手动安装，就不会被删了。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 锁定了一个包，结果它的安全更新也一直没装 | hold 会阻止所有升级 | 定期用 `apt-mark showhold` 检查，有安全公告时评估后手动升级 |
| `apt autoremove` 删掉了自己需要的软件 | 它当初是作为依赖装的，被标记为 auto | 用 `apt-mark manual 包名` 标记，再重新安装 |

### 6. 一句话总结

不想被升级就 `apt-mark hold`，不想被 autoremove 就 `apt-mark manual`。

## 181 ★★&nbsp;&nbsp;add-apt-repository：添加软件源或 PPA

> 级别：★★ 中级 · 软件包：`software-properties-common`

### 1. 作用

`add-apt-repository` 往系统里添加一个软件源，最常见的是 PPA（Personal Package Archive，Launchpad 上由个人或团队维护的软件源）。官方源里的版本太旧、需要更新版本的软件（如 git、PHP、某些驱动）时用它。它会自动导入签名密钥，并在 `/etc/apt/sources.list.d/` 下生成配置文件。

### 2. 基本格式

```bash
sudo add-apt-repository ppa:用户/名称
sudo add-apt-repository --remove ppa:用户/名称
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-y` | 不询问，直接添加 |
| `-r` / `--remove` | 删除这个源 |
| `-n` | 添加后不自动执行 apt update |

### 4. 常用示例

以下以 root 身份执行。

#### 4.1 添加 git 官方维护的 PPA

```
$ add-apt-repository -y ppa:git-core/ppa
...
For release candidates, go to https://launchpad.net/~git-core/+archive/candidate .
More info: https://launchpad.net/~git-core/+archive/ubuntu/ppa
Adding repository.

$ ls /etc/apt/sources.list.d/
git-core-ubuntu-ppa-resolute.sources
ubuntu.sources
```

生成的配置文件是 deb822 格式（`.sources`），签名密钥直接写在文件里：

```
$ cat /etc/apt/sources.list.d/git-core-ubuntu-ppa-resolute.sources
Types: deb
URIs: https://ppa.launchpadcontent.net/git-core/ppa/ubuntu/
Suites: resolute
Components: main
Signed-By:
 -----BEGIN PGP PUBLIC KEY BLOCK-----
...
```

添加后执行 `sudo apt install git` 就会装上 PPA 里的新版本。用 `apt-cache policy git` 可以确认版本来源。

#### 4.2 删除

```
$ add-apt-repository -y --remove ppa:git-core/ppa
...
Removing entry from /etc/apt/sources.list.d/git-core-ubuntu-ppa-resolute.sources
```

删除源不会把已经装上的新版本降回去。

#### 4.3 Ubuntu 自己的源长什么样

```
$ cat /etc/apt/sources.list.d/ubuntu.sources
Types: deb
URIs: http://archive.ubuntu.com/ubuntu/
Suites: resolute resolute-updates resolute-backports
Components: main universe restricted multiverse
Signed-By: /usr/share/keyrings/ubuntu-archive-keyring.gpg
...
```

国内服务器下载慢时，可以把 URIs 改成国内镜像站的地址。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 加了 PPA 后 `apt update` 报 404 | 这个 PPA 没有为 26.04（resolute）构建软件包 | 到 Launchpad 页面确认支持的版本，不支持就删除这个源 |
| 网上教程用 `apt-key add` 导入密钥，报命令不存在或已弃用 | apt-key 已经淘汰 | 用 add-apt-repository，或按软件官方说明把密钥放到 `/etc/apt/keyrings/` |
| 系统大版本升级后第三方源全部失效 | 升级时第三方源会被禁用 | 升级后逐个确认新版本是否支持，再重新启用 |
| 来路不明的 PPA 装了有问题的软件 | PPA 由个人维护，没有经过 Ubuntu 官方审核 | 只用软件官方维护的 PPA |

### 6. 一句话总结

需要新版本时 `add-apt-repository ppa:...`，用 `apt-cache policy` 确认来源，只加可信的源。

## 182 ★★&nbsp;&nbsp;update-alternatives：在同一功能的多个程序之间切换

> 级别：★★ 中级 · 软件包：`dpkg`

### 1. 作用

同一个功能可以由多个程序提供：`editor` 可以是 nano 或 vim，`java` 可以是 JDK 17 或 21，`python` 可以指向不同版本。Ubuntu 用“alternatives 系统”管理：`/usr/bin/editor` 是一个链接，指向 `/etc/alternatives/editor`，再指向真正的程序。`update-alternatives` 用来查看和切换这个指向。

### 2. 基本格式

```bash
update-alternatives --list 名称            # 有哪些候选
update-alternatives --display 名称         # 当前状态
sudo update-alternatives --config 名称     # 交互式选择
sudo update-alternatives --set 名称 路径   # 直接指定
sudo update-alternatives --auto 名称       # 恢复自动（按优先级选）
```

### 3. 常用示例

以下以 root 身份执行。

#### 3.1 查看候选和当前选择

```
$ update-alternatives --list editor
/bin/nano
/usr/bin/vim.basic
/usr/bin/vim.tiny

$ update-alternatives --display editor | head -3
editor - auto mode
  link best version is /bin/nano
  link currently points to /bin/nano
```

`auto mode` 表示按优先级自动选择，nano 优先级最高。

#### 3.2 交互式切换

```
$ update-alternatives --config editor
There are 3 choices for the alternative editor (providing /usr/bin/editor).

  Selection    Path                Priority   Status
------------------------------------------------------------
  0            /bin/nano            40        auto mode
  1            /bin/nano            40        manual mode
* 2            /usr/bin/vim.basic   30        manual mode
  3            /usr/bin/vim.tiny    15        manual mode

Press <enter> to keep the current choice[*], or type selection number:
```

输入编号回车即可。`*` 标记当前的选择。

#### 3.3 脚本里直接指定

```bash
sudo update-alternatives --set editor /usr/bin/vim.basic
sudo update-alternatives --set java /usr/lib/jvm/java-21-openjdk-amd64/bin/java
```

> ⚠️ java 那一行未实机验证（测试环境没有安装 JDK），路径以 `update-alternatives --list java` 的输出为准。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 用 `ln -sf` 手动改了 /usr/bin/java，升级 JDK 后又被改回去 | 这些链接归 alternatives 管理 | 用 update-alternatives 切换 |
| 切换了 java，javac 还是旧版本 | java 和 javac 是两组独立的 alternatives | 两个都要切换；或用 JDK 包自带的 `update-java-alternatives` |
| 手动选择后，装了新版本也不会自动切换 | 进入了 manual mode | `sudo update-alternatives --auto 名称` |

### 5. 一句话总结

多版本切换用 `sudo update-alternatives --config 名称`，不要手动改链接。

## 183 ★★&nbsp;&nbsp;do-release-upgrade：升级到新的 Ubuntu 版本

> 级别：★★ 中级 · 软件包：`ubuntu-release-upgrader-core`

### 1. 作用

`do-release-upgrade` 把系统从一个 Ubuntu 版本升级到下一个版本，比如从 24.04 升级到 26.04。它会更换软件源、下载新版本的软件包、处理配置文件冲突。`apt upgrade` 只在当前版本内升级，跨大版本必须用它。

### 2. 基本格式

```bash
sudo do-release-upgrade [参数]
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-c` | 只检查有没有新版本可升级 |
| `-d` | 升级到开发版（不要在生产环境使用） |
| `-f DistUpgradeViewNonInteractive` | 非交互式升级 |

升级到哪种版本由 `/etc/update-manager/release-upgrades` 决定：

```
$ grep -E "^Prompt" /etc/update-manager/release-upgrades
Prompt=lts
```

| Prompt 值 | 含义 |
|---|---|
| `lts` | 只升级到下一个 LTS 版本（服务器推荐） |
| `normal` | 升级到任何新版本（包括每半年一个的非 LTS 版本） |
| `never` | 不提示升级 |

### 4. 常用示例

```
$ do-release-upgrade -c
...
There is no development version of an LTS available.
To upgrade to the latest non-LTS development release
set Prompt=normal in /etc/update-manager/release-upgrades.
```

26.04 已经是当前最新的 LTS，所以没有可以升级的 LTS 版本。

升级前的标准步骤：

```bash
sudo apt update && sudo apt full-upgrade   # 先把当前版本升到最新
sudo reboot                                 # 重启一次
sudo do-release-upgrade                     # 再升级大版本
```

> ⚠️ 实际的大版本升级未实机验证。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 新的 LTS 刚发布，do-release-upgrade 说没有新版本 | LTS 之间的升级要等到第一个小版本（如 26.04.1）发布后才开放 | 等 .1 版本发布；这是为了让早期问题先被修复 |
| 通过 ssh 升级到一半网络断了 | 升级过程中断可能导致系统损坏 | 在 tmux 或 screen 里执行；升级程序也会在 1022 端口额外启动一个 ssh 作为备用 |
| 升级后第三方源的软件不见了或报错 | 升级时第三方源被禁用 | 逐个确认是否支持新版本，再重新启用 |
| 生产服务器直接升级后应用起不来 | 新版本的软件（PHP、Python、OpenSSL 等）不兼容 | 先在测试机或快照上演练；做好完整备份 |

### 6. 一句话总结

升大版本用 `sudo do-release-upgrade`，先备份、先在 tmux 里、先升级完当前版本。

## 184 ★★&nbsp;&nbsp;unattended-upgrade：自动安装安全更新

> 级别：★★ 中级 · 软件包：`unattended-upgrades`

### 1. 作用

`unattended-upgrade` 在无人值守的情况下自动安装更新，默认只装**安全更新**。Ubuntu 服务器默认已经启用：每天自动刷新软件包清单，并自动安装安全补丁。命令本身一般不用手动执行，常用的是检查它的配置和模拟运行。

### 2. 配置文件

| 文件 | 作用 |
|---|---|
| `/etc/apt/apt.conf.d/20auto-upgrades` | 总开关：是否每天刷新清单、是否自动升级 |
| `/etc/apt/apt.conf.d/50unattended-upgrades` | 详细规则：允许哪些来源、是否自动重启、黑名单 |
| `/var/log/unattended-upgrades/` | 执行日志 |

```
$ cat /etc/apt/apt.conf.d/20auto-upgrades
APT::Periodic::Update-Package-Lists "1";
APT::Periodic::Unattended-Upgrade "1";

$ grep -A4 "Allowed-Origins" /etc/apt/apt.conf.d/50unattended-upgrades
Unattended-Upgrade::Allowed-Origins {
	"${distro_id}:${distro_codename}";
	"${distro_id}:${distro_codename}-security";
	// Extended Security Maintenance; doesn't necessarily exist for
	// every release and this system may not have it installed, but if
```

`"1"` 表示每 1 天执行一次。

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `--dry-run` | 模拟执行，不真正安装 |
| `-v` | 显示详细过程 |
| `-d` | 显示调试信息 |

### 4. 常用示例

```
$ sudo unattended-upgrade --dry-run -v
...
Starting unattended upgrades script
Allowed origins are: o=Ubuntu,a=resolute, o=Ubuntu,a=resolute-security, o=UbuntuESMApps,a=resolute-apps-security, o=UbuntuESM,a=resolute-infra-security
...
Option --dry-run given, *not* performing real actions
Packages that will be upgraded: gpgv libattr1 libc-bin libc-gconv-modules-extra libc6 libgcrypt20 libpam-modules libpam-modules-bin libpam-runtime libpam0g zlib1g
...
```

可以看到允许的来源和这次会升级哪些包。

常见的配置调整（在 50unattended-upgrades 里取消注释并修改）：

| 配置项 | 作用 |
|---|---|
| `Unattended-Upgrade::Package-Blacklist` | 不自动升级的包，如数据库 |
| `Unattended-Upgrade::Automatic-Reboot "true";` | 需要时自动重启 |
| `Unattended-Upgrade::Automatic-Reboot-Time "03:00";` | 自动重启的时间 |

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 刚开机执行 apt 提示 `Could not get lock` | 后台的自动更新正在运行 | 等它结束；用 `ps aux \| grep unattended` 查看 |
| 安全更新装了，但 `/var/run/reboot-required` 一直存在 | 内核等更新需要重启才生效，默认不自动重启 | 安排维护时间重启，或开启 Automatic-Reboot |

### 6. 一句话总结

Ubuntu 默认自动装安全更新，用 `unattended-upgrade --dry-run -v` 看它会做什么。

## 185 ★★&nbsp;&nbsp;flatpak：Flatpak 软件包管理

> 级别：★★ 中级 · 软件包：`flatpak`（需 `sudo apt install flatpak`）

### 1. 作用

Flatpak 是另一种跨发行版的桌面软件分发格式，和 [snap](#cmd-snap) 类似：软件自带依赖、在沙箱里运行。它的主要软件仓库是 Flathub。Ubuntu 默认用 snap，没有预装 Flatpak；有些桌面软件只在 Flathub 上提供，或者 Flathub 版本更新，才需要装它。

服务器上一般用不到 Flatpak。

### 2. 基本格式

```bash
flatpak 子命令 [参数]
```

### 3. 常用子命令

| 子命令 | 作用 |
|---|---|
| `remote-add` | 添加仓库（通常只需要添加一次 Flathub） |
| `search 关键词` | 搜索 |
| `install 仓库 应用ID` | 安装 |
| `list` | 已安装的应用 |
| `run 应用ID` | 运行 |
| `update` | 更新全部 |
| `uninstall 应用ID` | 卸载 |

### 4. 常用示例

```
$ sudo flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo

$ flatpak remotes
flathub	system

$ flatpak search gimp
GIMP User Manual	GIMP User Manual	org.gimp.GIMP.Manual	2.10	2.10	flathub
GNU Image Manipulation Program	High-end image creation and manipulation	org.gimp.GIMP	3.2.6	stable	flathub
Resynthesizer	Resynthesizer GIMP Plugins	org.gimp.GIMP.Plugin.Resynthesizer	3.0.1	3	flathub
```

第三列 `org.gimp.GIMP` 是应用 ID，安装和运行时都用它：

```bash
flatpak install flathub org.gimp.GIMP
flatpak run org.gimp.GIMP
```

> ⚠️ install 和 run 未实机验证（测试环境没有图形界面）。

### 5. 一句话总结

需要 Flathub 上的桌面软件时用 Flatpak，命令里用的是应用 ID。

<a id="cmd-dpkg-reconfigure"></a>

## 271 ★&nbsp;&nbsp;dpkg-reconfigure：重新配置已安装的软件包

> 级别：★ 高级 · 软件包：`debconf`

### 1. 作用

有些软件包在安装时会问几个问题（时区、语言、键盘布局、邮件服务器类型），答案由 debconf 系统记录下来。`dpkg-reconfigure` 让这个软件包重新问一遍，按新的答案重新生成配置。

最常见的用法：`sudo dpkg-reconfigure tzdata`（改时区）、`locales`（生成语言）、`keyboard-configuration`（键盘布局）。

### 2. 基本格式

```bash
sudo dpkg-reconfigure 包名
```

| 参数 | 作用 |
|---|---|
| `-f noninteractive` | 不提问，直接使用已记录的答案（配合 debconf-set-selections） |
| `-p 级别` | 只问优先级不低于该级别的问题，`-p low` 会问全部问题 |

### 3. 常用示例

交互式修改时区：

```bash
sudo dpkg-reconfigure tzdata
```

执行后会弹出文字菜单，先选地区（Asia），再选城市（Shanghai）。

> ⚠️ 交互菜单未实机录制。

非交互式修改（先用 [debconf-set-selections](#cmd-debconf-set-selections) 写好答案）：

```
$ echo "tzdata tzdata/Areas select Asia" | sudo debconf-set-selections
$ echo "tzdata tzdata/Zones/Asia select Shanghai" | sudo debconf-set-selections
$ sudo rm -f /etc/localtime /etc/timezone
$ sudo DEBIAN_FRONTEND=noninteractive dpkg-reconfigure tzdata
...
Local time is now:      Thu Oct 29 18:07:13 CST 2026.
Universal Time is now:  Thu Oct 29 10:07:13 UTC 2026.

$ ls -l /etc/localtime
lrwxrwxrwx 1 root root 33 Oct 29 18:07 /etc/localtime -> /usr/share/zoneinfo/Asia/Shanghai
```

tzdata 优先读取现有的 /etc/localtime，所以要先删掉它，新答案才会生效。改时区更简单的办法是 `timedatectl set-timezone`，这里是为了演示 debconf 的工作方式。

### 4. 一句话总结

安装时问过的问题想重答，用 `sudo dpkg-reconfigure 包名`。

<a id="cmd-dpkg-deb"></a>

## 272 ★&nbsp;&nbsp;dpkg-deb：查看和制作 .deb 包

> 级别：★ 高级 · 软件包：`dpkg`

### 1. 作用

`dpkg-deb` 直接操作 `.deb` 文件：查看包的元数据和文件清单、不安装只解压、以及把一个目录打包成 .deb。最后这一点很实用：把公司内部的小工具、脚本、配置做成 .deb，就能用 apt/dpkg 统一安装、升级和卸载，也方便放进内部软件源。

### 2. 基本格式

```bash
dpkg-deb -I 包.deb             # 元数据
dpkg-deb -c 包.deb             # 文件清单
dpkg-deb -x 包.deb 目录        # 解压文件，不安装
dpkg-deb --build 目录 包.deb   # 打包
```

### 3. 常用示例

#### 3.1 查看包信息

```
$ dpkg-deb -I tree_2.3.1-1_amd64.deb
 new Debian package, version 2.0.
 size 53550 bytes: control archive=737 bytes.
     580 bytes,    14 lines      control
     367 bytes,     6 lines      md5sums
 Package: tree
 Version: 2.3.1-1
 Architecture: amd64
 Maintainer: Ubuntu Developers <ubuntu-devel-discuss@lists.ubuntu.com>
 Original-Maintainer: Florian Ernst <florian@debian.org>
 Installed-Size: 122
 Depends: libc6 (>= 2.38)
...
```

#### 3.2 自己做一个 .deb

目录结构：

```
hello/
├── DEBIAN/control              # 包的描述
└── usr/local/bin/hello-price   # 要安装的文件，路径就是安装后的位置
```

`hello/DEBIAN/control` 的内容：

```
Package: hello-price
Version: 1.0.0
Architecture: all
Maintainer: Tom <tom@example.com>
Description: 演示用的 deb 包
```

打包、安装、运行：

```
$ dpkg-deb --build --root-owner-group hello hello-price_1.0.0_all.deb
dpkg-deb: building package 'hello-price' in 'hello-price_1.0.0_all.deb'.

$ sudo dpkg -i hello-price_1.0.0_all.deb
...
Setting up hello-price (1.0.0) ...

$ hello-price
你好，价格系统
```

`--root-owner-group` 让包里的文件都属于 root，否则安装后文件的所有者会是打包人的 UID。`Architecture: all` 表示不区分 CPU 架构（脚本类）。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 打包报 `control directory has bad permissions` | DEBIAN 目录权限不对 | `chmod 755 hello/DEBIAN` |
| 安装后的文件所有者是一个陌生的 UID | 打包时没加 `--root-owner-group` | 加上后重新打包 |

> ⚠️ 第一条的报错文字未实机验证。

### 5. 一句话总结

查看 .deb 用 `dpkg-deb -I` / `-c`，自己打包用 `dpkg-deb --build --root-owner-group 目录`。

<a id="cmd-dpkg-query"></a>

## 273 ★&nbsp;&nbsp;dpkg-query：按格式查询已安装的包

> 级别：★ 高级 · 软件包：`dpkg`

### 1. 作用

`dpkg-query` 是 `dpkg -l`、`dpkg -s` 背后真正干活的命令。它多了一个 `-W -f` 选项，可以**按自定义格式**输出已安装软件包的信息，适合在脚本里生成清单、做版本检查、找出占空间最大的软件。

### 2. 基本格式

```bash
dpkg-query -W -f='格式' [包名...]
```

常用字段：`${Package}`、`${Version}`、`${Installed-Size}`（KB）、`${Status}`、`${Architecture}`。

### 3. 常用示例

```
$ dpkg-query -W -f='${Package} ${Version}\n' tree htop curl
curl 8.18.0-1ubuntu2.8
htop 3.4.1-5build2
tree 2.3.1-1
```

找出占空间最大的 5 个软件包：

```
$ dpkg-query -W -f='${Installed-Size}\t${Package}\n' | sort -nr | head -5
216141	ansible
135358	libllvm21
134196	docker.io
125427	buildah
108192	python3-botocore
```

单位是 KB，第一个约 211 MB。

判断某个包是否已安装：

```
$ dpkg-query -W nothere-pkg; echo "退出码=$?"
dpkg-query: no packages found matching nothere-pkg
退出码=1
```

导出整台机器的软件清单，用来在另一台机器上对照：

```bash
dpkg-query -W -f='${Package}=${Version}\n' > packages.txt
```

### 4. 一句话总结

脚本里查包和版本用 `dpkg-query -W -f='${Package} ${Version}\n'`。

<a id="cmd-debconf-set-selections"></a>

## 274 ★&nbsp;&nbsp;debconf-set-selections：预先写好安装时的答案

> 级别：★ 高级 · 软件包：`debconf`

### 1. 作用

自动化安装时，有些软件包会弹出配置问答（例如 iptables-persistent 问“要不要保存当前规则”，postfix 问邮件服务器类型），脚本会卡住。`debconf-set-selections` 预先把答案写进 debconf 数据库，安装时就直接使用，不再提问。

### 2. 基本格式

```bash
echo "包名 问题名 类型 答案" | sudo debconf-set-selections
```

问题名和类型可以从一台已经装好的机器上查到：

```bash
sudo debconf-get-selections | grep ^包名    # 需要 debconf-utils 包
sudo debconf-show 包名
```

### 3. 常用示例

```
$ sudo debconf-show tzdata
* tzdata/Areas: Asia
  tzdata/Zones/Atlantic:
...
* tzdata/Zones/Asia: Shanghai
  tzdata/Zones/Etc: UTC
...
```

带 `*` 的是已经回答过的问题。

自动化安装时的完整写法：

```bash
echo "iptables-persistent iptables-persistent/autosave_v4 boolean true" | sudo debconf-set-selections
echo "iptables-persistent iptables-persistent/autosave_v6 boolean true" | sudo debconf-set-selections
sudo DEBIAN_FRONTEND=noninteractive apt-get install -y iptables-persistent
```

> ⚠️ iptables-persistent 这三行未实机验证。用 debconf-set-selections 设置 tzdata 的过程已在 [dpkg-reconfigure](#cmd-dpkg-reconfigure) 中实测。

### 4. 一句话总结

自动化安装前用 `debconf-set-selections` 写好答案，配合 `DEBIAN_FRONTEND=noninteractive`。

## 276 ★&nbsp;&nbsp;pro：Ubuntu Pro 订阅管理

> 级别：★ 高级 · 软件包：`ubuntu-pro-client`

### 1. 作用

Ubuntu Pro 是 Canonical 提供的订阅服务（个人最多 5 台机器免费），主要内容：

| 服务 | 作用 |
|---|---|
| esm-infra | main 仓库软件包的扩展安全维护（LTS 标准支持 5 年到期后再延长） |
| esm-apps | universe 仓库软件包的安全更新（标准支持里没有） |
| livepatch | 内核安全补丁热更新，不用重启 |
| fips、usg 等 | 合规相关 |

`pro` 命令用来绑定订阅、查看和启用这些服务。

### 2. 基本格式

```bash
pro status                   # 查看各项服务的状态
sudo pro attach 令牌          # 绑定订阅（令牌在 ubuntu.com/pro 获取）
sudo pro enable 服务名        # 启用服务
sudo pro detach              # 解除绑定
```

### 3. 常用示例

```
$ pro status
WARNING: this output is intended to be human readable, and subject to change.
In scripts, prefer using machine readable data from the `pro api` command,
or use `pro status --format json`.

SERVICE          AVAILABLE  DESCRIPTION
anbox-cloud      yes        Scalable Android in the cloud
esm-apps         yes        Expanded Security Maintenance for Applications
esm-infra        yes        Expanded Security Maintenance for Infrastructure
landscape        yes        Management and administration tool for Ubuntu
livepatch        yes        Canonical Livepatch service

For a list of all Ubuntu Pro services, run 'pro status --all'
```

还没绑定订阅时，只显示哪些服务可用。绑定后会多出 ENTITLED、STATUS 两列。脚本里用 `pro status --format json`。

> ⚠️ attach 和 enable 未实机验证（需要订阅令牌）。

### 4. 一句话总结

`pro status` 看服务，`sudo pro attach 令牌` 免费开启 ESM 和 Livepatch。

## 277 ★&nbsp;&nbsp;ubuntu-drivers：自动安装硬件驱动

> 级别：★ 高级 · 软件包：`ubuntu-drivers-common`

### 1. 作用

`ubuntu-drivers` 检测电脑上的硬件（主要是 NVIDIA 显卡、部分无线网卡），列出可用的专有驱动，并推荐和安装合适的版本。桌面版“软件和更新 → 附加驱动”背后用的就是它。服务器装 NVIDIA 显卡做计算时也用它。

### 2. 基本格式

```bash
ubuntu-drivers 子命令
```

| 子命令 | 作用 |
|---|---|
| `devices` | 列出需要驱动的设备，以及可用的驱动包 |
| `list` | 列出适用于本机的驱动包 |
| `install` | 安装推荐的驱动 |
| `install nvidia:570` | 安装指定版本 |
| `install --gpgpu` | 安装用于计算（不带图形界面组件）的驱动，服务器用 |

### 3. 常用示例

```bash
ubuntu-drivers devices
sudo ubuntu-drivers install
sudo reboot
nvidia-smi                 # 装好后确认显卡驱动正常
```

> ⚠️ 本页未实机验证：测试环境没有独立显卡，`ubuntu-drivers list` 只输出了 `ERROR:root:aplay command not found` 这样与驱动无关的提示。版本号 `570` 仅为示例，以 devices 的输出为准。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 装好驱动重启后黑屏或分辨率很低 | 开启了安全启动，驱动模块没有签名，加载失败 | 安装时按提示设置 MOK 密码，重启时在蓝色界面完成注册，见 [mokutil](18-启动和内核.md#cmd-mokutil) |
| 从 NVIDIA 官网下载 .run 文件安装，系统升级后驱动失效 | 绕过了包管理 | 优先用 ubuntu-drivers 或 apt 安装 |

### 5. 一句话总结

装显卡驱动用 `sudo ubuntu-drivers install`，不要用官网的 .run 文件。

<a id="cmd-needrestart"></a>

## 278 ★&nbsp;&nbsp;needrestart：检查哪些服务需要重启

> 级别：★ 高级 · 软件包：`needrestart`（Ubuntu 服务器版默认安装）

### 1. 作用

升级了系统库（如 OpenSSL、glibc）之后，已经在运行的程序还在使用内存里的旧版本，安全补丁对它们并没有生效，直到它们重启。`needrestart` 检查哪些服务、哪些进程用的是旧库，以及内核是否需要重启。Ubuntu 服务器版在 apt 升级完成后会自动运行它，并提示要不要重启那些服务。

### 2. 基本格式

```bash
sudo needrestart [参数]
```

| 参数 | 作用 |
|---|---|
| `-b` | 批处理模式，输出机器可读的结果 |
| `-r l` | 只列出，不重启 |
| `-r a` | 自动重启需要重启的服务 |
| `-k` | 只检查内核 |

### 3. 常用示例

```
$ sudo needrestart -b
NEEDRESTART-VER: 3.11
NEEDRESTART-KCUR: 6.1.188-233.393.amzn2023.x86_64
NEEDRESTART-KSTA: 0
NEEDRESTART-UCSTA: 0
```

| 字段 | 含义 |
|---|---|
| KCUR | 当前运行的内核 |
| KSTA | 内核状态：1 表示不需要重启，2、3 表示有新内核需要重启 |
| SVC 行（如果有） | 需要重启的服务名 |

> 测试环境的 KSTA 是 0（无法判断），因为容器借用的是宿主机的内核。

在 `/etc/needrestart/needrestart.conf` 里把 `$nrconf{restart}` 改成 `'a'`，升级后就会自动重启服务，不再询问。

> ⚠️ 交互式提示和自动重启未实机验证。

### 4. 一句话总结

升级后用 `sudo needrestart -r l` 看哪些服务还在用旧库。

<a id="cmd-snapcraft"></a>

## 298 ★&nbsp;&nbsp;snapcraft：构建 Snap 软件包

> 级别：★ 高级 · 软件包：snap 版（`sudo snap install snapcraft --classic`）

### 1. 作用

`snapcraft` 把自己的程序打包成 [snap](#cmd-snap) 格式，发布到 Snap 商店或者在内部分发。打包的配置写在 `snapcraft.yaml` 里：程序从哪来、怎么编译、依赖哪些包、需要哪些权限（插槽 plugs）。

### 2. 基本格式

```bash
snapcraft init       # 在当前目录生成 snap/snapcraft.yaml 模板
snapcraft pack       # 构建，生成 .snap 文件
sudo snap install ./名称_版本_amd64.snap --dangerous   # 本地安装测试
```

`--dangerous` 表示安装一个没有经过商店签名的本地 snap。

### 3. snapcraft.yaml 的基本结构

```yaml
name: hello-price
base: core24
version: '1.0'
summary: 演示用的 snap
description: 演示用的 snap
grade: stable
confinement: strict

apps:
  hello-price:
    command: bin/hello-price

parts:
  hello:
    plugin: dump
    source: ./src
```

| 字段 | 含义 |
|---|---|
| `base` | 运行时基础环境，对应某个 Ubuntu LTS（core24 = 24.04） |
| `confinement` | `strict` 严格沙箱，`classic` 不受限 |
| `parts` | 怎么获取和构建程序，`plugin` 决定构建方式（dump、python、go、nil 等） |

> ⚠️ 本页未实机验证：snapcraft 需要通过 snap 安装，并依赖 LXD 或虚拟机进行构建，测试环境不具备。

### 4. 一句话总结

自己的程序做成 snap：写 snapcraft.yaml，`snapcraft pack` 构建。
