## 219 ★&nbsp;&nbsp;lxc：LXD 系统容器和虚拟机

> 级别：★ 高级 · 软件包：snap 版 LXD（`sudo snap install lxd`）

### 1. 作用

LXD 是 Canonical 维护的系统容器和虚拟机管理器，`lxc` 是它的命令行客户端。和 Docker 的区别：Docker 容器通常只运行一个应用；LXD 的系统容器里运行的是一个完整的 Ubuntu（有 systemd、能 ssh 登录、能装软件），用起来像一台轻量的虚拟机，但启动只要几秒、占用资源很少。LXD 也能创建真正的 KVM 虚拟机。

适合：给每个项目一个独立的测试服务器、在一台物理机上跑多个隔离的环境。

### 2. 常用命令

| 命令 | 作用 |
|---|---|
| `lxd init --minimal` | 首次使用前初始化 |
| `lxc launch ubuntu:26.04 名称` | 创建并启动一个 Ubuntu 26.04 容器 |
| `lxc launch ubuntu:26.04 名称 --vm` | 创建虚拟机 |
| `lxc list` | 列出实例、状态和 IP |
| `lxc exec 名称 -- bash` | 进入 |
| `lxc stop` / `start` / `delete 名称` | 停止 / 启动 / 删除 |
| `lxc snapshot 名称 快照名` / `lxc restore 名称 快照名` | 快照和恢复 |
| `lxc file push 本地文件 名称/路径` | 把文件拷进去 |
| `lxc config set 名称 limits.cpu=2 limits.memory=2GiB` | 限制资源 |

### 3. 常用示例

```bash
sudo snap install lxd
sudo usermod -aG lxd $USER         # 重新登录
lxd init --minimal
lxc launch ubuntu:26.04 test01
lxc list
lxc exec test01 -- bash
```

`lxc list` 会显示每个实例的名称、状态（RUNNING/STOPPED）、IPv4 地址、类型（CONTAINER/VIRTUAL-MACHINE）。

> ⚠️ 本页未实机验证：LXD 需要 snapd 和 systemd，测试环境不具备。

### 4. 一句话总结

要一台“几秒就有”的 Ubuntu 测试机：`lxc launch ubuntu:26.04 名称`。

<a id="cmd-virsh"></a>

## 220 ★&nbsp;&nbsp;virsh：管理 KVM 虚拟机

> 级别：★ 高级 · 软件包：`libvirt-clients`（配合 `qemu-kvm`、`libvirt-daemon-system`）

### 1. 作用

KVM 是 Linux 内核自带的虚拟化，libvirt 是管理它的标准框架，`virsh` 是 libvirt 的命令行工具：列出、启动、关闭、暂停虚拟机，修改配置、做快照。图形界面的 virt-manager、Proxmox 以外的很多管理平台底层都是 libvirt。

### 2. 常用命令

| 命令 | 作用 |
|---|---|
| `virsh list --all` | 所有虚拟机（包括已关机的） |
| `virsh start` / `shutdown` / `destroy 名称` | 启动 / 正常关机 / 强制断电 |
| `virsh autostart 名称` | 宿主机开机时自动启动 |
| `virsh dominfo 名称` | CPU、内存等信息 |
| `virsh edit 名称` | 编辑虚拟机的 XML 配置 |
| `virsh console 名称` | 连接串口控制台（`Ctrl+]` 退出） |
| `virsh snapshot-create-as 名称 快照名` | 快照 |
| `virsh domifaddr 名称` | 查看虚拟机的 IP |

### 3. 常用示例

```bash
sudo apt install qemu-kvm libvirt-daemon-system libvirt-clients virtinst
sudo usermod -aG libvirt $USER
kvm-ok                                  # 确认 CPU 支持虚拟化（cpu-checker 包）
virsh list --all
virsh start db01
virsh domifaddr db01
virsh shutdown db01
```

创建新虚拟机一般用 `virt-install` 或图形界面 virt-manager。

> ⚠️ 本页未实机验证：测试环境不能运行 KVM。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `virsh shutdown` 之后虚拟机一直不关 | 虚拟机里的系统没有响应 ACPI 关机信号 | 在虚拟机里装 `qemu-guest-agent`；实在不行用 `destroy`（等于拔电源） |
| 普通用户 `virsh list` 看不到虚拟机 | 连到了用户级的 libvirt，而不是系统级 | 加入 libvirt 组；或 `virsh -c qemu:///system list --all` |

### 5. 一句话总结

`virsh list --all` 看虚拟机，`start`/`shutdown` 开关，强关用 `destroy`。

## 221 ★&nbsp;&nbsp;qemu-img：创建和转换虚拟磁盘镜像

> 级别：★ 高级 · 软件包：`qemu-utils`（QEMU 10.2）

### 1. 作用

`qemu-img` 创建、查看、转换、调整虚拟机的磁盘镜像。常见格式：

| 格式 | 说明 |
|---|---|
| qcow2 | KVM 默认格式，按需占用空间，支持快照和压缩 |
| raw | 原始格式，性能最好，不支持快照 |
| vmdk | VMware |
| vhdx | Hyper-V |
| vdi | VirtualBox |

从 VMware、Hyper-V 迁移虚拟机到 KVM 时，就是用 qemu-img 转换磁盘格式。

### 2. 常用命令

| 命令 | 作用 |
|---|---|
| `qemu-img create -f qcow2 文件 大小` | 创建 |
| `qemu-img info 文件` | 查看格式、虚拟大小、实际占用 |
| `qemu-img convert -f 源格式 -O 目标格式 源 目标` | 转换 |
| `qemu-img resize 文件 +10G` | 扩容 |
| `qemu-img check 文件` | 检查是否损坏 |
| `qemu-img snapshot -c 名称 / -l / -a 名称 文件` | 创建 / 列出 / 恢复快照（虚拟机关机时） |

### 3. 常用示例

```
$ qemu-img create -f qcow2 vm.qcow2 20G
Formatting 'vm.qcow2', fmt=qcow2 cluster_size=65536 extended_l2=off compression_type=zlib size=21474836480 lazy_refcounts=off refcount_bits=16

$ ls -lh vm.qcow2
-rw-r--r-- 1 root root 193K Oct 29 10:08 vm.qcow2

$ qemu-img info vm.qcow2
image: vm.qcow2
file format: qcow2
virtual size: 20 GiB (21474836480 bytes)
disk size: 196 KiB
...
```

虚拟大小 20 GB，实际只占 196 KB，写入数据后才逐渐变大。

```
$ qemu-img resize vm.qcow2 +10G; qemu-img info vm.qcow2 | grep "virtual size"
Image resized.
virtual size: 30 GiB (32212254720 bytes)

$ qemu-img convert -f raw -O qcow2 raw.img raw.qcow2; ls -lh raw.img raw.qcow2
-rw-r--r-- 1 root root 1.0G Oct 29 10:08 raw.img
-rw-r--r-- 1 root root 193K Oct 29 10:08 raw.qcow2

$ qemu-img check vm.qcow2
No errors were found on the image.
Image end offset: 327680

$ qemu-img snapshot -c before-upgrade vm.qcow2; qemu-img snapshot -l vm.qcow2
Snapshot list:
ID      TAG               VM_SIZE                DATE        VM_CLOCK     ICOUNT
1       before-upgrade        0 B 2026-10-29 10:08:49  0000:00:00.000          0
```

从 VMware 迁移：

```bash
qemu-img convert -p -f vmdk -O qcow2 web01.vmdk web01.qcow2
```

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 虚拟机运行时用 qemu-img 改了镜像，镜像损坏 | 两个程序同时写一个文件 | 先关机；运行中的快照用 `virsh snapshot-create-as` |
| resize 之后虚拟机里看到的磁盘大小没变 | 只扩了磁盘，分区和文件系统没扩 | 在虚拟机里用 growpart 和 resize2fs 扩 |

### 5. 一句话总结

`qemu-img info` 看镜像，`convert` 换格式，`resize` 扩容，操作前先关机。

## 222 ★&nbsp;&nbsp;multipass：快速启动 Ubuntu 虚拟机

> 级别：★ 高级 · 软件包：snap 版（`sudo snap install multipass`）

### 1. 作用

`multipass` 是 Canonical 出品的工具，一条命令就能启动一台全新的 Ubuntu 虚拟机，Windows、macOS、Linux 上都能用。比自己装 KVM、下载 ISO、走安装流程快得多，适合在开发机上临时开几台 Ubuntu 做测试。

### 2. 常用命令

| 命令 | 作用 |
|---|---|
| `multipass find` | 可用的镜像 |
| `multipass launch 26.04 -n 名称 -c 2 -m 4G -d 20G` | 启动一台：2 核、4 GB 内存、20 GB 磁盘 |
| `multipass list` | 列出虚拟机和 IP |
| `multipass shell 名称` | 登录 |
| `multipass exec 名称 -- 命令` | 执行一条命令 |
| `multipass transfer 本地文件 名称:路径` | 传文件 |
| `multipass mount 本地目录 名称:路径` | 共享目录 |
| `multipass stop` / `delete` / `purge` | 停止 / 删除 / 彻底清除已删除的 |

### 3. 常用示例

```bash
sudo snap install multipass
multipass launch 26.04 -n dev01 -c 2 -m 4G -d 20G
multipass shell dev01
multipass delete dev01 && multipass purge
```

启动时可以用 `--cloud-init 文件.yaml` 传入初始化配置，见 [cloud-init](18-启动和内核.md#cmd-cloud-init)。

> ⚠️ 本页未实机验证：multipass 需要 snapd 和虚拟化支持，测试环境不具备。

### 4. 一句话总结

开发机上要一台干净的 Ubuntu：`multipass launch 26.04 -n 名称`，用完 `delete` + `purge`。

## 245 ★&nbsp;&nbsp;nsenter：进入其他进程的命名空间

> 级别：★ 高级 · 软件包：`util-linux`

### 1. 作用

容器隔离的基础是 Linux 的**命名空间**（namespace）：每个容器有自己的网络、进程列表、主机名、挂载点。`nsenter` 让你进入某个进程所在的命名空间执行命令。最常见的用途：容器镜像里没有 ip、ss、tcpdump 等工具，用 nsenter 从宿主机进入容器的**网络**命名空间，用宿主机上的工具排查容器的网络问题。需要 root。

| 命名空间 | 参数 | 隔离的内容 |
|---|---|---|
| net | `-n` | 网卡、IP、路由、端口 |
| pid | `-p` | 进程列表 |
| mnt | `-m` | 挂载点（文件系统视图） |
| uts | `-u` | 主机名 |
| ipc | `-i` | 进程间通信 |
| user | `-U` | 用户和组 ID |

### 2. 基本格式

```bash
sudo nsenter -t PID 命名空间参数 命令
```

`-t PID` 指定目标进程，后面写要进入哪些命名空间，不写命令则启动一个 Shell。

### 3. 常用示例

先用 [unshare](#cmd-unshare) 启动一个拥有独立网络的进程，再从外面进入它的网络命名空间：

```
$ sudo unshare --net --fork sleep 300 &

$ P=$(pgrep -n -x sleep); sudo nsenter -t $P -n ip -br link
lo               DOWN           00:00:00:00:00:00 <LOOPBACK>
```

这个进程的网络里只有一块没启用的 lo，和宿主机完全隔离。

排查 Docker 容器的网络：

```bash
PID=$(docker inspect -f '{{.State.Pid}}' web)
sudo nsenter -t $PID -n ss -tlnp          # 容器里监听了哪些端口
sudo nsenter -t $PID -n tcpdump -i eth0   # 在容器的网卡上抓包
```

工具来自宿主机，容器镜像里不需要安装。

查看一个进程属于哪些命名空间：

```
$ ls -l /proc/73/ns | head -4
total 0
lrwxrwxrwx 1 root root 0 Oct 29 10:08 cgroup -> cgroup:[4026532677]
lrwxrwxrwx 1 root root 0 Oct 29 10:08 ipc -> ipc:[4026532675]
lrwxrwxrwx 1 root root 0 Oct 29 10:08 mnt -> mnt:[4026533178]
```

两个进程方括号里的编号相同，就在同一个命名空间里。

> ⚠️ Docker 部分未实机验证。

### 4. 一句话总结

容器里没工具排查网络：`sudo nsenter -t 容器PID -n 宿主机的命令`。

<a id="cmd-unshare"></a>

## 246 ★&nbsp;&nbsp;unshare：在新的命名空间里运行程序

> 级别：★ 高级 · 软件包：`util-linux`

### 1. 作用

`unshare` 让程序在新建的命名空间里运行，和系统的其他部分隔离开。它是容器技术最底层的积木，Docker、Podman 做的事情，本质上就是 unshare 加上 cgroup 加上一个镜像。日常用途：在完全断网的环境里测试程序、临时改主机名而不影响系统、做隔离实验。

### 2. 基本格式

```bash
sudo unshare [命名空间参数] [命令]
```

| 参数 | 新建的命名空间 |
|---|---|
| `--net` | 网络（只有一块未启用的 lo） |
| `--uts` | 主机名 |
| `--pid --fork --mount-proc` | 进程（里面的第一个进程 PID 为 1） |
| `--mount` | 挂载点 |
| `--user --map-root-user` | 用户（普通用户也能在里面“当 root”） |

### 3. 常用示例

```
$ sudo unshare --net ip -br link
lo               DOWN           00:00:00:00:00:00 <LOOPBACK>

$ sudo unshare --uts bash -c 'hostname sandbox-test; hostname'; hostname
sandbox-test
ubuntu

$ sudo unshare --pid --fork --mount-proc ps aux
USER         PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root           1  0.0  0.0   7204  4012 ?        R    10:08   0:00 ps aux

$ unshare --user --map-root-user id
uid=0(root) gid=0(root) groups=0(root)
```

| 例子 | 说明 |
|---|---|
| `--net` | 里面看不到任何真实网卡，程序完全断网 |
| `--uts` | 里面改了主机名，外面仍是 ubuntu |
| `--pid` | 里面只看得到自己的进程，ps 自己就是 1 号 |
| `--user` | 里面显示是 root，但实际上没有获得宿主机的 root 权限 |

测试一个程序在“没有网络”时的表现：

```bash
sudo unshare --net ./myapp
```

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `--pid` 后 `ps` 仍然显示宿主机的全部进程 | ps 读的是 /proc，没有重新挂载 | 加 `--fork --mount-proc` |
| 普通用户执行 `unshare --user` 报权限错误 | Ubuntu 26.04 通过 AppArmor 限制了非特权用户创建用户命名空间（`kernel.apparmor_restrict_unprivileged_userns = 1`） | 用 sudo；或为需要的程序配置 AppArmor 规则 |

> ⚠️ 第二条未实机验证（测试环境以 root 执行）。限制参数已在 `/usr/lib/sysctl.d/10-apparmor.conf` 中确认存在。

### 5. 一句话总结

临时隔离运行：断网用 `unshare --net`，独立进程表用 `--pid --fork --mount-proc`。

## 247 ★&nbsp;&nbsp;chroot：切换根目录

> 级别：★ 高级 · 软件包：`rust-coreutils`（系统自带）

### 1. 作用

`chroot` 让一个程序把指定的目录当成 `/` 来运行，它看到的整个文件系统就是这个目录里的内容。最重要的用途是**系统救援**：服务器开不了机时，用安装盘或救援系统启动，挂载原来的硬盘，chroot 进去，就能在原系统的环境里重装引导程序、重设密码、修复软件包。

chroot 只切换文件系统视图，不隔离进程和网络，**不是安全的沙箱**。

### 2. 基本格式

```bash
sudo chroot 新根目录 [命令]
```

不写命令时，运行新根目录里的 `/bin/bash`（或 $SHELL）。

### 3. 常用示例

用 [debootstrap](#cmd-debootstrap) 生成了一个最小的 Ubuntu 系统在 /srv/rootfs，先把 /proc、/dev、/sys 挂进去，再 chroot：

```
$ sudo mount -t proc proc /srv/rootfs/proc
$ sudo mount --rbind /dev /srv/rootfs/dev
$ sudo mount --rbind /sys /srv/rootfs/sys

$ sudo chroot /srv/rootfs bash -c 'head -2 /etc/os-release; whoami; ls /home | wc -l'
PRETTY_NAME="Ubuntu 26.04 LTS"
NAME="Ubuntu"
root
0

$ sudo chroot /srv/rootfs dpkg -l | wc -l
92

$ sudo umount -R /srv/rootfs/dev /srv/rootfs/sys /srv/rootfs/proc
```

新系统里一共装了 92 个软件包，home 目录是空的，和宿主机互不相干。

系统救援的典型步骤（从 Ubuntu 安装 U 盘的“试用”模式启动）：

```bash
sudo mount /dev/sda2 /mnt                 # 原系统的根分区
sudo mount /dev/sda1 /mnt/boot/efi        # EFI 分区
for d in dev proc sys run; do sudo mount --rbind /$d /mnt/$d; done
sudo chroot /mnt
# 现在相当于登录进了原系统：
passwd tom                                # 重设密码
update-grub                               # 修复引导
exit
```

> ⚠️ 系统救援步骤未实机验证，分区名以 `lsblk` 为准。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| chroot 后 ls 等命令直接崩溃，报 `thread 'main' panicked` | 没有挂载 /proc，Ubuntu 26.04 的 Rust 版 coreutils 依赖它 | 先挂载 /proc、/dev、/sys |
| `chroot: failed to run command 'nothere': No such file or directory (os error 2)` | 新根目录里没有这个程序 | 程序路径以新根目录为准；新根目录里要有 /bin/bash |
| chroot 用完后删不掉目录，报 `Device or resource busy` | 挂进去的 /dev 等还没卸载 | `sudo umount -R 新根目录/dev` 等，再删除 |

第一条的实测（没有挂载 /proc 时）：

```
$ sudo chroot /srv/rootfs ls /

thread 'main' (5213) panicked at /build/rust-coreutils-u5JpDp/rust-coreutils-0.8.0/rust-vendor/rustix/src/backend/linux_raw/param/auxv.rs:269:22:
called `Result::unwrap()` on an `Err` value: ()
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
```

### 5. 一句话总结

救援时 `mount` 原系统，挂好 /dev /proc /sys，再 `chroot /mnt`。

## 248 ★&nbsp;&nbsp;debootstrap：构建一个最小的 Ubuntu 系统

> 级别：★ 高级 · 软件包：`debootstrap`

### 1. 作用

`debootstrap` 从软件源下载基础软件包，在一个空目录里装出一套最小的 Ubuntu（或 Debian）系统。用途：制作自定义的容器镜像或虚拟机镜像、为 chroot 准备一个干净的构建环境、在不支持安装程序的地方手工装系统。

### 2. 基本格式

```bash
sudo debootstrap [参数] 代号 目标目录 [镜像地址]
```

| 参数 | 作用 |
|---|---|
| `--variant=minbase` | 最小化：只装必需的包 |
| `--include=包,包` | 额外安装的包 |
| `--arch=arm64` | 指定架构 |

代号：26.04 是 `resolute`，24.04 是 `noble`。

### 3. 常用示例

```
$ time sudo debootstrap --variant=minbase resolute /srv/rootfs http://archive.ubuntu.com/ubuntu
...
I: Configuring apt...
I: Configuring libc-bin...
I: Base system installed successfully.

real	0m53.066s
user	0m7.015s
sys	0m3.520s

$ du -sh /srv/rootfs
153M	/srv/rootfs
```

不到一分钟，得到了一个 153 MB 的最小系统。国内网络可以把最后的地址换成国内镜像站。之后用 [chroot](#cmd-chroot) 进入，继续安装需要的软件。

### 4. 一句话总结

要一个干净的最小 Ubuntu：`sudo debootstrap --variant=minbase resolute 目录`。
