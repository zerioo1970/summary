## 035 ★★★&nbsp;&nbsp;tar：打包和解包

> 级别：★★★ 初级 · 软件包：`tar`（GNU 版）

### 1. 作用

`tar` 把多个文件和目录打包成一个文件，通常同时用 gzip 或 xz 压缩，得到 `.tar.gz` 或 `.tar.xz`。Linux 上的软件源码、备份、日志归档基本都是这种格式。

tar 会保留文件的权限、所有者和时间，所以 Linux 之间传文件、做备份时优先用 tar，不用 zip。

### 2. 基本格式

```bash
tar -czf 包名.tar.gz 文件或目录...     # 打包并压缩
tar -xzf 包名.tar.gz [-C 目标目录]      # 解包
tar -tzf 包名.tar.gz                    # 只看包里有什么
```

### 3. 常用参数

参数通常组合在一起写，记住前三个动作参数，其他的按需加：

| 参数 | 作用 |
|---|---|
| `-c` | create，创建新包 |
| `-x` | extract，解包 |
| `-t` | list，列出包里的内容 |
| `-f 文件` | 指定包的文件名，**必须放在参数最后**，紧跟文件名 |
| `-z` | 用 gzip 压缩/解压（`.tar.gz`、`.tgz`） |
| `-J` | 用 xz 压缩/解压（`.tar.xz`），压缩率更高、更慢 |
| `-v` | 显示处理了哪些文件 |
| `-C 目录` | 解包到指定目录 |
| `--exclude="模式"` | 打包时排除某些文件 |

### 4. 常用示例

#### 4.1 打包压缩一个目录

```
$ tar -czf logs.tar.gz logs

$ ls -l logs.tar.gz
-rw-r--r-- 1 tom tom 374 Oct 29 06:55 logs.tar.gz
```

#### 4.2 `-t`：解包前先看内容

```
$ tar -tzf logs.tar.gz
logs/
logs/app.log

$ tar -tvzf src.tar.gz
drwxr-xr-x tom/tom           0 2026-10-29 06:55 src/
-rw-r--r-- tom/tom         152 2026-10-29 06:55 src/products.csv
-rw-r--r-- tom/tom           6 2026-10-01 09:00 readme.txt
```

先看看包里是不是带了一层目录，免得解开后文件散落一地。

#### 4.3 `-v`：打包多个对象，并显示过程

```
$ tar -czvf src.tar.gz src readme.txt
src/
src/products.csv
readme.txt
```

#### 4.4 `-x -C`：解包到指定目录

```
$ mkdir restore; tar -xzf src.tar.gz -C restore; ls -R restore
restore:
readme.txt
src

restore/src:
products.csv
```

不加 `-C` 时解到当前目录。

#### 4.5 只解出其中一个文件

```bash
tar -xzf src.tar.gz -C restore src/products.csv
```

文件路径要和 `tar -t` 列出来的完全一致。

#### 4.6 `-J`：xz 格式

```
$ tar -cJf logs.tar.xz logs

$ tar -xf logs.tar.xz -C /tmp && ls /tmp/logs
app.log
```

解包时可以不写 `-z`、`-J`，`tar -xf` 会自动识别压缩格式。

#### 4.7 `--exclude`：备份时跳过某些文件

```bash
tar -czf ../demo.tar.gz --exclude="*.iso" .
```

备份网站时常用 `--exclude="*.log" --exclude="cache"` 跳过日志和缓存。

#### 4.8 带日期的备份文件名

```
$ tar -czf backup-$(date +%Y%m%d).tar.gz logs; ls backup-*
backup-20261029.tar.gz
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 写成 `tar -cfz x.tar.gz logs`，生成了一个叫 `z` 的文件 | `-f` 后面紧跟的就是文件名，这里是 `z` | `-f` 放在最后：`-czf` |
| 打包当前目录报 `tar: .: file changed as we read it`，包里还包含了它自己 | 包文件就生成在被打包的目录里 | 把包写到别的目录：`tar -czf ../x.tar.gz .` |
| 用绝对路径打包，提示 `Removing leading '/' from member names` | tar 自动去掉开头的 `/`，防止解包时覆盖系统文件 | 这是保护机制。想要相对路径，用 `-C`：`tar -czf x.tar.gz -C /home/tom/demo logs` |
| `tar -cJf` 报 `xz: not found` | 系统没装 xz（最小化镜像里常见） | `sudo apt install xz-utils` |
| 解包覆盖了同名文件 | tar 解包时直接覆盖 | 先 `-t` 看内容，再用 `-C` 解到一个新目录 |

第二条的实测（包名 all.tar.gz 出现在了自己的内容里）：

```
$ tar -czf all.tar.gz --exclude="*.iso" .
tar: .: file changed as we read it
```

第三条的实测：

```
$ tar -czf logs2.tar.gz /home/tom/demo/logs
tar: Removing leading `/' from member names

$ tar -tzf logs2.tar.gz
home/tom/demo/logs/
home/tom/demo/logs/app.log
```

### 6. 一句话总结

打包 `tar -czf 包 目录`，看内容 `-tzf`，解包 `-xzf 包 -C 目录`，`-f` 永远放最后。

## 036 ★★★&nbsp;&nbsp;zip：压缩成 zip 格式

> 级别：★★★ 初级 · 软件包：`zip`

### 1. 作用

`zip` 把文件和目录压缩成 `.zip` 文件。Linux 内部传文件用 tar 更合适，但要发给 Windows 用户、上传到只认 zip 的系统时，用 zip。

解压用 [unzip](#cmd-unzip)。

### 2. 基本格式

```bash
zip [参数] 压缩包.zip 文件或目录...
```

压缩包名在前，要压缩的内容在后，和 tar 的顺序一样。

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-r` | 递归压缩目录（压缩目录必须加） |
| `-q` | 不显示过程 |
| `-e` | 加密码，执行后会提示输入 |
| `-9` | 最高压缩率（`-1` 最快，默认 `-6`） |
| `-u` | 更新：只加入新增或有改动的文件 |
| `-d` | 从压缩包里删除指定文件 |
| `-x "模式"` | 排除某些文件 |

### 4. 常用示例

#### 4.1 压缩单个文件

```
$ zip readme.zip readme.txt
  adding: readme.txt (stored 0%)
```

`stored 0%` 表示文件太小，直接存储，没有压缩。

#### 4.2 `-r`：压缩目录

```
$ zip -r logs.zip logs
  adding: logs/ (stored 0%)
  adding: logs/app.log (deflated 49%)
```

`deflated 49%` 表示这个文件压缩后小了 49%。

#### 4.3 看压缩包里有什么

```
$ unzip -l logs.zip
Archive:  logs.zip
  Length      Date    Time    Name
---------  ---------- -----   ----
        0  2026-10-29 06:55   logs/
      404  2026-10-28 11:30   logs/app.log
---------                     -------
      404                     2 files
```

#### 4.4 `-e`：加密码

```bash
zip -r -e salary.zip 工资表/
```

执行后会两次提示输入密码，输入时屏幕不显示。

> ⚠️ 4.4 未实机验证：输入密码需要真实终端，测试环境里 zip 报错 `Invalid command arguments (stderr is not a tty)`。

#### 4.5 `-x`：排除文件

```bash
zip -r project.zip project -x "*.log" -x "*/node_modules/*"
```

#### 4.6 `-d`：从包里删掉一个文件

```
$ zip -d logs.zip logs/app.log
deleting: logs/app.log
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `zip logs.zip logs` 之后，压缩包里只有一个空目录 | 没加 `-r`，只压了目录本身 | 加 `-r` |
| `zip error: Nothing to do!` | 只写了压缩包名，没写要压缩什么；或者文件名写错 | 检查命令末尾的文件列表 |
| 解压后文件权限、所有者全变了 | zip 格式不完整保存 Linux 的所有者等信息 | Linux 之间备份用 tar |
| 把 `-e` 加密当成安全措施 | zip 传统加密强度很弱 | 敏感数据用 `gpg` 加密，或用 `7z` 的 AES 加密 |

### 6. 一句话总结

压目录用 `zip -r 包.zip 目录`，给 Windows 用户用 zip，Linux 之间用 tar。

## 037 ★★★&nbsp;&nbsp;unzip：解压 zip 文件

> 级别：★★★ 初级 · 软件包：`unzip`

### 1. 作用

`unzip` 解压 `.zip` 文件，也可以只查看或测试压缩包的内容。从 Windows 同事那里收到的压缩包、从网上下载的 zip 软件包，都用它解。

### 2. 基本格式

```bash
unzip [参数] 压缩包.zip [要解出的文件...] [-d 目标目录]
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-d 目录` | 解压到指定目录（不存在会自动创建） |
| `-l` | 只列出内容，不解压 |
| `-o` | 遇到同名文件直接覆盖，不询问 |
| `-n` | 遇到同名文件一律跳过 |
| `-q` | 不显示过程 |
| `-t` | 测试压缩包是否完整 |
| `-O 编码` | 指定文件名的编码，解决中文文件名乱码，如 `-O GBK` |

### 4. 常用示例

#### 4.1 `-l`：先看内容

```
$ unzip -l pkg.zip
Archive:  pkg.zip
  Length      Date    Time    Name
---------  ---------- -----   ----
        0  2026-10-29 06:55   logs/
      404  2026-10-28 11:30   logs/app.log
        0  2026-10-29 06:55   src/
      152  2026-10-29 06:55   src/products.csv
        6  2026-10-01 09:00   readme.txt
---------                     -------
      562                     5 files
```

#### 4.2 `-d`：解压到指定目录

```
$ unzip pkg.zip -d out
Archive:  pkg.zip
   creating: out/logs/
  inflating: out/logs/app.log
   creating: out/src/
  inflating: out/src/products.csv
 extracting: out/readme.txt
```

#### 4.3 遇到同名文件

再解压一次到同一个目录，unzip 会逐个询问：

```
replace out/logs/app.log? [y]es, [n]o, [A]ll, [N]one, [r]ename:
```

| 输入 | 效果 |
|---|---|
| `y` / `n` | 覆盖 / 跳过这一个 |
| `A` | 后面全部覆盖 |
| `N` | 后面全部跳过 |
| `r` | 改个名字保存 |

不想被询问：覆盖用 `unzip -o`，跳过用 `unzip -n`。

#### 4.4 只解出一个文件

```
$ unzip pkg.zip readme.txt -d one
Archive:  pkg.zip
 extracting: one/readme.txt
```

#### 4.5 `-t`：检查压缩包是否损坏

```
$ unzip -t pkg.zip
Archive:  pkg.zip
    testing: logs/                    OK
    testing: logs/app.log             OK
    testing: src/                     OK
    testing: src/products.csv         OK
    testing: readme.txt               OK
No errors detected in compressed data of pkg.zip.
```

下载的大文件解压报错时，先用 `-t` 确认是不是下载不完整。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| Windows 上打包的 zip，解压后中文文件名是乱码 | Windows 中文版的 zip 工具用 GBK 编码保存文件名，Linux 默认按 UTF-8 解读 | `unzip -O GBK 文件.zip` |
| 解压后当前目录多了一堆散乱的文件 | 压缩包里没有外层目录 | 先 `unzip -l` 看结构，再用 `-d 新目录` 解压 |
| `unzip: cannot find or open nothere.zip, nothere.zip.zip or nothere.zip.ZIP.` | 文件名或路径写错 | 用 `ls` 确认文件名，输入时按 Tab 补全 |
| `unzip: command not found` | 部分最小化安装没有 unzip | `sudo apt install unzip` |

> ⚠️ 第一条未实机验证：测试环境没有 Windows 生成的压缩包。`-O` 参数已在 Ubuntu 26.04 的 `unzip -h` 中确认存在。

### 6. 一句话总结

先 `unzip -l` 看结构，再 `unzip 包 -d 目录`；中文乱码加 `-O GBK`。

## 081 ★★★&nbsp;&nbsp;gzip：压缩单个文件

> 级别：★★★ 初级 · 软件包：`gzip`

### 1. 作用

`gzip` 把一个文件压缩成 `.gz` 格式。日志轮转后的旧日志（`syslog.2.gz`）、`.tar.gz` 里的压缩层，用的都是 gzip。文本类文件（日志、CSV、SQL 导出）通常能压到原来的 10%–50%。

gzip 只压缩**单个文件**，并且默认会**用压缩后的文件替换原文件**。要把多个文件或目录打成一个包，用 [tar](#cmd-tar)。

### 2. 基本格式

```bash
gzip [参数] 文件...
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-k` | `--keep` | 保留原文件 |
| `-d` | `--decompress` | 解压，等同 gunzip |
| `-l` | `--list` | 查看压缩率 |
| `-c` | `--stdout` | 输出到屏幕（标准输出），原文件不动 |
| `-r` | `--recursive` | 把目录里的每个文件分别压缩 |
| `-v` | `--verbose` | 显示压缩率 |
| `-1` … `-9` | | 压缩级别：1 最快，9 压得最小，默认 6 |

### 4. 常用示例

#### 4.1 压缩

```
$ gzip app.log; ls -l app.log*
-rw-r--r-- 1 tom tom 234 Oct 29 07:08 app.log.gz
```

原来的 app.log 不见了，只剩 app.log.gz。

#### 4.2 `-l`：看压缩率

```
$ gzip -l app.log.gz
         compressed        uncompressed  ratio uncompressed_name
                234                 404  48.5% app.log
```

#### 4.3 `-k`：保留原文件

```
$ gzip -k app.log; ls app.log*
app.log  app.log.gz
```

#### 4.4 `-9 -v`：最大压缩并显示结果

```
$ gzip -9 -v app.log
app.log:         48.5% -- replaced with app.log.gz
```

#### 4.5 不解压直接查看

```
$ zcat app.log.gz | head -2
2026-10-28 09:00:01 INFO  服务启动
2026-10-28 09:00:05 INFO  连接数据库成功
```

`zcat`、`zless`、`zgrep` 可以直接读 .gz 文件，查旧日志时不用先解压。

#### 4.6 `-r`：逐个压缩目录里的文件

```
$ gzip -r logs; ls logs
app.log.gz
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 压缩后原文件没了 | gzip 默认替换原文件 | 需要保留就加 `-k` |
| `gzip: app.log.gz already exists;        not overwritten` | 同名的 .gz 已经存在 | 删掉旧的 .gz，或加 `-f` 强制覆盖 |
| `gzip: logs is a directory -- ignored` | gzip 不能把目录压成一个文件 | 用 `tar -czf logs.tar.gz logs` |
| 压缩正在写入的日志，程序继续写的内容丢了 | 程序仍往原来那个（已被删除的）文件里写 | 先让程序切换日志文件（logrotate 会处理），再压缩旧文件 |

### 6. 一句话总结

`gzip 文件` 压缩并替换，`-k` 保留原文件，查看 .gz 用 `zcat`、`zgrep`。

## 082 ★★★&nbsp;&nbsp;gunzip：解压 .gz 文件

> 级别：★★★ 初级 · 软件包：`gzip`

### 1. 作用

`gunzip` 解压 `.gz` 文件，还原出原文件，并删除 .gz 文件。它等同于 `gzip -d`。

`.tar.gz` 文件不要用 gunzip，用 `tar -xzf` 一步解开。

### 2. 基本格式

```bash
gunzip [参数] 文件.gz...
```

### 3. 常用参数

| 参数 | 长格式 | 作用 |
|---|---|---|
| `-k` | `--keep` | 保留 .gz 文件 |
| `-c` | `--stdout` | 解压到屏幕（标准输出），.gz 文件不动 |
| `-r` | `--recursive` | 解压目录里所有的 .gz |
| `-f` | `--force` | 目标文件已存在时强制覆盖 |

### 4. 常用示例

#### 4.1 解压

```
$ gunzip app.log.gz; ls -l app.log*
-rw-r--r-- 1 tom tom 404 Oct 29 07:08 app.log
```

#### 4.2 `-c`：解压成另一个文件，保留 .gz

```
$ gunzip -c app.log.gz > copy.log; ls app.log* copy.log
app.log.gz  copy.log
```

#### 4.3 `gzip -d`：效果相同

```
$ gzip -d app.log.gz; ls app.log*
app.log
```

#### 4.4 `-r`：解压整个目录

```
$ gunzip -r logs; ls logs
app.log
```

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `gzip: nothere.gz: No such file or directory` | 文件名写错 | 用 ls 确认，输入时按 Tab 补全 |
| 对 .tar.gz 用了 gunzip，得到一个 .tar 文件 | gunzip 只去掉 gzip 那一层 | 继续 `tar -xf 文件.tar`；以后直接 `tar -xzf 文件.tar.gz` |
| 只是想查一下旧日志，解压后占满了磁盘 | 大日志解压后体积会变成好几倍 | 用 `zgrep 关键词 文件.gz` 或 `zless` 直接查 |

### 6. 一句话总结

`gunzip 文件.gz` 解压，`-k` 保留压缩包，只是查看就用 `zcat`。

## 158 ★★&nbsp;&nbsp;xz：高压缩率的单文件压缩

> 级别：★★ 中级 · 软件包：`xz-utils`

### 1. 作用

`xz` 和 [gzip](#cmd-gzip) 一样压缩单个文件，压缩率更高，但速度更慢、更耗内存。Linux 内核源码、很多软件的发布包都用 `.tar.xz` 格式。适合“压一次、存很久、下载很多次”的场景；日常日志压缩用 gzip 更快。

用法和 gzip 几乎一样：默认替换原文件，`-k` 保留，`-d` 解压。

### 2. 基本格式

```bash
xz [参数] 文件...
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-k` | 保留原文件 |
| `-d` | 解压（等同 `unxz`） |
| `-l` | 查看压缩信息 |
| `-0` … `-9` | 压缩级别，默认 6 |
| `-T0` | 使用所有 CPU 核心并行压缩 |
| `-f` | 目标已存在时覆盖 |

### 4. 常用示例

```
$ xz -k logs/app.log; ls -l logs/
total 8
-rw-r--r-- 1 tom tom 404 Oct 28 11:30 app.log
-rw-r--r-- 1 tom tom 276 Oct 28 11:30 app.log.xz

$ xz -l logs/app.log.xz
Strms  Blocks   Compressed Uncompressed  Ratio  Check   Filename
    1       1        276 B        404 B  0.683  CRC64   logs/app.log.xz
```

Ratio 0.683 表示压缩后是原来的 68.3%。文件越大、重复内容越多，压缩率越高。

打包时直接用 tar 调用 xz：`tar -cJf 包.tar.xz 目录`，见 [tar](#cmd-tar)。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 压缩几 GB 的文件要很久 | xz 默认单线程，压缩率高、速度慢 | 加 `-T0` 多核并行；对速度敏感就用 gzip 或 zstd |
| 小内存的机器上用 `-9` 压缩，报内存不足 | 高压缩级别要几百 MB 内存 | 降低级别，用默认的 `-6` |

### 6. 一句话总结

`xz -k -T0 文件` 压得更小，代价是更慢；日常用 gzip，发布包用 xz。

## 159 ★★&nbsp;&nbsp;bzip2：bzip2 格式压缩

> 级别：★★ 中级 · 软件包：`bzip2`

### 1. 作用

`bzip2` 也是单文件压缩工具，压缩率和速度介于 gzip 和 xz 之间。现在新项目很少主动选用它，但旧的备份、旧软件的源码包（`.tar.bz2`）还很常见，所以要会解压。

### 2. 基本格式

```bash
bzip2 [参数] 文件       # 压缩，生成 .bz2
bunzip2 文件.bz2        # 解压
bzcat 文件.bz2          # 不解压直接查看
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-k` | 保留原文件 |
| `-d` | 解压 |
| `-c` | 输出到标准输出 |

### 4. 常用示例

```
$ bzip2 -k src/products.csv; ls -l src/
total 8
-rw-r--r-- 1 tom tom 152 Oct 29 08:41 products.csv
-rw-r--r-- 1 tom tom 150 Oct 29 08:41 products.csv.bz2

$ bunzip2 -c src/products.csv.bz2 | head -2
code,name,category,price
U001,探头A,探头,12000

$ bzcat src/products.csv.bz2 | wc -l
6
```

很小的文件压缩后几乎不变小（152 → 150），因为压缩格式本身有额外开销。

解开 `.tar.bz2`：`tar -xjf 包.tar.bz2`，或直接 `tar -xf`，tar 会自动识别。

### 5. 一句话总结

遇到 `.bz2` 用 `bunzip2` 或 `bzcat`，`.tar.bz2` 用 `tar -xf`。

## 160 ★★&nbsp;&nbsp;7z：7-Zip 压缩和解压

> 级别：★★ 中级 · 软件包：`7zip`（7-Zip 26.00，需 `sudo apt install 7zip`）

### 1. 作用

`7z` 是 7-Zip 的命令行版本。它支持 `.7z` 格式（压缩率高、支持 AES-256 加密），还能解压几乎所有常见格式：zip、rar（只能解压）、tar、gz、iso 等。从 Windows 同事那里收到 `.7z` 或 `.rar` 文件时用它。

### 2. 基本格式

```bash
7z a 压缩包.7z 文件或目录...     # 压缩（a = add）
7z l 压缩包                      # 查看内容（l = list）
7z x 压缩包 [-o目录]             # 解压，保留目录结构（x = extract）
```

### 3. 常用参数

| 参数 | 作用 |
|---|---|
| `-o目录` | 解压到指定目录（`-o` 和目录之间**没有空格**） |
| `-p密码` | 设置或输入密码 |
| `-mhe=on` | 连文件名也加密（只对 .7z 格式有效） |
| `-mx=9` | 最高压缩级别 |

### 4. 常用示例

#### 4.1 压缩

```
$ 7z a demo.7z logs src

7-Zip 26.00 (x64) : Copyright (c) 1999-2026 Igor Pavlov : 2026-02-12
 64-bit locale=C.UTF-8 Threads:8 OPEN_MAX:1024, ASM

Scanning the drive:
2 folders, 4 files, 982 bytes (1 KiB)

Creating archive: demo.7z

Add new data to archive: 2 folders, 4 files, 982 bytes (1 KiB)


Files read from disk: 4
Archive size: 981 bytes (1 KiB)
Everything is Ok
```

#### 4.2 查看和解压

```
$ 7z l demo.7z | tail -6
2026-10-28 11:30:00 ....A          404          730  logs/app.log
2026-10-28 11:30:00 ....A          276               logs/app.log.xz
2026-10-29 08:41:35 ....A          152               src/products.csv
2026-10-29 08:41:35 ....A          150               src/products.csv.bz2
------------------- ----- ------------ ------------  ------------------------
2026-10-29 08:41:36                982          730  4 files, 2 folders

$ 7z x demo.7z -oout7z | tail -3
Files: 4
Size:       982
Compressed: 981
```

#### 4.3 加密压缩

```
$ 7z a -p'Zip@2026' -mhe=on secret.7z src | tail -2
Archive size: 527 bytes (1 KiB)
Everything is Ok
```

`-mhe=on` 让别人不输密码连里面有哪些文件都看不到。之后执行 `7z l secret.7z` 或 `7z x secret.7z` 会提示输入密码。

### 5. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `7z x 包 -o /tmp/out` 报错 | `-o` 和目录之间不能有空格 | 写成 `-o/tmp/out` |
| 用 `7z e` 解压，所有文件都散落在同一层 | `e` 不保留目录结构 | 用 `x` |
| 网上教程用的 `p7zip-full`、`7za` 命令找不到 | Ubuntu 26.04 提供的是官方的 `7zip` 包，命令是 `7z` | `sudo apt install 7zip` |
| 在命令行里写 `-p密码`，密码留在了 history 里 | 密码是命令参数 | 只写 `-p` 不带密码，7z 会提示输入 |

### 6. 一句话总结

`7z a` 压缩、`7z x 包 -o目录` 解压，加密用 `-p -mhe=on`。

<a id="cmd-zcat"></a>

## 161 ★★&nbsp;&nbsp;zcat：不解压直接查看 .gz 文件

> 级别：★★ 中级 · 软件包：`gzip`

### 1. 作用

`zcat` 把 `.gz` 文件解压后的内容直接输出到屏幕，磁盘上的 .gz 文件保持不变。查看被轮转压缩了的旧日志（`syslog.2.gz`、`access.log.3.gz`）时，不用先 gunzip。它等同于 `gunzip -c`。

同一家族还有 `zless`（分页看）、`zgrep`（搜索）、`zdiff`（比较）。

### 2. 基本格式

```bash
zcat 文件.gz... | 其他命令
```

### 3. 常用示例

```
$ zcat logs/app.log.gz | head -2
2026-10-28 09:00:01 INFO  服务启动
2026-10-28 09:00:05 INFO  连接数据库成功
```

把当前日志和所有压缩过的旧日志合在一起统计：

```bash
zcat -f /var/log/nginx/access.log* | wc -l
```

`-f` 让 zcat 遇到没压缩的普通文件也照常输出。

### 4. ⚠️ 踩坑警告

| 现象 | 原因 | 怎么改 |
|---|---|---|
| `gzip: logs/app.log: not in gzip format` | 文件没有压缩过 | 用 cat；或 `zcat -f` 两种都能处理 |

### 5. 一句话总结

旧日志是 .gz，用 `zcat` 或 `zless` 直接看，不用解压。

<a id="cmd-zgrep"></a>

## 162 ★★&nbsp;&nbsp;zgrep：在 .gz 文件里搜索

> 级别：★★ 中级 · 软件包：`gzip`

### 1. 作用

`zgrep` 在 `.gz` 压缩文件里搜索关键词，参数和 [grep](03-文本处理.md#cmd-grep) 一样。查“上周的日志里有没有这个订单号”时，不用先把十几个 .gz 文件解压。

### 2. 基本格式

```bash
zgrep [grep 的参数] 关键词 文件.gz...
```

### 3. 常用示例

```
$ zgrep ERROR logs/app.log.gz
2026-10-28 10:02:13 ERROR 订单 A1002 保存失败：超时
2026-10-28 11:30:40 ERROR 连接数据库失败

$ zgrep -c INFO logs/app.log.gz
5
```

一次搜索全部轮转日志（压缩的和没压缩的都行）：

```bash
zgrep -h "A1002" /var/log/app/app.log*
```

`-h` 不显示文件名。

### 4. 一句话总结

在压缩日志里找东西用 `zgrep`，参数和 grep 相同。
