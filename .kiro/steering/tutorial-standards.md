# 教程编写规范（自动加载）

编写任何教程 / 学习材料前，先读规范全文：

#[[file:教程编写规范.md]]

## 不读全文也必须守住的红线

1. **读者不是编程新人**：20 年 C#/SQL 企业开发经验。不解释变量、循环、数据库表。讲"为什么这样设计""什么时候不该用"。
2. **单章上限**：≤ 90 分钟、≤ 400 行、**新概念 ≤ 3 个**。每章必须能独立跑通。
3. **先能跑再讲为什么**：图解 → 最小可运行代码 → 拆解运行结果 → 改坏一处试试。禁止先铺理论。
4. **每个概念必须给反例**（什么时候不该用），这是必填项。
5. **代码完整可运行**，禁 `...` 省略，首行注释写文件路径，长代码落盘 `code/chNN/`；未实机验证须标注。
6. **类比分场景**：前端 / React / TS **禁用** C#、WebForm 类比；Python / ML / LangChain **可以**用 C#、SQL 类比。
7. **前端一律 TypeScript**，strict 开启，**禁 `any`**。后端示例用 Spring Boot 3.5 + MyBatis-Flex + SQL Server + Gradle。
8. **禁数学推导**，只用均值/标准差/百分比/差分/相关性/概率直觉，用具体数值代替符号。
9. **Mermaid ≤ 2 列节点**、`graph TB`、标签每行 ≤ 20 中文字用 `<br/>` 换行、禁带 direction 的 subgraph 左右对照。
10. **参考答案放文件最末**，`---` + 提示注释 + 30 空行隔离，正文不提前透露。
11. **禁**跳步（"以此类推""留给读者"）、空洞小结、营销词（强大/优雅/丝滑/开箱即用）、编造踩坑。
12. 交付前过一遍规范第 13 节自查清单，并更新 README 进度表。

## 修改规范的方式

用户说「改教程规范：……」时：改 `教程编写规范.md` → 直推 main → **同步更新全局记忆**（否则其他仓库的会话仍用旧规则）。
